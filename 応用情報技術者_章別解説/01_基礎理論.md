# 第1章 基礎理論

## この章の地図

基礎理論は、IT の「土台になる数学」です。高校数学に近い部分もありますが、応用情報ではそれをコンピュータの判断、圧縮、言語処理、AI、性能評価に使います。

条件を正しく表すには集合と論理が必要です。情報を短く表したり誤りに強くしたりするには、情報理論と符号化が必要です。文字列を機械的に判定するには、オートマトンと形式言語が役立ちます。点と線で関係や経路を扱うと、ネットワークや依存関係をグラフとして見られます。不確実なデータを扱うときは確率、統計、回帰分析が必要になり、コンピュータで近似的に答えを求めるときは数値計算の限界を知る必要があります。AI も、データから規則を学ぶ仕組みとして、この基礎の上にあります。

## なぜこの章を学ぶのか

基礎理論は、すぐにアプリの画面やサーバの形として見える知識ではありません。そのため初学者には「何の役に立つのか」が見えにくい章です。しかし、IT の深い部分ではこの章の考え方が何度も出てきます。

たとえば、ログインできるかどうかを判断する条件は論理です。ファイルを圧縮する仕組みは情報理論です。検索エンジンがページ同士のつながりを見るときはグラフ理論です。障害検知や売上予測では確率・統計・回帰分析を使います。AI も、データを数式で扱う基礎の上に成り立っています。

この章を学ぶと、個別の技術をばらばらの名前として見るのではなく、「これは条件の問題だ」「これは確率の問題だ」「これは関係をグラフで見ればよい」と見抜けるようになります。これは高度な IT 知識の土台です。

## 1.1 集合と論理

この節を学ぶ理由は、「条件を正しく扱う力」を身につけるためです。コンピュータは、あいまいな雰囲気では判断できません。「会員で、支払い済みで、利用停止中ではない人だけ入れる」のような条件を、正確に表す必要があります。

集合は対象をグループ分けする道具、論理は条件を組み合わせる道具です。これを知ると、検索条件、アクセス制御、プログラムの if 文、SQL の WHERE 句、セキュリティルールを読み書きできるようになります。

集合は「条件に合うものの集まり」です。記号の形だけを見るのではなく、現実の条件を図や式に直す力が重要です。たとえば `A ∪ B` は「A または B」で、A に入るものと B に入るものを合わせた集合です。`∪` は和集合を表します。`A ∩ B` は「A かつ B」で、A と B の両方に入る共通部分です。`A - B` は A から B に入るものを取り除く差集合です。`A^c` は A ではないもの、つまり補集合です。`A ⊆ B` は、A の要素がすべて B に含まれるという意味です。

論理は、真か偽かで判断できる文を扱います。`P ∧ Q` は「P かつ Q」、`P ∨ Q` は「P または Q」、`¬P` は「P ではない」です。`P -> Q` は「P ならば Q」、`P <-> Q` は「P と Q が同値」、つまり P と Q の真偽がいつも一致するという意味です。

「P ならば Q」は、P が真で Q が偽のときだけ偽です。日常語の「ならば」と少し違うので注意します。たとえば「雨なら傘を持つ」は、雨なのに傘を持たないときだけ約束違反です。

命題とは、真か偽かをはっきり決められる文です。「7 は素数である」は真の命題です。「今日は暑い」は人によって基準が違うので、そのままでは命題として扱いにくい文です。しかし「教室の気温が 28 度以上である」なら測定すれば真偽を決められます。コンピュータに条件を渡すときは、このようにあいまいな言葉を判定可能な条件へ変える必要があります。

論理演算の結果は、真理値表で確かめるとぶれません。`P -> Q` が分かりにくいときは、約束として読みます。「P なら Q」という約束が破られるのは、P が起きたのに Q が起きなかったときだけです。

```text
P      Q      P -> Q
true   true   true
true   false  false
false  true   true
false  false  true
```

最後の 2 行で `P` が false のときに true になるのは、約束の前提である P が起きていないからです。「雨なら傘を持つ」という約束で、雨が降っていない日には、傘を持っても持たなくても約束違反ではありません。これを空虚真と呼ぶことがあります。名前は難しいですが、意味は「前提が成り立っていないので、その条件付き約束は破られていない」ということです。

`P <-> Q` は、`P -> Q` と `Q -> P` の両方が成り立つことです。つまり P と Q が同じ真偽になるときだけ true です。システムでいうと、「管理者であること」と「管理者画面に入れること」が同値なら、管理者だけが入り、管理者は必ず入れるという意味になります。ただし実務では、緊急停止中や多要素認証未完了など別条件が加わることがあるため、本当に同値にしてよいかは慎重に考えます。

## ド・モルガンの法則

ド・モルガンは、否定が中に入ると `かつ` と `または` が入れ替わる法則です。

```text
¬(P ∧ Q) = ¬P ∨ ¬Q
¬(P ∨ Q) = ¬P ∧ ¬Q
```

実務では、SQL の WHERE 条件、セキュリティポリシー、業務ルール、プログラムの分岐条件を正しく否定するときに使います。

```text
「20歳以上かつ会員である」の否定
= 「20歳未満または会員でない」
```

## 論理式の簡略化

論理式は、真理値表やカルノー図で簡単にできます。目的は、回路や条件分岐を少なくすることです。

簡略化で使う等式は、ただの変形規則ではなく、条件を削っても意味が変わらないことを保証する道具です。

```text
P ∧ true = P
P ∨ false = P
P ∧ false = false
P ∨ true = true
P ∧ P = P
P ∨ P = P
P ∧ ¬P = false
P ∨ ¬P = true
P ∨ (P ∧ Q) = P
P ∧ (P ∨ Q) = P
```

最後の 2 つは吸収律です。複雑な条件式から不要な条件を削ると、プログラムや論理回路を単純にできます。

たとえば `P ∨ (P ∧ Q) = P` を言葉で確認します。左辺は「P、または、P かつ Q」です。もし P が true なら、左側の `P` だけで全体は true です。Q が true でも false でも関係ありません。もし P が false なら、`P ∧ Q` も必ず false です。なぜなら「P かつ Q」は P が false の時点で成り立たないからです。したがって、左辺全体の真偽は P だけで決まり、`P` と同じになります。

式変形として見ると、分配法則を使っても確認できます。

```text
P ∨ (P ∧ Q)
= (P ∧ true) ∨ (P ∧ Q)
```

ここで `P = P ∧ true` と置き換えました。`true` と「かつ」を取っても P の真偽は変わらないからです。次に、共通している `P` をくくります。

```text
(P ∧ true) ∨ (P ∧ Q)
= P ∧ (true ∨ Q)
```

`true ∨ Q` は、Q が true でも false でも true です。したがって、

```text
P ∧ (true ∨ Q)
= P ∧ true
= P
```

となります。このような変形を理解すると、「複雑な if 条件を安全に短くする」「回路のゲート数を減らす」「SQL の WHERE 句を読みやすくする」といった実務判断につながります。

## 1.2 情報理論と符号化

この節を学ぶ理由は、「情報を量として見る力」を身につけるためです。コンピュータは、文字、音声、画像、動画をすべて 0/1 の形で扱います。では、どれくらいの 0/1 が必要なのか、どうすれば短くできるのか、どこまで正確に表せるのか。それを考えるのが情報理論と符号化です。

この知識は、圧縮ファイル、音楽配信、画像形式、通信量、暗号、機械学習の特徴量などにつながります。「データ量が大きい」「圧縮率が高い」「ビット数が足りない」という言葉の意味を、感覚ではなく理屈で説明できるようになります。

情報量は「どれくらい意外か」です。珍しい出来事ほど情報量が大きくなります。

```text
情報量 I = -log2(p)
```

`p` は事象が起こる確率です。`log2` は「2 を何乗したらその数になるか」を表します。確率 `p` は 1 以下なので `log2(p)` は 0 以下になります。情報量を正の値として扱うため、前にマイナスを付けています。

なぜ `log2` を使うのでしょうか。情報量は「候補を何回半分にしたか」と考えると分かりやすいからです。

コイン投げでは、表か裏かの 2 通りがあります。表が出る確率は `1/2` です。表だと分かると、2 個あった候補が 1 個に絞られます。これは「1 回の 2 択に答えた」ということなので 1 ビットです。

```text
I = -log2(1/2)
```

ここで、

```text
1/2 = 2^(-1)
```

なので、

```text
log2(1/2) = -1
```

したがって、

```text
I = -log2(1/2)
  = -(-1)
  = 1
```

確率が `1/4` の出来事なら、4 個の候補から 1 個に絞るイメージです。4 個を 2 個、2 個を 1 個へと、2 回半分にします。

```text
1/4 = 2^(-2)
log2(1/4) = -2
I = -log2(1/4)
  = -(-2)
  = 2
```

だから情報量は 2 ビットです。つまり、珍しいことほど「それを知った価値」が大きい、という意味です。

平均情報量はエントロピーとも呼ばれます。

```text
H = -Σ p_i log2(p_i)
```

この式は、1 つ 1 つの出来事の情報量を、起こりやすさで重み付けして平均したものです。

`H` は平均情報量、つまり 1 記号あたり平均してどれくらいの情報があるかを表します。`Σ` はシグマと読み、「条件に合うものを全部足す」という意味です。ここでは、記号 A、記号 B、記号 C というように、出てくる可能性のあるすべての記号について足し合わせます。

`p_i` は i 番目の記号が出る確率です。たとえば A が 1/2、B が 1/4、C が 1/4 の確率で出るなら、それぞれが `p_i` です。`-log2(p_i)` は、その記号が 1 回出たときの情報量です。珍しい記号ほど `p_i` が小さくなり、`-log2(p_i)` は大きくなります。

式の中で `p_i` を掛けているのは、平均を取るためです。よく出る記号は何度も現れるので、全体の平均に強く影響します。めったに出ない記号は 1 回出たときの情報量は大きいですが、出る回数が少ないので平均への影響は小さくなります。したがって、各記号の情報量 `-log2(p_i)` に、その記号が出る確率 `p_i` を掛けてから、全部足します。

2 種類の記号 A/B が同じ確率で出る場合を計算します。

```text
P(A) = 1/2
P(B) = 1/2
```

平均情報量は、

```text
H = -{ P(A)log2(P(A)) + P(B)log2(P(B)) }
```

値を入れます。

```text
H = -{ (1/2)log2(1/2) + (1/2)log2(1/2) }
```

`log2(1/2) = -1` なので、

```text
H = -{ (1/2)(-1) + (1/2)(-1) }
  = -{ -1/2 - 1/2 }
  = -{ -1 }
  = 1
```

平均 1 ビットの情報量です。

全ての記号が同じ確率で出るとき、エントロピーは最大になります。偏りがあると、よく出る記号を短い符号にできるので圧縮できます。たとえば日本語文で「の」や「、」がよく出るなら、それらを短く表すと全体を短くできます。

## 情報源符号化

情報源符号化は、データを短く表すための符号化です。代表例はハフマン符号です。ハフマン符号では、出現確率の小さい記号を 2 つ選び、それらをまとめて木にします。まとめたものを 1 つの候補として戻し、また確率の小さいもの同士をまとめます。これを繰り返して木を作り、枝に 0/1 を割り当てます。

ポイントは「よく出る記号ほど短い符号になる」ことです。また、どの符号も他の符号の先頭部分にならないようにします。これを接頭語条件といい、復号を一意にするために必要です。

## ディジタル符号化

音声や画像のようなアナログ情報をディジタル化するには、標本化、量子化、符号化を行います。標本化は、連続した信号を一定間隔で測ることです。量子化は、測った値を有限個の段階に丸めることです。符号化は、その段階を 0/1 の列として表すことです。

標本化定理は、「どれくらい細かく測れば元の波形を復元できるか」を示します。

```text
元の信号の最高周波数を f とすると、2f 以上の周波数で標本化すれば復元できる。
```

音声 CD の 44.1kHz は、人間の可聴域を考えて十分高い周波数で標本化している例です。

## 1.3 オートマトン

この節を学ぶ理由は、「状態を持つ処理」を理解するためです。現実のシステムには、今どんな状態かによって次の動きが変わるものがたくさんあります。自動販売機、ログイン画面、注文処理、通信手順、ゲームの画面遷移などです。

オートマトンを学ぶと、「入力を受け取ったら状態が変わる」という見方ができるようになります。これは、正規表現、入力チェック、通信プロトコル、コンパイラの字句解析を理解する土台になります。

オートマトンは「状態を持つ機械」です。入力を 1 文字ずつ読み、状態を移動して、最後に受理するか拒否するかを決めます。有限オートマトンは、取り得る状態の集合、読める入力記号の集合、最初にいる初期状態、受理してよい受理状態、そして入力を読んだときに次の状態へ移る遷移規則で定義されます。

例として、偶数個の `1` を含む 0/1 文字列を受理する機械を考えます。

状態 E は、ここまで読んだ `1` の個数が偶数であることを表します。状態 O は、ここまで読んだ `1` の個数が奇数であることを表します。0 を読んでも `1` の個数は変わらないので、状態はそのままです。1 を読むと `1` の個数が 1 増えるため、偶数は奇数へ、奇数は偶数へ変わります。つまり 1 を読むたびに E と O が入れ替わります。

受理状態は E です。入力を最後まで読んだ時点で E にいれば、`1` の個数が偶数だったと判断できます。ここで重要なのは、機械が `1` の個数そのものを全部数えているわけではないことです。偶数か奇数かだけ分かればよいので、状態は E と O の 2 つで足ります。

このように、数え上げる代わりに「今どちらの状態か」だけを保持すればよいのが有限オートマトンです。

有限オートマトンで扱いやすいのは、「有限個の状態だけで判断できる文字列」です。一方、括弧の対応のように、いくつ開き括弧が積まれているかを数え続ける必要がある処理では、有限個の状態だけでは足りません。そこでスタックを持つプッシュダウンオートマトンという考え方が出てきます。スタックは後から入れたものを先に取り出す構造なので、開き括弧を積み、閉じ括弧で取り出す処理に向きます。

さらに一般的な計算モデルとして、チューリングマシンがあります。チューリングマシンは、無限に長いテープ、読み書きヘッド、状態、遷移規則を持つ抽象的な機械です。現実のコンピュータそのものではありませんが、「計算できるとはどういうことか」を考えるための基準になります。有限オートマトン、プッシュダウンオートマトン、チューリングマシンを比べると、記憶できる情報が増えるほど扱える問題も広がることが分かります。

## 正規表現

正規表現は、文字列の集合を表す記法です。有限オートマトンと同じ表現力を持ちます。

`a|b` は「a または b」を表します。縦棒 `|` は選択です。`ab` は「a の後に b が続く」ことを表します。間に記号がないので分かりにくいですが、正規表現では並べて書くこと自体が連結を意味します。

`a*` は「a の 0 回以上の繰返し」です。0 回も含むので、空文字列も許します。たとえば `a*` は、空文字列、`a`、`aa`、`aaa` を含みます。`(ab)*` は、`ab` というまとまりを 0 回以上繰り返します。したがって、空文字列、`ab`、`abab`、`ababab` は含みますが、`aba` は最後の `a` が余るので含みません。

正規表現を理解すると、入力検証、ログ検索、構文解析の入口で「どの文字列を許すか」を厳密に表せます。

## 1.4 形式言語

この節を学ぶ理由は、「コンピュータが読める文法」を理解するためです。人間の文章は多少あいまいでも通じますが、プログラムや設定ファイルでは、文法が少し違うだけでエラーになります。

形式言語を学ぶと、プログラミング言語、正規表現、SQL、JSON、HTML のような「決まった規則で書かれた文字列」を、機械がどう読むのかが分かります。これは、コンパイラや入力検証の理解にもつながります。

形式言語は、文法規則で作れる文字列の集合です。プログラミング言語は形式言語の一種です。文法を機械にも読める形で書く記法の 1 つが BNF です。

```text
<式> ::= <項> | <式> + <項>
```

`::=` は「左辺は右辺で定義される」という意味です。`|` は選択です。

構文解析では、入力文字列が文法に合っているかを調べます。

字句解析では、文字列をトークンに分けます。トークンとは、プログラムを読むときの意味のある最小単位です。たとえば `total = price + tax` なら、`total`、`=`、`price`、`+`、`tax` のように分けます。人間が文章を単語に分ける作業に近いです。

構文解析では、トークンの並びが文法に合っているかを調べます。`price + tax` は式として読めますが、`+ tax price` のような並びは、多くの言語では文法に合いません。構文解析は、トークン列を木構造にして、「この部分が式」「この部分が代入文」といった形を作ります。

意味解析では、文法としては正しくても意味として正しいかを調べます。宣言されていない変数を使っていないか、数値に文字列を足そうとしていないか、関数に渡す引数の数が合っているか、といった確認です。つまり、字句解析は部品に分ける作業、構文解析は形を見る作業、意味解析はその形が意味として成り立つかを見る作業です。

正規文法、文脈自由文法など、文法の種類によって扱える構造が変わります。括弧の対応や式の入れ子は、正規表現だけでは扱いにくく、文脈自由文法が必要です。

## 1.5 グラフ理論

この節を学ぶ理由は、「つながり」を計算できる形にするためです。IT では、ものごとの関係を扱う場面が非常に多くあります。ネットワークの機器同士、SNS の人間関係、プロジェクト作業の依存関係、Web ページのリンク、配送拠点の経路などです。

グラフ理論を学ぶと、「どこからどこへ行けるか」「最短経路はどれか」「どの作業を先にやるべきか」「どこがボトルネックか」を構造として考えられるようになります。

グラフは、点と線で関係を表す道具です。点を頂点と呼び、人、都市、コンピュータ、作業などを表します。線を辺と呼び、人間関係、道路、通信回線、依存関係などを表します。矢印があるグラフは有向グラフ、向きがないグラフは無向グラフです。辺に距離や費用がある場合は、重み付きグラフとして扱います。

コンピュータの中でグラフを持つ方法も、目的で選びます。隣接行列は、頂点同士がつながっているかを表にして持つ方法です。頂点数が少なく、辺の有無をすぐ知りたいときに向きます。隣接リストは、各頂点から出ている辺の一覧を持つ方法です。辺が少ないグラフでメモリを節約したいときに向きます。

グラフで解く問題には、最短経路、最小全域木、トポロジカルソートがあります。最短経路は、最もコストの小さい経路を探す問題です。最小全域木は、全頂点をつなぎつつ辺の合計重みを最小にする問題です。トポロジカルソートは、順序関係のある作業を矛盾しない順に並べる問題です。

DAG は閉路のない有向グラフです。作業順序や依存関係の表現に使います。

最短経路を求める代表的な方法にダイクストラ法があります。辺の重みが負でないとき、出発点から各頂点までの最短距離を少しずつ確定していく方法です。ここで「確定」とは、「これより短い経路はもう出てこない」と判断することです。

小さな例で見ます。出発点を A とし、辺の重みを次のようにします。

```text
A -> B: 2
A -> C: 5
B -> C: 1
B -> D: 4
C -> D: 2
```

最初は、A までの距離を 0、他を未確定の無限大として考えます。無限大は「まだ到達経路が見つかっていない」という印です。

```text
A: 0
B: ∞
C: ∞
D: ∞
```

A から直接行ける B と C を更新します。

```text
B = Aまでの距離 + A->B
  = 0 + 2
  = 2

C = Aまでの距離 + A->C
  = 0 + 5
  = 5
```

未確定の中で距離が最小なのは B の 2 なので、B を確定します。次に B から C と D へ進む候補を計算します。

```text
A -> B -> C の距離 = 2 + 1 = 3
```

いま C は 5 でしたが、3 の方が短いので C を 3 に更新します。

```text
C = min(5, 3) = 3
```

`min` は小さい方を選ぶ関数です。なぜ小さい方を選ぶかというと、最短距離を持ちたいからです。同じく D も候補を出します。

```text
A -> B -> D の距離 = 2 + 4 = 6
D = 6
```

次に未確定で最小なのは C の 3 なので、C を確定します。C から D へ行くと、

```text
A -> B -> C -> D の距離 = 3 + 2 = 5
```

いま D は 6 でした。5 の方が短いので更新します。

```text
D = min(6, 5) = 5
```

最後に D が確定し、A から D への最短距離は 5 だと分かります。この例では、A から D へ直接近そうな道を選ぶのではなく、途中の B、C を通る方が短くなりました。ネットワーク経路、地図アプリ、配送、依存関係の最適化では、このように「局所的に見える近さ」ではなく、合計コストで判断します。

## 1.6 確率と統計

この節を学ぶ理由は、「不確実なことを扱う力」を身につけるためです。システム障害、攻撃、売上、アクセス数、AI の予測は、必ずしも 100% 確定しているわけではありません。だからこそ、起こりやすさやデータの傾向を数値で見る必要があります。

確率と統計を学ぶと、監視アラートの誤検知、A/B テスト、品質管理、機械学習の評価、リスク分析を理解できます。「平均だけ見て安心してよいのか」「珍しい事象をどう判断するか」を考えられるようになります。

確率は「起こりやすさ」を 0 から 1 で表します。

```text
P(A ∪ B) = P(A) + P(B) - P(A ∩ B)
P(A | B) = P(A ∩ B) / P(B)
```

`A ∪ B` は「A または B」です。`P(A) + P(B)` と足すだけでは、A と B の両方に入っている部分 `A ∩ B` を 2 回数えてしまいます。だから、重なった部分を 1 回ぶん引きます。

例として、40 人のクラスで、数学が得意な人が 18 人、英語が得意な人が 15 人、両方得意な人が 6 人だとします。

```text
数学または英語が得意な人数
= 18 + 15 - 6
= 27
```

`18 + 15` では、両方得意な 6 人を「数学側」と「英語側」で 2 回数えています。集合の和では同じ人を 1 人として数えたいので、6 人を引きます。

`P(A | B)` は「B が起きたと分かったときに A が起きる確率」です。条件付き確率です。

なぜ `P(A ∩ B) / P(B)` なのでしょうか。`B が起きたと分かった` という条件では、世界全体ではなく、B が起きた場合だけを母集団として見ます。その中で A も起きている割合を見るので、

```text
条件付き確率 = B の中で A も起きる割合
             = P(A ∩ B) / P(B)
```

になります。

```text
P(A | B) = P(B | A)P(A) / P(B)
```

この式がベイズの定理です。ベイズの定理は、条件付き確率の式を変形して作れます。

まず、`P(A | B)` の定義から、

```text
P(A | B) = P(A ∩ B) / P(B)
```

両辺に `P(B)` を掛けます。両辺に同じ数を掛けても等式は保たれます。

```text
P(A | B)P(B) = P(A ∩ B)
```

同じように、`P(B | A)` の定義から、

```text
P(B | A) = P(A ∩ B) / P(A)
```

両辺に `P(A)` を掛けると、

```text
P(B | A)P(A) = P(A ∩ B)
```

どちらも同じ `P(A ∩ B)` を表しているので、

```text
P(A | B)P(B) = P(B | A)P(A)
```

`P(A | B)` だけを左辺に残したいので、両辺を `P(B)` で割ります。

```text
P(A | B) = P(B | A)P(A) / P(B)
```

検査、スパム判定、機械学習で重要です。陽性率が高くても、元の発生率が低いと、実際に陽性である確率は思ったより低いことがあります。

確率分布は、値がどのように出やすいかを表します。二項分布は、成功/失敗のような結果を n 回繰り返す場面で使います。ポアソン分布は、一定時間にまれな事象が何回起きるかを扱います。正規分布は、平均付近が多く、左右対称に広がる分布です。

期待値は平均的な値、分散はばらつきの大きさです。

ここでいう期待値は、「次に必ずその値になる」という予言ではありません。長い目で見た平均です。たとえば、あるサービスで 1 日に起きる重大障害の件数を考えます。重大障害が 0 件の日が 70%、1 件の日が 20%、2 件の日が 10% だとします。

```text
X の値       0件      1件      2件
確率         0.7      0.2      0.1
```

`X` は確率変数です。確率変数とは、結果によって値が変わる量です。ここでは「1 日の重大障害件数」が `X` です。期待値は、それぞれの値に、その値が出る確率を掛けて足します。

```text
E(X) = Σ x_i p_i
```

`E(X)` は `X` の期待値です。`x_i` は取り得る値、`p_i` はその値が出る確率です。`Σ` は全部足す記号なので、この式は「値 × 確率」を全パターンについて足す、という意味です。

具体的に計算します。

```text
E(X) = 0 × 0.7 + 1 × 0.2 + 2 × 0.1
```

まず、それぞれの掛け算をします。

```text
0 × 0.7 = 0
1 × 0.2 = 0.2
2 × 0.1 = 0.2
```

これを足します。

```text
E(X) = 0 + 0.2 + 0.2
     = 0.4
```

期待値は 0.4 件です。これは「毎日 0.4 件の障害が起きる」という意味ではありません。1 日の障害件数は 0 件、1 件、2 件のどれかです。0.4 件とは、長期間でなら 1 日あたり平均 0.4 件くらいになる、という意味です。運用では、この値を使って年間件数、対応要員、障害対応コストを見積もることがあります。

しかし、期待値だけでは足りません。次の 2 つのサービスを考えます。

```text
サービスA: 毎日だいたい 0 件から 1 件の障害
サービスB: ほとんどの日は 0 件だが、たまに大量の障害
```

平均が同じでも、運用の怖さは違います。そこで分散を見ます。分散は、値が平均からどれくらい離れやすいかを測る量です。

```text
V(X) = Σ (x_i - μ)^2 p_i
```

`V(X)` は分散です。`μ` は平均、ここでは期待値 `0.4` です。`x_i - μ` は「その値が平均からどれだけ離れているか」です。なぜ二乗するのでしょうか。平均との差は、平均より小さいと負になります。たとえば 0 件は平均 0.4 件より小さいので `0 - 0.4 = -0.4` です。このまま足すと、正の差と負の差が打ち消し合ってしまいます。ばらつきの大きさを測りたいので、差を二乗して正の値にします。

さきほどの分布で計算します。平均 `μ` は 0.4 でした。

0 件の日は、平均から `0 - 0.4 = -0.4` 離れています。これを二乗します。

```text
(-0.4)^2 = (-0.4) × (-0.4) = 0.16
```

0 件の日の確率は 0.7 なので、平均との差の二乗に確率を掛けます。

```text
0.16 × 0.7 = 0.112
```

1 件の日は、平均から `1 - 0.4 = 0.6` 離れています。

```text
0.6^2 = 0.6 × 0.6 = 0.36
0.36 × 0.2 = 0.072
```

2 件の日は、平均から `2 - 0.4 = 1.6` 離れています。

```text
1.6^2 = 1.6 × 1.6 = 2.56
2.56 × 0.1 = 0.256
```

最後に全部足します。

```text
V(X) = 0.112 + 0.072 + 0.256
     = 0.44
```

分散は 0.44 です。ただし、分散は差を二乗しているので、単位も二乗されています。障害件数で考えていたのに、分散は「件数の二乗」のような扱いになります。そのままだと感覚的に読みにくいので、平方根を取った標準偏差も使います。

```text
標準偏差 = sqrt(分散)
         = sqrt(0.44)
         ≒ 0.66
```

`sqrt` は平方根です。平方根は「何を 2 回掛けるとその数になるか」を表します。`0.66 × 0.66 = 0.4356` で 0.44 に近いので、標準偏差は約 0.66 件です。標準偏差は元の値と同じ単位で読めるため、「平均 0.4 件のまわりに、だいたい 0.66 件くらいの揺れがある」と考えられます。

統計をシステムで使うときは、平均、分散、標準偏差、中央値、外れ値を分けて見ます。中央値は、データを小さい順に並べたとき真ん中に来る値です。応答時間や売上のように一部だけ極端に大きい値が混じるデータでは、平均が引っ張られます。平均は全体の合計を見たいときに強く、中央値は典型的な利用者体験を見るときに強いです。どちらが正しいかではなく、何を判断したいかで使い分けます。

## 1.7 回帰分析

この節を学ぶ理由は、「データから予測する力」を身につけるためです。気温とアイスの売上、広告費と申込数、サーバ台数と応答時間のように、ある値が別の値に影響することがあります。

回帰分析を学ぶと、過去データから関係を式で表し、未知の値を予測できます。AI やデータ分析の入口でもあり、単なるグラフの見た目ではなく、数式として関係を扱えるようになります。

回帰分析は、変数の関係を式で表す方法です。1 つの説明変数から 1 つの目的変数を予測する最も基本的な形が単回帰です。

```text
y = ax + b
```

`x` が説明変数、`y` が目的変数です。説明変数とは、予測に使う入力のことです。目的変数とは、予測したい結果のことです。`a` は傾きで、`x` が 1 増えたときに `y` がどれだけ増えるかを表します。`b` は切片で、`x = 0` のときの `y` の値です。最小二乗法では、実測値と予測値の差の二乗和が最小になる直線を求めます。

説明変数が複数ある場合は、重回帰を使います。

```text
y = a1x1 + a2x2 + ... + b
```

`x1`、`x2` のように複数の入力を使い、それぞれに `a1`、`a2` という重みを掛けます。たとえば売上を予測するとき、気温、曜日、広告費を同時に使うような場合です。

結果が 0/1、承認/否認、購入/非購入、障害あり/なしのような場合には、ロジスティック回帰で確率を予測します。

```text
p = 1 / (1 + e^(-z))
```

この式では、`z` が入力から計算したスコア、`p` が 0 から 1 の範囲の確率です。分母の `1 + e^(-z)` は必ず正なので、`p` も正になります。また `z` が大きいほど `e^(-z)` は小さくなり、分母が 1 に近づくため `p` は 1 に近づきます。名前は回帰ですが、分類にも使われます。

## 1.8 数値計算

この節を学ぶ理由は、「コンピュータは近似で答えを出すことが多い」と理解するためです。現実の計算には、手で簡単に解けない方程式や、完全に正確には表せない小数がたくさんあります。

数値計算を学ぶと、シミュレーション、AI、画像処理、科学技術計算で、なぜ誤差が出るのか、どの方法なら安定して答えに近づけるのかを考えられるようになります。

コンピュータは多くの場合、厳密解ではなく近似解を求めます。二分法は、解がある区間を半分に狭めていく方法です。速くはありませんが、条件が合えば安定しています。ニュートン法は、接線を使って解に高速に近づく方法です。ただし初期値が悪いと失敗することがあります。ガウスの消去法は、連立一次方程式を段階的に変形して解く方法です。

数値計算では誤差の種類も重要です。丸め誤差は、コンピュータが有限桁で数を表すために丸めた結果として出ます。打切り誤差は、無限に続く計算を途中で止めたために出ます。桁落ちは、近い値同士を引き算したときに有効桁が減る現象です。情報落ちは、大きい値と小さい値を足したとき、小さい値が結果に反映されにくくなる現象です。

小数の誤差は、「コンピュータが計算を雑にしている」から起きるのではありません。多くのコンピュータは 2 進数で小数を表します。10 進数の `0.5` は 2 進数では `0.1` と表せます。なぜなら、2 進小数の小数第 1 位は `1/2` を表すからです。`0.1₂` は `1 × 1/2 = 0.5` です。

一方、10 進数の `0.1` は 2 進数では有限桁でぴったり表せません。10 進数の `1/3 = 0.3333...` が終わらないのと同じように、基数が変わると、有限で表せる数も変わります。コンピュータは決められた桁数で近い値に丸めるため、`0.1 + 0.2` の結果が表示上 `0.30000000000000004` のようになることがあります。これは足し算そのものを間違えたのではなく、入力の時点で `0.1` と `0.2` が近似値として入っているためです。

浮動小数点数は、だいたい次の形で数を表します。

```text
値 = 符号 × 仮数 × 基数^指数
```

符号は正か負かを表します。仮数は有効な数字の並びです。指数は小数点をどれだけ動かすかを表します。たとえば 10 進数で `1.23 × 10^4` は、`1.23` に 10 を 4 回掛けるという意味です。

```text
1.23 × 10^4
= 1.23 × 10000
= 12300
```

なぜ `10^4 = 10000` なのでしょうか。指数の 4 は、10 を 4 個掛けるという意味だからです。

```text
10^4 = 10 × 10 × 10 × 10
     = 10000
```

浮動小数点では、この指数を変えることで、とても大きい数やとても小さい数を限られたビット数で扱えます。その代わり、仮数に入る桁数は有限です。計算結果が仮数に収まりきらないと丸められます。だから金融、科学技術計算、機械学習、画像処理では、どの型を使うか、どの順番で足すか、どこまで誤差を許すかを設計します。正しいプログラムでも、数値表現を理解していないと、結果の信頼性を誤って判断してしまいます。

モンテカルロ法は、乱数を使って近似的に答えを求める方法です。乱数とは、規則がないように見える数の列です。コンピュータが作る乱数は厳密には計算で作られた疑似乱数であることが多いですが、十分よく散らばっていればシミュレーションに使えます。

円周率を例にすると、1 辺の長さが 2 の正方形の中に、半径 1 の円を描きます。正方形の面積は `2 × 2 = 4`、円の面積は `π × 1^2 = π` です。正方形の中にランダムな点を大量に打つと、点が円の中に入る割合は、面積の割合に近づきます。

```text
円の中に入る割合 ≒ 円の面積 / 正方形の面積
              = π / 4
```

ここで `π` を求めたいので、両辺に 4 を掛けます。等式や近似式の両辺に同じ数を掛けると、左右の関係は保たれます。

```text
4 × 円の中に入る割合 ≒ 4 × (π / 4)
```

右辺の `4 × (π / 4)` は、`π` を 4 で割ってから 4 を掛けているので、4 が打ち消されます。

```text
π ≒ 4 × 円の中に入る割合
```

たとえば 10000 点を打って 7850 点が円の中に入ったなら、割合は `7850 / 10000 = 0.785` です。したがって、

```text
π ≒ 4 × 0.785
  = 3.14
```

となります。点を増やすほど一般には近づきやすくなりますが、必ず一直線に正解へ近づくわけではありません。モンテカルロ法は、金融リスク、待ち行列、物理シミュレーション、ゲーム AI、在庫や需要の予測など、場合分けが多すぎて手で全パターンを追えない問題で使われます。重要なのは、「乱数を使うから雑」ではなく、「確率的にどのくらい信頼できるか」を点の数やばらつきと一緒に見ることです。

画像や音声を扱う技術も、基礎理論とつながっています。画像はピクセルという小さな点の集まりとして表せます。ピクセルは picture element の略で、画面を構成する最小単位です。白黒画像なら各ピクセルの明るさを数値で持ち、カラー画像なら赤、緑、青の強さを組み合わせます。たとえば 8 ビットで 1 色を表すなら、`2^8 = 256` 段階です。赤、緑、青をそれぞれ 8 ビットで持つと、1 ピクセルは `8 × 3 = 24` ビットになります。

```text
横 1920 × 縦 1080 × 24 ビット
```

この式は、画面全体にあるピクセル数に、1 ピクセルあたりのビット数を掛けています。まずピクセル数は、

```text
1920 × 1080 = 2,073,600 ピクセル
```

です。そこへ 1 ピクセル 24 ビットを掛けます。

```text
2,073,600 × 24 = 49,766,400 ビット
```

バイトへ直すには 8 で割ります。1 バイトは 8 ビットだからです。

```text
49,766,400 / 8 = 6,220,800 バイト
```

約 6.2MB です。圧縮していないフル HD 画像 1 枚でもこれだけの大きさになるため、画像形式や圧縮、GPU、メモリ帯域の理解が必要になります。

文字も、コンピュータの中では数値として扱われます。文字コードは、文字と数値の対応表です。ASCII は英数字や基本的な記号を扱う古い文字コードで、英語中心の範囲では十分でした。しかし日本語、絵文字、世界中の文字を扱うには足りません。そこで Unicode が使われます。Unicode は、世界中の文字に番号を割り当てる大きな体系です。

UTF-8 は、Unicode の番号をバイト列として保存する方式の 1 つです。ここで大事なのは、Unicode と UTF-8 は同じものではないということです。Unicode は「文字にどんな番号を割り当てるか」の体系で、UTF-8 は「その番号をどうバイト列にするか」の方式です。たとえば同じ文字でも、保存形式を取り違えると文字化けが起きます。文字化けは、データが壊れたとは限らず、読む側が違う対応表で解釈している場合にも起きます。

さらに難しいのが、見た目が同じでも内部表現が違う文字です。たとえば濁点付きの文字は、1 つの文字として表す方法と、基本の文字に濁点を組み合わせて表す方法があります。人間には同じに見えても、コンピュータがバイト列として比べると違うものとして扱うことがあります。これをそろえる処理を Unicode 正規化と呼びます。ログイン ID、ファイル名、検索、名寄せでは、「見た目が同じか」と「内部のバイト列が同じか」を区別しないと、見つからない、重複する、認証で失敗する、といった問題が起きます。

コンピュータグラフィックスでは、ラスタ画像とベクタ画像を区別します。ラスタ画像はピクセルの集まりなので写真に向きますが、拡大するとギザギザが見えます。ベクタ画像は線や曲線を数式や座標で表すため、拡大してもきれいに描き直せます。3D CG では、物体を頂点、辺、面で表し、座標変換で回転や移動を行い、投影によって 3 次元の世界を 2 次元の画面に写します。ここでも行列、三角関数、補間、標本化が使われます。CG は見た目の技術に見えますが、実際には数学とハードウェア性能の上に成り立っています。

## 1.9 AI

この節を学ぶ理由は、「AI を魔法ではなく技術として理解する」ためです。AI は急に答えを思いついているわけではありません。データを集め、特徴を取り出し、モデルを学習し、未知の入力に対して予測や分類をしています。

AI を学ぶと、画像認識、推薦、チャットボット、不正検知、需要予測がどのような考え方で動いているかが見えます。同時に、データの偏り、誤判定、説明可能性、運用中の劣化といった限界も理解できるようになります。

AI は、人間の知的作業を機械で実現しようとする技術です。細かい数式だけでなく、方式の違い、使いどころ、限界を理解することが重要です。教師あり学習は、入力と正解のペアから学びます。画像に「猫」「犬」の正解ラベルを付けて分類モデルを学習するような場合です。教師なし学習は、正解なしでデータの構造を見つけます。似た利用者をクラスタに分ける、データを少ない軸に圧縮する、といった使い方です。強化学習は、行動と報酬から方策を学びます。ゲームやロボット制御のように、試行錯誤しながらよい行動を見つける場面で使われます。

ディープラーニングは、多層のニューラルネットワークで特徴を自動的に学習する方法です。画像、音声、自然言語で強い一方、大量データ、計算資源、過学習対策が必要です。

AI の性能を見るときは、単に「当たった割合」だけでは足りません。目的によって、次の指標を使い分けます。

正解率は、全体のうち正しく分類できた割合です。全体が 100 件あり、90 件を正しく分類できたなら正解率は 90% です。ただし、珍しい異常を見つける問題では、正解率だけを見ると危険です。たとえば 1000 件中 990 件が正常なら、全部を正常と答えるだけで正解率は 99% になりますが、異常は 1 件も見つけられません。

適合率は、陽性と予測したもののうち、本当に陽性だった割合です。不正検知で「不正だ」と警告したものの中に、本物の不正がどれくらいあるかを見る指標です。誤警報が多いと、調査担当者が疲弊し、本当に重要な警告を見落としやすくなります。

再現率は、本当の陽性のうち、陽性と見つけられた割合です。病気の検査なら、本当に病気の人をどれだけ見逃さずに見つけたかを表します。見逃しが重大な問題では、再現率が特に重要になります。

F値は、適合率と再現率のバランスを見る指標です。適合率だけを上げようとすると、かなり自信のあるものだけを陽性にして見逃しが増えることがあります。再現率だけを上げようとすると、少しでも怪しいものを全部陽性にして誤警報が増えることがあります。F値は、この両方を同時に見たいときに使います。

適合率、再現率、F値は、混同行列から計算できます。混同行列とは、予測と実際の組合せを数えた表です。陽性と予測して本当に陽性だった数を TP、陽性と予測したが実際は陰性だった数を FP、陰性と予測したが実際は陽性だった数を FN とします。TP は True Positive、FP は False Positive、FN は False Negative の略です。

適合率は、陽性と予測したものの中で本当に陽性だった割合なので、分母は `TP + FP` です。なぜなら、陽性と予測したものは、本当に陽性だった TP と、間違って陽性にした FP に分かれるからです。

```text
適合率 = TP / (TP + FP)
```

再現率は、本当の陽性の中で見つけられた割合なので、分母は `TP + FN` です。本当の陽性は、見つけられた TP と、見逃した FN に分かれます。

```text
再現率 = TP / (TP + FN)
```

F値は、適合率と再現率の調和平均です。普通の平均ではなく調和平均を使うのは、片方だけが高くても全体を高く評価しすぎないためです。

```text
F値 = 2 × 適合率 × 再現率 / (適合率 + 再現率)
```

たとえば適合率が 1.0、再現率が 0.1 なら、普通の平均は `(1.0 + 0.1) / 2 = 0.55` です。しかし実際には、見逃しが多いので高く評価しすぎです。F値では、

```text
F値 = 2 × 1.0 × 0.1 / (1.0 + 0.1)
    = 0.2 / 1.1
    ≒ 0.18
```

となり、片方だけ高い状態を厳しく見ます。ここで `0.2 / 1.1` は、分子と分母を同じ 10 倍にして `2 / 11` と見ても同じです。`2 / 11` は約 `0.1818...` なので、小数第 2 位程度に丸めて `0.18` と読めます。

医療検査や不正検知では、正解率だけでは危険です。見逃しが重いのか、誤検知が重いのかで重視する指標が変わります。

AI で特に重要なのが過学習です。過学習は、学習データにはよく合うのに、未知のデータでは性能が落ちる状態です。授業で配られた練習問題の答えだけに合わせすぎて、少し形の違う問題になると解けない状態に近いです。AI の目的は、学習データを完全に再現することではなく、まだ見ていないデータにも対応できることです。この性質を汎化といいます。

過学習を調べるために、データを訓練データ、検証データ、テストデータに分けます。訓練データはモデルを学習するために使います。検証データは、設定やモデル選択を調整するために使います。テストデータは、最後に性能を確認するために使います。テストデータまで何度も見ながら調整すると、そのテストに合わせてしまい、本当の未知データへの性能を測れなくなります。

過学習を抑える方法には、正則化、データ拡張、早期終了、モデルを必要以上に複雑にしないことがあります。正則化は、モデルが複雑になりすぎることにペナルティを与える考え方です。早期終了は、検証データの性能が悪くなり始めた時点で学習を止める方法です。AI を使うときは、精度の数字だけでなく、その数字がどのデータで測られ、運用後も保たれるのかを見る必要があります。

## 実務で使える理解

- 論理問題は、頭の中だけで考えず真理値表にする。
- 情報量は、確率が小さいほど大きいと先に判断する。
- 符号化は「一意に復号できるか」を見る。
- オートマトンは、状態がどんな情報を保持しているかを日本語で説明する。
- グラフ問題は、点、辺、重み、向きの有無を先に整理する。
- 確率は、条件付きか同時確率かを見分ける。
- 期待値は長期的な平均、分散と標準偏差はばらつきを見る道具として使う。
- 回帰分析は、説明変数と目的変数を逆にしない。
- AI は、学習データ、正解ラベル、評価指標を確認する。

## 自分の言葉で説明する

- ド・モルガンの法則を例で説明できる。
- `P -> Q` が偽になる条件を、具体例で説明できる。
- 情報量 `-log2(p)` の意味を説明できる。
- ハフマン符号で、出現確率が高い記号ほど短くなる理由を説明できる。
- 有限オートマトン、正規表現、形式文法の関係を説明できる。
- 隣接行列と隣接リストの使い分けを説明できる。
- 条件付き確率とベイズの定理を混同しない。
- 期待値、分散、標準偏差を、具体的な確率分布から計算できる。
- 平均と中央値の使い分けを、外れ値のあるデータで説明できる。
- 回帰分析と分類の違いを説明できる。
- 丸め誤差、桁落ち、情報落ちを区別できる。
- 教師あり、教師なし、強化学習の違いを例で説明できる。

## 深く身につけるための補講

基礎理論は、後のすべての章を支える「考え方の道具箱」です。ここで大事なのは、公式の形だけを追うことではなく、現実のシステムを抽象化して扱う力です。

たとえば、ログイン条件を考えます。

```text
利用者が社員であり、かつ、多要素認証済みであり、かつ、アクセス元が許可範囲である
```

これは論理式です。セキュリティ設定、SQL、プログラム分岐、ファイアウォールルールは、すべて「条件を正しく書く」作業です。条件を 1 つ間違えると、許可してはいけない人を許可したり、許可すべき人を拒否したりします。論理は数学のためだけにあるのではなく、システムの振る舞いを安全に固定するためにあります。

## 例で理解する: ベイズの定理

ある監視システムが、障害のあるサーバを 99% の確率で検知できるとします。一方、正常なサーバを誤って障害と判定する確率が 1% あるとします。サーバ全体のうち、本当に障害があるのは 0.1% です。

直感では「アラートが出たら 99% 障害」と思いがちです。しかし実際には違います。

100,000 台で考えます。

本当に障害があるサーバは、100,000 台の 0.1% なので 100 台です。0.1% は `0.1 / 100 = 0.001` なので、`100,000 × 0.001 = 100` です。残りは正常なので、`100,000 - 100 = 99,900` 台です。

障害 100 台のうち、検知率が 99% なら、検知されるのは `100 × 0.99 = 99` 台です。正常 99,900 台のうち、誤検知率が 1% なら、誤ってアラートになるのは `99,900 × 0.01 = 999` 台です。

アラート総数は `99 + 999 = 1,098` 件です。そのうち本当に障害なのは 99 件なので、確率は約 9% です。

これはセキュリティ監視、医療検査、不正検知、機械学習の評価で非常に重要です。珍しい事象を検知するシステムでは、検知性能が高くても誤検知が大量に出ることがあります。

## 例で理解する: グラフは関係の地図

グラフは、点と線の図ではなく「関係を計算可能にする形式」です。

たとえばネットワークならルータが頂点、回線が辺です。SNS なら人が頂点、フォロー関係が辺です。プロジェクトなら作業が頂点、依存関係が辺です。コンパイラならモジュールが頂点、`import` が辺です。物流なら拠点が頂点、輸送路が辺です。

このように置き換えると、同じアルゴリズムが別分野で使えます。

最短経路は、ある頂点から別の頂点へ行くとき、辺の重みの合計が最も小さい経路を求める問題です。ネットワークなら最も速い通信経路、物流なら最短または最小コストの配送経路に対応します。

最小全域木は、すべての頂点をつなぎつつ、辺の重みの合計を最小にする構造です。すべての拠点を回線でつなぎたいが、工事費は最小にしたい、という場面で考え方が使えます。

トポロジカルソートは、依存関係を壊さない順序に並べる方法です。「データベースを作ってからアプリを接続する」「部品 A を作ってから部品 B を組み立てる」のように、先にやるべき作業がある場合に使います。

強連結成分は、有向グラフの中で互いに到達できる頂点のまとまりです。Web ページ同士のリンク、モジュール同士の依存関係、SNS の関係などで、「この範囲は内部でぐるぐる行き来できる」と分かります。依存関係の循環を見つけるときにも重要です。

高度な理解とは、「これはグラフで表せる」と気づけることです。

## AI を深く理解する入口

機械学習は、魔法ではありません。入力から出力への関数を、データから近似する技術です。

```text
モデル: y = f(x)
学習: f が正しい y を出すようにパラメータを調整する
評価: 未知の x に対してもよい y を出せるか確認する
```

ここで重要なのは、学習データと現実世界がずれると性能が落ちることです。これをデータ分布の変化、またはデータドリフトと呼びます。

たとえば、昔の購買データで学習した推薦モデルは、流行の変化で外れやすくなります。平常時の通信ログで学習した異常検知は、新しい業務システム導入後に誤検知することがあります。特定地域の画像だけで学習したモデルは、別地域の画像で失敗することがあります。

AI の理解では、アルゴリズム名よりも、データ、目的関数、評価指標、運用中の監視をセットで考えます。

## ありがちな誤解

- 論理式は数学の問題ではなく、システムの許可・拒否・分岐を決める仕様そのもの。
- 確率は「気分の度合い」ではなく、条件を明示して初めて意味を持つ。
- 平均だけではデータを理解できない。分散、外れ値、分布の形を見る。
- 期待値は「次に起きる値」ではない。長い期間で見た平均的な値。
- 相関があることは、因果があることを意味しない。
- AI の精度は 1 つの数値で決まらない。適合率、再現率、運用コスト、説明可能性も見る。
