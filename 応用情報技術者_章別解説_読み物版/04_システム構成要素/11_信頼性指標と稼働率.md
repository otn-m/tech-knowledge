# 第4章・第11話　信頼性指標と稼働率――「止まりにくい」を数字にする


## 1 RASIS

システムを評価する五つの観点の頭文字を並べたものが**RASIS**です。

## 2 Reliability――信頼性

決められた条件・期間、故障せず正しく働く性質です。

「どれだけ壊れにくいか」を見ます。平均故障間隔、故障率などが関係します。

## 3 Availability――可用性

必要なときに利用できる性質です。

壊れても一分で直れば利用不能時間は短くなります。壊れにくさだけでなく、修理・切替えの速さも効きます。

## 4 Serviceability――保守性

故障を見つけ、原因を特定し、修理・交換・復旧しやすい性質です。

- 部品を動作中に交換できる。
- ログから原因箇所を絞れる。
- 交換手順が簡単である。
- 保守部品と担当者をすぐ用意できる。

などです。

## 5 Integrity――完全性

データや処理結果が正しく、欠けず、許可なく変更されていない性質です。

止まらず動いていても、預金残高を誤って返せば良いシステムではありません。可用性と完全性は別の問いです。

## 6 Security――安全性

不正利用、情報漏えい、改ざん、破壊などから守られる性質です。

ここでのSecurityを「事故を起こさない安全性」と訳す古い説明もありますが、現代の試験では情報セキュリティの機密性・完全性・可用性などとの関係も意識します。

RASISは一つの点数ではありません。五つの観点から弱点を探す確認表です。

## 7 MTBF

**MTBF**、Mean Time Between Failuresは、修理して使い続ける装置が、故障から次の故障まで平均どれだけ正常に動くかを表す時間です。日本語では**平均故障間動作時間**、平均故障間隔などと呼びます。

三回の正常動作時間が100時間、140時間、120時間なら、

```text
MTBF = (100+140+120)÷3
     = 360÷3
     = 120時間
```

平均120時間ごとに必ず故障するという予言ではありません。多数回・多数台を見た平均です。

## 8 MTTF

修理せず寿命で交換する部品が、故障するまで平均どれだけ動くかを**MTTF**、Mean Time To Failureと呼びます。

MTBFとMTTFは文脈で混用されることがありますが、修理して繰り返す系か、故障まで一回を測るかを区別します。

## 9 MTTR

**MTTR**、Mean Time To Repairは、故障してから修理・復旧するまでの平均時間です。

復旧時間が1時間、3時間、2時間なら、

```text
MTTR = (1+3+2)÷3 = 2時間
```

測定開始を障害発生、検知、担当者到着のどこにするかで値が変わります。運用では定義をそろえます。

## 10 稼働率

修理可能な単純モデルで、一周期を考えます。

```text
正常に動く MTBF時間 → 故障 → 修理する MTTR時間 → 再開
```

全時間は`MTBF+MTTR`、利用できる時間はMTBFなので、**稼働率**は、

```text
稼働率 = MTBF ÷ (MTBF + MTTR)
```

です。

### 例

MTBF 1,000時間、MTTR 10時間なら、

```text
1,000÷(1,000+10)
= 1,000÷1,010
≈ 0.990099
≈ 99.01%
```

MTBFを長くするか、MTTRを短くすれば稼働率が上がります。

## 11 MTTR短縮の効果

MTBF 1,000時間のまま、MTTRを10時間から1時間へ短くします。

```text
1,000÷(1,000+1)
≈ 99.9001%
```

故障頻度を変えなくても、自動切替え、交換しやすい設計、監視、手順改善で可用性を大きく上げられます。

## 12 停止率と年間停止時間

稼働率99.9%なら、停止率は、

```text
100%-99.9%=0.1%=0.001
```

一年を365日とすると、

```text
365×24 = 8,760時間
8,760×0.001 = 8.76時間
```

年間約8時間46分です。

代表値を計算します。

| 稼働率 | 年間停止時間の概算 |
|---:|---:|
| 99% | 87.6時間、約3日15時間36分 |
| 99.9% | 8.76時間、約8時間46分 |
| 99.99% | 0.876時間、約52.6分 |
| 99.999% | 0.0876時間、約5.26分 |

9が一つ増えるごとに許される停止時間がおおむね10分の1になります。

## 13 直列システムの稼働率

二つの要素が両方動く必要があり、互いの故障が独立なら、全体稼働率は掛け算です。

```text
A 0.99 ─ B 0.98

全体 = 0.99×0.98
     = 0.9702
     = 97.02%
```

部品を直列に増やすほど、全体稼働率は各部品より低くなります。

なぜ掛けるのでしょうか。「Aが動く、かつ、Bも動く」という二条件が同時に成立する確率だからです。

## 14 並列システムの稼働率

AかBのどちらか一方が動けばよい構成を考えます。

直接「少なくとも一方が動く」を数えるより、反対の「両方止まる」を1から引きます。

各稼働率99%、停止率1%=0.01なら、

```text
両方停止 = 0.01×0.01 = 0.0001
全体稼働 = 1-0.0001 = 0.9999 = 99.99%
```

一般に独立な二台の稼働率がA、Bなら、

```text
並列稼働率 = 1 - (1-A)(1-B)
```

です。

## 15 直列と並列が混ざる計算

Webサーバ二台の並列部分が各99%、その先に一台だけのDB 98%があるとします。

まずWeb並列部は、

```text
1-(1-0.99)²
= 1-0.0001
= 0.9999
```

次にDBと直列なので、

```text
0.9999×0.98
= 0.979902
≈ 97.99%
```

Webを二重化してもDBが一台なら、全体はDBへ強く制限されます。

## 16 独立という前提

並列計算の大きな改善は、故障が独立だという前提です。

二台が次を共有すると、同時停止が増えます。

- 電源
- 建物
- 通信回線
- ソフトウェアの欠陥
- 誤設定
- 管理権限

共通原因故障があるのに単純式だけを使うと、稼働率を過大評価します。

## 17 故障率とFIT

単位時間当たりに故障する割合を**故障率**と呼び、`λ`で表すことがあります。待ち行列の到着率にもλを使いますが、文脈が違います。

故障率が一定という単純モデルでは、

```text
MTBF ≈ 1÷故障率
```

です。

**FIT**、Failures In Timeは、10億時間当たりの故障数を表します。

100FITなら、

```text
故障率 = 100÷1,000,000,000
         = 0.0000001 /時間
MTBF ≈ 1÷0.0000001
     = 10,000,000時間
```

一個が本当に一千万時間動くまで試すという意味ではなく、多数部品の観測・統計から表します。

## 18 バスタブ曲線

機器の寿命に伴う故障率を時間順に描くと、浴槽の断面に似ることがあります。これを**バスタブ曲線**と呼びます。

```text
故障率
高 |＼                 ／
   |  ＼_____________／
低 +--------------------→ 時間
    初期   偶発故障期   摩耗期
```

### 初期故障期

製造不良、接続不良などが早期に現れ、時間とともに減ります。

### 偶発故障期

比較的一定の低い故障率が続くとみなします。一定故障率の計算を適用しやすい期間です。

### 摩耗故障期

部品の劣化・消耗により故障率が上がります。寿命前交換が必要です。

MTBFの一定値だけを、全寿命へ無条件に当てはめません。

## 19 RTOとRPO

障害後、サービスを何時間以内に再開するかという目標が**RTO**、Recovery Time Objective、目標復旧時間です。

障害時点から過去何分までのデータ損失を許すかという目標が**RPO**、Recovery Point Objective、目標復旧時点です。

```text
最後の復旧可能時点 ----- 障害 ----- 再開
        ← RPO →            ← RTO →
```

RTO 1時間、RPO 5分なら、障害から一時間以内に再開し、失うデータを原則5分以内へ抑える仕組みが必要です。

毎日一回のバックアップは最大約24時間分を失うため、RPO 5分を満たしません。復元に三時間掛かればRTO 1時間も満たしません。

## 20 数字を業務へ戻す

稼働率99.9%でも、重要な締切の10分前に8時間止まれば大損害です。一分停止が年間526回でも、利用者体験は悪くなります。

次も決めます。

- 計画停止を含めるか。
- 一部機能・一部地域停止をどう数えるか。
- 何時から何時までが対象か。
- 応答が遅すぎる状態を停止とみなすか。
- データ誤りを停止とみなすか。

数式は設計を助けますが、業務影響の定義は人が決めます。

2. 正常動作が200、300、400時間の三回ならMTBFを求めてください。
3. MTBF 2,000時間、MTTR 5時間の稼働率を求めてください。
4. 稼働率99.95%の年間停止時間を分で求めてください。1年525,600分とします。
5. 稼働率98%と99%の二要素が直列のとき全体稼働率を求めてください。
6. 各稼働率98%の二台が独立な並列なら全体稼働率を求めてください。
7. 同じ電源の二台へ単純な独立並列式を当てる危険を説明してください。
8. RTO 30分、RPO 10分に対し、日次バックアップの復元に2時間掛かる場合、何が不足しますか。
