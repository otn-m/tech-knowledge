# 第5章　ソフトウェア――機械の資源を管理し、人が使える形へする

一つずつなら正しく動く二つのプログラムも、同時に動かすと互いを止めることがあります。
同じデータを書き換えようとし、同じ記憶領域や装置を取り合い、互いが手放す資源を待ち続けるからです。

競合を解消して計算が終わっても、利用者が操作方法を見つけられなければ、仕事は終わりません。
ソフトウェアが役立つには、機械の資源を分け合う仕組みと、人が目的へ進める接点の両方が必要です。

この章では、OSが見えないところで行う調整から、画面、音、画像として人に届くところまでをたどります。
「動いた」という一言の中に、いくつの条件が隠れているかを確かめます。

## この章で身に付けること

- OSがCPU、記憶、装置、ファイル、利用者を管理する理由を説明する。
- プロセス・スレッドの状態遷移とスケジューリングを手で追う。
- 競合、同期、排他、デッドロックを実行順から見つける。
- 固定・可変区画、ページング、セグメント、仮想記憶を計算する。
- 入出力、バッファ、スプール、DMA、チャネルを区別する。
- OSのアカウント、監査、障害回復、プログラム形態を説明する。
- ミドルウェア、シェル、API、ライブラリ、フレームワークを区別する。
- ディレクトリ、パス、リンク、ファイル編成、バックアップを適用する。
- 開発・言語処理ツールを工程と目的から選ぶ。
- OSSライセンス、依存部品、安全性、支援を確認する。
- 情報アーキテクチャ、UI、UX、人間中心設計を利用者の行動から評価する。
- 音声・画像・動画のデータ量、形式、圧縮、XRを説明する。

## 学習の進め方

1. OS部分では、状態遷移・時間線・ページ枠を必ず紙に書きます。
2. ファイル部分では、木構造と復元に必要な世代を図にします。
3. UI部分では、「誰が、どこで、何を達成するか」を先に書きます。
4. メディア計算はHz、ビット、秒、チャネルを省略しません。
5. 総合演習は20問ずつ解き、誤答した本文に戻ります。

最初の二つのプログラムが、同じ装置を待たずに動けるようになっても、それで仕事が完了したとは限りません。
データを失わず、障害から戻り、利用者が次の操作を判断できて、ようやく結果が現実へ届きます。

命令の正しさは出発点です。
限られた資源の上で、その正しさを人の目的まで途切れさせないことが、ソフトウェアの役割です。
