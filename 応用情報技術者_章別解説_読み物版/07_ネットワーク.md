# 第7章　ネットワーク――一台の機器を世界の相手へつなぐ


## このファイルで初めて使う用語

本文で使う前に、ここでは次の意味を置きます。略語は正式名、日本語名、本文での役割の順です。

- **MACアドレス**：同じLAN内で機器のインタフェースを識別する番号。（[詳説](<07_ネットワーク/07_Ethernet・スイッチ・VLAN.md#1 MACアドレス>)）
- **IPv4**：32ビットのIPアドレスを使う方式。（[詳説](<07_ネットワーク/09_IPv4とサブネット.md#2 IPv4アドレス>)）
- **IPv6**：128ビットのIPアドレスを使う方式。（[詳説](<07_ネットワーク/10_ARP・DHCP・IPv6・NAT.md#16 IPv6>)）
- **サブネットマスク**：IPv4アドレスのどこまでがネットワーク部かを示す値。（[詳説](<07_ネットワーク/09_IPv4とサブネット.md#5 サブネットマスク>)）
- **CIDR**：Classless Inter-Domain Routing（クラスレスドメイン間経路制御）。アドレスのネットワーク部の長さを `/24` などで表し、柔軟に分割する方式。（[詳説](<07_ネットワーク/09_IPv4とサブネット.md#6 CIDR表記>)）
- **ルータ**：宛先IPアドレスを見て、別のネットワークへパケットを送る装置。（[詳説](<07_ネットワーク/11_ルーティング.md#1 ルータ>)）
- **ARP**：Address Resolution Protocol（アドレス解決プロトコル）。同じIPv4ネットワーク内で、IPアドレスに対応するMACアドレスを調べる仕組み。（[詳説](<07_ネットワーク/10_ARP・DHCP・IPv6・NAT.md#1 ARP>)）
- **DHCP**：Dynamic Host Configuration Protocol（動的ホスト構成プロトコル）。IPアドレスやDNS情報を端末へ自動配布する仕組み。（[詳説](<07_ネットワーク/10_ARP・DHCP・IPv6・NAT.md#5 DHCP>)）
- **NAT**：Network Address Translation（ネットワークアドレス変換）。IPアドレスを別のIPアドレスへ変換する仕組み。（[詳説](<07_ネットワーク/10_ARP・DHCP・IPv6・NAT.md#12 NAT>)）
- **ジッタ**：パケットごとの遅延時間のばらつき。（[詳説](<07_ネットワーク/04_トラフィックと品質.md#9 ジッタ>)）
- **SNMP**：Simple Network Management Protocol（簡易ネットワーク管理プロトコル）。ネットワーク機器の状態取得や設定に使う管理プロトコル。（[詳説](<07_ネットワーク/13_アプリケーション層プロトコル.md#20 SNMP>)）
- **VPN**：Virtual Private Network（仮想私設網）。公衆ネットワーク上に、暗号などで保護した論理的な専用経路を作る仕組み。（[詳説](<07_ネットワーク/17_仮想ネットワーク.md#6 VPN>)）
- **ファイアウォール**：通信元、宛先、ポートなどの規則で通信を許可・遮断する仕組み。（[詳説](<07_ネットワーク/10_ARP・DHCP・IPv6・NAT.md#23 ファイアウォール>)）
- **SLA**：Service Level Agreement（サービスレベル合意）。提供者と顧客が、サービス水準や責任を合意した文書。（[詳説](<07_ネットワーク/15_WANと通信サービス.md#15 SLA>)）
- **STP**：Segmentation, Targeting, Positioning（市場細分化・標的設定・位置付け）。市場を分け、狙う層を選び、自社の位置付けを決めるマーケティング手順。（[詳説](<07_ネットワーク/02_信号・媒体・回線速度.md#4 より対線>)）
- **IoT**：機器や物をネットワークへつなぎ、測定、制御、最適化する仕組み。（[詳説](<07_ネットワーク/21_IoTと省電力無線.md#1 IoT>)）


ネットワークは、複数の機器を通信路で結び、共通の規則で情報をやり取りする仕組みです。

この一文には、機器、通信路、信号、速度、住所、経路、誤り、混雑、アプリケーション、安全、運用という多くの話題が含まれます。この章では、どの用語も知っているものとして扱いません。

最初は二台の機器を一本の線でつなぐ場面から始めます。次に、信号を小さなデータのまとまりにし、スイッチとルータで渡し、IPアドレスで遠隔の相手を示し、TCPやUDPで相手のアプリへ届けます。その上でWeb、電子メール、モバイル通信、IoTまで進みます。

最後には、URLを一つ入力した後の全工程を端から端までたどり、「つながらない」「遅い」という現象を層と区間で切り分けられることを目指します。

## この章で身に付けること

- LAN、WAN、ISP、通信回線、媒体を具体的な接続図で説明する。
- bit/s、転送時間、誤り率、呼量、アーランB式の意味を読み取る。
- トポロジ、回線交換、パケット交換、全二重・半二重を用途から比べる。
- OSI基本参照モデルとTCP/IPの層を、実際の装置・プロトコルへ対応させる。
- 同期、フレーム化、誤り検出・訂正、フロー制御の目的を説明する。
- Ethernet、MACアドレス、スイッチ、VLAN、STP（Spanning Tree Protocol、スイッチのループを防ぐプロトコル）を一つのLANの動きとして追う。
- 無線LANの接続、暗号化、CSMA/CA、干渉、隠れ端末、メッシュを説明する。
- IPv4のサブネットを計算し、IPv6、ARP、DHCP、NATを使い分ける。
- 経路表の最長一致を読み、RIP、OSPF、BGP、ICMPの役割を区別する。
- TCPとUDPの動作、ポート番号、再送、流量・輻輳制御を説明する。
- DNS、HTTP、メール、FTPなどのアプリケーション層を端から端まで追う。
- 接続装置、WANサービス、監視、SNMP、VPN、SDN、NFV、SD-WANを選ぶ。
- イントラネット、エクストラネット、モバイル、5G、IoT、LPWAを説明する。
- 通信速度、遅延、可用性、電池寿命を単位から計算する。
- 障害を端末・区間・層・アプリケーションへ分け、証拠から切り分ける。

## 応用情報技術者試験での扱われ方

- **典型設問:** 「第1〜6話では、机の上に二台の機器があるつもりで、信号とデータの区切りを図にします。」
- **条件語:** `MACアドレス`を本文の定義と対応させます。
- **最初の着眼点:** 問われた語の上位概念、対象、役割、成立条件を分けて思い出します。
- **途中の組立て・式:** 『何であるか』に加え、『何へ何をするか』と、似た語との境界を一文にします。 本文の `/24` を使います。記号、単位、成立条件を置いてから代入し、結果の意味まで答えます。
- **典型誤答と理由:** 略語展開や日常語の印象だけでは、対象・役割・成立条件のいずれかが抜け、近い用語と区別できません。

## 第7部　総合演習

[第23話　第7章総合演習](07_ネットワーク/23_第7章総合演習.md)

80問を使い、基礎概念、速度・遅延・呼量・可用性計算、OSI、LAN、IP、TCP・UDP、アプリケーション、WAN、運用、仮想化、モバイル、IoT、障害切分け、設計を横断します。全問に解答と考え方があります。

## 学習の進め方

1. 第1〜6話では、机の上に二台の機器があるつもりで、信号とデータの区切りを図にします。
2. 第7〜8話では、フレームの送信元・宛先MACアドレスを区間ごとに書きます。
3. 第9〜11話では、IPv4アドレスを必ず2進数または範囲へ直し、経路表はプレフィックス長を比較します。
4. 第12〜15話では、「下位が運ぶもの」と「上位が意味を決めるもの」を分けます。
5. 第16〜17話では、正常値、変更、物理的な共通部品を記録します。
6. 第18〜21話では、利用者の一操作がどのサーバ・プロトコルを通るか矢印で描きます。
7. 第22話は、分からない段階があれば対応する前の話へ戻りながら読みます。
8. 総合演習は10問ずつ解き、計算式と判断理由を書いてから解答を読みます。

ネットワークを理解するとは、機器名と略語を大量に覚えることではありません。人の目的を小さな通信へ分解し、それぞれの層が何を保証し、何を保証しないかを説明できることです。
