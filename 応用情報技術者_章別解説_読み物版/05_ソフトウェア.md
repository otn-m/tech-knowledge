# 第5章　ソフトウェア――機械の資源を管理し、人が使える形へする


## このファイルで初めて使う用語

本文で使う前に、ここでは次の意味を置きます。略語は正式名、日本語名、本文での役割の順です。

- **デッドロック**：複数処理が互いの資源解放を待ち、永久に進めなくなる状態。（[詳説](<05_ソフトウェア/05_同期・排他・デッドロック.md#13 デッドロック>)）
- **仮想記憶**：補助記憶も使い、各プログラムへ広い独立したアドレス空間を見せる仕組み。（[詳説](<05_ソフトウェア/07_仮想記憶.md#第5章・第7話　仮想記憶――プログラム用の番地を、実物の番地へ変換する>)）
- **スケジューリング**：どの処理へ、いつ、どれだけCPUを使わせるか決めること。（[詳説](<05_ソフトウェア/04_CPUスケジューリング.md#第5章・第4話　CPUスケジューリング――次に誰へ実行時間を渡すか>)）
- **ページング**：仮想記憶を固定大のページへ分け、必要部分を主記憶へ置く方式。（[詳説](<05_ソフトウェア/06_実記憶管理.md#15 セグメント方式への入口>)）
- **ページフォールト**：必要なページが主記憶になく、補助記憶から読み込む必要が生じること。（[詳説](<05_ソフトウェア/07_仮想記憶.md#7 ページフォールト>)）
- **スラッシング**：ページ入替えが過度に増え、実際の処理が進まなくなる状態。（[詳説](<05_ソフトウェア/07_仮想記憶.md#15 スラッシング>)）
- **OSS**：Open Source Software（オープンソースソフトウェア）。所定のライセンスに従い、ソースコードの利用・変更・再配布が認められるソフトウェア。（[詳説](<05_ソフトウェア/14_オープンソースソフトウェア.md#第5章・第14話　オープンソースソフトウェア――読めるコードにも利用条件がある>)）
- **UX**：User Experience（利用者体験）。利用前後を含め、製品やサービスを通じて人が得る体験。（[詳説](<05_ソフトウェア/16_UX・画面・帳票・コード設計.md#第5章・第16話　UX・画面・帳票・コード設計――機能を、目的達成の体験へ変える>)）
- **セグメント**：TCPがアプリのデータを分けた単位。（[詳説](<05_ソフトウェア/06_実記憶管理.md#15 セグメント方式への入口>)）
- **認可**：認証後、その主体にどの操作を許すか決めること。（[詳説](<05_ソフトウェア/09_ユーザー・セキュリティ・障害管理.md#6 認証と認可>)）


この章では、アプリを一度も起動したことがない読者にも分かるよう、ソフトウェアとOSの違いから始めます。

一つのCPUを複数の仕事へ分け、限られた主記憶を守り、装置の速度差を吸収し、ファイルへ名前を付け、利用者の権限を確かめるのがOSです。その上で、ミドルウェア、開発道具、OSSを使ってアプリを作ります。

最後は、作った機能を人が本当に使えるよう、UI、UX、アクセシビリティを設計し、文字、音、画像、動画へ変換します。「ソフトウェアが動く」と「利用者が安全に目的を達成できる」の間をつなぐ章です。

## この章で身に付けること

- OSがCPU、記憶、装置、ファイル、利用者を管理する理由を説明する。
- プロセス・スレッドの状態遷移とスケジューリングを手で追う。
- 競合、同期、排他、デッドロックを実行順から見つける。
- 固定・可変区画、ページング、セグメント、仮想記憶を計算する。
- 入出力、バッファ、スプール、DMA、チャネルを区別する。
- OSのアカウント、監査、障害回復、プログラム形態を説明する。
- ミドルウェア、シェル、API、ライブラリ、フレームワークを区別する。
- ディレクトリ、パス、リンク、ファイル編成、バックアップを適用する。
- 開発・言語処理ツールを工程と目的から選ぶ。
- OSSライセンス、依存部品、安全性、支援を確認する。
- 情報アーキテクチャ、UI、UX、人間中心設計を利用者の行動から評価する。
- 音声・画像・動画のデータ量、形式、圧縮、XRを説明する。

## 応用情報技術者試験での扱われ方

- **典型設問:** 「OS部分では、状態遷移・時間線・ページ枠を必ず紙へ書きます。」
- **条件語:** `デッドロック`を本文の定義と対応させます。
- **最初の着眼点:** 初期状態と終了条件を置き、状態が変わるたびに値や主体を一行ずつ記録します。
- **途中の組立て・式:** 入力→判定→更新→出力の順を追い、分岐と例外でも同じ規則が保たれるか確かめます。 対象→入力→処理→出力の流れと、成立条件・限界を対応させます。選択問題でも不採用案が条件へ反する箇所を示します。
- **典型誤答と理由:** 処理名を暗記しただけでは、順序の逆転、更新前後の値、失敗後に残る状態を取り違えます。

## 学習の進め方

1. OS部分では、状態遷移・時間線・ページ枠を必ず紙へ書きます。
2. ファイル部分では、木構造と復元に必要な世代を図にします。
3. UI部分では、「誰が、どこで、何を達成するか」を先に書きます。
4. メディア計算はHz、ビット、秒、チャネルを省略しません。
5. 総合演習は20問ずつ解き、誤答した本文へ戻ります。

ソフトウェアは、命令が正しいだけでは完成しません。限られた資源で壊れず動き、障害から戻り、人が迷わず安全に目的を達成できて、初めて役に立ちます。
