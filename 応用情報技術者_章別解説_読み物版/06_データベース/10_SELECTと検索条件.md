# 第6章・第10話　SELECTと検索条件――必要な行と列を取り出す

この話では、次の表を使います。

```text
books
book_id | title          | category | price | stock | published_on
1       | はじめての星   | 科学     | 1200  | 3     | 2025-04-01
2       | 海辺の地図     | 小説     | 1800  | 0     | 2024-09-10
3       | 雲のしくみ     | 科学     | 1500  | 2     | NULL
4       | 小さな料理     | 料理     | 900   | 5     | 2026-01-20
```

## 1 すべての列を読む

```sql
SELECT *
FROM books;
```

`*`はすべての列です。学習・確認には便利ですが、アプリでは必要な列を明示します。

- 表へ列が追加されると結果が変わる。
- 大きな列まで読み通信量が増える。
- 不要な個人情報まで取得する。
- 同名列があると扱いにくい。

## 2 列を選ぶ

```sql
SELECT book_id, title, price
FROM books;
```

関係代数の射影に対応する考えです。

## 3 WHEREで行を絞る

```sql
SELECT book_id, title
FROM books
WHERE stock > 0;
```

`WHERE`は条件が真になる行を残します。選択に対応します。

## 4 比較演算子

```text
=   等しい
<>  等しくない
<   より小さい
<=  以下
>   より大きい
>=  以上
```

製品によって`!=`も使えますが、標準的な`<>`を読めるようにします。

```sql
WHERE price >= 1000
```

は価格が1000以上です。1000を含みます。

## 5 AND、OR、NOT

```sql
WHERE category = '科学'
  AND stock > 0
```

両方を満たす行です。

```sql
WHERE category = '科学'
   OR category = '料理'
```

少なくとも一方を満たす行です。

`NOT`は条件を否定します。

## 6 括弧で優先順を明示する

```sql
WHERE category = '科学'
   OR category = '料理'
  AND stock > 0
```

は人が意図したまとまりと違う可能性があります。演算の優先順位へ頼らず括弧で表します。

```sql
WHERE (category = '科学' OR category = '料理')
  AND stock > 0
```

## 7 BETWEEN

範囲を表します。

```sql
WHERE price BETWEEN 1000 AND 1600
```

一般に両端を含み、`price >= 1000 AND price <= 1600`と同じ考えです。

日時では時刻を含む上端に注意します。「7月14日の全時刻」を表すのに、日付時刻列へ`BETWEEN '2026-07-14 00:00' AND '2026-07-14 23:59'`とすると、秒以下を落とす危険があります。翌日の開始未満とする方法を検討します。

## 8 IN

候補のいずれかと等しい条件です。

```sql
WHERE category IN ('科学', '料理')
```

多数の`OR`を読みやすくできます。

## 9 LIKEとパターン文字列

文字列のパターンを調べます。

```sql
WHERE title LIKE 'はじめて%'
```

多くのSQLでは、

- `%`――0文字以上の任意の文字列。
- `_`――任意の1文字。

です。

`%星%`のように先頭も不定だと、通常の先頭順索引を効率よく使いにくい場合があります。全文検索用の転置インデックスなどを検討します。

## 10 NULLを調べる

NULLは普通の値ではないため、次のようには調べません。

```sql
-- 意図どおりにならない
WHERE published_on = NULL
```

`IS NULL`を使います。

```sql
WHERE published_on IS NULL
```

NULLでない行は`IS NOT NULL`です。

## 11 三値論理

SQLの条件結果には、真、偽に加えて**不明**があります。

`published_on`がNULLの行で、

```sql
published_on < DATE '2025-01-01'
```

を評価しても、早いとも遅いとも分かりません。結果は不明です。`WHERE`は真の行だけを残し、偽と不明を残しません。

`NOT (published_on < ...)`としても、不明の否定は不明です。NULL行が自動的に入るわけではありません。

## 12 NOT INとNULL

```sql
WHERE book_id NOT IN (2, 3)
```

は分かりやすいです。しかし候補を副問合せから取り、その中にNULLがあると、「どの候補とも違う」と確定できず、予想外に行が出ないことがあります。

NULLの可能性を除くか、`NOT EXISTS`を使う設計を検討します。

## 13 DISTINCT

重複する結果行を一つへします。

```sql
SELECT DISTINCT category
FROM books;
```

結果は科学、小説、料理です。

`DISTINCT`は「なぜ重複したか」を隠す道具にもなり得ます。結合条件誤りや表設計の問題がないか先に確認します。重複除去には並べ替え・ハッシュなどの費用がかかります。

## 14 列に別名を付ける

```sql
SELECT title AS book_title,
       price * stock AS inventory_value
FROM books;
```

`AS`で結果列へ**相関名**、別名を付けます。表へ別名を付ける場合も相関名と呼びます。

計算列`inventory_value`は保存列とは限らず、問い合わせ時に計算した結果です。

## 15 四則演算とNULL

```sql
SELECT price * stock
FROM books;
```

数値列を計算できます。一般に、計算へNULLが一つ混ざると結果もNULLです。「分からない値を足しても結果は分からない」と考えます。

NULLを0へ置き換える関数がありますが、0と不明を同じにしてよい業務か確認します。

## 16 CASE式

条件によって結果を変えます。

```sql
SELECT title,
       CASE
         WHEN stock = 0 THEN '在庫なし'
         WHEN stock <= 2 THEN '残りわずか'
         ELSE '在庫あり'
       END AS stock_status
FROM books;
```

上から最初に当てはまった結果を使います。条件の順番が重要です。

## 17 ORDER BY

結果の並びを指定します。

```sql
SELECT title, price
FROM books
ORDER BY price ASC, title ASC;
```

- `ASC`――昇順、小さい方から。
- `DESC`――降順、大きい方から。

同じ価格の行は書名順です。完全に再現可能な順番が必要なら、最後に主キーなど一意になる列を加えます。

`ORDER BY`がなければ、保存順・主キー順に見えても順序は保証されません。

## 18 結果件数を制限する

上位10件、次の20件などを返す構文があります。標準的な`FETCH FIRST`、製品ごとの`LIMIT`など表記が違います。

ページ番号が深くなるほど多くの行を読み飛ばす方式は遅くなる場合があります。最後に見た一意キーより後を取る方式もあります。

## 19 論理的な評価順

文字の記述順と、意味を考える順は違います。

```text
FROM       元になる行集合を作る
WHERE      行を絞る
GROUP BY   集団へ分ける
HAVING     集団を絞る
SELECT     出す列・式を作る
ORDER BY   並べる
```

最初は`FROM → WHERE → SELECT → ORDER BY`をたどります。集計は第12話で加えます。

## 20 条件式で列へ関数をかける費用

```sql
WHERE EXTRACT(YEAR FROM published_on) = 2026
```

各行の列を計算してから比べるため、普通の`published_on`索引を使いにくい場合があります。

```sql
WHERE published_on >= DATE '2026-01-01'
  AND published_on <  DATE '2027-01-01'
```

のような範囲条件なら索引を使いやすい場合があります。結果の正しさを保ち、実行計画で確認します。

3. 1000以上1600以下を`BETWEEN`で書いてください。
4. `%`と`_`の違いを答えてください。
5. NULLを`= NULL`で調べない理由を答えてください。
6. `DISTINCT`の役割と注意を答えてください。
7. `ORDER BY`がない結果の順序は保証されますか。
8. SQLの論理的な順序を`FROM`から答えてください。
