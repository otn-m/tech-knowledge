# 第6章・第12話　集約・グループ化・ウィンドウ関数――多くの行を数え、比べる

売上明細が何万行あっても、経営者が見たいのは「商品別の合計」「月別の平均」「売上順位」かもしれません。行を集団として計算します。

## 1 集約関数

複数行から一つの値を求める関数が**集約関数**、集合関数です。

- `COUNT`――件数。
- `SUM`――合計。
- `AVG`――平均。
- `MIN`――最小。
- `MAX`――最大。

```sql
SELECT COUNT(*) AS book_count,
       SUM(stock) AS total_stock,
       AVG(price) AS average_price,
       MIN(price) AS minimum_price,
       MAX(price) AS maximum_price
FROM books;
```

## 2 COUNTの違い

```sql
COUNT(*)
```

は行数を数えます。

```sql
COUNT(published_on)
```

は`published_on`がNULLでない行を数えます。

```sql
COUNT(DISTINCT category)
```

はNULLを除く異なるカテゴリ数を数えるのが一般的です。

同じ表でも値が違うため、何を数えるかを明示します。

## 3 NULLと集約

多くの集約関数はNULLを計算対象から除きます。

```text
点数: 80, 100, NULL
AVG(score) = (80+100)÷2 = 90
```

NULLを0点として平均した値60とは違います。「未受験」を0点と扱うか、平均対象外にするかは業務規則です。

全行がNULL、または対象行がないとき、`SUM`や`AVG`がNULLになることがあります。0と区別します。

## 4 GROUP BY

同じ値を持つ行を集団へ分け、集団ごとに集約します。

```sql
SELECT category,
       COUNT(*) AS book_count,
       AVG(price) AS average_price
FROM books
GROUP BY category;
```

```text
科学 | 2 | 1350
小説 | 1 | 1800
料理 | 1 | 900
```

## 5 SELECTへ書ける列

グループ化した問合せでは、`SELECT`に通常、

- `GROUP BY`へ書いた列。
- 集約関数で計算した値。

を置きます。

```sql
-- titleはカテゴリ内で一つに決まらない
SELECT category, title, AVG(price)
FROM books
GROUP BY category;
```

カテゴリ「科学」には複数書名があるため、どのtitleを出すか決まりません。エラーにするDBMSが一般的です。緩く一値を返す設定でも、その値へ意味を持たせません。

## 6 複数列でグループ化

```sql
SELECT category, publisher_id, COUNT(*)
FROM books
GROUP BY category, publisher_id;
```

カテゴリと出版社の組ごとに一集団です。

## 7 WHEREとHAVING

`WHERE`はグループ化**前の行**を絞ります。

`HAVING`はグループ化**後の集団**を絞ります。

```sql
SELECT category, AVG(price) AS average_price
FROM books
WHERE stock > 0
GROUP BY category
HAVING AVG(price) >= 1000;
```

順に読むと、

1. 在庫がある本だけ残す。
2. カテゴリごとに分ける。
3. 平均価格を計算する。
4. 平均1000以上のカテゴリだけ残す。

です。

## 8 WHEREへ書ける条件は先に絞る

```sql
HAVING category = '科学'
```

と書ける製品・状況でも、集約前に判定できる条件は`WHERE`へ置くと、早く行を減らせる可能性があり、意図も明確です。

集約結果への条件は`HAVING`が必要です。

## 9 条件付き集計

`CASE`を集約の中に使います。

```sql
SELECT
  COUNT(*) AS all_books,
  SUM(CASE WHEN stock > 0 THEN 1 ELSE 0 END) AS available_books
FROM books;
```

一回の走査で複数条件の件数を求められます。真なら1、偽なら0を足します。

## 10 集約で行が減る

`GROUP BY category`をすると、結果の一行は本一冊ではなくカテゴリ一つを表します。

元の個々の書名・価格は結果から失われます。集計結果から元の全行を復元できません。詳細が必要なら別の問合せか、次のウィンドウ関数を使います。

## 11 ウィンドウ関数

元の各行を残したまま、関連する行の集団について計算するものが**ウィンドウ関数**です。

```sql
SELECT title,
       category,
       price,
       AVG(price) OVER (PARTITION BY category) AS category_average
FROM books;
```

各本の行を残しつつ、その本のカテゴリ平均を横へ付けます。

## 12 PARTITION BY

ウィンドウ計算の対象を集団へ分けます。

```sql
OVER (PARTITION BY category)
```

`GROUP BY`と似ていますが、結果行を一集団一行へつぶしません。

## 13 順位

```sql
SELECT title,
       price,
       ROW_NUMBER() OVER (ORDER BY price DESC) AS row_no,
       RANK()       OVER (ORDER BY price DESC) AS price_rank,
       DENSE_RANK() OVER (ORDER BY price DESC) AS dense_rank
FROM books;
```

- `ROW_NUMBER`――同値でも1,2,3と別番号。
- `RANK`――同順位の次を飛ばす。1,2,2,4。
- `DENSE_RANK`――同順位の次を飛ばさない。1,2,2,3。

同値時に一意な順番が必要なら、主キーを追加して順序を決めます。

## 14 累計

```sql
SELECT sold_on,
       amount,
       SUM(amount) OVER (
         ORDER BY sold_on, sale_id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_total
FROM sales;
```

最初の行から現在行までの合計です。

同じ日付が複数あるとき、順序の同値処理や`ROWS`と`RANGE`の違いで結果が変わり得ます。安定した順序とフレーム範囲を明示します。

## 15 前後の行を見る

```sql
SELECT measured_at,
       temperature,
       LAG(temperature) OVER (ORDER BY measured_at) AS previous_temperature
FROM measurements;
```

`LAG`は前の行、`LEAD`は後の行の値を参照します。前回比、次回予定などに使います。

## 16 上位N件を集団ごとに取る

カテゴリごとに価格上位2冊を求めます。

```sql
WITH ranked AS (
  SELECT b.*,
         ROW_NUMBER() OVER (
           PARTITION BY category
           ORDER BY price DESC, book_id
         ) AS rn
  FROM books AS b
)
SELECT *
FROM ranked
WHERE rn <= 2;
```

まず全行へカテゴリ内順位を付け、外側で2位までを選びます。

## 17 集計の誤り――結合で水増しする

注文一件に明細3行、支払2行があるとします。注文へ明細と支払を同時に結合すると、3×2=6行になり、明細金額や支払額を重複集計する危険があります。

各多側を注文単位へ先に集約してから結合するなど、結果の粒度をそろえます。

## 18 粒度

一行が何を表すかを**粒度**と呼びます。

```text
売上明細表: 一商品明細が一行
日別売上表: 一日が一行
月別商品売上: 一月・一商品が一行
```

集計・結合前に各データの粒度を言葉で確認すると、水増しを防ぎやすくなります。

## 19 論理順序をもう一度

```text
FROM/JOIN  行の候補を作る
WHERE      行を絞る
GROUP BY   集団へ分ける
HAVING     集団を絞る
SELECT     集約・列・ウィンドウ結果を作る
ORDER BY   並べる
```

ウィンドウ関数の結果を同じ段階の`WHERE`で直接絞れない場合、共通表式や副問合せで一段外へ出します。
