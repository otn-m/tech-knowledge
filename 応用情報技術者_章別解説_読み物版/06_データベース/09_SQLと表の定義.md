# 第6章・第9話　SQLと表の定義――データベースへ構造と要求を伝える

関係DBへ、「利用者という表を作ってほしい」「番号1025の利用者を探してほしい」と伝えるための代表的な言語が**SQL**です。

SQLは一般にStructured Query Languageに由来する名前として扱われます。製品ごとに拡張や細かな違いがありますが、標準化された共通の土台があります。

## 1 SQLは何を伝えるか

多くのSQLでは、保存装置のどの位置から何バイト読むかという手順を書きません。欲しい結果や行う変更を宣言します。

```sql
SELECT name
FROM users
WHERE user_id = 1025;
```

これはおおまかに、

```text
users表から
user_idが1025の行について
name列を取り出す
```

という意味です。

## 2 SQL文の見た目

```sql
SELECT name
FROM users
WHERE user_id = 1025;
```

- `SELECT`、`FROM`、`WHERE`はSQLの予約語です。
- `users`、`name`、`user_id`は設計者が付けた名前です。
- `1025`は数値です。
- 最後の`;`は一文の終わりです。

予約語の大文字・小文字を区別しない製品が多く、読みやすさのため予約語を大文字で書く慣習があります。名前の大文字小文字や引用規則は製品ごとに確認します。

## 3 コメント

処理意図を人へ説明する文字がコメントです。

```sql
-- 返却されていない貸出を調べる
SELECT loan_id
FROM loans
WHERE returned_at IS NULL;
```

コメントは実行結果を変えません。ただし古い説明を残すと誤解を生むため、コードと一緒に更新します。

## 4 SQLの大きな分類

### 4.1 DDL

表、ビュー、スキーマなどの構造を定義する言語が**DDL**、Data Definition Language、データ定義言語です。

代表は`CREATE`、`ALTER`、`DROP`です。

### 4.2 DML

データの検索・追加・変更・削除を行う言語が**DML**、Data Manipulation Language、データ操作言語です。

代表は`SELECT`、`INSERT`、`UPDATE`、`DELETE`です。

### 4.3 権限とトランザクション

`GRANT`、`REVOKE`で権限を扱い、`COMMIT`、`ROLLBACK`で一連の変更を確定・取消しします。分類名は教材・製品で細分されることがあります。命令の役割を理解します。

## 5 独立言語方式と親言語方式

SQLを対話用画面やコマンドから単独で実行する使い方が**独立言語方式**、会話型SQL、コマンド方式です。

プログラム言語のコードからSQLを利用する使い方が**親言語方式**です。SQLをコード中へ書く**埋込みSQL**、ライブラリ・ドライバから呼ぶ方式などがあります。

画面フォームへ条件を入力し、裏で問合せ、クエリを作る道具もあります。

## 6 表を作るCREATE TABLE

利用者表を定義します。

```sql
CREATE TABLE users (
  user_id       INTEGER      NOT NULL,
  name          VARCHAR(100) NOT NULL,
  registered_on DATE         NOT NULL,
  member_type   VARCHAR(20)  NOT NULL,
  PRIMARY KEY (user_id)
);
```

上から読みます。

1. `users`という表を作る。
2. `user_id`は整数で必須。
3. `name`は最大長を持つ文字列で必須。
4. `registered_on`は日付で必須。
5. `member_type`は文字列で必須。
6. `user_id`を主キーにする。

## 7 データ型

列に入れる値の種類が**データ型**です。

### 7.1 数値型

- `INTEGER`――整数。
- `DECIMAL(p,s)`――十進の固定小数点。合計p桁、小数部s桁などと指定する。
- 浮動小数点型――非常に広い範囲を近似で扱う。

金額を二進浮動小数点で近似すると端数問題が起こるため、必要な十進桁を正確に扱う型を検討します。

### 7.2 文字型

- `CHAR(n)`――固定長文字列。
- `VARCHAR(n)`――可変長文字列。

文字数とバイト数、末尾空白、照合順序、大小文字の扱いは製品・設定で違います。

### 7.3 日付型・時刻型

- `DATE`――日付を扱う**日付型**。
- `TIME`――時刻。
- `TIMESTAMP`――日付と時刻。

時刻帯を持つか、夏時間をどう扱うかを確認します。日時を単なる文字列にすると、存在しない日付や並べ替えの問題が起きます。

### 7.4 真偽・二進・大きな値

真偽値、バイト列、大きな文字・画像を扱う型があります。製品差があります。巨大なデータをDB内へ置くか、外部保存して参照だけ持つかは、整合性、バックアップ、配信性能で決めます。

## 8 列制約

列のすぐ後ろへ規則を書けます。

```sql
score INTEGER NOT NULL CHECK (score BETWEEN 0 AND 100)
```

- `NOT NULL`――NULLを許さない**非NULL制約**。
- `UNIQUE`――重複を許さない一意性制約。
- `CHECK`――条件を満たさせる検査制約。
- `DEFAULT`――値を省略したときの既定値。

`DEFAULT`は「分からない値」を勝手に0へする機能ではありません。業務上本当に既定値が決まる場合に使います。

## 9 表制約

複数列をまとめる制約は、表の要素として書くと読みやすくなります。

```sql
CREATE TABLE results (
  student_id INTEGER NOT NULL,
  subject_id INTEGER NOT NULL,
  score      INTEGER CHECK (score BETWEEN 0 AND 100),
  PRIMARY KEY (student_id, subject_id)
);
```

主キーが二列の組であることが明確です。

## 10 外部キー制約

```sql
CREATE TABLE loans (
  loan_id  INTEGER PRIMARY KEY,
  user_id  INTEGER NOT NULL,
  book_id  INTEGER NOT NULL,
  loaned_on DATE NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(user_id),
  FOREIGN KEY (book_id) REFERENCES books(book_id)
);
```

`REFERENCES`は参照先を示します。存在しない利用者・本の貸出を防ぎます。

## 11 CASCADE

参照先の更新・削除に合わせ、参照側へ処理を連鎖させる指定が`CASCADE`です。

```sql
FOREIGN KEY (user_id) REFERENCES users(user_id)
  ON DELETE CASCADE
```

利用者を削除すると、その利用者の貸出も消える指定です。貸出履歴を残す業務なら不適切です。便利な構文ではなく、業務上の削除方針として選びます。

## 12 ALTER TABLE

既存の表定義を変更します。

```sql
ALTER TABLE users
ADD COLUMN email VARCHAR(254);
```

巨大表への列・制約追加は、長いロック、全行検査、保存容量を伴う場合があります。本番では製品の実行方法、退避、戻し方を確認します。

## 13 DROP

定義ごと削除する命令が`DROP`です。

```sql
DROP TABLE users;
```

行だけでなく表構造を削除します。`DELETE`とは違います。関連ビュー・外部キーへの影響、バックアップを確認します。

## 14 名前と予約語

表・列名に予約語、空白、特殊文字を使うと、引用符が必要になり移植・入力が難しくなります。意味が明確で一貫した命名規則を決めます。

```text
悪い例: data1, item, value
改善例: loaned_on, returned_on, member_type
```

ただし長すぎる名前も読みにくくなります。略語辞書を整えます。

## 15 スキーマという名前空間

SQLでは、表などをまとめる名前空間も**スキーマ**と呼びます。

```text
library.users
library.loans
accounting.payments
```

三層スキーマの一般概念と、SQL製品上のスキーマという入れ物は関連しますが、完全に同じ一対一の意味ではありません。文脈を見ます。

## 16 方言と標準

自動採番、文字列結合、日付計算、ページ分割、真偽型などは製品差があります。

```text
標準で共通する考えを学ぶ
使用製品の仕様を確認する
移植が必要な箇所を分離する
```

SQLが動いたことと、他製品でも同じ結果・性能になることは別です。

## 17 文字列と数値を区別する

文字列は引用符で囲みます。

```sql
'山田花子'
'2026-07-14'
```

数値は通常囲みません。

```sql
1025
80.5
```

日付リテラルの標準的な書き方や暗黙変換は製品差があります。値を文字列連結せず、後に学ぶプレースホルダで型と値を渡します。


## 確認問題

1. SQLが保存装置の読取り手順ではなく、主に何を宣言する言語か答えてください。
2. DDLとDMLを区別し、命令を一つずつ挙げてください。
3. 独立言語方式と親言語方式を区別してください。
4. `NOT NULL`、`UNIQUE`、`CHECK`の役割を答えてください。
5. 複合主キーを表制約として書く利点を答えてください。
6. 外部キーの`REFERENCES`は何を示しますか。
7. `DROP TABLE`と行を削除する操作の違いを答えてください。
8. 金額へ浮動小数点型を安易に使わない理由を答えてください。

1. **解法の入口:** 初期状態と終了条件を置き、状態が変わるたびに値や主体を一行ずつ記録します。 問題は「SQLが保存装置の読取り手順ではなく、主に何を宣言する言語か答えてください。」です。
   **途中手順:** 入力→判定→更新→出力の順を追い、分岐と例外でも同じ規則が保たれるか確かめます。 到達点は「欲しい結果や行いたい定義・変更を宣言します。」です。
   **結論:** 欲しい結果や行いたい定義・変更を宣言します。
   **この誤答が起きる理由:** 処理名を暗記しただけでは、順序の逆転、更新前後の値、失敗後に残る状態を取り違えます。
