# 第6章・第11話　結合と副問合せ――複数の表から一つの答えを作る

利用者表と貸出表を結べば、利用者名と借りた資料を1つの結果にできます。
2つの表をつないだのだから、利用者も1人につき1行のままと思うかもしれません。
しかし、1人に貸出が3件あれば、その利用者の行も3行に増えます。

結合後の行数は、表の数ではなく、キーの対応関係で決まります。

## 1 使用する表

```text
users
user_id | name
1       | 青木
2       | 伊藤
3       | 上田

loans
loan_id | user_id | book_id | loaned_on
101     | 1       | 10      | 2026-07-01
102     | 1       | 20      | 2026-07-02
103     | 2       | 10      | 2026-07-03

books
book_id | title
10      | 星の図鑑
20      | 海の物語
30      | 山の料理
```

## 2 内部結合

```sql
SELECT u.name, b.title, l.loaned_on
FROM loans AS l
JOIN users AS u
  ON l.user_id = u.user_id
JOIN books AS b
  ON l.book_id = b.book_id;
```

`AS l`は表の別名、相関名です。
`l.user_id`は`loans`表の`user_id`を意味します。

`ON`が結合条件です。
対応する行だけを残すため、貸出のない上田と、一度も借りられていない山の料理は出ません。

## 3 列名を修飾する

複数表に`user_id`があるため、

```sql
l.user_id
u.user_id
```

のように表名・別名を付けます。
同名列がなくても、長いSQLでは出所を明確にできます。

## 4 結合条件を忘れる

```sql
FROM users AS u, loans AS l
```

条件なしで2表を並べると直積になります。
利用者3行×貸出3行=9行です。

古いカンマ形式でも`WHERE`に結合条件を書けますが、条件漏れを見分けやすくするため、`JOIN ... ON`を使う書き方が一般的です。

## 5 一対多で行が増える

青木は貸出を2件持つので、結合結果に青木が2行出ます。
これは重複誤りではありません。
2つの異なる貸出事実に対応します。

```text
青木 | 星の図鑑 | 2026-07-01
青木 | 海の物語 | 2026-07-02
```

氏名だけを選ぶと同じ見た目になりますが、元の貸出行は違います。

## 6 左外部結合

内部結合では、対応する貸出がない利用者は結果から消えます。
「貸出が0件の利用者」も調べたいなら、対応がないという事実をNULL付きの行として残す必要があります。

貸出がない利用者も残します。

```sql
SELECT u.name, l.loan_id
FROM users AS u
LEFT JOIN loans AS l
  ON u.user_id = l.user_id;
```

結果には、

```text
上田 | NULL
```

が出ます。
左の`users`を全部残し、対応しない右側をNULLにします。

## 7 外部結合とWHEREの落とし穴

```sql
SELECT u.name, l.loaned_on
FROM users AS u
LEFT JOIN loans AS l
  ON u.user_id = l.user_id
WHERE l.loaned_on >= DATE '2026-07-01';
```

貸出のない行では`l.loaned_on`がNULLで、`WHERE`条件は真になりません。
上田が消え、目的によっては内部結合のようになります。

右表のどの行と対応させるかという条件なら、`ON`に置く方法を検討します。

```sql
LEFT JOIN loans AS l
  ON u.user_id = l.user_id
 AND l.loaned_on >= DATE '2026-07-01'
```

`ON`と`WHERE`は外部結合で結果が違い得ます。

## 8 右外部結合と完全外部結合

- `RIGHT JOIN`：右表の全行を残す。
- `FULL OUTER JOIN`：左右どちらの未対応行も残す。

左右を入れ替えれば、右外部結合を左外部結合として書けます。
製品によって完全外部結合の対応が違います。

## 9 自己結合

```text
employees
employee_id | name | manager_id
1           | 青木 | NULL
2           | 伊藤 | 1
3           | 上田 | 1
```

部下と上司の氏名を出します。

```sql
SELECT e.name AS employee_name,
       m.name AS manager_name
FROM employees AS e
LEFT JOIN employees AS m
  ON e.manager_id = m.employee_id;
```

同じ表を`e`と`m`という2役で読みます。

## 10 副問合せ

複数表から答えを作る方法は、結合だけではありません。
平均より高い点数のように、ある問合せの結果を別の条件へ使う場合は、問合せを内側へ置けます。

SQL文の中に置く別の問合せが**副問合せ**、サブクエリです。

```sql
SELECT title
FROM books
WHERE book_id IN (
  SELECT book_id
  FROM loans
  WHERE user_id = 1
);
```

内側が青木の借りた本番号集合を作り、外側がその書名を取り出します。

## 11 単一行副問合せ

必ず1行1値を返す副問合せなら、普通の比較に使えます。

```sql
SELECT title, price
FROM books
WHERE price > (
  SELECT AVG(price)
  FROM books
);
```

平均価格より高い本です。
副問合せが複数行を返すのに`=`を使うとエラーになる場合があります。
返す形を確認します。

## 12 EXISTS

副問合せが1行でも返すかを調べます。

```sql
SELECT u.user_id, u.name
FROM users AS u
WHERE EXISTS (
  SELECT 1
  FROM loans AS l
  WHERE l.user_id = u.user_id
);
```

貸出が1件以上ある利用者です。
`SELECT 1`の1という値自体は使わず、行の存在だけを見ます。

## 13 NOT EXISTS

```sql
SELECT u.user_id, u.name
FROM users AS u
WHERE NOT EXISTS (
  SELECT 1
  FROM loans AS l
  WHERE l.user_id = u.user_id
);
```

貸出が1件もない利用者です。
候補にNULLが混ざる`NOT IN`より意図を安全に表しやすい場合があります。

## 14 相関副問合せ

内側が外側の現在行を参照するものが**相関副問合せ**です。

先の`EXISTS`では、内側が`u.user_id`を使っています。

```text
外側の利用者を1行見る
  ↓
その利用者番号の貸出があるか内側で調べる
  ↓
次の利用者へ
```

論理的には外側の各行に対応して評価します。
DBMSは同じ結果になる結合に変形することがあります。
相関だから必ず遅い、書換えれば必ず速いとは限らず、実行計画と実測を見ます。

## 15 すべてを満たす二重NOT EXISTS

「すべての必須科目を修了した社員」は、未修了の必須科目が1件も存在しない、と言い換えられます。

```sql
SELECT e.employee_id
FROM employees AS e
WHERE NOT EXISTS (
  SELECT 1
  FROM required_courses AS r
  WHERE NOT EXISTS (
    SELECT 1
    FROM completions AS c
    WHERE c.employee_id = e.employee_id
      AND c.course_id = r.course_id
  )
);
```

外側の`NOT EXISTS`は「未修了科目が存在しない」です。
関係演算の商に対応する考えです。

## 16 共通表式、CTE

長い問合せの途中結果に名前を付けるものが**共通表式**、CTEです。

```sql
WITH active_users AS (
  SELECT DISTINCT user_id
  FROM loans
  WHERE loaned_on >= DATE '2026-01-01'
)
SELECT u.name
FROM users AS u
JOIN active_users AS a
  ON a.user_id = u.user_id;
```

読みやすさ、再帰問合せ、段階化に使えます。
必ず物理的な一時表を作るわけではなく、最適化方法は製品・指定で違います。

## 17 結合か副問合せか

同じ結果を複数の書き方で表せる場合があります。

- 結果に相手表の列も出すなら結合が自然。
- 存在するかだけなら`EXISTS`が意図を表しやすい。
- 1値と比較するなら単一行副問合せが読みやすい。

短さだけで選ばず、重複行、NULL、意図、実行計画を確認します。

## 18 N+1問題

利用者100人を一度検索し、アプリが1人ずつ貸出を追加検索すると、

```text
利用者一覧 1回
各利用者の貸出 100回
合計101回
```

のDB往復になります。
これを**N+1問題**と呼ぶことがあります。

結合、一括IN検索、事前読込みで減らせます。
一方、一度に巨大な結果を作ると通信量・メモリが増えます。
往復回数と結果量を測ります。

## 19 結合前後の件数を調べる

意図しない重複が出たら、すぐ`DISTINCT`で隠さず、

1. 各表のキーは何か。
2. 結合列は一意か。
3. 1対1、1対多、多対多のどれか。
4. 欠けた結合条件はないか。
5. NULLの結合キーがあるか。

を確認します。

利用者と貸出を結合して行が増えたとき、`DISTINCT`で消せば元の件数に戻るとは限りません。
1対多の関係が作った3行は、それぞれ異なる貸出を表す正しい結果かもしれないからです。
結合前後のキーと件数を予測し、欲しい答えの粒度と一致しているかを確かめます。


## 確認問題

1. `ON`は何を指定しますか。
2. 1対多の結合で一側の行が繰り返されるのは誤りですか。
3. 左外部結合で右側に対応行がないと、右の列は何になりますか。
4. 右表の条件を`WHERE`に置くと左外部結合の未対応行が消える場合がある理由を答えてください。
5. 自己結合の例を答えてください。
6. `EXISTS`は副問合せの何を調べますか。
7. 相関副問合せとは何ですか。
8. N+1問題の101回が何から成るか答えてください。

## 解答と解説

1. **解答**：どの行同士を対応させるかという結合条件です。
2. **解答**：誤りとは限りません。
   多側の各事実に対応して一側が繰り返されます。
3. **解答**：NULLになります。
4. **解答**：未対応行の右列はNULLで、比較条件が真にならず`WHERE`で除かれるためです。
5. **解答**：社員表を部下と上司の2役で結ぶ場合です。
6. **解答**：1行でも返るかという存在を調べます。
7. **解答**：内側の問合せが外側の現在行を参照する副問合せです。
8. **解答**：一覧取得1回と、100人分の個別取得100回です。
