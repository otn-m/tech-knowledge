# 第0部A パソコンとITの超入門――機械を見たことがないところから

画面のボタンをクリックすると、少し待って別のページが現れます。
目に見えるのは、マウスを押す操作と画面の変化だけです。
その間に働くのが、本体、OS、ブラウザ、ネットワーク、Webサーバです。
必要に応じてデータベースも使われます。

これらの名前は、1回の操作を実現するために、どの部分が何を担当するかを表しています。
クリックを受け取るところからページを表示するところまでを追うと、それぞれの役割と、互いのつながりが分かります。

## 操作を受け取り、結果を返す機械

### 1 コンピュータは「指示された処理をする機械」

人に「紙に書かれた100個の数を全部足してください」と頼むと、その人は数を読み、足し算をし、答えを書きます。
コンピュータの仕事も、大まかには同じ3段階に分けられます。

```text
受け取る → 決められた処理をする → 結果を返す
```

受け取る情報や指示を**入力**、それに対して行う仕事を**処理**、返す結果を**出力**と呼びます。
電卓なら、数字と「足す」という指示を受け取り、内部で足し算をして、答えを画面に表示します。

```text
入力: 12、+、30
処理: 12と30を足す
出力: 42
```

コンピュータは、決められた処理を速く、何度も繰り返すことを得意とします。
ただし、「いい感じにして」「常識で判断して」という指示は、そのままでは実行できません。
どのような場合に何をするかを、機械が扱える形で決める必要があります。

コンピュータに、人間のような姿は必要ありません。
机の上で使うパソコン、持ち運べるノートパソコン、スマートフォンも、その仲間です。
自動販売機の中や、自動車のブレーキとエンジンを制御する装置にも、コンピュータがあります。
離れた人の画面に文字や画像を送る機械も含まれ、これは後で「サーバ」として説明します。
形や目的が違っても、入力を受け、決められた処理をし、結果を出す点は共通しています。

1台の出力を別のコンピュータが入力として受け取れば、この3段階をつなげて仕事を進められます。
Webページの表示でも、こうした受渡しが続きます。

### 2 パソコンの外から見える部品

冒頭のクリックを受け取る**パソコン**は、個人がさまざまな仕事に使えるコンピュータです。
personal computerを短くしてPCとも呼びます。
典型的なパソコンでは、画面、キーボード、マウスを本体につないで使います。

```text
                 ┌───────────────┐
                 │      画面       │
                 │ 文字や絵を表示  │
                 └───────────────┘
                        │
┌──────────┐    ┌───────────────┐
│ キーボード │    │      本体       │
│文字を入れる│    │ 計算し、記憶する │
└──────────┘    └───────────────┘
                        │
                 ┌──────────┐
                 │  マウス    │
                 │場所を指す  │
                 └──────────┘
```

文字や写真、ボタンを表示する部分が**画面**です。
ディスプレイ、モニターとも呼ばれ、処理の結果を利用者に伝えます。
これに対し、文字や数字を入れる**キーボード**には、多数の押せる部分が並んでいます。
その一つ一つがキーです。

**マウス**は、机の上で動かして画面上の場所を指す部品です。
マウスを動かすと、画面上の小さな矢印である**ポインタ**も動きます。
本体の内部には、計算をする部品、作業中の情報を置く部品、長く情報を保存する部品などがあります。
内部の詳しい仕組みは第3章で学びます。

ノートパソコンでは、本体、画面、キーボードが一体になっています。
マウスの代わりに使う、指を滑らせる平らな部分が**タッチパッド**です。
スマートフォンでは、画面に直接触れて操作します。

#### 入力装置と出力装置

外部から情報を入れる部品は**入力装置**、外部へ結果を出す部品は**出力装置**です。
キーボード、マウス、マイク、カメラ、温度センサは入力装置に、画面、プリンタ、スピーカーは出力装置に当たります。

この区別は、部品の形ではなく役割によるものです。
指で操作できる画面は、表示する出力装置であると同時に、触れた場所を受け取る入力装置でもあります。

### 3 電源を入れて操作する

機械を動かすために電気を供給することを、電源を入れるといいます。
本体の電源ボタンを押すと、パソコンは内部の部品を確認し、利用の準備を進めます。
準備が終わると、背景や文字、小さな絵が画面に現れます。

画面の小さな絵を**アイコン**と呼びます。
利用者が目的に応じて使うソフトウェアである**アプリ**や、名前を付けて保存する一まとまりのデータである**ファイル**を表しています。
アプリとファイルの詳しい違いは、後の節で確かめます。

#### マウスの基本操作

マウスのボタンを1回押し、すぐ離す操作が**クリック**です。
一般には左側のボタンを使います。
ポインタを対象に合わせてクリックすると、「この対象を選ぶ」「このボタンを押す」という指示を送れます。

短い間に2回押す**ダブルクリック**は、画面上のものを開く操作などに使われます。
ボタンを押したままマウスを動かし、別の場所で離す操作は**ドラッグ**です。
ものを移動したり、範囲を選んだりするときに使います。

同じクリックでも、指している場所によって結果は変わります。
機械が「たぶんこの辺を押したかったのだろう」と常に推測してくれるわけではありません。

#### ウィンドウ、ボタン、メニュー

パソコンでは、文章作成などの仕事ごとに、四角い領域が画面上に開きます。
この領域が**ウィンドウ**です。
英語で窓を意味し、1枚の画面に複数の仕事の領域を並べられます。

```text
┌──────────── 文章を書くウィンドウ ────────────┐
│ ファイル  編集  表示                         │ ← メニュー
│                                              │
│ ここへ文章を入力します。                      │ ← 入力欄
│                                              │
│                         [ 保存 ]              │ ← ボタン
└──────────────────────────────────────┘
```

ウィンドウの中にも、役割の異なる部品があります。
**ボタン**は、クリックすると決められた操作を始める部品で、実物の押しボタンを画面に表したものと考えられます。
**メニュー**には、選べる操作が並びます。
飲食店のメニューに注文できる料理が並ぶのと同じように、画面のメニューには実行できる操作が並んでいます。

文字や数字を入れる場所は**入力欄**です。
入力欄をクリックしてからキーボードを押すと、そこに文字が表示されます。

## 処理の手順と機械の分担

### 4 データとプログラム

コンピュータが扱う文字、数、写真、音などを、まとめて**データ**と呼びます。
学校の名簿なら氏名、学生番号、生年月日が、写真アプリなら写真を構成する色の情報や撮影日時がデータです。

そのデータに対して行う処理の手順を、機械が扱える形で記録したものが**プログラム**です。
料理にたとえるなら、材料がデータ、調理手順を書いたレシピがプログラム、レシピに従って調理する人や器具がコンピュータに当たります。
ただし、料理人は書かれていないことを常識で補えますが、コンピュータには曖昧さの少ない手順を渡す必要があります。

```text
データ: 80点、75点、90点
プログラム:
  1. 三つの点数を足す
  2. 3で割る
  3. 結果を表示する
出力: 平均81.666…点
```

点数を変えても、「足して個数で割る」という手順は同じです。
そのため、同じプログラムに別のデータを渡して平均を求められます。
データと手順を分けて考えると、何を変え、何をそのまま使えるかが分かります。

#### データの意味は0と1だけでは決まらない

コンピュータの内部では、データは最終的に0と1の並びとして扱われます。
同じ並びでも、数、文字、色のどれとして読むかによって意味は変わります。

本棚に`42`という札が付いていても、それだけでは本の冊数か棚番号か、気温なのかを決められません。
同じように、データを使うには値だけでなく、その値をどう解釈するかという約束も必要です。
第1章以降でも、この区別を使います。

### 5 ソフトウェア、アプリ、OS

プログラムと、それを動かすためのデータをまとめて**ソフトウェア**と呼びます。
一方、本体や内部の電子部品のように、手で触れられる機械部分は**ハードウェア**です。
パソコンは、この両方を使って仕事をします。

```text
ハードウェア: 本体、画面、キーボード、内部の電子部品
ソフトウェア: 文章作成、写真表示、計算などを行うプログラム群
```

利用者が特定の目的に使うソフトウェアが**アプリケーションソフトウェア**です。
短く「アプリ」とも呼びます。
文章を書く、表を作って計算する、写真を見る、メールを読み書きするといった用途ごとに、アプリがあります。
インターネット上の文書を結ぶ仕組みである**Web**（World Wide Web）のページを見るブラウザも、その一つです。

ただし、ブラウザが画面、マウス、保存装置をすべて直接動かすなら、ほかのアプリにも同じ機能を個別に用意しなければなりません。
そこで、複数のアプリに共通する仕事を**OS**が引き受けます。
OSはOperating Systemの略で、日本語ではオペレーティングシステムと呼ぶ基本ソフトウェアです。

OSは、各アプリに計算する時間を割り当て、使う記憶場所を分けます。
キーボードの入力をアプリへ渡し、画面への表示を管理するのもOSの仕事です。
さらに、ファイルを保存して後で探せるようにし、利用者ごとに許される操作を分けます。

```text
利用者
  ↓ 操作
アプリ
  ↓ 共通の仕事を依頼
OS
  ↓ 機械を制御
ハードウェア
```

文章作成アプリを閉じても、OSは動き続けます。
通常のアプリが画面や保存装置を共通の方法で使えるのは、OSがそれらを管理しているためです。
利用者の操作は、アプリとOSを通じて、ハードウェアの動作につながります。

## 作業中の情報を保存して残す

### 6 作業中の記憶と、長く残す保存

アプリで文章を書いている間、その文章は作業中の情報です。
後でも使えるように残すには、作業中の情報を置く場所と、保存する場所を区別します。
勉強中に本や紙を広げる机と、使い終わった資料を戻す本棚の関係に似ています。
机はすぐ手が届きますが、置ける量に限りがあり、本棚は多くの資料を置ける一方、取りに行く時間がかかります。

コンピュータの**メモリ**は、実行中のプログラムと、今使っているデータを一時的に置く場所です。
主記憶とも呼ばれ、計算と命令の実行を担う中心部品の**CPU**（Central Processing Unit、中央処理装置）から素早く使えます。
ただし、一般的なメモリの内容は、電源を切ると失われます。

ファイルを長く残す場所が**保存装置**です。
半導体に保存する**SSD**（Solid State Drive）や、磁気円盤に保存する**HDD**（Hard Disk Drive、ハードディスク）などがあります。
保存装置は、一般にはメモリより遅いものの、大量のデータを置け、電源を切っても内容が残ります。

```text
              メモリ                  保存装置
役割          今使うものを置く        後でも使うものを残す
速さ          速い                    比較的遅い
容量          比較的小さい            比較的大きい
電源を切る    通常は内容が消える      内容が残る
たとえ        作業机                  本棚・倉庫
```

保存ボタンを押さずに電源を切って文章が消えるのは、変更内容がメモリにしかなく、保存装置へ書かれていなかったためです。
画面に見えていることと、後にも残るように保存されたことは、同じではありません。

机と本棚のたとえは役割をつかむ助けになりますが、実際の管理はもっと複雑です。
OSがデータを自動で一時保存したり、保存装置の一部をメモリの代わりに使ったりする仕組みもあります。
これらは第3章と第5章で学びます。

### 7 ファイルとフォルダ

保存装置には、文章や写真を一まとまりずつ残します。
この保存されたデータのまとまりが**ファイル**です。
1つの文章、1枚の写真、1曲分の音、1つのプログラムなどを、それぞれファイルとして保存できます。

見分けるために付ける名前が**ファイル名**です。
`旅行の予定.txt`や`写真001.jpg`の末尾にある`.txt`、`.jpg`は、データの種類を知る手掛かりになります。
この末尾部分を**拡張子**と呼びます。

ファイルが増えると、名前だけでは探しにくくなります。
大量の紙を1つの引出しに乱雑に入れないように、ファイルも分類して入れ物にまとめます。
この入れ物が**フォルダ**で、ディレクトリとも呼びます。
フォルダの中には、さらに別のフォルダを入れられます。

```text
文書
├─ 学校
│  ├─ 時間割.txt
│  └─ 課題.txt
└─ 旅行
   ├─ 予定.txt
   └─ 持ち物.txt
```

このように、親子関係で枝分かれする形が**階層構造**です。
ファイルの名前と、そのファイルを置く場所を分けて考えます。

ファイルを使う操作には、次のものがあります。

- **作成する**：新しいファイルを作る。
- **開く**：内容を使える状態にする。
- **保存する**：変更内容を保存装置に残す。
- **コピーする**：同じ内容を持つ別のファイルを作る。
- **移動する**：置かれているフォルダを変える。
- **名前を変更する**：内容を変えずに呼び名を変える。
- **削除する**：不要として取り除く。

とくに、コピーと移動では、操作後に残るファイルが違います。
コピーでは元のファイルと複製の2つが残り、移動では同じファイルの置き場所が変わります。

## 離れた相手から情報を受け取る

### 8 通信とネットワーク

パソコンでは、1台の中で情報を処理し、保存するだけでなく、別のコンピュータと情報をやり取りすることもあります。
Webページの閲覧も、その一例です。
2台以上の機器をつなぎ、情報をやり取りできるようにしたものが**ネットワーク**です。

近くの機器は電線や光ファイバーでつなげるほか、線を使わず電波でもつなげます。
ただし、つながっているだけでは、情報を正しく渡せません。
送信側と受信側が、情報の表し方と送り方について、同じ約束を使う必要があります。

世界中の多数のネットワークを互いにつないだ仕組みが**インターネット**です。
1台の巨大な機械が全体を担うのではなく、多くの組織や家庭のネットワークが、共通の約束に従って情報を受け渡しています。

```text
家庭のネットワーク ─┐
学校のネットワーク ─┼─ インターネット ─ 企業のネットワーク
会社のネットワーク ─┘
```

インターネットは、通信を行うための基盤です。
Webは、その基盤を利用する仕組みの一つで、両者は同じものではありません。
メールや音声通話にもインターネットを利用できますが、それらはWebページそのものではありません。

### 9 ブラウザ、Webページ、Webサイト

その通信を使って、文書や画像を互いに参照できる形で公開し、閲覧する仕組みが**Web**です。
World Wide Webを短くした名前です。
Web上の1枚の文書を**Webページ**、関連するページを一まとまりとして公開したものを**Webサイト**と呼びます。
本の1ページと、本全体の関係に近いと考えられます。

ページのデータを受け取り、文字、画像、ボタンとして画面に表示するアプリが**Webブラウザ**です。
短く「ブラウザ」とも呼びます。
ブラウザには、見たい場所を表す文字列を入力する欄があり、この文字列が**URL**です。

```text
https://example.com/news/index.html
```

URL全体は、どの方法で、どの相手から、どの内容を取りに行くかを示しています。
今は住所のようなものと考え、各部分の詳しい意味は第7章で学びます。

ブラウザにURLを入力して実行すると、ネットワークの向こう側へ「このページを送ってください」と要求を送ります。
相手からデータが返ると、ブラウザがそれを組み立てて画面に表示します。
表示されたページは、こうした要求と応答の結果です。

### 10 サーバとクライアント

ページを要求するブラウザと、データを送り返す相手は、異なる役割を担当しています。
図書館で利用者が本を頼み、職員が探して渡す関係に似ています。
ネットワーク上でサービスを要求し、利用する側が**クライアント**です。
要求を受けて、サービスやデータを提供する側を**サーバ**と呼びます。

Webを閲覧する場面では、ブラウザがクライアントです。
ページを保存し、要求に応じて送り返すコンピュータやソフトウェアは、Webサーバとして働きます。

```text
ブラウザ                         Webサーバ
  │ 「ページをください」             │
  ├────────────────────────→│
  │                                 │ 保存場所から探す
  │     「ページのデータです」        │
  │←────────────────────────┤
  │ 画面へ表示                       │
```

図の矢印は、情報が進む向きを表しています。
最初にクライアントから要求が進み、次にサーバから応答が返ります。

「サーバ」は、機械の形を指す名前とは限りません。
ある通信で要求する側だった機械が、別の通信では提供する側になることもあります。
また、役割を持つソフトウェアを指す場合と、そのソフトウェアを動かす機械を指す場合があるため、前後の文脈で見分けます。

### 11 データベース

サーバが提供する情報を、複数の人や処理が共同で使う場合もあります。
学校の学生情報を紙で管理すると、人数が増えるほど探すのが大変です。
複数の職員が同時に書き換えると、どれが最新か分からなくなることもあります。
データの保存に加えて、探し方と更新の管理が必要になります。

目的に沿って整理し、複数の処理から共同利用できるようにしたデータの集まりが**データベース**です。
一般には、条件に合うデータを探す、新しいデータを加える、間違った値が入らないよう制限する、といった仕事を伴います。
複数人が同時に更新しても矛盾しないようにし、閲覧と変更の権限を分け、故障後に正しい状態へ戻すことも必要です。

こうした仕事を管理するソフトウェアを**DBMS**と呼びます。
Database Management Systemの略で、データベース管理システムという意味です。
データの集まりと、それを管理するソフトウェアを区別し、詳しい仕組みは第6章で学びます。

## クリックから表示までのつながり

### 12 一回のクリックを全体で追う

ブラウザで学校のWebサイトを開き、「今日のお知らせ」をクリックする場面を、入力から表示まで追ってみます。
マウスから表示までの仕事を、担当する役割ごとに分けると、次の11段階です。

1. 利用者がマウスを動かし、ポインタをボタンに合わせる。
2. クリックが入力装置からパソコンに伝わる。
3. OSが、クリックされた場所の情報をブラウザに渡す。
4. ブラウザ内のプログラムが、「お知らせページを要求する」と判断する。
5. ブラウザがネットワークを通じてWebサーバに要求を送る。
6. Webサーバが要求を受け取る。
7. 必要なら、Webサーバがデータベースに今日のお知らせを問い合わせる。
8. データベースが該当するデータを返す。
9. Webサーバがページのデータをブラウザに返す。
10. ブラウザが受け取ったデータを文字や画像として組み立てる。
11. OSが画面を制御し、利用者にお知らせを表示する。

```text
利用者
  ↓ クリック
入力装置
  ↓
OS → ブラウザ → ネットワーク → Webサーバ → データベース
  ↑                  ← 応答       ← データ ──┘
  └──── 画面へ表示 ─────────────────────┘
```

利用者に見えるのは最初のクリックと最後の表示ですが、その間には11の段階があります。
一つの処理が出した情報を次の処理が受け取り、入力、処理、出力をつないでページを表示しています。

実際の通信には、相手の場所を調べる、データを小分けにする、届かなければ送り直す、通信相手が本物か確かめる、といった処理もあります。
第3章から第8章では、この1回の操作を支える機械や仕組みを詳しく学びます。

### 13 初めて出た言葉の整理

| 言葉 | この時点での意味 |
|---|---|
| 入力 | コンピュータが受け取る情報や指示 |
| 処理 | 入力に対して行う仕事 |
| 出力 | 処理後に返す結果 |
| データ | コンピュータが扱う数、文字、画像など |
| プログラム | コンピュータに行わせる処理の手順 |
| ハードウェア | 手で触れられる機械部分 |
| ソフトウェア | プログラムと、それを動かすためのデータ |
| アプリ | 利用者が特定目的に使うソフトウェア |
| OS | 複数のアプリに共通する基本的な管理を行うソフトウェア |
| メモリ | 実行中に使う情報を一時的に置く場所 |
| 保存装置 | 情報を電源断後も残す場所 |
| ファイル | 保存された、ひとまとまりのデータ |
| フォルダ | ファイルや別のフォルダを整理する入れ物 |
| ネットワーク | 複数の機器をつないで通信できるようにしたもの |
| インターネット | 多数のネットワークを相互接続した仕組み |
| Web | インターネット上の文書などを参照・閲覧する仕組み |
| ブラウザ | Webページを受け取り表示するアプリ |
| クライアント | サービスを要求し利用する側 |
| サーバ | 要求を受け、サービスやデータを提供する側 |
| データベース | 目的に沿って整理し共同利用するデータの集まり |

この表は、それぞれの言葉がどの役割を指すかを確かめるために使えます。
たとえばブラウザはアプリであり、ページを要求するときにはクライアントです。
入力から表示までの流れで、受け取るもの、行う処理、返すものを確認すれば、近い言葉も役割の違いとして区別できます。
