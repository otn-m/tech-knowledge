# 第0部A パソコンとITの超入門――機械を見たことがないところから

画面上のボタンをクリックすると、一呼吸置いて新しいページが現れます。
手元で見えるのは、マウスを指先で押したことと、画面の表示が切り替わったことだけです。
しかしそのわずかな間に、本体、OS、ブラウザ、ネットワーク、Webサーバ、さらにはデータベースに至るまで、驚くほど多くの裏方が連携して働いています。
これらの名前は、たった1回の操作を実現するために、どの部分が何を担当しているのかを表す役割の名前です。
クリックを受け取るところからページが表示されるまでの道のりを順にたどってみましょう。それぞれの部品や仕組みが何を担い、どのように手を取り合っているのかが自然と見えてきます。

## 操作を受け取り、結果を返す機械

### 1 コンピュータは「指示された処理をする機械」

人に「紙に書かれた100個の数を全部足してください」と頼むと、その人は数を読み、頭の中で計算し、紙に答えを書くのが通例です。
コンピュータの仕事も、大まかにはこれと同じ3段階に分けられます。

```text
受け取る → 決められた処理をする → 結果を返す
```

受け取る情報や指示を**入力**、それに対して行う仕事を**処理**、返す結果が**出力**です。
電卓の動作を思い浮かべてみてください。
数字と「足す」という指示を受け取り、内部で足し算をして、画面に答えを表示します。

```text
入力: 12、+、30
処理: 12と30を足す
出力: 42
```

コンピュータは、決められた処理をミスなく高速に、何万回でも繰り返すことが得意な機械です。
一方で、「いい感じにして」「常識で判断して」といった曖昧な指示は、そのままでは実行できません。
どのような条件のときに何をするのかを、あらかじめ機械が扱える厳密な形で決めておくことが不可欠です。

コンピュータと聞いても、SF映画に出てくるロボットのような姿を思い浮かべる必要はありません。
机の上で使うデスクトップパソコンや持ち運べるノートパソコンはもちろん、ポケットに入っているスマートフォンも立派なコンピュータです。
自動販売機の内部や、自動車のブレーキとエンジンを電子制御する機構にも、小さなコンピュータが組み込まれています。
また、離れた場所から手元の画面へ文字や画像を送り返してくれる機械も含まれる概念です。
形や用途は違っても、「入力を受け取り、決められた処理を行い、結果を出力する」という基本構造はすべて共通しています。

そして、あるコンピュータの出力を別のコンピュータが入力として受け取れば、処理をバトンのようにつないで大きな仕事を進めることが可能です。
普段目にするWebページの表示も、まさにこの受渡しの連続によって成り立っています。

### 2 パソコンの外から見える部品

冒頭のクリックを受け取る**パソコン**は、個人がさまざまな仕事に使えるコンピュータです。
英語の「personal computer」を短くして「PC」とも呼びます。
典型的なパソコンでは、画面、キーボード、マウスを本体につないで使うのが一般的です。

```text
                 ┌───────────────┐
                 │      画面       │
                 │ 文字や絵を表示  │
                 └───────────────┘
                        │
┌──────────┐    ┌───────────────┐
│ キーボード │    │      本体       │
│文字を入れる│    │ 計算し、記憶する │
└──────────┘    └───────────────┘
                        │
                 ┌──────────┐
                 │  マウス    │
                 │場所を指す  │
                 └──────────┘
```

文字や写真、ボタンを表示する部分を画面と呼びます。
ディスプレイやモニターとも呼ばれ、処理の結果を利用者に伝える表示機器です。
これに対し、文字や数字を入力するキーボードには、たくさんのボタンが並んでいます。
そのボタンの一つひとつが「キー」です。

マウスは、机の上で動かして画面上の場所を指し示す部品として機能します。
マウスを動かすと、画面上の小さな矢印であるポインタも連動して動く仕組みです。
本体の内部には、計算を行う部品、作業中の情報を置く部品、長く情報を保存する部品などが収められています。
内部の詳しい仕組みは第3章で学ぶ項目です。

ノートパソコンでは、本体、画面、キーボードが一つの箱にまとまっています。
マウスの代わりに使う、指を滑らせる平らな板状の部品がタッチパッドです。
また、スマートフォンのように画面に直接触れて操作する機器も広く普及しています。

#### 入力機器と出力機器

外部から情報や指示を入れる部品を入力機器、外部へ結果を出す部品が出力機器です。
キーボード、マウス、マイク、カメラ、温度センサは入力機器に当たり、画面、プリンタ、スピーカーは出力機器に当たります。
この区別は、部品の外見というより、果たす役割に着目した分類です。
たとえば指で触れて操作するスマートフォンの画面は、情報を映し出す出力機器であると同時に、触れた位置を感知する入力機器でもあります。

### 3 電源を入れて操作する

本体の電源ボタンを押すと、パソコンは内部の部品に異常がないかを確かめ、動作の準備を整えます。
準備が完了すると、画面に背景画像や文字、小さな絵が現れる仕組みです。

画面上に並ぶ小さな絵をアイコンと呼びます。
利用者が目的に応じて使うソフトウェアであるアプリや、名前を付けて保存する一まとまりのデータであるファイルを絵文字のように表現したものです。
アプリとファイルの詳しい違いは、後の節で確かめます。

#### マウスの基本操作

マウスのボタンを1回押し、すぐに指を離す操作をクリックと呼びます。
通常は左側のボタンを使うのが基本です。
ポインタを目的の場所に合わせてクリックすると、「これを選ぶ」「このボタンを押す」という合図を送れます。

短い間にすばやく2回押すダブルクリックは、ファイルを開くときなどに使われる操作です。
また、ボタンを押したままマウスを動かし、別の場所で指を離す操作をドラッグと呼びます。
アイコンを移動させたり、複数の対象をまとめて選んだりするときに重宝する操作です。

同じクリックでも、指している場所によって結果はまったく異なります。
機械は意図を推測してくれるわけではないため、目的の位置を正確に指すことが肝要です。

#### ウィンドウ、ボタン、メニュー

パソコンでは、文章作成などの仕事ごとに、四角い領域が画面上に開きます。
この領域が**ウィンドウ**です。
英語で窓を意味し、1枚の画面の中に複数の作業場所を並べられます。

```text
┌──────────── 文章を書くウィンドウ ────────────┐
│ ファイル  編集  表示                         │ ← メニュー
│                                              │
│ ここへ文章を入力します。                      │ ← 入力欄
│                                              │
│                         [ 保存 ]              │ ← ボタン
└──────────────────────────────────────┘
```

ウィンドウの中にも、それぞれ役割の異なる部品が配置されています。
ボタンは、クリックすると決められた処理を開始する部品で、実物の押しボタンを画面の中に再現したものです。
メニューには、利用者が選べる操作の一覧が並んでいます。
飲食店のメニューに注文できる料理が並ぶのと同じように、画面のメニューには実行できる操作が並んでいる設計です。

文字や数字を入力する枠線で囲まれた場所を入力欄と呼びます。
入力欄をクリックしてからキーボードを押すと、そこに文字が打ち込まれる仕組みです。

## 処理の手順と機械の分担

### 4 データとプログラム

コンピュータが扱う文字、数値、写真、音などを、まとめてデータと呼びます。
学校の名簿であれば氏名、学生番号、生年月日がデータであり、写真アプリであれば写真を構成する色の情報や撮影日時がデータです。

そのデータに対して行う処理の手順を、機械が扱える形で記録したものを**プログラム**と呼びます。
料理にたとえるなら、食材がデータ、調理手順を書いたレシピがプログラム、レシピに従って包丁を動かす料理人がコンピュータに当たる関係です。
ただし、料理人は「塩ひとつまみ」といった大まかな指示でも経験で補えますが、コンピュータには曖昧さのない明確な手順を渡さなければなりません。

```text
データ: 80点、75点、90点
プログラム:
  1. 三つの点数を足す
  2. 3で割る
  3. 結果を表示する
出力: 平均81.666…点
```

点数が変わっても、「足して個数で割る」という手順そのものは変わらないのが特徴です。
そのため、同じプログラムに別のデータを渡すだけで、誰の点数であっても平均を求められます。
データと手順を分けて考えることで、何を変え、何をそのまま使い回せるのかを整理できるわけです。

#### データの意味は0と1だけでは決まらない

コンピュータの内部では、あらゆるデータが最終的に「0」と「1」の並びとして扱われます。
しかし、同じ「0」と「1」の並びであっても、それを数値として読むのか、文字として読むのか、色の情報として読むのかによって、まったく異なる意味になる点に注意が必要です。

本棚に`42`という番号札が付いていても、それだけでは本の冊数なのか、棚の番号なのか、それとも室温なのかは判断できません。
同じように、データを正しく扱うには値そのものだけでなく、「その値をどう解釈するのか」という約束事（データの型や形式）が欠かせない要素です。
この区別は、第1章以降の学習でも重要な基盤になります。

### 5 ソフトウェア、アプリ、OS

プログラムと、それを動かすためのデータをまとめて**ソフトウェア**と呼びます。
これに対し、本体や内部の電子回路のように、手で触れられる機械そのものは**ハードウェア**です。
コンピュータは、この両方がそろって初めて仕事ができます。

```text
ハードウェア: 本体、画面、キーボード、内部の電子部品
ソフトウェア: 文章作成、写真表示、計算などを行うプログラム群
```

利用者が特定の目的のために使うソフトウェアがアプリケーションソフトウェアです。
日常会話では短く「アプリ」と呼ぶのが一般的といえます。
文章を書く、表計算をする、写真を見る、メールをやり取りするといった目的ごとに、専用のアプリが用意されているのが通常です。
世界中に広がる文書網であるWeb（World Wide Web）のページを閲覧するためのブラウザも、アプリの一つに数えられます。

アプリごとに画面の制御やストレージの管理を一から個別に開発していては、膨大な手間がかかってしまうのが実情です。
そこで、あらゆるアプリに共通する基盤の仕事を一手に引き受ける基本ソフトウェアとして、**OS**が機能します。
OSはOperating Systemの略称であり、オペレーティングシステムと呼ばれる存在です。

OSは、それぞれのアプリに計算時間を順番に割り当て、使う記憶場所が重ならないように切り分ける役割を果たします。
キーボードやマウスからの入力を受け取って適切なアプリへ渡し、画面のどの位置に何を表示するかを調整するのもOSの仕事です。
さらに、ファイルをストレージに整理して後から探せるようにし、利用者ごとに使える機能を制限する権限管理も担います。

```text
利用者
  ↓ 操作
アプリ
  ↓ 共通の仕事を依頼
OS
  ↓ 機械を直接制御
ハードウェア
```

文章作成アプリを終了してもパソコンの画面が消えないのは、裏でOSが動き続けているためです。
アプリが画面やストレージを簡単な操作で使えるのは、OSが間に入ってハードウェアの複雑な制御を引き受けているからにほかなりません。
利用者の操作は、アプリとOSという2つのソフトウェアを経由して、最終的にハードウェアの物理的な動作へと伝わっていく構造です。

## 作業中の情報を保存して残す

### 6 作業中の記憶と、長く残す保存

アプリで文章を書いている間、その文章は手元の作業中の情報として保持されます。
後から再び使えるように残しておくには、「作業中の情報を置く場所」と「長く安全に残す場所」を明確に区別することが大切です。
勉強中にノートや参考書を広げる机と、使い終わった本をしまっておく本棚の関係をイメージすると分かりやすくなります。
机の上はすぐに手が届いて素早く作業できますが、広さに限りがあるのが難点です。
一方の本棚は大量の本を保管できますが、取り出しに行くのに少し時間がかかります。

コンピュータの**メモリ**は、いま実行しているプログラムや、いま使っているデータを一時的に広げておく場所です。
専門用語では主記憶とも呼ばれ、計算と命令の実行を一手に担う中心部品CPU（Central Processing Unit）から極めて高速に読み書きできます。
ただし、一般的なメモリには電源を切ると中身がすべて消えてしまうという決定的な弱点があるのも事実です。

そこで、作成した文章や写真を後まで長期保存するために**ストレージ**（補助記憶）を活用します。
半導体メモリを使ってデータを記録するSSD（Solid State Drive）や、磁気を帯びた円盤を回転させて記録するHDD（Hard Disk Drive）などが代表例です。
ストレージはメモリに比べて読み書きに時間がかかるものの、大容量のデータを保管でき、電源を切っても内容が消えずに残り続けます。

```text
              メモリ                  ストレージ
役割          いま使うものを置く      後でも使うものを残す
速さ          非常に高速              比較的低速
容量          比較的小さい            非常に大きい
電源を切る    中身が消える（揮発性）  中身が残る（不揮発性）
たとえ        作業机                  本棚・倉庫
```

保存操作を行わないまま電源を切ると文章が消えてしまうのは、変更内容がメモリの上にしかなく、ストレージへ書き写されていなかったためです。
画面に見えている状態と、後まで残るように保存された状態とは、決して同一ではありません。

机と本棚の比喩は直感的な理解に役立ちますが、実際の内部ではより高度な工夫が凝らされているのが通例です。
OSが作業中のデータを定期的に自動保存したり、メモリ不足時にストレージの一部を作業場所として借りたりする仕組みも存在します。
これらの詳細な機構は、第3章と第5章で体系的に学ぶトピックです。

### 7 ファイルとフォルダ

ストレージには、作成した文章や写真をひとまとまりの単位で記録します。
この保存されたデータのまとまりが**ファイル**です。
1つの文章、1枚の写真、1曲の音楽、1つのプログラムなどが、それぞれ独立した1個のファイルとして保存されます。

無数のファイルを見分けるために付ける名前がファイル名です。
名前の末尾に`.txt`や`.jpg`といった文字列が付いている例をよく見かけます。
この末尾の部分を拡張子と呼び、ファイルの種類を見分ける重要な手掛かりです。

ファイルが増えてくると、名前だけを頼りに探すのは難しくなります。
大量の書類を1つの引き出しにそのまま詰め込む手法を脱し、見出し付きの紙ばさみに仕分けて整理するように、分類用の入れ物で管理するのが賢明です。
この入れ物を**フォルダ**と呼びます（システムによってはディレクトリとも呼ばれます）。
フォルダの中には、ファイルをしまうだけでなく、さらに別のフォルダを入れて細かく分類できる構造です。

```text
文書
├─ 学校
│  ├─ 時間割.txt
│  └─ 課題.txt
└─ 旅行
   ├─ 予定.txt
   └─ 持ち物.txt
```

このように、枝分かれしながら深くなっていく構造を階層構造（ツリー構造）と呼びます。
ファイルの名前だけでなく、どのフォルダに入っているかという置き場所（パス）とセットで対象を特定する仕組みです。

ファイルを扱う基本操作には、作成、閲覧、保存、複製、移動、名称変更、削除などがあります。
特に「コピー」と「移動」は混同しやすい操作の代表格です。
コピーを行うと元のファイルと複製ファイルの2つが存在することになりますが、移動ではファイルの置き場所が変わるだけで、ファイル自体は1つのまま保たれます。

## 離れた相手から情報を受け取る

### 8 通信とネットワーク

パソコンは、1台の内部で計算して保存するだけでなく、離れた場所にある別のコンピュータとデータをやり取りすることも日常的に行っています。
Webページを閲覧する行為も、まさにそうした通信の一環です。
2台以上のコンピュータをつなぎ、互いに情報を送受信できるようにした仕組みを**ネットワーク**と呼びます。

機器同士を有線ケーブルでつなぐことも、電波を用いて無線で通信することも可能です。
ただし、単にケーブルや電波で物理的につながっているだけでは、正しく意思疎通を行えません。
送信側と受信側がデータの表現形式や送受信の手順について共通の約束事（プロトコル）をそろえておくことが不可欠です。

世界中の無数のネットワークを、共通の約束事に従って相互接続した地球規模の通信網を**インターネット**と呼びます。
中心となる1台のスーパーコンピュータが世界中を統括する形態とは異なり、各地のネットワーク同士がバケツリレーのようにデータを中継し合って成り立っている構造です。

```text
家庭のネットワーク ─┐
学校のネットワーク ─┼─ インターネット ─ 企業のネットワーク
会社のネットワーク ─┘
```

インターネットは、世界中にデータを届けるための道路網に当たります。
これに対して、次に説明する「Web」は、その道路網を使って荷物をやり取りする具体的なサービスの一つです。
インターネット上ではWebだけでなく電子メールやオンライン通話なども稼働しており、両者を同一視してはいけません。

### 9 ブラウザ、Webページ、Webサイト

インターネットという通信基盤の上で、文書同士をリンクで結びつけ、自由に閲覧できるようにした仕組みがWebです。
Web上に公開されている1枚の文書をWebページと呼び、関連するページ群を束ねたものをWebサイトと呼びます。
本でたとえるなら、1枚のページと、一冊の本全体に相当する関係です。

ページのデータを受け取り、文字や画像を配置して画面へ組み立てるアプリを**Webブラウザ**と呼びます。
日常会話では単に「ブラウザ」と呼ばれるのが通例です。
ブラウザの上部には、見たいページの位置を指定する文字列の入力欄が用意されています。
この指定文字列が**URL**です。

```text
https://example.com/news/index.html
```

URLはインターネット上の住所に当たり、通信方式、相手のサーバ、取り出すファイルを指し示しています。
詳しい組み立ての規則は第7章で学ぶ内容です。

ブラウザのURL欄に入力して実行すると、ネットワークの向こう側にあるWebサーバへ向けて要求が送られます。
相手からデータが届くと、ブラウザがそれを解釈して画面にページを表示する流れです。
画面に見えているWebページは、すべてこの要求と応答の結果として届けられます。

### 10 サーバとクライアント

Webページを要求するブラウザと、データを送り返す相手のコンピュータは、異なる役割を分担する関係です。
図書館のカウンターで利用者が本をリクエストし、職員が書庫から探して手渡す場面を想像してみてください。
サービスやデータを要求する側を**クライアント**と呼び、データを提供する側をサーバと呼びます。

Webページを閲覧するときは、手元のパソコンで動くブラウザがクライアントです。
そして、要求されたページをストレージから探し出し、ネットワーク越しに送り返すコンピュータやプログラムを**Webサーバ**と呼びます。

```text
ブラウザ（クライアント）               Webサーバ
        │                                 │
        │ 「ページをください（要求）」     │
        ├────────────────────────────────→│
        │                                 │ 保存場所から探す
        │   「ページのデータです（応答）」 │
        │←────────────────────────────────┤
        │                                 │
  画面へ組み立てて表示
```

図の矢印は、データが流れる向きを表しています。
クライアントから要求が送られ、それを受け取ったサーバから応答が返ってくるのが基本サイクルです。

サーバという言葉は、特定の形をした専用の機械だけを指すとは限りません。
通信の場面において「提供する側の役割」を務めているソフトウェアやコンピュータを広く指す用語です。
したがって、同じコンピュータであっても場面によってクライアントにもサーバにもなり得ます。
文脈に応じて物理的な機器を指しているのか、ソフトウェアの役割を指しているのかを見極めることが肝要です。

### 11 データベース

Webサーバが送り返すデータは、あらかじめ用意された固定のファイルだけとは限りません。
頻繁に更新される情報を通常のテキストファイルで管理しようとすると、検索に時間がかかるのが難点です。
さらに、複数の利用者が同時にファイルを書き換えた場合、データが上書きされて消失するリスクも生じます。

そこで、大量のデータを規則に従って整理し、安全・高速に共同利用できるようにした仕組みが**データベース**です。
データベースは、高速検索、データ整合性の維持、同時実行制御、障害復旧など多岐にわたる機能を備えています。

こうした複雑な管理を一手に引き受ける専門のソフトウェアが**DBMS**（データベース管理システム）です。
保管されているデータの集まりと、それを管理するソフトウェアとを明確に区別して理解しておきましょう。詳しい仕組みは第6章でじっくり学びます。

## クリックから表示までのつながり

### 12 一回のクリックを全体で追う

ここまで見てきた部品や仕組みの連携を確かめるため、最初のクリックの場面へと立ち戻ります。
「今日のお知らせ」ボタンをクリックしてから画面に表示されるまでの過程は、11の段階に整理できる流れです。

1. 利用者がマウスを動かし、画面上のボタンにポインタを合わせる。
2. マウスのボタンを押すと、入力機器からパソコン本体へ電気信号が送られる。
3. OSがその信号を受け取り、「ブラウザの画面内のこの位置がクリックされた」と判定してブラウザに伝える。
4. ブラウザがクリックされた場所を確認し、「今日のお知らせページが必要だ」と判断する。
5. ブラウザがネットワークを経由して、Webサーバへ向けてページを求める要求（リクエスト）を送り出す。
6. インターネットを通って、Webサーバが要求を受け取る。
7. Webサーバは必要に応じて、データベース（DBMS）へ「今日のお知らせの文章を取り出してほしい」と問い合わせる。
8. データベースが条件に合う最新のお知らせデータを検索し、Webサーバへ送り返す。
9. Webサーバはそのデータを使ってWebページの形を組み立て、ブラウザへ向けて応答（レスポンス）を送信する。
10. ブラウザが送られてきたHTMLなどのデータを受け取り、文字や画像の配置を計算して画面用の描画データを組み立てる。
11. OSが画面（ディスプレイ）の表示を制御し、利用者の目の前にお知らせの内容が映し出される。

```text
利用者
  ↓ マウス操作
入力機器
  ↓ 電気信号
OS → ブラウザ ──要求──→ ネットワーク ──→ Webサーバ ──問い合わせ──→ データベース
  ↑                         │                     │                       │
  │                         │←──────応答───────┴←────データ返却─────┘
  │                         ↓
  └──── 画面へ表示 ──── ブラウザが組み立て
```

利用者に見えるのは、最初のクリックと最後の画面変化だけにすぎません。
しかしその間では、入力機器、OS、ブラウザ、ネットワーク、Webサーバ、データベースが整然と仕事をつないでいるわけです。

実際の通信では、住所の特定、データの分割転送、再送制御、暗号化などの高度な処理も並行して行われます。
第3章から第8章にかけて、この1回の操作を支えている精密な仕組みを、一歩ずつ解き明かしていきましょう。

### 13 初めて出た言葉の整理

本節で登場した重要な用語を整理しておきます。

| 用語 | 本節での位置づけと役割 |
|---|---|
| 入力 | コンピュータが外部から受け取る情報や指示 |
| 処理 | 入力された情報に対して行われる計算や加工 |
| 出力 | 処理を行った結果として外部へ返される情報 |
| データ | コンピュータが扱う文字、数値、画像などの情報そのもの |
| プログラム | コンピュータに実行させる処理の手順を記述したもの |
| ハードウェア | 手で触れることができる機械や電子部品そのもの |
| ソフトウェア | コンピュータを動かすプログラムや手順の総称 |
| アプリ | 利用者が特定の目的（文章作成、Web閲覧など）のために使うソフトウェア |
| OS | ハードウェアの制御やアプリ共通の基本管理を担う中核ソフトウェア |
| メモリ | 実行中のプログラムやデータを一時的に広げておく高速な作業場所（主記憶） |
| ストレージ | 電源を切ってもデータが消えないように長期保管する場所（SSD、HDDなど） |
| ファイル | ストレージに記録される、名前の付いたデータのひとまとまり |
| フォルダ | ファイルや別のフォルダを階層的に整理・分類するための入れ物 |
| ネットワーク | 複数のコンピュータをつなぎ、データを送受信できるようにした仕組み |
| インターネット | 世界中のネットワーク同士を共通の約束事に基づいて相互接続した地球規模の通信網 |
| Web | インターネット上で文書や画像をリンクで結びつけ、閲覧できるようにした仕組み |
| ブラウザ | Webサーバからデータを受け取り、画面にWebページとして組み立てて表示するアプリ |
| クライアント | ネットワークを通じてサービスやデータを要求する側の機器やアプリ |
| サーバ | クライアントからの要求を受け取り、サービスやデータを提供する側の機器やアプリ |
| データベース | 大量のデータを規則的に整理し、複数の処理から安全・高速に共同利用できるようにした仕組み |

これらの言葉は、機械的に暗記するための単語集ではありません。
たとえばブラウザはアプリの一種であり、通信時にはクライアントの役割を務める存在です。
ひとつの対象が場面によって異なる名称で呼ばれるのは、着目している側面が異なるからにほかなりません。
「誰が何を受け取り、何をして、誰に渡すのか」という関係性の中で捉え直すことで、概念の理解が一段と深まるはずです。
