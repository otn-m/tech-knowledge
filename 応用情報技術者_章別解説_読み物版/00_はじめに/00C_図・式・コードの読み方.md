# 第0部C 図・式・コードの読み方――記号の集まりに見えなくする

矢印を見れば、何かが右へ進む図だと読めそうです。
ところが、別の図では時間が下へ進み、矢印が親子関係を表すこともあります。
記号`=`も、数式では左右が等しいことを表し、コードでは右側の値を左側へ入れる操作を表す場合があります。

形が同じなら意味も同じだと思って読むと、図、式、コードの途中で説明が合わなくなります。
反対に、記号を一つずつ暗記しても、図の種類や使用言語が変われば意味を決められません。
必要なのは、記号の形から意味を推測することではなく、その記号が「何を」「どの向きに」「どう変えるか」を周囲の説明と対応させる読み方です。

## 1 図は何かを省略した模型

地図には、現実の建物を実物大で描けません。
道、駅、方角など、目的に必要なものだけを選んで描きます。
ITの図も同じです。

詳しく描かれた図ほど正確に見えるかもしれません。
しかし、何を省略したかが分からなければ、描かれていない距離や時間まで図から読み取ってしまいます。
図を見る前に、次の2点を確認します。

1. この図は何を知るための図か。
2. 現実の何が省略されているか。

たとえば次の図は、利用者がWebページを受け取る通信の向きだけを示しています。

```text
利用者のブラウザ ──要求──→ Webサーバ
利用者のブラウザ ←─応答──── Webサーバ
```

コンピュータの形、距離、通信時間は描いていません。
左にあるからブラウザが西側にある、という意味もありません。

## 2 箱、線、矢印

ITの図でよく使う3つの部品があります。
形は単純ですが、その形だけで意味が一つに決まるわけではありません。

### 箱

箱は、機械、ソフトウェア、処理、データの集まりなどを表します。
箱だけでは何を表すか決まらないため、箱の中の名前と図の説明を読みます。

```text
┌──────────┐
│ 注文を受け付ける │  ← 処理を表す箱
└──────────┘
```

### 線

線は、2つのものに関係があることを示します。
単なる接続、通信できる関係、親子関係など、意味は図の種類によって違います。

### 矢印

矢印は向きを持つ線です。
次のような意味があります。

- データが進む向き
- 処理が進む順番
- 呼出しの向き
- 親から子への関係
- 時間の進行

矢印の向きだけを追うと、データと処理順を同じものとして読んでしまいます。
矢印を見たら、「何が」「どこから」「どこに」進むのかを文章にします。

```text
注文画面 ──注文内容──→ 注文処理
```

これは「注文画面から注文処理に、注文内容というデータが進む」と読みます。

## 3 上下や左右は、図ごとに意味が違う

一般的には、処理順を左から右または上から下に描くことが多くあります。
しかし、必ずそうとは限りません。

木の形をした図では、上が親、下が子を表すことがあります。

```text
学校
├─ 1年
│  ├─ A組
│  └─ B組
└─ 2年
   ├─ A組
   └─ B組
```

時間を表す図では、横方向が時間の場合があります。

```text
時刻 →  0    1    2    3    4
処理A    [────────]
処理B         [────────]
```

軸や凡例があれば先に読みます。
凡例は、色や記号の意味を示す説明欄です。

## 4 表は行と列の交点を読む

表は、同じ種類の情報を並べて比較する道具です。
横方向を**行**、縦方向を**列**と呼びます。

```text
商品     単価     個数
りんご   120円      3
みかん    80円      5
```

表の中では数字が整然と並ぶため、値だけを先に拾いたくなります。
しかし、`120円`だけでは商品も数量も決まりません。
最初に列の見出しを読みます。
次に1行ずつ横に読みます。

1行目は「りんごの単価は120円で、個数は3」です。
上の見出しと左の対象を合わせて意味が決まります。

### 空欄と0は同じとは限らない

表の空欄は、「値がない」「まだ分からない」「入力し忘れた」など複数の意味になり得ます。
0は、値が分かっていて量が0であることを表します。

```text
欠席回数 0回      欠席がないことが分かっている
欠席回数 空欄     未確認かもしれない
```

データベースでは、この違いが重要になります。

## 5 数式は左から機械的に読まない

次の式を考えます。

```text
平均 = 合計 ÷ 個数
```

記号が少ないので、左から読み上げれば理解できそうです。
しかし、式が省略した量と操作を補わなければ、計算の理由までは分かりません。
この式は「平均という値は、合計を個数で割った値と等しい」という文章です。

文字だけの式でも同じです。

```text
m = s ÷ n
```

記号の対応が分からなければ読めません。

```text
m: 平均
s: 合計
n: 個数
```

対応を入れると、先ほどと同じ文章になります。

### 式を読む七つの手順

本編の式は、次の7点を確認します。

1. **目的**――何を求め、どの判断に使う式か。
2. **記号の意味**――各文字・添字・定数が何を表すか。
3. **単位**――入力の単位と、計算後に残る単位は何か。
4. **演算理由**――なぜ足す、引く、掛ける、割る、累乗するのか。
5. **計算順**――括弧、累乗、乗除、加減をどの順で行うか。
6. **結果の意味**――得た数を現実の文章に戻すと何を表すか。
7. **適用条件**――分母が0でない、独立である、単純モデルであるなど、どの条件で使えるか。

小さな数字の代入は、4〜6を確かめる実演として行います。
順序は式に合わせて変えても、7項目のどれかを読者の推測に任せないようにします。

#### 七項目を埋める例――平均

式 `m = s ÷ n` を、点数 `70, 80, 90` の平均を求める場面で7項目すべてに戻します。

1. **目的**――3人の点数を1人当たりの代表値にし、同じ条件の集団と比較するため平均を求める。
2. **記号の意味**――`m`は平均、`s`は合計、`n`は個数。
   ここでは`s=70+80+90`、`n=3`である。
3. **単位**――各値と合計は点、個数は人。
   `点÷人`を「1人当たりの点」と読み、結果は点で表す。
4. **演算理由**――全員分を足した総量を人数で等分するため、合計を個数で割る。
5. **計算順**――先に`s=70+80+90=240`点を求め、次に`m=240÷3=80`点とする。
6. **結果の意味**――3人の点数を均等にならした1人当たりの点数は80点である。
7. **適用条件**――`n>0`であり、3つの値が同じ尺度・同じ意味の点数であること。
   平均だけでは散らばりや外れ値を表せないことにも注意する。

### 添字と指数を見分ける

右下の小さな数字は、何番目かを表すラベルであることが多くあります。

```text
x₁  1番目のx
x₂  2番目のx
```

右上の小さな数字は、累乗を表すことがあります。

```text
x² = x × x
```

位置が違えば意味が違います。

### Σは「決められた範囲を全部足す」

第1章以降で、ギリシャ文字の大文字Σが現れます。
「シグマ」と読みます。

```text
Σ xᵢ
```

これは、指定されたすべての`xᵢ`を足すという短い書き方です。
`x₁=3`、`x₂=5`、`x₃=7`なら、次の意味です。

```text
Σ xᵢ = x₁ + x₂ + x₃
     = 3 + 5 + 7
     = 15
```

本文では、どこからどこまで足すかも毎回説明します。

## 6 コードは「機械に実行させる手順の表記」

プログラムを人が読み書きしやすい形で表した文章を、**コード**またはソースコードと呼びます。

たとえば、点数が60以上かを調べる手順は、次のような擬似コードで表せます。

```text
もし 点数 >= 60 なら
    「合格」と表示する
そうでなければ
    「不合格」と表示する
```

**擬似コード**は、特定のプログラミング言語の厳密な文法より、手順を伝えることを優先した書き方です。

コード全体を眺めるだけなら、条件によってどちらの行が実行されたかを見落とせます。
点数が75なら、値を置いて次のように追います。

1. 点数に75を入れる。
2. `75>=60`を調べる。
3. 75は60以上なので、条件は成り立つ。
4. 「合格」と表示する。
5. 「そうでなければ」側は実行しない。

### 記号を一つずつ読む

コードでは、数学と少し違う記号が使われる場合があります。

| 記号例 | よくある意味 |
|---|---|
| `=` | 値を入れる、または等しい |
| `==` | 左右が等しいか比較する |
| `!=` | 左右が等しくないか比較する |
| `>` | より大きい |
| `>=` | 以上 |
| `()` | 条件、引数、計算順序などを囲む |
| `[]` | 複数の値や番号指定などを表す |
| `"..."` | 文字列を囲む |
| `,` | 複数のものを区切る |

意味は言語によって違う場合があるため、コードの前で使用言語を確認します。

### 変数の状態を表で追う

次の擬似コードは、1から3までを合計します。

```text
合計 = 0
合計 = 合計 + 1
合計 = 合計 + 2
合計 = 合計 + 3
表示する(合計)
```

数学では`合計=合計+1`は成り立ちません。
冒頭で見たとおり、同じ`=`でも、プログラムの`=`が「右側を計算し、その結果を左側に入れる」という代入を表す場合、この行は意味を持ちます。

| 実行後の行 | 計算 | 合計の新しい値 |
|---|---|---:|
| `合計=0` | 最初の値を入れる | 0 |
| `合計=合計+1` | 0+1 | 1 |
| `合計=合計+2` | 1+2 | 3 |
| `合計=合計+3` | 3+3 | 6 |

最後に6が表示されます。
コードは一度に全体を理解しようとせず、1行実行するたびに何が変わるかを追います。

## 7 SQLはデータベースへの依頼文

第6章では、次のようなコードが現れます。

```sql
SELECT name
FROM students
WHERE score >= 80;
```

これはSQLという言語で、データベースに欲しい結果を伝える文です。

```text
SELECT name       nameという列が欲しい
FROM students     studentsという表から
WHERE score >= 80 scoreが80以上の行だけ
```

全体を日本語に戻すと、「students表から、scoreが80以上の行を選び、そのname列を返してください」です。

英単語を知っているだけでは十分ではありません。
元の表から、条件で行がどう減り、列がどう選ばれ、どの結果表になるかを追います。

## 8 時系列表は同時処理の問題を見つける

2人が同じ在庫を更新する場面では、文章だけだと順番を見失いやすくなります。
時刻ごとに表にします。

```text
時刻  処理A             処理B             在庫
 1    在庫1を読む                           1
 2                     在庫1を読む          1
 3    在庫を0にする                         0
 4                     在庫を0にする         0
```

最後の在庫が0なら、1個の商品が売れて正しく処理されたように見えます。
しかし、上から下へ時間を追うと、AとBがどちらも「在庫1」を読んでおり、2人とも購入に成功する矛盾が見つかります。

時系列表では、次の順に読みます。

1. 時間がどちらに進むか確認する。
2. 1行ずつ、各登場人物の操作を見る。
3. 共有する値がいつ変わるか確認する。
4. 古い値を基にした処理がないか探す。

## 9 木構造とネットワーク図を混同しない

枝分かれした図でも、意味は異なる場合があります。

フォルダの図では、各項目に親が1つある階層を示します。

```text
親フォルダ
├─ 子フォルダA
└─ 子フォルダB
```

道路網の図では、1地点が複数地点と相互につながる場合があります。

```text
A ─ B
│ ╲ │
C ─ D
```

形が似ていても、「親子関係」なのか「移動可能な接続」なのかを確認します。

## 10 読めないときの戻り方

図、式、コードが読めなくなったら、次の順で問題を切り分けます。

1. 初めて見る言葉がないか。
2. 記号の意味が説明されているか。
3. 何を入力し、何を出すものか。
4. どちら向きに時間やデータが進むか。
5. 1つ前の状態は何か。
6. 次の一手で何が変わったか。
7. 数字や名前を、もっと小さな例に置き換えられないか。

分からない図を長時間眺め続けても、形から意味を推測する状態は変わりません。
「矢印の意味が分からない」「`n`が何を表すか分からない」「時間の向きが分からない」のように、分からない最小部分に名前を付けると、凡例、記号の定義、直前の状態のどこへ戻ればよいかが決まります。

## 11 章末確認

1. 図を見る前に確認する2つのことを答えてください。
2. 矢印を文章に戻すとき、何を確認しますか。
3. 表の`0`と空欄が同じとは限らない理由を説明してください。
4. 式`T=D÷V`について、`T`が時間、`D`が距離、`V`が速さなら、日本語の文章に戻してください。
5. `x₂`と`x²`の違いを説明してください。
6. コード中の`合計=合計+1`が意味を持つのは、`=`をどのように読む場合ですか。
7. SQL例の`FROM`と`WHERE`は、それぞれ何を指定していましたか。
8. 同時処理を時系列表で読むとき、共有する値について何を確認しますか。

## 解答と考え方

1. **考え方**：描かれている形へ意味を付ける前に、図の目的と省略範囲を確定します。
   **解答**：何を知るための図か、現実の何を省略した図かを確認します。
   **誤答しやすい点**：図に距離や時間が描かれていなければ、箱の間隔や矢印の長さから推測することはできません。
   **復習箇所**：[1 図は何かを省略した模型](#1 図は何かを省略した模型)を参照してください。
2. **考え方**：矢印の形だけで意味を決めず、図の説明や凡例から移動する対象を特定します。
   **解答**：何が、どこから、どこに進むかを確認します。
   さらに、矢印がデータ、処理順、呼出しなどのどれを表すかを凡例や本文で確かめます。
   **誤答しやすい点**：右向きだから時間の進行だとは限らず、データの送信や呼出しを表す場合もあります。
   **復習箇所**：[矢印](#矢印)を参照してください。
3. **考え方**：値が確定して0なのか、値自体が未入力または不明なのかを分けます。
   **解答**：0は値が分かっていて量が0であることを表せます。
   空欄は未入力、未知、該当なしなど、別の状態かもしれません。
   **誤答しやすい点**：空欄を一律に0として計算すると、未確認の値を確認済みの0へ変えてしまいます。
   **復習箇所**：[空欄と0は同じとは限らない](#空欄と0は同じとは限らない)を参照してください。
4. **考え方**：左辺の記号を求める量、右辺の記号と演算をその求め方として文章へ戻します。
   **解答**：「時間は、距離を速さで割った値である」です。
   たとえば120kmを60km/時で進む時間は`120÷60=2時間`です。
   **誤答しやすい点**：`D`と`V`の意味を逆にすると、単位が時間にならず、式が表す現実の操作も変わります。
   **復習箇所**：[式を読む七つの手順](#式を読む七つの手順)を参照してください。
5. **考え方**：小さな2の位置を見て、添字による番号か、指数による累乗かを判定します。
   **解答**：`x₂`は2番目のxというラベルであることが多く、`x²`はxを2回掛ける累乗です。
   **誤答しやすい点**：右下の2を`x×x`と読むと、値を区別するラベルを計算へ変えてしまいます。
   **復習箇所**：[添字と指数を見分ける](#添字と指数を見分ける)を参照してください。
6. **考え方**：同じ`=`でも、数学上の等しさではなく、実行によって値を更新する記号かを確認します。
   **解答**：右側の現在値を計算し、その結果を左側の変数に入れる「代入」として読む場合です。
   **誤答しやすい点**：等式として読むと「合計と合計に1を足した値が等しい」という成り立たない文になります。
   **復習箇所**：[変数の状態を表で追う](#変数の状態を表で追う)を参照してください。
7. **考え方**：元になる表と、そこから残す行の条件を分けてSQLを読みます。
   **解答**：`FROM`は元になる表、`WHERE`は残す行の条件を指定します。
   **誤答しやすい点**：`WHERE`は返す列を指定する句ではなく、条件に合う行を選ぶ句です。
   **復習箇所**：[7 SQLはデータベースへの依頼文](#7 SQLはデータベースへの依頼文)を参照してください。
8. **考え方**：初期状態と終了条件を置き、状態が変わるたびに値や主体を1行ずつ記録します。
   **解答**：共有値を各処理がいつ読み、いつ書き換え、古い値に基づいて処理していないかを確認します。
   **誤答しやすい点**：最後の在庫だけを見ると0で正常に見えますが、2人が同じ更新前の値を読んだ事実を見落とします。
   **復習箇所**：[8 時系列表は同時処理の問題を見つける](#8 時系列表は同時処理の問題を見つける)を参照してください。

冒頭では、矢印や`=`が同じ形なのに違う意味を持つことが、読みにくさの原因でした。
読み終えた時点でも記号の形は変わりません。
それでも、図なら目的と省略、式なら量と演算、コードなら実行順と状態を確かめれば、意味を周囲の説明から決められます。
