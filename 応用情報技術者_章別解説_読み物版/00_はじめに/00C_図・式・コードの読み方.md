# 第0部C 図・式・コードの読み方――記号の集まりに見えなくする

ブラウザからWebサーバへ向かう矢印は、要求を送る向きを表します。
同じ矢印でも、別の図では処理の順番や親子関係を表すことがあります。
数式の`=`は左右が等しいことを示す記号です。
コードでは、右側の値を左側へ入れる操作を示す場合があります。

記号の形が同じでも、意味まで同じとは限りません。
図の種類や使用言語を確認し、記号が表す対象、向き、変化を説明と対応させます。
この対応が分かれば、図や式を見たときに、何を追えばよいかが決まります。

## 図に描かれた情報を読み分ける

### 1 図は何かを省略した模型

図は、現実のすべてを写したものではありません。
地図が建物を実物大で描かず、道や駅、方角などを選んで示すように、ITの図も目的に必要な情報を選んでいます。

たとえば、ブラウザとWebサーバの通信は、次のように描けます。

```text
利用者のブラウザ ──要求──→ Webサーバ
利用者のブラウザ ←─応答──── Webサーバ
```

この図から読めるのは、要求と応答が進む向きです。
機械の形、距離、通信時間は描いていませんし、ブラウザが左にあるから西側にある、という意味もありません。
詳しく見える図でも、描かれていない情報まで読み取れるわけではありません。

図を読むときには、何を知るための図か、現実の何を省略しているかを確認します。
この2点によって、図から判断できる範囲が決まります。

### 2 箱、線、矢印

こうした図でよく使われる部品が、箱、線、矢印です。
どれも単純な形ですが、図の中で何を表しているかは、名前や説明によって決まります。

#### 箱

箱は、機械、ソフトウェア、処理、データの集まりなどを表します。
次の箱なら、中の名前から、注文を受け付ける処理を表していると分かります。

```text
┌──────────┐
│ 注文を受け付ける │  ← 処理を表す箱
└──────────┘
```

箱の形だけから、機械なのか処理なのかを決めず、名前と図の説明を読みます。

#### 線

線は、2つのものの関係を表します。
接続、通信できる関係、親子関係など、意味は図の種類によって異なります。

#### 矢印

矢印は向きを持つ線で、データの移動、処理の順番、呼出しの向き、親から子への関係、時間の進行などを表します。

```text
注文画面 ──注文内容──→ 注文処理
```

この矢印は、「注文画面から注文処理へ、注文内容というデータを渡す」と読めます。
矢印の向きだけでなく、何が、どこから、どこへ進むかを確かめると、データの移動と処理順を区別できます。

### 3 上下や左右は、図ごとに意味が違う

矢印の意味と同じように、上下や左右の配置も図ごとに読み分けます。
処理順を左から右、または上から下へ描くことは多いものの、すべての図がその規則に従うわけではありません。

木の形をした図では、上が親、下が子という関係を示す場合があります。

```text
学校
├─ 1年
│  ├─ A組
│  └─ B組
└─ 2年
   ├─ A組
   └─ B組
```

この上下を時間の順番として読むことはできません。
一方、処理の実行時間を示す次の図では、横方向に時間が進みます。

```text
時刻 →  0    1    2    3    4
処理A    [────────]
処理B         [────────]
```

図に軸や**凡例**があれば、それを先に読みます。
凡例は、色や記号の意味を示す説明欄です。
配置や線の形を見る前に、図が使っている規則を確かめます。

### 4 表は行と列の交点を読む

表でも、値だけを拾うと意味を取り違えます。
横方向の並びが**行**、縦方向の並びが**列**で、行と列の見出しを組み合わせて各値を読みます。

```text
商品     単価     個数
りんご   120円      3
みかん    80円      5
```

`120円`だけでは、何の値かを決められません。
列の見出しを読み、次に1行を横に追うと、「りんごの単価は120円で、個数は3」と分かります。
表は、このように同じ種類の情報を並べて比較するための道具です。

#### 空欄と0は同じとは限らない

値が書かれていない場合にも、その意味を確かめます。
空欄には、値がない、まだ分からない、入力し忘れた、といった複数の意味があり得ます。
0の場合は、値が分かっていて、その量が0です。

```text
欠席回数 0回      欠席がないことが分かっている
欠席回数 空欄     未確認かもしれない
```

欠席回数が0回なら、欠席がないことが分かっています。
空欄なら、未確認かもしれません。
データベースでも、この違いが重要になります。

## 5 数式は左から機械的に読まない

数式も、記号が表す量を確かめてから読みます。

```text
平均 = 合計 ÷ 個数
```

これは「平均は、合計を個数で割った値と等しい」という文章です。
記号を左から読み上げるだけでなく、どの量にどの操作をするかを読み取ります。
同じ関係を文字で書くこともできます。

```text
m = s ÷ n
```

この形だけでは、各文字が何を表すかが分かりません。
文字の定義を対応させると、先ほどと同じ式として読めます。

```text
m: 平均
s: 合計
n: 個数
```

### 式を読む七つの手順

式を使うときには、記号の意味に加え、単位や成立条件も確かめます。
確認するのは、次の7項目です。

1. **目的**：何を求め、どの判断に使う式か。
2. **記号の意味**：各文字、添字、定数が何を表すか。
3. **単位**：入力の単位と、計算後に残る単位は何か。
4. **演算理由**：なぜ足す、引く、掛ける、割る、累乗するのか。
5. **計算順**：括弧、累乗、乗除、加減をどの順で行うか。
6. **結果の意味**：得た数を文章に戻すと、現実の何を表すか。
7. **適用条件**：分母が0でない、独立である、単純なモデルであるなど、どの条件で使えるか。

小さな数を代入して計算すると、演算の理由、計算順、結果の意味を具体的に確かめられます。
確認の順序は式に合わせて変えても、7項目はすべて明らかにします。

#### 七項目を埋める例――平均

点数`70,80,90`の平均を求め、同じ条件の集団と比較する場面で、`m=s÷n`を使います。
目的は、3人の点数を1人当たりの代表値にすることです。
記号を対応させると、`m`は平均、`s`は合計、`n`は人数です。
この例では`s=70+80+90`、`n=3`と置きます。

各値と合計の単位は点、個数の単位は人です。
`点÷人`は「1人当たりの点」と読み、結果は点で表します。
全員の点数を足した量を人数で等分するため、合計を個数で割ります。

計算では、先に`s=70+80+90=240`点を求め、次に`m=240÷3=80`点とします。
この80点は、3人の点数を均等にならしたときの1人当たりの点数です。

式を使う条件は、`n>0`で、3つの値が同じ尺度と意味の点数であることです。
また、平均だけでは点数の散らばりや外れ値を表せません。

### 添字と指数を見分ける

文字の周りに付く小さな数字にも、異なる役割があります。
右下の数字は、何番目かを区別するラベルであることが多くあります。

```text
x₁  1番目のx
x₂  2番目のx
```

一方、右上の数字は累乗を表す場合があります。

```text
x² = x × x
```

この場合の2は、2番目というラベルではなく、`x`を2個掛けるという操作を示します。
同じ小さな数字でも、位置と式の説明を合わせて読みます。

### Σは「決められた範囲を全部足す」

多くの値の足し算を短く表す記号が、ギリシャ文字の大文字Σです。
「シグマ」と読み、第1章以降に現れます。

```text
Σ xᵢ
```

これは、指定された範囲の`xᵢ`をすべて足すという意味です。
`x₁=3`、`x₂=5`、`x₃=7`を足す場合には、次のように読みほどけます。

```text
Σ xᵢ = x₁ + x₂ + x₃
     = 3 + 5 + 7
     = 15
```

どこからどこまでを足すかによって結果が変わるため、本文でも、その範囲を毎回説明します。

## コードの実行と値の変化

### 6 コードは「機械に実行させる手順の表記」

数式は量の関係を表しますが、コードでは機械に実行させる手順を読みます。
プログラムを人が読み書きしやすい形で表した記述が、**コード**またはソースコードです。
たとえば、点数が60以上かを調べる手順は、次のように表せます。

```text
もし 点数 >= 60 なら
    「合格」と表示する
そうでなければ
    「不合格」と表示する
```

この**擬似コード**は、特定の言語の厳密な文法よりも、手順を伝えることを優先した書き方です。
全体を眺めるだけでなく、具体的な点数を入れて、実際に通る行を追います。
75点の場合は、次の順になります。

1. 点数に75を入れる。
2. `75>=60`を調べる。
3. 75は60以上なので、条件は成り立つ。
4. 「合格」と表示する。
5. 「そうでなければ」側は実行しない。

2つの表示が書かれていても、両方を実行するわけではありません。
条件の結果によって、どちらの行を実行するかが決まります。

#### 記号を一つずつ読む

コードには、数学と少し異なる記号の使い方があります。

| 記号例 | よくある意味 |
|---|---|
| `=` | 値を入れる、または等しい |
| `==` | 左右が等しいか比較する |
| `!=` | 左右が等しくないか比較する |
| `>` | より大きい |
| `>=` | 以上 |
| `()` | 条件、引数、計算順序などを囲む |
| `[]` | 複数の値や番号指定などを表す |
| `"..."` | 文字列を囲む |
| `,` | 複数のものを区切る |

たとえば`=`が代入を表すのか、等しさを表すのかは、使用言語によって変わる場合があります。
コードの前に書かれた言語を確認してから、各記号の意味を読みます。

#### 変数の状態を表で追う

次の擬似コードは、1から3までを合計します。

```text
合計 = 0
合計 = 合計 + 1
合計 = 合計 + 2
合計 = 合計 + 3
表示する(合計)
```

数学の等式としては、`合計=合計+1`は成り立ちません。
しかし、ここでの`=`は、右側を計算し、その結果を左側に入れる**代入**です。
右側には、その行を実行する前の「合計」の値を使います。

| 実行後の行 | 計算 | 合計の新しい値 |
|---|---|---:|
| `合計=0` | 最初の値を入れる | 0 |
| `合計=合計+1` | 0+1 | 1 |
| `合計=合計+2` | 1+2 | 3 |
| `合計=合計+3` | 3+3 | 6 |

最初に0を入れ、1を足して1、2を足して3、3を足して6になります。
最後に表示する値は、この6です。
1行実行するたびに、前の値と新しい値を対応させると、冒頭で見た等号と代入の違いを確かめられます。

### 7 SQLはデータベースへの依頼文

コードには、計算の手順を順番に書くものだけでなく、欲しい結果を伝えるものもあります。
第6章で扱う**SQL**は、データベースへの依頼を記述する言語です。

```sql
SELECT name
FROM students
WHERE score >= 80;
```

この文では、表、条件、欲しい列を指定しています。

```text
SELECT name       nameという列が欲しい
FROM students     studentsという表から
WHERE score >= 80 scoreが80以上の行だけ
```

全体では、「students表から、scoreが80以上の行を選び、そのname列を返してください」という意味です。
英単語の意味だけでなく、元の表に対して何を選ぶかを確かめます。
条件によって行がどう減り、列がどう選ばれ、どの結果表になるかを追います。

## 同時処理と項目の関係を図で確かめる

### 8 時系列表は同時処理の問題を見つける

複数の処理が同時に動く場面でも、実行に伴う値の変化を追います。
ただし、文章だけでは、どちらが先に値を読み、いつ書き換えたかを見失いやすくなります。
2人が同じ在庫を更新する例を、時刻ごとに並べます。

```text
時刻  処理A             処理B             在庫
 1    在庫1を読む                           1
 2                     在庫1を読む          1
 3    在庫を0にする                         0
 4                     在庫を0にする         0
```

最後の在庫だけを見ると、0なので1個の商品が正しく売れたように見えます。
しかし、上から下へ追うと、AもBも最初に「在庫1」を読んでいます。
どちらも購入に成功しているため、在庫1個に対して2人が買えたという矛盾が分かります。

時系列表は、次の順で読みます。

1. 時間がどちらに進むか確認する。
2. 1行ずつ、各登場人物の操作を見る。
3. 共有する値がいつ変わるか確認する。
4. 古い値を基にした処理がないか探す。

最終値に加えて、そこへ至る読取りと書込みの順序を追うことで、同時処理の問題を見つけられます。

### 9 木構造とネットワーク図を混同しない

時系列表が操作の順序を表すのに対し、項目同士の関係を表す図もあります。
その場合も、線の形だけで関係を決めず、何をつないでいるかを確かめます。

フォルダの図では、各項目に親が1つある階層を示します。

```text
親フォルダ
├─ 子フォルダA
└─ 子フォルダB
```

一方、道路網では、1地点が複数の地点と互いにつながる場合があります。

```text
A ─ B
│ ╲ │
C ─ D
```

どちらにも枝分かれした線がありますが、フォルダでは親子関係、道路網では移動可能な接続を表します。
見た目の似た線を、同じ意味で読まないようにします。

## 10 読めないときの戻り方

ブラウザとWebサーバの図では、矢印は要求と応答の向きでした。
点数の式では`=`は等しさを、合計を更新するコードでは代入を表していました。
図、式、コードを読むときは、記号を覚えるだけでなく、その場でどの量や操作を表すかを確かめます。

途中で読めなくなったら、次の順で、分からない部分を切り分けます。

1. 初めて見る言葉がないか。
2. 記号の意味が説明されているか。
3. 何を入力し、何を出すものか。
4. どちら向きに時間やデータが進むか。
5. 1つ前の状態は何か。
6. 次の一手で何が変わったか。
7. 数字や名前を、もっと小さな例に置き換えられないか。

形だけを長く眺めても、記号の意味は決まりません。
「矢印が何を表すか分からない」なら凡例へ、「`n`が何か分からない」なら記号の定義へ戻ります。
「次の値がなぜ変わるか分からない」なら、直前の状態から1行ずつ追います。
分からない最小部分を特定すると、説明のどこを読み直すかが決まります。
