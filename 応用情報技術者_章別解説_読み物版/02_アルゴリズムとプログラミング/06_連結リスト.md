# 第2章・第6話　連結リスト――離れた要素を「次の場所」でつなぐ

配列では、途中へ要素を入れるたびに後続要素を動かします。
ならば、要素をリンクでつなげば、挿入はいつでも速くなるのでしょうか。

リンクの付替え自体は速くても、付け替える場所を探す時間は別にかかります。


## 1 ノードとリンク

リストの各要素をノード、節点と呼びます。

単方向リストのノードには、

- データ。
- 次ノードへの参照、ポインタ、リンク。

があります。

```text
Node
  data
  next
```

最後の`next`には、次がないことを示すNULLなどを入れます。

## 2 先頭参照

リスト全体を使うには、最初のノードがどこかを覚えます。

```text
head → [A|・] → [B|・] → [C|NULL]
```

`head`を失うと、ほかに参照がなければ全ノードに到達できません。

空リストでは、`head=NULL`とします。

## 3 順番は住所ではなくリンクで決まる

主記憶上のアドレスが、

```text
A 100番地
B 700番地
C 240番地
```

でも、リンクがA→B→Cなら、この順です。

物理的な並びと、論理的な並びを分けます。

## 4 リストを走査する

```text
current = head
while current != NULL
    current.dataを処理
    current = current.next
```

`current`は今見ているノードへの参照です。

各ノードを一度通るので、n要素の全走査は`O(n)`です。

最後に`current=current.next`を忘れると、同じノードを永遠に見ます。

## 5 i番目へ直接飛べない

10番目を取りたい場合でも、先頭からリンクを9本たどります。

```text
0番 → 1番 → 2番 → ... → 10番
```

したがって、任意位置の参照は`O(n)`です。

配列ならアドレス計算で`O(1)`です。

## 6 先頭へ挿入する

元のリストです。

```text
head → A → B → C
```

Xを先頭に入れます。

1. `X.next=head`として、Xから旧先頭Aにつなぐ。
2. `head=X`として、先頭をXに変える。

```text
head → X → A → B → C
```

順序が重要です。
先に`head=X`だけ行うと、旧先頭Aへの参照を失う場合があります。

操作自体は`O(1)`です。

## 7 途中へ挿入する

「連結リストは挿入に強い」とだけ覚えると条件を落とします。
挿入位置の直前ノードが分かっている場合に限り、リンクの変更は`O(1)`です。

AとBの間にXを入れます。

```text
A → B
```

1. `X.next=A.next`でX→B。
2. `A.next=X`でA→X。

```text
A → X → B
```

先にA→Xに変え、Bへの参照を別に保存していなければ、残りを見失う恐れがあります。

挿入位置の直前Aを既に持っていれば、リンク変更は`O(1)`です。
しかしAを探すところからなら`O(n)`です。

「リストの挿入は常にO(1)」ではありません。

## 8 削除する

削除するノードBが分かっていれば、Bだけを消せばよさそうです。
単方向リストでは、Aの`next`をCへ付け替えるため、Bの直前にあるAも必要です。

A→B→CからBを外します。

```text
A.next = B.next
```

結果はA→Cです。

Bの直前Aを知っていれば`O(1)`です。
Bだけを知っていても、単方向リストでは前ノードに戻れません。

削除後、Bが動的に確保した領域なら、誰も使っていないことを確認して解放します。
自動回収の言語では、参照されなくなった後にガベージコレクタが回収します。

## 9 末尾参照

末尾に頻繁に追加するなら、最後のノードを`tail`でも覚えます。

```text
head → A → B → C ← tail
```

新しいXを末尾に入れるには、

```text
tail.next = X
tail = X
```

で`O(1)`です。

空リストに最初の1個を入れるときは、headとtailの両方をXにします。
最後の1個を削除したときは両方NULLにします。

## 10 番兵ノード

データを持たないノードを1個増やすのは、無駄に見えるかもしれません。
その1個が常に先頭へ残ることで、空リストと先頭要素の処理を通常の途中操作へ近づけられます。

データを持たない特別な先頭ノードを置く場合があります。

```text
sentinel → A → B → C
```

空でもsentinelは存在し、先頭挿入・削除を途中と同じ形で扱いやすくなります。

番兵ノードを通常データとして数えないようにします。

## 11 双方向リスト

各ノードに、次だけでなく前への参照も持たせます。

```text
NULL ← A ⇄ B ⇄ C → NULL
```

```text
Node
  data
  prev
  next
```

前後に移動でき、対象ノードを知っていれば削除しやすくなります。

一方、参照欄が増え、挿入・削除時に更新するリンクも増えます。

## 12 双方向リストへ挿入する

前後どちらへも移動できる分、挿入も簡単になるとは限りません。
新しいノードの前後に加え、両隣から新しいノードへ向かう参照も更新します。

AとBの間にXを入れます。

更新する関係は4つです。

```text
X.prev = A
X.next = B
A.next = X
B.prev = X
```

1つ忘れると、前向きには通れるが後ろ向きに戻れない、という壊れ方をします。

更新前後の不変条件を確認します。

- A.next.prevはA。
- B.prev.nextはB。
- head.prevはNULL。
- tail.nextはNULL。

## 13 環状リスト

最後の次を先頭につなぎます。

```text
A → B → C
↑       ↓
└───────┘
```

順番に持ち回る処理、ラウンドロビンなどに使えます。

NULLが来ないため、走査終了条件を、

- 開始ノードに戻った。
- 指定個数を処理した。

などにします。
終了条件を誤ると無限ループになります。

## 14 線形リストという抽象概念

要素が1列の順序を持つデータ構造を線形リストと呼びます。

線形リストは、

- 配列で実装する順次リスト。
- リンクで実装する連結リスト。

などがあります。

「リスト」という抽象的な操作と、「リンク付リスト」という実装を分けます。

## 15 メモリ配置と局所性

配列は要素が連続しているため、CPUのキャッシュに近くの要素が一緒に入りやすく、順走査が高速です。

連結リストはノードが離れている可能性があり、

- 次アドレスを読むまで先に進めない。
- キャッシュミスが増える。
- ポインタ分の記憶量が増える。

ことがあります。

Big-Oが同じ`O(n)`でも、実際の速度は違います。

## 16 メモリ管理の危険

手動でメモリを管理する環境では、

### メモリリーク

確保したノードを解放せず、参照も失う。

### ダングリングポインタ

解放済みノードへの参照を使う。

### 二重解放

同じ領域を2回解放する。

### NULL参照

ノードがないNULLを、ノードとして読む。

などがあります。

自動メモリ管理でも、不要なノードへの参照を保持し続ければ回収されず、実質的なリークになります。

## 17 循環参照

参照数が0でなければ、まだ使われている対象だと判断したくなります。
互いだけを参照する2つのノードは、外部から到達できなくなっても参照数が0になりません。

AがBを参照し、BがAを参照します。

```text
A → B
↑   ↓
└───┘
```

単純な参照カウント方式では、外部から使われなくても互いの参照数が0にならず、回収できない場合があります。

到達可能性をたどるガベージコレクタは、外部の根から到達できない循環を回収できます。

## 18 リストを逆順にする

単方向リストA→B→CをC→B→Aにします。

3つの参照を使います。

```text
prev = NULL
current = head

while current != NULL
    nextNode = current.next
    current.next = prev
    prev = current
    current = nextNode

head = prev
```

各回で、

1. 次を失わないよう保存。
2. 現在ノードの矢印を逆向きに。
3. prevとcurrentを1つ進める。

とします。

`nextNode`を保存する前に矢印を変えると、未処理部分に到達できなくなります。

## 19 ループ不変条件で逆順を説明する

各回の先頭で、

- `prev`から、処理済み部分が逆順につながっている。
- `current`から、未処理部分が元の順につながっている。

とします。

1ノードを未処理から処理済みに移しても、この性質が保たれます。
最後に`current=NULL`なら未処理がなく、`prev`が全体の新先頭です。

## 20 リストでよく使う操作の計算量

単方向リストで、位置への参照が既にあるかに注意します。

| 操作 | 代表的な計算量 |
|---|---:|
| 先頭参照 | O(1) |
| i番目参照 | O(n) |
| 値の探索 | O(n) |
| 先頭挿入 | O(1) |
| 既知ノード後に挿入 | O(1) |
| 挿入位置を探して挿入 | O(n) |
| 既知の前ノードがある削除 | O(1) |
| tailありの末尾追加 | O(1) |

## 21 配列とリストを比べる

| 観点 | 配列 | 連結リスト |
|---|---|---|
| i番目参照 | O(1) | O(n) |
| 途中挿入 | 要素移動O(n) | 場所が既知ならリンク変更O(1) |
| メモリ | 連続領域 | ノードごとに分散可能 |
| 追加情報 | 少ない | ポインタが必要 |
| キャッシュ局所性 | 良い傾向 | 悪い傾向 |
| 容量拡張 | 再確保・コピー | ノードごとに追加 |

未来に多い操作、件数、実際の実装費用で選びます。
