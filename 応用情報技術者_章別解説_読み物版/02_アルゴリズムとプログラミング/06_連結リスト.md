# 第2章・第6話　連結リスト――離れた要素を「次の場所」でつなぐ

配列の途中に要素を入れると、後続の要素を動かす必要があります。
連結リストでは、要素を結ぶリンクを付け替えて順序を変えます。
ただし、付け替える場所が既に分かっていることと、その場所をこれから探すことでは、必要な時間が違います。

連結リストを読むときは、値だけでなく、どの要素からどの要素へ到達できるかを追います。
挿入や削除の途中で参照を失うと、残りの要素が記憶領域に存在していても使えなくなるからです。

## リンクをたどって要素に到達する

### 1 ノードとリンク

リストの各要素をノード、または節点と呼びます。
単方向リストのノードは、データと、次のノードへの参照を持ちます。
この参照をポインタ、リンクとも呼びます。

```text
Node
  data
  next
```

最後の`next`には、次のノードがないことを示すNULLなどを入れます。

### 2 先頭参照

リスト全体を使うには、最初のノードがどこかを覚えます。

```text
head → [A|・] → [B|・] → [C|NULL]
```

`head`を失うと、ほかに参照がなければ全ノードに到達できません。

空リストでは、`head=NULL`とします。

### 3 順番は住所ではなくリンクで決まる

A、B、Cのアドレスが次のように離れていても、リンクがA→B→Cなら、この順序で要素をたどります。

```text
A 100番地
B 700番地
C 240番地
```

主記憶上の物理的な並びと、リンクで定める論理的な並びは別です。

### 4 リストを走査する

```text
current = head
while current != NULL
    current.dataを処理
    current = current.next
```

`current`は今見ているノードへの参照です。

各ノードを一度通るので、n要素の全走査は`O(n)`です。

最後に`current=current.next`を忘れると、同じノードを永遠に見ます。

### 5 i番目へ直接飛べない

先頭を1番目として10番目の要素を取り出す場合も、先頭からリンクを9本たどる必要があります。
0から番号を付ける場合は、次の図の10番へ到達するまでに10本のリンクをたどります。

```text
0番 → 1番 → 2番 → ... → 10番
```

先頭から離れるほど、たどるリンクが増えるため、任意位置の参照は`O(n)`です。
配列では位置をアドレス計算で求められるので、参照は`O(1)`です。

## 参照を保持して順序を変える

### 6 先頭へ挿入する

元のリストです。

```text
head → A → B → C
```

Xを先頭に入れます。

1. `X.next=head`として、Xから旧先頭Aにつなぐ。
2. `head=X`として、先頭をXに変える。

```text
head → X → A → B → C
```

順序が重要です。
先に`head=X`だけ行うと、旧先頭Aへの参照を失う場合があります。

操作自体は`O(1)`です。

### 7 途中へ挿入する

途中への挿入では、挿入位置の直前ノードへの参照を使います。
その参照が既に分かっていれば、必要なのはリンクの変更だけです。

AとBの間にXを入れます。

```text
A → B
```

1. `X.next=A.next`でX→B。
2. `A.next=X`でA→X。

```text
A → X → B
```

先にA→Xに変え、Bへの参照を別に保存していなければ、残りを見失う恐れがあります。

挿入位置の直前Aを既に持っていれば、リンク変更は`O(1)`です。
しかしAを探すところからなら`O(n)`です。

挿入全体の計算量には、位置を探す費用も含めます。

### 8 削除する

単方向リストでBを削除するには、Bへ向かうリンクを変更します。
Aの`next`をCへ付け替えるので、Bだけでなく、その直前のAへの参照が必要です。

A→B→CからBを外します。

```text
A.next = B.next
```

結果はA→Cです。

Bの直前Aを知っていれば`O(1)`です。
Bだけを知っていても、単方向リストでは前ノードに戻れません。

削除後、Bが動的に確保した領域なら、誰も使っていないことを確認して解放します。
自動回収の言語では、参照されなくなった後にガベージコレクタが回収します。

### 9 末尾参照

末尾へ頻繁に追加する場合は、最後のノードへの参照を`tail`として保持します。

```text
head → A → B → C ← tail
```

新しいXを末尾に入れるには、現在の末尾からXへつなぎ、その後で`tail`をXへ更新します。
この2つの更新は`O(1)`で行えます。

```text
tail.next = X
tail = X
```

空リストへ最初の1個を入れるときは、`head`と`tail`の両方をXにします。
最後の1個を削除したときは、両方をNULLにします。

### 10 番兵ノード

データを持たない特別な先頭ノードを、番兵ノードとして置く場合があります。

```text
sentinel → A → B → C
```

空リストでも`sentinel`は存在するため、先頭への挿入や先頭要素の削除を、途中の操作と同じ形で扱いやすくなります。
番兵ノードは通常のデータとして数えません。

## 前後と循環のリンクを持たせる

### 11 双方向リスト

各ノードに、次だけでなく前への参照も持たせます。

```text
NULL ← A ⇄ B ⇄ C → NULL
```

```text
Node
  data
  prev
  next
```

前後に移動でき、対象ノードを知っていれば削除しやすくなります。

一方、参照欄が増え、挿入・削除時に更新するリンクも増えます。

### 12 双方向リストへ挿入する

双方向リストでは、新しいノードから前後へ向かう参照と、両隣から新しいノードへ向かう参照を更新します。

AとBの間にXを入れます。

更新する関係は4つです。

```text
X.prev = A
X.next = B
A.next = X
B.prev = X
```

1つ忘れると、前向きには通れるが後ろ向きに戻れない、という壊れ方をします。

更新前後の不変条件を確認します。

- A.next.prevはA。
- B.prev.nextはB。
- head.prevはNULL。
- tail.nextはNULL。

### 13 環状リスト

最後の次を先頭につなぎます。

```text
A → B → C
↑       ↓
└───────┘
```

順番に持ち回る処理、ラウンドロビンなどに使えます。

NULLには到達しないため、開始ノードに戻ったことや、指定個数の処理を終えたことを、走査の終了条件にします。
終了条件を誤ると無限ループになります。

## 抽象的な操作と記憶配置を分ける

### 14 線形リストという抽象概念

要素が1列の順序を持つデータ構造を、線形リストと呼びます。
線形リストは、配列を使う順次リストとしても、リンクを使う連結リストとしても実装できます。

「リストにどのような操作ができるか」という抽象的な規則と、「要素をリンクでつなぐ」という実装方法は分けて考えます。

### 15 メモリ配置と局所性

配列では要素が連続しているため、近くの要素がまとめてCPUのキャッシュに入りやすく、順番に走査するときに有利です。

連結リストでは、ノードが離れた場所にある可能性があります。
次のアドレスを読むまで先へ進めず、キャッシュミスも増えやすくなります。
また、データに加えてポインタを保存する記憶領域も必要です。
同じ`O(n)`の走査でも、このような配置の違いによって実際の速度は変わります。

### 16 メモリ管理の危険

手動でメモリを管理する環境では、次のような誤りに注意が必要です。

#### メモリリーク

確保したノードを解放せず、参照も失う。

#### ダングリングポインタ

解放済みノードへの参照を使う。

#### 二重解放

同じ領域を2回解放する。

#### NULL参照

ノードがないNULLを、ノードとして読む。

自動メモリ管理でも、不要なノードへの参照を保持し続ければ回収されず、実質的なリークになります。

### 17 循環参照

AがBを参照し、BがAを参照していると、外部から到達できなくなっても、互いへの参照が残ります。

```text
A → B
↑   ↓
└───┘
```

単純な参照カウント方式では、両者の参照数が0にならず、回収できない場合があります。
外部の根から到達できるかを調べるガベージコレクタなら、到達できない循環を回収できます。

## 逆順への変更を不変条件で確かめる

### 18 リストを逆順にする

単方向リストA→B→CをC→B→Aにします。

3つの参照を使います。

```text
prev = NULL
current = head

while current != NULL
    nextNode = current.next
    current.next = prev
    prev = current
    current = nextNode

head = prev
```

各回では、参照を失わない順序で次の3つの操作を行います。

1. 次を失わないよう保存。
2. 現在ノードの矢印を逆向きに。
3. prevとcurrentを1つ進める。

`nextNode`を保存する前に矢印を変えると、未処理部分に到達できなくなります。

### 19 ループ不変条件で逆順を説明する

各回の先頭では、2つの参照が次の状態を表します。

- `prev`から、処理済み部分が逆順につながっている。
- `current`から、未処理部分が元の順につながっている。

1ノードを未処理から処理済みに移しても、この性質が保たれます。
最後に`current=NULL`なら未処理がなく、`prev`が全体の新先頭です。

## 操作の条件を含めて計算量を比べる

### 20 リストでよく使う操作の計算量

単方向リストで、位置への参照が既にあるかに注意します。

| 操作 | 代表的な計算量 |
|---|---:|
| 先頭参照 | O(1) |
| i番目参照 | O(n) |
| 値の探索 | O(n) |
| 先頭挿入 | O(1) |
| 既知ノード後に挿入 | O(1) |
| 挿入位置を探して挿入 | O(n) |
| 既知の前ノードがある削除 | O(1) |
| tailありの末尾追加 | O(1) |


### 21 配列とリストを比べる

配列と連結リストでは、位置の参照、途中への挿入、容量の拡張にかかる費用が違います。

| 観点 | 配列 | 連結リスト |
|---|---|---|
| i番目参照 | O(1) | O(n) |
| 途中挿入 | 要素移動O(n) | 場所が既知ならリンク変更O(1) |
| メモリ | 連続領域 | ノードごとに分散可能 |
| 追加情報 | 少ない | ポインタが必要 |
| キャッシュ局所性 | 良い傾向 | 悪い傾向 |
| 容量拡張 | 再確保・コピー | ノードごとに追加 |

AとBの間へXを入れる操作では、直前のAを既に参照できるなら、連結リストのリンク変更は定数時間です。
Aを探す必要があるなら、その探索時間も含めて比べます。
多く行う操作、件数、実装に必要な費用を合わせて選びます。
