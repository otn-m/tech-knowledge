# 第2章・第8話　木とヒープ――枝分かれする関係を保存し、探索する

ファイルシステムのディレクトリ、企業の組織図、生物の分類体系などでは、1つの親概念から複数の子概念へと関係性が樹状に枝分かれします。
このような階層的な包含関係をモデル化して管理するデータ構造が「木構造（ツリー）」です。

```text
会社
├─ 営業部
│  ├─ 東日本課
│  └─ 西日本課
│ 
└─ 開発部
   ├─ 製品A班
   └─ 製品B班
```

木構造を利用する目的に応じて、ノード同士を分岐させる構造規則は大きく変化します。
二分探索木はキー値を高速に探索するため、ヒープは最大値や最小値を効率よく取り出すため、B木はディスクなどの外部ストレージから少ないアクセス回数で検索するための規則を備えるわけです。
同一のデータ群を格納する場合であっても、採用する枝分かれ規則や木の平衡度合いによって、検索や更新に要する処理ステップ数は劇的に変動します。

## 木の関係と形を定義する

### 1 木を作る部品

木構造は、頂点とそれを結ぶ枝の集まりによって構成される階層モデルです。
データの実体を保持する各要素をノード（節点）、ノード間を階層的につなぐ接続線をエッジ（辺、枝）と呼びます。
最上位に位置して親を持たない唯一の頂点が根（ルート: root）であり、1段上位のノードを親、1段下位のノードを子、同一の親を持つノード同士を兄弟と呼ぶわけです。
子ノードを1つも持たない末端のノードを葉（リーフ: leaf）、1つ以上の子ノードを持つノードを内部ノードと呼びます。
木構造の幾何学的な定義として、根以外のすべてのノードは自分を指す親ノードを厳密に1つだけ保持する構造です。

### 2 部分木

あるノードを起点として、その下位にぶら下がるすべての子孫ノードと辺を切り出した小規模な木を部分木と呼びます。

```text
    A
   / \
  B   C
 / \
D   E
```

上記の木において、ノードBを根とする部分木はノードB、D、Eの集合で構成されます。

木構造は、「単一の根ノードと、0個以上の独立した部分木の集合」として再帰的に定義できるデータ構造です。

```text
根 + 0個以上の部分木
```

全体構造と局所構造が自己相似形を成しているため、木構造に対するアルゴリズムは再帰関数と極めて自然に適合します。

### 3 深さと高さ

根ノードの深さを基準値の0と定めます。
根から当該ノードに至るまでに経由する辺の本数が、そのノードの「深さ（depth）」です。

前述の木構造の例では、各ノードの深さは次の階層に対応します。

- 根ノードAの深さは0。
- 子ノードBおよびCの深さは1。
- 葉ノードDおよびEの深さは2。

これに対し「木の高さ（height）」は、根から最も深い葉ノードに至る最大経路の辺の数として定義するのが一般的です。
ただし文献によってはノードの段数そのものを高さと定義する流儀もあるため、前提の定義を事前に確認しておかなければなりません。

### 4 木の基本性質

グラフ理論の観点から見ると、すべての頂点が連結されており閉路（サイクル）を一切持たない無向グラフが木です。

`n`個のノードから構成される木構造には、常に厳密に`n-1`本の辺が存在します。

任意の2つのノード間には、ノード同士を結ぶ単純パスが必ず1本だけ存在します。
もし2ノード間に複数の経路が存在してしまうと、それらの経路が合流してループ（閉路）が形成されてしまうためです。

### 5 多分木と二分木

#### 多分木

各ノードが3個以上の子ノードを自由に保持できる木構造を多分木（マルチツリー）と呼びます。
ファイルシステムのディレクトリ構造や組織の階層図を表現する用途で幅広く活用される形式です。

#### 二分木

すべてのノードが持つ子の数が高々2個に制限された木構造を二分木（バイナリツリー）と呼びます。
2つの子ノードは「左の子」と「右の子」として厳密に区別される構造です。

```text
    A
   / \
 左   右
```

左の子と右の子を左右反転させて入れ替えた場合、それは数学的に別の二分木として識別されます。

### 6 完全二分木

最下段以外のすべての深さレベルがノードで完全に満たされており、かつ最下段のノード群が左端から隙間なく詰められた二分木を完全二分木と呼びます。

```text
      A
    /   \
   B     C
  / \   /
 D   E F
```

完全二分木はノードの欠落がないため、ポインタを用いずに平坦な配列上に隙間なく高密度で格納可能です。
なお「すべての内部ノードが正確に2個の子を持つ木」を完全二分木と呼ぶ異説も存在するため、各種試験等では「左詰めの完全二分木」という定義を慎重に確認します。

## 配列で表し高さを考える

### 7 配列で完全二分木を持つ

ここで`floor(x)`とは、実数x以下の最大の整数を返す**床関数**（切り捨て）のことです。
たとえば`floor(1.5)=1`となります。
完全二分木を上段のレベル順かつ左から右へと配列に並べると、親から子への添字は2倍の計算で求まり、子から親への添字は2による除算と床関数によって導出可能です。

根ノードをインデックス1に配置する場合、ノード`i`の親子関係は次の明快な計算式で特定できます。

```text
左の子 = 2i
右の子 = 2i+1
親 = floor(i/2)
```

根ノードをインデックス0から配置する場合は、オフセットの計算式が次のようにシフトします。

```text
左の子 = 2i+1
右の子 = 2i+2
親 = floor((i-1)/2)
```

配列の開始インデックスが0か1かによって計算式が異なるため、両者の流儀を混同してはなりません。

#### 配列添字の数値例

0始まりの配列表現における計算関係を具体的に確認してみましょう。
この配置規約では、親ノードは`floor((i-1)/2)`、左の子は`2i+1`、右の子は`2i+2`です。
たとえば添字3のノードの親は`floor((3-1)/2)=1`番地となり、左右の子はそれぞれ7番地と8番地に対応します。
完全二分木をレベル順に配列へ詰めることで、複雑なポインタ管理を排して算術演算だけで親子間を往来できるわけです。

### 8 平衡木

左右の部分木の高さのバランスが極端に偏らないよう、自律的に高さを均等に保つ木構造を平衡木（バランス木）と呼びます。

木の高さがノード数nに対して`O(log n)`に抑制されていれば、根から葉に至る探索の計算量も`O(log n)`で維持できます。
もし昇順ソート済みのデータを素朴な二分木へ次々に挿入すると、木が一直線に伸びて高さが`O(n)`に退化し、探索性能が線形探索と同等まで悪化してしまうわけです。

## 訪れる順序を決める

### 9 木の走査

木構造に含まれるすべてのノードを、一定の規則的な順序で漏れなく1回ずつ訪問する処理を走査（巡回: トラバーサル）と呼びます。

二分木の走査においては、親ノードのデータを左右の部分木に対してどのタイミングで処理するかによって、代表的な3つの走査順序に分類されます。

```text
    A
   / \
  B   C
 / \
D   E
```


### 10 先行順

親ノードを最初に処理し、続いて左部分木、最後に右部分木を再帰的に走査する順序です。
この巡回手順はpreorderとも呼ばれます。

```text
A, B, D, E, C
```

```text
preorder(node)
    もしnodeがNULLなら戻る
    nodeを処理
    preorder(node.left)
    preorder(node.right)
```

木構造をファイル等へシリアライズして保存する場合や、数式を前置記法（ポーランド記法）へ変換する場面などで活用されます。

### 11 中間順

左部分木を再帰走査した後に親ノードを処理し、最後に右部分木を走査する順序です。
この走査方式はinorderとも呼ばれます。

```text
D, B, E, A, C
```

二分探索木に対して中間順の走査を適用すると、すべてのキー値が小さい順（昇順ソート済み）で整然と出力される特性を持ちます。

### 12 後行順

左右の両部分木を先にすべて処理し終えた後、最後に親ノードの処理を実行する順序です。
この順序関係はpostorderとも呼ばれます。

```text
D, E, B, C, A
```

子ノードの評価結果が親ノードの処理に先立って必要となるため、木全体のメモリ解放、ディレクトリ容量の集計、あるいは数式の後置記法（逆ポーランド記法）の生成などで重宝されます。

### 13 深さ優先と幅優先

先行順・中間順・後行順はいずれも、1つの枝を葉に向かって深く掘り下げる「深さ優先走査（DFS）」の範疇に属するアルゴリズムです。
実装にはプログラムの再帰呼出し、または明示的なスタックが用いられます。

対して幅優先走査（BFS: レベル順走査）では、深さ0の根、深さ1の階層、深さ2の階層というように、根から近い同一階層のノード群を横方向に網羅して訪問する手順です。

```text
A, B, C, D, E
```

階層ごとの横断的な訪問順序を制御するためには、データ構造としてキューを用います。

## キーの順序で探索する

### 14 二分探索木

二分木を構成する各ノードとその左右の部分木に対して、厳密な順序関係の不変条件を課した木構造を二分探索木（BST: Binary Search Tree）と呼ぶわけです。

```text
左部分木のキー < ノードのキー < 右部分木のキー
```

この大小関係の制約により、探索対象キーとの1回の大小比較だけで、次の探索範囲を左右いずれかの部分木へと半分に絞り込めます。
なお重複するキー値を許可するか否かは、要件に応じて別途定義することが一般的です。

```text
      8
    /   \
   3     12
  / \    / \
 1   6  10  14
```


### 15 二分探索木で探す

上記の二分探索木からキー値10を探索するステップを追跡してみましょう。

1. 根のキー8と比較する。
   目的の10は8より大きいため、左部分木を丸ごと切り捨てて右の子12へ進む。
2. 次のノード12と比較する。
   10は12より小さいため、右部分木を切り捨てて左の子10へ進む。
3. ノードのキー10と完全に一致したため、探索成功として処理を終える。

比較を1回行うたびに、探索対象から外れた逆側の部分木全体を探索候補から除外できます。
木が美しく平衡していれば探索計算量は高速な`O(log n)`ですが、直線状に偏った木では最悪`O(n)`まで劣化する点に留意が必要です。

### 16 挿入する

二分探索木へ新しいキー値5を追加するアルゴリズムを追跡してみましょう。

```text
5>3なので右
5<6なので左
空きへ5
```

```text
   3
    \
     6
    /
   5
```

根ノードから通常の探索と同様に大小比較を進め、ポインタがNULLに到達した末端の空きスロットへ新しい葉ノードとして配置する手順です。

### 17 削除する三場合

二分探索木から既存のノードを削除する処理は、削除対象ノードが持つ子の数に応じて3つのケースに分岐します。

#### 子が0個

削除対象が葉ノードである場合、親ノードからの参照リンクを単にNULLへ書き換えて切り離します。

#### 子が1個

削除対象ノードをバイパスし、親ノードからその唯一の子ノードへと直接リンクをつなぎ替えるわけです。

```text
親 → 削除対象 → 子
親 ─────────→ 子
```


#### 子が2個

削除対象ノードの位置へ、左右の順序関係を維持できる別のノードの値を代替値として昇格させます。
代替値の候補には、右部分木の最小値（inorder successor: 後継ノード）か、左部分木の最大値（inorder predecessor: 前任ノード）のいずれかを採用する仕組みです。

昇格させた値の元のノードを部分木から削除します。
後継ノードは右部分木を左へ突き当たりまでたどった端点に位置するため左の子を持たず、その削除は「子が0個または1個」の簡単なケースへと帰着されるわけです。

## 高さの偏りを抑える

### 18 偏った探索木

二分探索木における各操作の処理効率は、根から葉に至る最長経路である木の高さに全面的に依存します。
キーの大小順序が正しく維持されていたとしても、木の高さが肥大化していれば探索の優位性は完全に失われてしまいます。

キー値1、2、3、4、5を昇順で素朴に連続挿入したケースを観察してみましょう。

```text
1
 \
  2
   \
    3
     \
      4
       \
        5
```

この木は枝分かれを一切持たず、実質的に単方向連結リストと変わりありません。
この縮退状態では、探索も挿入も最悪計算量が`O(n)`の線形時間へと転落します。
入力データの順序傾向に性能が翻弄される事態を回避するため、木の形状を自律的に整える平衡二分探索木が必要となるわけです。

### 19 AVL木

すべてのノードにおいて、左部分木の高さと右部分木の高さの差が常に-1、0、1の許容範囲内に収まるよう自律制御する木構造がAVL木です。

左右部分木の高さの差を平衡係数（balance factor）と定義します。
要素の挿入や削除によって平衡係数の絶対値が2に達して不均衡が生じた場合、木構造の局所的な「回転（rotation）」を実行して平衡度を復元します。
キー値の中間順（ソート順序）は厳格に保持したまま、木の深さだけを低減させるわけです。
外側に伸びた不均衡パターンは単回転で解消し、内側に折れ曲がった不均衡パターンは二重回転を適用して解消します。

### 20 右回転

キーが30、20、10の順で挿入され、左側に一直線に偏った状態を想定してみましょう。

```text
    30
   /
  20
 /
10
```

中間ノード20を新たな部分木の根へと引き上げる「右回転」を実行します。

```text
   20
  /  \
10   30
```

キーの大小関係`10 < 20 < 30`を完全に維持しながら、部分木の全体の高さを2段から1段へと短縮できました。

### 21 左回転と二重回転

右側へ一直線にノードが偏ったアンバランスに対しては、対称となる「左回転」を適用して是正します。

左の子の右側に「く」の字型に折れ曲がってノードが挿入された局面では、単一の回転だけでは不均衡を解消できません。

```text
  30
 /
10
  \
  20
```

このようなケースでは、まず子ノード10を左回転させて直線の偏りに変換し、その直後に親ノード30を右回転させる「左-右二重回転」を実行する手順です。
回転操作を完了した後は、影響を受けたノード群の高さと平衡係数を葉から根へと遡って再計算します。

## 外部ストレージの読取り回数を減らす

### 22 B木

1つのノード内に複数のキー値を格納し、3個以上の子ノードへと枝分かれできる多分平衡探索木がB木（B-tree）です。

```text
       [20 | 50]
      /    |    \
  <20   20..50   >50
```

1つのノードが保持する分岐数を意図的に拡大することで、木全体の高さを極端に低く抑え込みます。
ハードディスクやSSDのような外部記憶では、データがページやブロックと呼ばれる固定長単位で読み書きされます。
CPU内部のメモリ比較回数よりも、低速な補助記憶（SSDやHDD）からのブロック読取り回数を削減することが極めて重要です。

### 23 B木への挿入

B木において新しいキー値を追加する際は、必ず最下層の葉ノードから探索を開始してキーを挿入します。
キーの追加によってノードの許容容量が上限を超過した場合、中央値のキーを親ノードへ昇格させ、残りのキー群を左右2つの新規ノードへと分割します。

親ノードも同様に満杯になれば、このノード分割が上層へと順次連鎖していく仕組みです。
根ノードが分割された瞬間にのみ新しい根が新設され、木全体の高さが一様に1段だけ増加します。
すべての葉ノードが完全に同一の深さに揃うため、木全体の完全な平衡状態が永続的に維持される構造です。

派生構造であるB+木では、実データへのポインタを葉ノードのみに集約し、さらに葉ノード同士を双方向リンクで数珠つなぎに連結します。
リレーショナルデータベースのインデックス機構として事実上の標準仕様となっている構造です。

### 24 順序木

兄弟ノードの並び順そのものに意味論的な重要性が付与されている木構造を順序木と呼びます。

HTMLやXML文書のDOMツリー、プログラミング言語の構文解析木（AST）などでは、子の出現順序を入れ替えてしまうと文書や数式の意味が破壊されてしまいます。
二分木も左の子と右の子を厳密に区別して運用するため、順序木の一種として位置づけられるわけです。

## 最大値と最小値を根へ集める

### 25 ヒープ――親が子より優先される完全二分木

ヒープ（二分ヒープ）は、すべての親子ノード間に一定の大小関係が常に成立している完全二分木構造です。
最大ヒープにおいては「親ノードの値 >= 子ノードの値」というヒープ条件が満たされ、根ノードには常に木全体の最大値が鎮座します。

```text
      9
    /   \
   7     8
  / \   /
 2   5 3
```

根ノードの9が木全体の最大値に対応するわけです。
最小ヒープにおいては「親ノードの値 <= 子ノードの値」が成立し、根ノードに木全体の最小値が配置されます。
兄弟ノード間や異なる枝の間には大小関係の制約が一切存在しないため、ヒープは二分探索木とは明確に異なる構造です。

### 26 ヒープを配列へ置く

ヒープは形状として完全二分木を満たすため、ポインタを用いずに0始まりの平坦な配列へ左詰めで格納できます。

```text
[9,7,8,2,5,3]
```

インデックス`i`のノードに対応する親子関係は、次の単純な算術式で瞬時に計算可能です。

```text
左の子 2i+1
右の子 2i+2
親 floor((i-1)/2)
```

ポインタ用の追加メモリを一切消費せず、配列のキャッシュ局所性を最大限に活用できます。

### 27 ヒープへ追加する

最大ヒープに対して新しい要素10を追加する手順を観察してみましょう。

1. 完全二分木の形状を保つため、新しい要素を配列の末尾（最下段の左端の空き）に一時配置する。
2. 配置した要素と親ノードの値を比較し、子の方が大きければ親子を入れ替える。
3. 根ノードに到達するか親の方が大きくなるまで、この比較と交換を上方へ向かって反復する。

この再配置処理を上方移動（sift up、またはbubble up）と呼びます。
最悪でも木の高さの分しか比較と交換が進まないため、追加操作の計算量は`O(log n)`です。

### 28 最大値を取り出す

最大ヒープから最重要データである根の最大値を取り出すアルゴリズムを確認します。

1. 根ノードに格納されている最大値を取り出して保存する。
2. 配列の末尾要素を空いた根の位置へと移送し、配列の要素数を1つ減らす。
3. 根に置かれた暫定要素を左右の子ノードのうち大きい方と比較し、親の方が小さければ交換する。
4. ヒープの不変条件が満たされるか葉に達するまで、この比較と交換を下方向へ反復する。

この下降処理を下方移動（sift down、またはtrickle down）と呼ぶわけです。
取り出し操作全体の計算量も、木の高さに比例するため`O(log n)`で完了します。

### 29 ヒープの再構成

任意の順序で並んだ無秩序な配列を、一括してヒープの不変条件を満たす配列へと仕立て直す操作をヒープ構築（heapify）と呼ぶわけです。

葉ノード群は子を持たないため、それ単体で最初からヒープ条件を充足しています。
したがって、最も深い内部ノード（添字`floor(n/2)-1`）から根ノード0に向かって逆順に走査し、各ノードに対して下方移動（sift down）を適用していく手順です。

全要素を空ヒープに1個ずつ`push`していく手法では`O(n log n)`を要しますが、このボトムアップ構築法を採用すると全体計算量は`O(n)`の線形時間で完了します。
木の下位に存在する大量のノード群ほど必要な下方移動ステップ数が小さく、高コストな長距離移動を行うノードは上層のわずかな個数に限られるためです。

数学的な移動量の総和を概算すると次の式が成り立ちます。

```text
最大移動量 ≤ n/4×1 + n/8×2 + n/16×3 + … < n
```

したがって作業量全体の総和は要素数nに対して完全に線形比例する計算です。
1要素ずつ挿入する愚直な手法と、ボトムアップ構築法の計算量の相違を正確に把握しておく必要があります。

### 30 ヒープソート

ヒープの性質を応用すると、効率的な整列アルゴリズムであるヒープソートを構築可能です。

1. 与えられた配列全体をボトムアップ構築により最大ヒープに仕立てる。
2. 根の最大値と配列の末尾要素を交換する。
3. 交換された末尾位置を確定済み領域としてヒープの対象範囲から除外する。
4. 根に移動した要素に対して下方移動を適用し、残余範囲を最大ヒープとして再構成する。
5. 未整列の要素が1個になるまで、手順2から4を反復する。

最悪時間計算量は常に保証された`O(n log n)`であり、配列内部で領域をやりくりするため追加メモリは定数`O(1)`で済みます。
ただし離れた位置の要素同士を交換するため、等しいキーの順序が保持されない不安定ソート（unstable sort）に分類される手法です。

### 31 優先度付きキューとしてのヒープ

二分ヒープを活用すると、極めて効率的な優先度付きキューを実現できます。

最高優先度データの確認は根を覗くだけなので瞬時の`O(1)`であり、新規タスクの追加と最重要タスクの払い出しはいずれも`O(log n)`で完結する仕組みです。
すべてのデータを完全に整列し直す必要がなく、「その時点で最も優先すべき要素」を繰り返し1つずつ取り出したいシステム設計において最適な選択肢です。

## 必要な操作から木を選ぶ

### 32 木を選ぶ

| 目的 | 構造 |
|---|---|
| 階層関係の直観的な表現 | 多分木・順序木 |
| キー値の順序維持と高速探索 | 平衡二分探索木 |
| 外部ストレージのインデックス | B木・B+木 |
| 最優先データの連続的取り出し | ヒープ |
| 最短経路や階層順の幅優先走査 | 木の幅優先探索 |

階層関係を忠実に保持したいのか、任意のキー値を高速検索したいのか、あるいは極値のみを次々に取り出したいのかによって、適用すべき木のアルゴリズムは異なります。
根8から10を絞り込んで探索する二分探索木と、根9から最大値を即座に供給するヒープの違いに見られるように、システムが最も頻繁に要求する操作特性を見極めて最適な構造を選定する姿勢が大切です。
