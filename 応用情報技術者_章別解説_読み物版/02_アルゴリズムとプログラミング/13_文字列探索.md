# 第2章・第13話　文字列探索――文章の中から語を見つける

文章、商品番号、DNAの並び、通信データなどから、目的の並びを探すことがあります。
このとき探される対象を**テキスト**、探したい短い文字列を**パターン**と呼ぶわけです。

```text
本文:   THE CAT SAT ON THE MAT
探す語: CAT
```

この例のCATは目でも見つけられますが、数百万文字から何万回も探す場合は、比較の仕方が処理時間を左右します。
高速な文字列探索では、比較済みの情報から、次に一致し得る位置を求めます。
その際、どの文字列を同じと扱うか、重なる一致を返すかという検索の仕様も必要です。

## 一致の定義と素朴な探索

### 1 一致とは何か

文字列とは、文字を順番に並べたデータ列を意味します。

```text
文字列 CAT
位置   0 1 2
文字   C A T
```

パターンが見つかるとは、テキスト中の連続した範囲が、長さも各位置の文字も同じであることです。

大文字と小文字を別とするなら、`Cat`と`CAT`は一致しません。
空白、改行、全角・半角、濁点の表し方なども、文字の並びとしては違う場合があります。
検索前に何を同じと扱うか決める必要があります。

### 2 最も素朴な方法

テキストの各位置にパターンを重ね、左から順に文字を比較していく手法です。

```text
テキスト: A B A B A C
パターン: A B A C

位置0:    A B A B A C
          A B A C
          ○ ○ ○ ×
```

最後で違ったので、パターンを1文字右にずらします。

```text
位置1:    A B A B A C
            A B A C
            ×
```

さらにずらします。

```text
位置2:    A B A B A C
              A B A C
              ○ ○ ○ ○
```

位置2で見つかりました。

#### 2.1 擬似コード

```text
テキスト長をn、パターン長をmとする

iを0からn-mまで繰り返す
    j = 0
    j < m かつ text[i+j] == pattern[j] の間
        j = j + 1
    もしj == mなら
        位置iで見つかった
```

パターンを置ける最後の開始位置が`n-m`です。
たとえば本文6文字、パターン4文字なら、開始位置は0、1、2の3か所です。

### 3 素朴法が遅くなる例

次のように同じ文字が多いと、毎回ほとんど最後まで一致してから失敗します。

```text
テキスト:   A A A A A A A A B
パターン:   A A A A B
```

1回失敗するたび、またAを最初から比べ直します。
最悪では、テキストのおよそnか所でパターンのおよそm文字を比べるのでO(nm)です。

しかし、一度比較した結果には情報があります。
その情報を使い、明らかに失敗する位置を飛ばすのが高速な探索法です。

## 接頭辞と接尾辞をKMP法で再利用する

### 4 KMP法の中心となる考え

**KMP法**は、考案者Knuth、Morris、Prattの名字の頭文字を取った名前です。

左から比較し、失敗したとき、パターン自身の繰返し構造を使います。
テキスト側の比較位置を後ろに戻しません。

先ほどの例をもう一度見ます。

```text
テキスト: A B A B A C
パターン: A B A C
          ○ ○ ○ ×
```

失敗前に`ABA`まで一致しました。

`ABA`の先頭と末尾には、同じ`A`があります。

```text
一致済み: A B A
接頭辞:   A
接尾辞:       A
```

したがって、末尾のAは、次の候補の先頭Aとして再利用できます。
全部を捨てて1文字だけ右に動かす必要はありません。

```text
テキスト: A B A B A C
旧候補:   A B A C
新候補:       A B A C
```

新候補の最初のAはすでに一致すると分かっています。
次のBから比べられます。

### 5 接頭辞と接尾辞

文字列の先頭から取った連続部分が接頭辞、末尾までの連続部分が接尾辞です。

文字列全体を除いた`ABAB`の真の接頭辞としては、以下の3通りが存在します。

```text
A
AB
ABA
```

一方、真の接尾辞は次のとおりです。

```text
B
AB
BAB
```

双方に共通する最長の要素は`AB`であり、その長さは2となります。

KMP法は、パターンの各位置について「そこまで一致した文字列の、接頭辞でも接尾辞でもある最長部分の長さ」を事前に表として保持する設計です。

### 6 失敗関数・部分一致表

KMP法では、一致済みの部分の接頭辞と接尾辞の重なりを、表に記録します。
この表を活用すれば、一致の可能性を漏らすことなく、比較を再開すべき位置を効率的に特定できるわけです。

教材により失敗関数、部分一致表、prefix table、`lps`配列などと呼ばれます。
定義やインデックスの取り方にはいくつかの流儀が存在する点に留意が必要です。
本書では`lps[i]`を以下の定義に従って扱うものとします。

> パターンの0番目からi番目までについて、文字列全体ではない接頭辞と接尾辞が一致する最大長

例として、パターン`ABABAC`に対する表を実際に構築してみましょう。

| i | そこまでの文字列 | 最長の共通接頭辞・接尾辞 | lps[i] |
|---:|---|---|---:|
| 0 | A | なし | 0 |
| 1 | AB | なし | 0 |
| 2 | ABA | A | 1 |
| 3 | ABAB | AB | 2 |
| 4 | ABABA | ABA | 3 |
| 5 | ABABAC | なし | 0 |

`ABABA`では、先頭3文字と末尾3文字がどちらも`ABA`なので3です。

### 7 lps表をどう作るか

毎位置で全接頭辞を調べても作れますが、前までの結果を再利用するとO(m)で作れます。

```text
lps[0] = 0
len = 0
i = 1

i < m の間
    もし pattern[i] == pattern[len] なら
        len = len + 1
        lps[i] = len
        i = i + 1
    そうでなく len > 0 なら
        len = lps[len - 1]
    そうでなければ
        lps[i] = 0
        i = i + 1
```

ここで`len`は、現在分かっている共通接頭辞・接尾辞の長さです。

不一致なのに`len > 0`なら、iを進めず、より短い候補`lps[len-1]`に戻します。
「長さlenでは無理でも、その接尾辞の中にさらに短い接頭辞が残るかもしれない」からです。

### 8 KMP検索の手順

`i`をテキストの位置、`j`をパターンの位置とします。

```text
i = 0
j = 0

i < n の間
    もし text[i] == pattern[j] なら
        i = i + 1
        j = j + 1

        もし j == m なら
            開始位置 i-m で発見
            j = lps[j-1]

    そうでなく j > 0 なら
        j = lps[j-1]

    そうでなければ
        i = i + 1
```

不一致時に`j > 0`なら、テキスト位置iは進めません。
今のテキスト文字を、パターン内のもっと短い候補と再比較します。

`j == 0`で失敗したときだけ、今のテキスト文字から始まる一致はないのでiを進めます。

### 9 KMP法の計算量

前処理でlps表を作るのにO(m)、検索にO(n)です。
合計O(n+m)です。

検索中、テキスト位置iは後ろに戻りません。
パターン位置jが戻ることはありますが、全体として比較回数は長さに比例する範囲に抑えられます。

KMP法は、同じパターンを多数のテキストに探す場合、lps表を一度作って再利用できます。

## 右から比較して候補を飛ばすBM法

### 10 BM法――右端から比べ、大きく飛ばす

**BM法**は、BoyerとMooreの名字から取った名称です。
パターンをテキストに重ね、通常はパターンの右端から左向きに比べます。

```text
テキスト: H E R E  I S  A  S I M P L E  E X A M P L E
パターン: E X A M P L E
                    ← 右端から比較
```

不一致文字とパターン内の文字配置を見て、パターンを1文字より大きく動かせます。
実用上、特に文字の種類が多くパターンが長い場合、平均的に高速です。

BM法には主に2つの移動規則があります。

- 不一致文字規則、またはbad character rule
- よい接尾辞規則、またはgood suffix rule

まず、不一致になったテキスト文字を使う規則から見ていきます。

### 11 不一致文字規則

パターン`EXAMPLE`を検索中、ある位置でテキスト文字`S`と比較して不一致になったケースを想定してみましょう。

`S`はパターン中にありません。
パターンのどの文字をそのSに重ねても一致し得ないため、Sを丸ごと飛び越えるように大きく移動できるわけです。

```text
テキスト: ... S ...
旧位置:      EXAMPLE
新位置:              EXAMPLE
```

不一致となった文字がパターン内に含まれる場合は、その文字の最も右側にある出現位置をテキスト側の不一致文字へと合わせます。

例えばパターン`ABCA`で不一致文字が`B`なら、パターン内のBをその位置へ一致させる候補を残す設計です。

### 12 右端位置表

そのため、各文字がパターン内で最後に出現する位置を事前に表として構築しておきます。

パターン`ABCA`なら次です。

| 文字 | 右端位置 |
|---|---:|
| A | 3 |
| B | 1 |
| C | 2 |
| その他 | -1 |

パターン位置jでテキスト文字cと不一致なら、基本的な移動量は次のように計算できます。

```text
shift = max(1, j - rightmost[c])
```

`max`は大きい方を選ぶ関数です。
最低でも1動かします。

ただし、完全なBM法やHorspool法などの変種では、表の作り方や移動量が異なります。
試験問題では、提示された表と規則を読み、その流儀で追ってください。

### 13 よい接尾辞規則

右から何文字か一致した後、左側で失敗したとします。

```text
パターンの末尾 ... X Y Z が一致済み
```

一致済みの`XYZ`と同一の並びがパターン内のより左側にあれば、その部分をテキストの`XYZ`に合わせる形をとるわけです。

同一の並びが存在しないなら、`XYZ`の末尾とパターンの接頭辞が重なる位置までパターンを動かします。
それすら存在しない場合は、パターン全体を一気に飛び越えて前進させることが可能です。

本格的なBM法では、不一致文字規則とよい接尾辞規則の双方を計算し、より大きく安全にシフトできる側を採用します。

この表の構築は複雑です。
右から比較し、すでに分かった不一致・一致情報を使って、あり得ない開始位置を飛ばすことが基本です。

#### よい接尾辞規則を短い例で作る

パターン`ABABA`を右から照合し、末尾の`BA`までは一致したものの、その直前で不一致になったとしましょう。
先頭を1番目として数えると、一致済み接尾辞`BA`と同じ並びが、パターン内の位置2〜3にもあります。
したがって、その位置を現在のテキストの`BA`に合わせるように2文字シフトさせることが可能です。
これがよい接尾辞表に記録する移動候補です。

同時に、不一致になったテキスト文字がパターンの右側に現れる位置から不一致文字規則の移動量も求めます。
すでに一致した照合結果を無駄にせず、より大きな前進幅をもたらす規則を選択するわけです。
接尾辞がパターン内に再出現しない場合は、接尾辞の末尾と合致するパターン接頭辞の有無も探索します。

### 14 BM法の速さをどう理解するか

BM法は1回の不一致でパターンを大幅に移動できるため、実際のテキストでは全文字を照合することなく走査を完了できるケースも少なくありません。

ただし、前進できる文字数は文字の出現頻度や並び方に依存します。
短いパターンや繰返しの多いデータでは利点が小さくなり、単純な規則だけの実装では、偏った入力で時間がかかることもあります。
完全なBM法には最悪時を線形に抑える工夫がありますが、実装はKMP法より複雑です。

### 15 KMP法とBM法の違い

| 観点 | KMP法 | BM法 |
|---|---|---|
| 主な比較方向 | 左から右 | パターンの右から左 |
| 前処理 | 接頭辞・接尾辞の表 | 不一致文字表、よい接尾辞表 |
| 強み | テキスト位置を戻さず最悪O(n+m) | 実用上、大きく飛ばして速いことが多い |
| 分かりやすい利用場面 | 同じ文字が繰り返す並び | 長いパターン、文字種類の多い文章 |

どちらも、過去の比較結果を捨てず、次にあり得る位置を計算する点は同じです。

## パターンの種類と一致の仕様を決める

### 16 複数のパターンを探す場合

禁止語一覧のように、多数のパターンを一度に探す場合があります。
1語ずつKMP法を繰り返すと、登録語数の分だけ本文を再読しなければならず非効率です。

そこでパターン群を木構造にまとめる**トライ木**や、失敗時の状態遷移を組み込んだ**Aho-Corasick法**を用いれば、1回のテキスト走査ですべての語を検出できます。

```text
        root
       /    \
      C      D
      |      |
      A      O
     / \     |
    T   R    G
```

例えばCATとCARは共通の先頭部分CAを共有し、DOGは独立した別の枝へと分岐する構造です。

### 17 正規表現は別の道具

「数字が3個、その後にハイフン、さらに数字が4個」のような形を探したいことがあります。
単一の固定文字列にとどまらず、多様な文字列の規則やパターンを指定する道具が**正規表現**です。

```text
[0-9]{3}-[0-9]{4}
```

これは固定文字列探索とは問題設定が違います。
多くの正規表現エンジンでは、入力パターンを有限オートマトンへ変換してマッチングを行う仕組みです。

ただし、処理系の実装方式やパターンの記述によっては、バックトラックが多発して実行時間が著しく増大する危険性もあります。
外部から渡された表現を無制限に実行させないなど、安全性への配慮も必要です。

### 18 Unicodeと検索

見た目が同じでも、内部の符号の並びが異なる文字があります。
たとえば「é」は、1文字の符号で表す方法と、eとアクセント記号を組み合わせる方法があります。

このような場合、単純なバイト比較では意図せず不一致と判定されてしまうわけです。
したがって、必要に応じて事前に**Unicode正規化**を適用し、内部表現を統一しておかなければなりません。

また、次の選択も必要です。

- 大文字と小文字を区別するか。
- 全角と半角を同じとするか。
- ひらがなとカタカナを同じとするか。
- 濁点をどう扱うか。
- 言語ごとの並べ替え・比較規則をどうするか。

アルゴリズムが正しくても、「同じ文字」の仕様が曖昧なら利用者の期待と違う結果になります。

## 空文字列と重なる一致を扱う

### 19 空パターンと重なり

空文字列を検索したとき何を返すかは、仕様で決めます。
多くのライブラリは位置0で一致したと扱いますが、すべて同じとは限りません。

パターン`ANA`を`BANANA`から探すと、位置1と位置3で見つかり、2つの一致は1文字重なります。

```text
B A N A N A
  A N A
      A N A
```

1つ見つけた後、パターン長だけ進めると重なる一致を見落とします。
重複した出現をすべて網羅すべきか、非重複の一致のみで十分かを事前に仕様化しておくことが肝要です。

### 20 検索のテスト

テストに際しては、少なくとも以下のようなケースを網羅的に検証する必要があります。

- 先頭で一致する。
- 末尾で一致する。
- 中央で一致する。
- 一致しない。
- パターンがテキストより長い。
- テキストとパターンが同じ。
- 同じ文字ばかりである。
- 複数回一致する。
- 一致が重なる。
- 空文字列を含む。
- 日本語や結合文字を含む。

単純法は遅くても実装が分かりやすいので、小さなランダム入力でKMP法やBM法の結果と比べる正解生成器として役立ちます。

CATを探す素朴法も、KMP法も、BM法も、一致する位置を求める目的は同じです。
違うのは、不一致が分かった後に、比較済みの情報からどれだけの候補を除けるかです。
速さを比較するときは、テキストとパターンの性質に加え、文字の同一性と一致の返し方をそろえます。
