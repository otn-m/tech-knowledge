# 第2章・第13話　文字列探索――文章の中から語を見つける

文章、商品番号、DNAの並び、通信データなどから、目的の並びを探したいことがあります。

```text
本文:   THE CAT SAT ON THE MAT
探す語: CAT
```

本文のような探される側を**テキスト**、探したい短い文字列を**パターン**と呼びます。

人間は目でCATを見つけられます。
しかし数百万文字から何万回も探すなら、比較の仕方が処理時間を左右します。

---

## 1 一致とは何か

文字列は文字を順番に並べたものです。

```text
文字列 CAT
位置   0 1 2
文字   C A T
```

パターンが見つかるとは、テキスト中の連続した範囲が、長さも各位置の文字も同じであることです。

大文字と小文字を別とするなら、`Cat`と`CAT`は一致しません。
空白、改行、全角・半角、濁点の表し方なども、文字の並びとしては違う場合があります。
検索前に何を同じと扱うか決める必要があります。

## 2 最も素朴な方法

テキストの各位置にパターンを重ね、左から文字を比べます。

```text
テキスト: A B A B A C
パターン: A B A C

位置0:    A B A B A C
          A B A C
          ○ ○ ○ ×
```

最後で違ったので、パターンを1文字右にずらします。

```text
位置1:    A B A B A C
            A B A C
            ×
```

さらにずらします。

```text
位置2:    A B A B A C
              A B A C
              ○ ○ ○ ○
```

位置2で見つかりました。

### 2.1 擬似コード

```text
テキスト長をn、パターン長をmとする

iを0からn-mまで繰り返す
    j = 0
    j < m かつ text[i+j] == pattern[j] の間
        j = j + 1
    もしj == mなら
        位置iで見つかった
```

パターンを置ける最後の開始位置が`n-m`です。
たとえば本文6文字、パターン4文字なら、開始位置は0、1、2の3か所です。

## 3 素朴法が遅くなる例

不一致が見つかったら、開始位置を1文字進めてやり直すのが素直です。
一致済みの部分自身に繰返しがあれば、その情報から、比較を再開できる位置が分かります。

次のように同じ文字が多いと、毎回ほとんど最後まで一致してから失敗します。

```text
テキスト:   A A A A A A A A B
パターン:   A A A A B
```

1回失敗するたび、またAを最初から比べ直します。
最悪では、テキストのおよそnか所でパターンのおよそm文字を比べるのでO(nm)です。

しかし、一度比較した結果には情報があります。
その情報を使い、明らかに失敗する位置を飛ばすのが高速な探索法です。

---

## 4 KMP法の中心となる考え

**KMP法**は、考案者Knuth、Morris、Prattの名字の頭文字を取った名前です。

左から比較し、失敗したとき、パターン自身の繰返し構造を使います。
テキスト側の比較位置を後ろに戻しません。

先ほどの例をもう一度見ます。

```text
テキスト: A B A B A C
パターン: A B A C
          ○ ○ ○ ×
```

失敗前に`ABA`まで一致しました。

`ABA`の先頭と末尾には、同じ`A`があります。

```text
一致済み: A B A
接頭辞:   A
接尾辞:       A
```

したがって、末尾のAは、次の候補の先頭Aとして再利用できます。
全部を捨てて1文字だけ右に動かす必要はありません。

```text
テキスト: A B A B A C
旧候補:   A B A C
新候補:       A B A C
```

新候補の最初のAはすでに一致すると分かっています。
次のBから比べられます。

## 5 接頭辞と接尾辞

文字列の先頭から取った連続部分を**接頭辞**、末尾までの連続部分を**接尾辞**と呼びます。

`ABAB`の真の接頭辞は、文字列全体を除けば次です。

```text
A
AB
ABA
```

真の接尾辞は次です。

```text
B
AB
BAB
```

両方にある最長のものは`AB`、長さ2です。

KMP法は、パターンの各途中位置について、「そこまで一致した文字列の、接頭辞でも接尾辞でもある最長部分の長さ」を前もって表にします。

## 6 失敗関数・部分一致表

不一致の後に大きく飛べば速くなりますが、飛ばした範囲に一致候補があっては困ります。
部分一致表は、すでに一致した接頭辞と接尾辞の重なりだけを使い、捨てても安全な比較を決めます。

教材により**失敗関数**、**部分一致表**、**prefix table**、`lps`配列などと呼ばれます。
表し方や値の定義が少し違う流儀もあります。
ここでは`lps[i]`を次の意味にします。

> パターンの0番目からi番目までについて、文字列全体ではない接頭辞と接尾辞が一致する最大長

パターン`ABABAC`の表を作ります。

| i | そこまでの文字列 | 最長の共通接頭辞・接尾辞 | lps[i] |
|---:|---|---|---:|
| 0 | A | なし | 0 |
| 1 | AB | なし | 0 |
| 2 | ABA | A | 1 |
| 3 | ABAB | AB | 2 |
| 4 | ABABA | ABA | 3 |
| 5 | ABABAC | なし | 0 |

`ABABA`では、先頭3文字と末尾3文字がどちらも`ABA`なので3です。

## 7 lps表をどう作るか

毎位置で全接頭辞を調べても作れますが、前までの結果を再利用するとO(m)で作れます。

```text
lps[0] = 0
len = 0
i = 1

i < m の間
    もし pattern[i] == pattern[len] なら
        len = len + 1
        lps[i] = len
        i = i + 1
    そうでなく len > 0 なら
        len = lps[len - 1]
    そうでなければ
        lps[i] = 0
        i = i + 1
```

ここで`len`は、現在分かっている共通接頭辞・接尾辞の長さです。

不一致なのに`len > 0`なら、iを進めず、より短い候補`lps[len-1]`に戻します。
「長さlenでは無理でも、その接尾辞の中にさらに短い接頭辞が残るかもしれない」からです。

## 8 KMP検索の手順

`i`をテキストの位置、`j`をパターンの位置とします。

```text
i = 0
j = 0

i < n の間
    もし text[i] == pattern[j] なら
        i = i + 1
        j = j + 1

        もし j == m なら
            開始位置 i-m で発見
            j = lps[j-1]

    そうでなく j > 0 なら
        j = lps[j-1]

    そうでなければ
        i = i + 1
```

不一致時に`j > 0`なら、テキスト位置iは進めません。
今のテキスト文字を、パターン内のもっと短い候補と再比較します。

`j == 0`で失敗したときだけ、今のテキスト文字から始まる一致はないのでiを進めます。

## 9 KMP法の計算量

前処理でlps表を作るのにO(m)、検索にO(n)です。
合計O(n+m)です。

検索中、テキスト位置iは後ろに戻りません。
パターン位置jが戻ることはありますが、全体として比較回数は長さに比例する範囲に抑えられます。

KMP法は、同じパターンを多数のテキストに探す場合、lps表を一度作って再利用できます。

## 10 BM法――右端から比べ、大きく飛ばす

**BM法**は、BoyerとMooreの名字から取った名称です。
パターンをテキストに重ね、通常はパターンの右端から左向きに比べます。

```text
テキスト: H E R E  I S  A  S I M P L E  E X A M P L E
パターン: E X A M P L E
                    ← 右端から比較
```

不一致文字とパターン内の文字配置を見て、パターンを1文字より大きく動かせます。
実用上、特に文字の種類が多くパターンが長い場合、平均的に高速です。

BM法には主に2つの移動規則があります。

- **不一致文字規則**、またはbad character rule
- **よい接尾辞規則**、またはgood suffix rule

まず分かりやすい不一致文字規則を学びます。

## 11 不一致文字規則

パターン`EXAMPLE`を検索中、ある位置でテキスト文字`S`と比較して不一致になったとします。

`S`はパターン中にありません。
ならば、そのSにパターンのどの文字を重ねても、今の付近では一致を始められないため、Sを丸ごと越えるように移動できます。

```text
テキスト: ... S ...
旧位置:      EXAMPLE
新位置:              EXAMPLE
```

不一致文字がパターン内にある場合は、その文字の右端の出現をテキスト側の不一致文字に合わせます。

たとえばパターン`ABCA`で不一致文字が`B`なら、パターン内のBをその位置に合わせる候補を残します。

## 12 右端位置表

各文字がパターン中で最後に現れる位置を前もって表にします。

パターン`ABCA`なら次です。

| 文字 | 右端位置 |
|---|---:|
| A | 3 |
| B | 1 |
| C | 2 |
| その他 | -1 |

パターン位置jでテキスト文字cと不一致なら、基本的な移動量は次のように計算できます。

```text
shift = max(1, j - rightmost[c])
```

`max`は大きい方を選ぶ関数です。
最低でも1動かします。

ただし、完全なBM法やHorspool法などの変種では、表の作り方や移動量が異なります。
試験問題では、提示された表と規則を読み、その流儀で追ってください。

## 13 よい接尾辞規則

右から何文字か一致した後、左側で失敗したとします。

```text
パターンの末尾 ... X Y Z が一致済み
```

一致済みの`XYZ`と同じ並びがパターン内のもっと左にあれば、そこをテキストの`XYZ`に合わせます。

同じ並びがなければ、`XYZ`の末尾とパターンの接頭辞が重なる位置まで動かします。
それもなければパターン全体を越えるほど動かせます。

完全なBM法は、不一致文字規則とよい接尾辞規則のうち、安全に大きく動かせる方を使います。

この表の構築は複雑です。
右から比較し、すでに分かった不一致・一致情報を使って、あり得ない開始位置を飛ばすことが基本です。

## 14 BM法の速さをどう理解するか

何文字も飛ばせる例を見ると、BM法では比較回数が文字列長より大幅に少なくなるように見えます。
飛べる距離は文字の並びに依存し、短いパターンや繰返しの多いデータでは利点が小さくなります。

BM法は、1回の不一致でパターンを大きく動かせるため、実際の文章ではテキスト全文字を比較せずに済む場合があります。

ただし、単純な規則だけの実装や偏った入力では、常に理想的とは限りません。
完全なBM法には最悪時を線形に抑える工夫がありますが、実装はKMP法より複雑です。

## 15 KMP法とBM法の違い

| 観点 | KMP法 | BM法 |
|---|---|---|
| 主な比較方向 | 左から右 | パターンの右から左 |
| 前処理 | 接頭辞・接尾辞の表 | 不一致文字表、よい接尾辞表 |
| 強み | テキスト位置を戻さず最悪O(n+m) | 実用上、大きく飛ばして速いことが多い |
| 分かりやすい利用場面 | 同じ文字が繰り返す並び | 長いパターン、文字種類の多い文章 |

どちらも、過去の比較結果を捨てず、次にあり得る位置を計算する点は同じです。

## 16 複数のパターンを探す場合

禁止語一覧のように、多数のパターンを一度に探す場合があります。
1語ずつKMP法を行うと、語数だけ本文を読み直します。

パターンを木のようにまとめる**トライ木**や、失敗時の移動を加えた**Aho-Corasick法**を使うと、複数語を一度の走査で探せます。

```text
        root
       /    \
      C      D
      |      |
      A      O
     / \     |
    T   R    G
```

CAT、CAR、DOGは、共通の先頭CAを共有します。

## 17 正規表現は別の道具

文字列を探すという目的は同じでも、正規表現は固定した1語だけを探す仕組みではありません。
文字の集合や繰返しを含むパターンを表す分、処理系やパターンによって計算量も変わります。

「数字が3個、その後にハイフン、さらに数字が4個」のような形を探したいことがあります。
固定した1語ではなく文字列の規則を指定する道具が**正規表現**です。

```text
[0-9]{3}-[0-9]{4}
```

これは固定文字列探索とは問題設定が違います。
正規表現エンジンは、有限オートマトンなどに変換して一致を調べる場合があります。

利用する処理系や書き方によっては、特定の正規表現で非常に時間がかかることもあります。
外部から渡された表現を無制限に実行させないなど、安全性への配慮も必要です。

## 18 Unicodeと検索

画面で同じ文字に見えても、結合文字や正規化形式が違えば、符号位置の並びは一致しないことがあります。
検索前にどの正規化を施すかは、見た目の一致をどこまで同一視するかという仕様です。

見た目が同じでも、内部の符号の並びが異なる文字があります。
たとえば「é」は、1文字の符号で表す方法と、eとアクセント記号を組み合わせる方法があります。

そのまま比較すると不一致になることがあります。
必要なら**Unicode正規化**で表現をそろえます。

また、次の選択も必要です。

- 大文字と小文字を区別するか。
- 全角と半角を同じとするか。
- ひらがなとカタカナを同じとするか。
- 濁点をどう扱うか。
- 言語ごとの並べ替え・比較規則をどうするか。

アルゴリズムが正しくても、「同じ文字」の仕様が曖昧なら利用者の期待と違う結果になります。

## 19 空パターンと重なり

空文字列を検索したとき何を返すかは、仕様で決めます。
多くのライブラリは位置0で一致したと扱いますが、すべて同じとは限りません。

パターン`ANA`を`BANANA`から探すと、位置1と位置3で見つかり、2つの一致は1文字重なります。

```text
B A N A N A
  A N A
      A N A
```

1つ見つけた後、パターン長だけ進めると重なる一致を見落とします。
重複一致を許すか、重ならない一致だけを欲しいかを仕様化します。

## 20 検索のテスト

少なくとも次を試します。

- 先頭で一致する。
- 末尾で一致する。
- 中央で一致する。
- 一致しない。
- パターンがテキストより長い。
- テキストとパターンが同じ。
- 同じ文字ばかりである。
- 複数回一致する。
- 一致が重なる。
- 空文字列を含む。
- 日本語や結合文字を含む。

単純法は遅くても実装が分かりやすいので、小さなランダム入力でKMP法やBM法の結果と比べる正解生成器として役立ちます。

## よい接尾辞規則を短い例で作る

パターン`ABABA`を右から照合し、末尾の`BA`までは一致したがその左で不一致になったとします。
一致済み接尾辞`BA`と同じ並びはパターン内の位置2〜3にもあります。
そこを現在のテキストの`BA`に合わせるよう2文字移動できます。
これがよい接尾辞表に記録する移動候補です。

同時に、不一致になったテキスト文字がパターンの右側に現れる位置から不一致文字規則の移動量も求めます。
完全なBM法では、既に一致した文字を壊さず安全に移動できる2つの候補のうち大きい方を使います。
接尾辞がパターン内に再出しない場合は、その接尾辞の末尾と一致するパターン接頭辞も調べます。


## 21 確認問題

1. テキストとパターンはそれぞれ何ですか。
2. 素朴な文字列探索法を説明してください。
3. テキスト長n、パターン長mの素朴法の最悪計算量は何ですか。
4. 同じ文字が続く入力で素朴法が遅くなりやすい理由は何ですか。
5. KMPという名前は何に由来しますか。
6. 接頭辞と接尾辞を説明してください。
7. `ABAB`の、全体を除く最長の共通接頭辞・接尾辞は何ですか。
8. lps表は何を記録しますか。
9. KMP法が不一致時にテキスト位置を後ろに戻さなくてよい理由を説明してください。
10. KMP法の前処理と検索を合わせた計算量は何ですか。
11. BM法は通常、パターンのどちら側から比較しますか。
12. 不一致文字がパターン内に一度もないとき、大きく移動できるのはなぜですか。
13. 不一致文字規則とよい接尾辞規則は、何のための規則ですか。
14. KMP法とBM法に共通する考えは何ですか。
15. 多数のパターンを一度に探す方法の例を答えてください。
16. 固定文字列探索と正規表現検索の違いを説明してください。
17. 見た目が同じUnicode文字が一致しないことがあるのはなぜですか。
18. `BANANA`中の`ANA`は何回、どこで重なって現れますか。
19. 空パターンの扱いを仕様で決めるべき理由は何ですか。
20. 高速検索法を単純法と比較テストする利点は何ですか。

## 解答

1. テキストは探される長い文字列、パターンは探したい文字列です。
2. パターンをテキストの各開始位置に重ね、左から一致するか比べ、不一致なら1文字ずらします。
3. O(nm)です。
4. 毎回ほぼ最後まで一致して失敗し、同じ文字を何度も比較し直すからです。
5. Knuth、Morris、Prattという3人の名字です。
6. 接頭辞は先頭からの連続部分、接尾辞は末尾までの連続部分です。
7. `AB`、長さ2です。
8. 各位置までの文字列で、真の接頭辞と接尾辞が一致する最大長を記録します。
9. 一致済み部分の接頭辞・接尾辞の重なりを使い、次にあり得るパターン位置を分かるからです。
10. O(n+m)です。
11. 右端から左向きです。
12. そのテキスト文字に合わせられるパターン文字がなく、間の開始位置も一致し得ないからです。
13. 不一致後に、正しさを保ったままパターンを何文字移動できるか決めます。
14. 過去の比較結果を再利用し、明らかに一致しない候補位置を飛ばすことです。
15. トライ木とAho-Corasick法などです。
16. 固定文字列探索は決まった文字列を探し、正規表現は文字列の形・規則を指定して探します。
17. 1文字の符号と基底文字＋結合記号など、内部の符号列が異なる表現があるからです。
18. 位置1と位置3の2回で、1文字Aが重なります。
19. どこでも一致と考えるか、無効と考えるかなど、自然な解釈が1つではないからです。
20. 複雑な高速版の結果を、遅くても単純で確認しやすい基準と照合できるからです。
