# 第2章・第12話　グラフアルゴリズム――道、つながり、最短経路を調べる


## このファイルで初めて使う用語

本文で使う前に、ここでは次の意味を置きます。略語は正式名、日本語名、本文での役割の順です。

- **AC**：Actual Cost（実コスト）。実際にかかった費用。（[詳説](<../10_マネジメント/07_コスト見積りとEVM.md#7 EVMの三つの基本値>)）


地図には町と道があります。人間関係の図には人と関係線があります。Webにはページとリンクがあります。

このような「もの」と「もの同士のつながり」を表す道具が**グラフ**です。ここでいうグラフは、棒グラフや折れ線グラフではありません。

- ものを**頂点**、または**ノード**と呼ぶ。
- つながりを**辺**、または**エッジ**と呼ぶ。

この授業では、グラフをコンピュータへどう置くか、全部の頂点をどう回るか、最短経路をどう求めるかを、一つの小さな地図で追います。

---

## 1 まず、何を解きたいのか

次の町と道を考えます。

```text
      B
     / \
    A   D──E
     \ /
      C
```

頂点はA、B、C、D、Eです。辺はA―B、A―C、B―D、C―D、D―Eです。

グラフに対する代表的な質問は次のとおりです。

- AからEへ行けるか。
- Aとつながっている町を全部挙げられるか。
- AからEまで辺を最も少なくする道はどれか。
- 各道の距離が違うなら、合計距離が最短の道はどれか。
- 矢印で表された作業の前後関係に、循環はないか。

質問が違えば、使うアルゴリズムも変わります。

## 2 無向グラフと有向グラフ

AからBへもBからAへも通れる道は、向きのない辺で表します。これが**無向グラフ**です。

```text
A──B
```

AからBへだけ進める一方通行は矢印で表します。これが**有向グラフ**です。

```text
A → B
```

有向グラフでは、AからBへ行けても、BからAへ行けるとは限りません。

## 3 重みとは何か

辺へ数字を付けることがあります。この数字を**重み**と呼びます。

```text
A ──5km── B
```

重みは距離に限りません。

- 移動時間
- 運賃
- 通信の遅れ
- 作業に必要な日数
- 損失や危険度

「最短経路」の短さは、辺の本数ではなく重みの合計を意味する場合があります。問題文で何を最小にするのかを必ず確かめます。

## 4 隣接行列で置く

グラフをプログラムで扱うには、記憶装置へ形を変えて置きます。

**隣接行列**は、行と列を頂点にして、辺があれば1、なければ0とする表です。

```text
    A B C D E
A   0 1 1 0 0
B   1 0 0 1 0
C   1 0 0 1 0
D   0 1 1 0 1
E   0 0 0 1 0
```

A行B列が1なので、AとBには辺があります。無向グラフでは表が対角線を挟んで左右対称になります。

頂点がV個なら、V×V個の場所を使います。辺が少ないグラフでも大きな表が必要ですが、「AとBは直接つながるか」は表を一か所見るだけで分かります。

## 5 隣接リストで置く

**隣接リスト**は、各頂点から直接行ける相手だけを並べます。

```text
A: B, C
B: A, D
C: A, D
D: B, C, E
E: D
```

頂点数をV、辺数をEと書くと、必要な記憶量はおおむねO(V+E)です。辺が少ないグラフに向きます。

ここで`V`と`E`は値そのものではなく、規模を表す文字です。`O(V+E)`は、頂点と辺を合わせた数にだいたい比例して作業が増える、という意味です。

## 6 探索で一番大切なvisited

グラフには輪があり得ます。

```text
A──B
|  /
C
```

AからB、BからC、CからAと進み続けると、終わりません。

そこで、訪れた頂点を覚える印を用意します。慣例的に`visited`と名付けます。英語で「訪問済み」という意味です。

```text
visited[A] = true
```

すでに印がある頂点には、もう探索を広げません。この一行が、無限に回ることと同じ場所を何度も調べることを防ぎます。

---

## 7 幅優先探索――近い場所から調べる

**幅優先探索**、英語でBreadth-First Search、略して**BFS**は、出発点から辺一本で行ける場所、次に辺二本で行ける場所、という順で調べます。

待ち行列である**キュー**を使います。先に入れたものを先に取り出すFIFOの箱でした。

### 7.1 手順

1. 出発点Aを訪問済みにし、キューへ入れる。
2. キューの先頭を取り出す。
3. その頂点の隣で未訪問のものを、訪問済みにしてキューへ入れる。
4. キューが空になるまで繰り返す。

大切なのは、キューへ入れる時点で訪問済みにすることです。取り出すまで待つと、同じ頂点が複数の親から何度も入る場合があります。

### 7.2 Aから実際にたどる

隣接頂点をアルファベット順で見ることにします。

| 操作 | 取り出した頂点 | 新しく入れた頂点 | キュー |
|---|---|---|---|
| 初期化 | ― | A | A |
| 1 | A | B、C | B、C |
| 2 | B | D | C、D |
| 3 | C | なし | D |
| 4 | D | E | E |
| 5 | E | なし | 空 |

訪問順はA、B、C、D、Eです。

### 7.3 擬似コード

```text
BFS(start)
    空のキューqを作る
    visited[start] = true
    qへstartを入れる

    qが空でない間
        v = qの先頭を取り出す
        vを処理する

        vの各隣接頂点nextについて
            もし visited[next] がfalseなら
                visited[next] = true
                qへnextを入れる
```

### 7.4 BFSで最短本数が分かる理由

重みのないグラフでは、BFSは辺一本先、二本先、三本先と層ごとに進みます。ある頂点へ最初に着いたとき、それより少ない本数の経路はもう前の層で調べ終わっています。

したがって、最初に着いた経路が辺の本数で最短です。

```text
distance[start] = 0
distance[next] = distance[v] + 1
parent[next] = v
```

`parent`は、どの頂点から来たかを記録する箱です。Eから親を逆にたどれば、E←D←B←Aとなり、逆向きに並べてA→B→D→Eという経路を復元できます。

---

## 8 深さ優先探索――行けるところまで進む

**深さ優先探索**、英語でDepth-First Search、略して**DFS**は、一つの道を行けるところまで進み、行き止まりなら戻って別の道を調べます。

積み重ねの箱である**スタック**か、関数が自分を呼ぶ**再帰**を使います。

### 8.1 再帰版

```text
DFS(v)
    visited[v] = true
    vを処理する

    vの各隣接頂点nextについて
        もし visited[next] がfalseなら
            DFS(next)
```

Aから、隣をアルファベット順で見ると、A→B→D→Cまで深く進み、Dへ戻ってEへ進むため、訪問順の一例はA、B、D、C、Eです。

隣接頂点を見る順が変われば訪問順も変わります。DFSという方法が同じでも、順序が一つに決まるとは限りません。

### 8.2 明示的なスタック版

```text
空のスタックsを作る
sへstartを積む

sが空でない間
    v = sから取り出す
    もしvが訪問済みなら続ける
    visited[v] = true
    vを処理する
    vの未訪問の隣をsへ積む
```

積む順と取り出される順は逆になります。再帰版と全く同じ訪問順にしたいときは、隣を積む順にも注意します。

## 9 BFSとDFSの使い分け

| 方法 | 主な道具 | 進み方 | 得意なこと |
|---|---|---|---|
| BFS | キュー | 近い層から広がる | 重みなし最短経路、最少手数 |
| DFS | スタック・再帰 | 一枝を深く進む | 到達判定、連結成分、循環、全列挙 |

隣接リストを使えば、どちらも各頂点と各辺をほぼ一度ずつ見るためO(V+E)です。

BFSは同じ層の頂点を多数キューに保持する場合があります。DFSは深いグラフで再帰の呼出しが多くなり、呼出しスタックを使い切る場合があります。

## 10 つながった島を数える

互いに道がある頂点のまとまりを**連結成分**と呼びます。

```text
A──B    C──D    E
```

この図には、{A,B}、{C,D}、{E}の三成分があります。

全頂点を順に見て、未訪問の頂点を見つけるたびにBFSかDFSを一回始めます。探索を始めた回数が連結成分の数です。

```text
count = 0
すべての頂点vについて
    もしvが未訪問なら
        DFS(v)
        count = count + 1
```

## 11 有向グラフの循環を調べる

作業Aが終わってからB、Bが終わってからC、Cが終わってからAという条件は実行不能です。

```text
A → B → C
↑       ↓
└───────┘
```

有向グラフのDFSでは、頂点を三状態に分ける方法があります。

- 未訪問
- 探索中――今の再帰経路上にいる
- 完了――その先を全部調べた

探索中の頂点へ戻る辺を見つけたら、循環があります。単なる訪問済みだけでは、「今の経路へ戻った」のか「別枝で調べ終えた」のかを区別できません。

## 12 トポロジカルソート

矢印を「先に行うもの→後に行うもの」と考え、すべての順序条件を守る並びを作ることを**トポロジカルソート**と呼びます。

料理の例です。

```text
材料を切る → 炒める → 盛り付ける
米を炊く ─────────→ 盛り付ける
```

入口へ来る矢印の本数を**入次数**と呼びます。入次数0、つまり前提作業がない頂点をキューへ入れます。

1. 入次数0の頂点を取り出し、結果へ加える。
2. そこから出る辺を削ったことにし、行き先の入次数を1減らす。
3. 新たに0になった頂点をキューへ入れる。
4. 全頂点を出せれば成功。途中でキューが空なのに頂点が残れば循環がある。

複数の頂点が同時に入次数0なら、正しい並びは複数あり得ます。

## 13 重み付き最短経路を考える

次の道には距離があります。

```text
      4       3
 A ───── B ───── D
 │       │       ▲
 2       1       │
 │       │       │
 ▼       ▼       │
 C ──────────────┘
       5
```

辺はA→Bが4、A→Cが2、B→Cが1、B→Dが3、C→Dが5です。

AからDへは、A→B→Dなら7、A→C→Dなら7、A→B→C→Dなら10です。この例の最短距離は7です。

頂点までの現時点で分かっている最小距離を`dist`という配列に置きます。

```text
dist[A] = 0
dist[ほか] = ∞
```

∞は本当の巨大な数ではなく、「まだ到達方法が分からない」という印です。

## 14 緩和――もっと短い道が見つかったら直す

辺u→vの重みをwとします。uまでの距離にwを足したものが、今のvの距離より短ければ更新します。

```text
もし dist[u] + w < dist[v] なら
    dist[v] = dist[u] + w
    parent[v] = u
```

この更新を**緩和**と呼びます。「候補をゆるめる」という日常語とは結び付きにくい専門語なので、まずは「より短い候補で上書きする操作」と覚えてください。

## 15 ダイクストラ法

**ダイクストラ法**は、辺の重みがすべて0以上のとき、一つの出発点から各頂点への最短距離を求めます。

考え方は、「まだ確定していない頂点の中で、暫定距離が最小のものを次に確定する」です。

### 15.1 手作業で追う

初めはAだけ0です。

| 確定する頂点 | 緩和後のA | B | C | D |
|---|---:|---:|---:|---:|
| 初期 | 0 | ∞ | ∞ | ∞ |
| A | 0 | 4 | 2 | ∞ |
| C | 0 | 4 | 2 | 7 |
| B | 0 | 4 | 2 | 7 |
| D | 0 | 4 | 2 | 7 |

Aを確定するとB=4、C=2です。未確定で最小のC=2を確定し、D=2+5=7とします。次はB=4を確定します。B→Dなら4+3=7で同じなので変わりません。最終的にD=7です。

### 15.2 なぜ負の辺があると使えないのか

ダイクストラ法は、「今いちばん小さい頂点は、後からもっと短くならない」と考えて確定します。

しかし負の重みがあると、遠く見えた頂点を経由して距離が大きく下がるかもしれません。

```text
A → B  重み2
A → C  重み5
C → B  重み-10
```

A→Bは2に見えますが、A→C→Bは`5+(-10)=-5`です。Bを2で早く確定すると誤ります。

よって、負の辺が一つでもある可能性を無視してダイクストラ法を使ってはいけません。

### 15.3 優先度付きキューを使う

未確定の中から最小距離を毎回探すため、最小値を素早く取り出せる優先度付きキュー、通常はヒープを使います。

```text
dist[start] = 0
優先度付きキューへ (0, start) を入れる

キューが空でない間
    (d, v) = 最小の組を取り出す
    もし d != dist[v] なら続ける

    vから出る各辺(v, next, w)について
        もし d + w < dist[next] なら
            dist[next] = d + w
            parent[next] = v
            キューへ (dist[next], next) を入れる
```

同じ頂点の古い距離がキューに残る場合があります。取り出した`d`が現在の`dist[v]`と違えば、古い候補なので捨てます。

隣接リストと二分ヒープを使う代表的な計算量はO((V+E) log V)です。

## 16 ベルマン・フォード法

**ベルマン・フォード法**は、負の辺があっても使える単一始点最短経路アルゴリズムです。

すべての辺を何度も緩和します。

頂点がV個あり、負閉路がなければ、単純な最短経路に含まれる辺は最大V-1本です。そのため全辺の緩和をV-1回繰り返せば距離が伝わります。

```text
dist[start] = 0
ほかは∞

V-1回繰り返す
    更新した = false
    すべての辺(u, v, w)について
        もしdist[u]が∞でなく dist[u]+w < dist[v] なら
            dist[v] = dist[u] + w
            parent[v] = u
            更新した = true
    もし一度も更新しなければ早く終了
```

計算量はO(VE)で、通常はダイクストラ法より遅い代わりに、負の辺を扱えます。

## 17 負閉路とは何か

一周すると重みの合計が負になる輪を**負閉路**と呼びます。

```text
A → B  重み1
B → C  重み-3
C → A  重み1
一周の合計 = -1
```

この輪を回るたび距離が1ずつ小さくなります。1周、2周、3周と回れば、いくらでも小さくできるので、有限の「最短距離」が存在しません。

ベルマン・フォード法でV-1回緩和した後、もう一度全辺を見てまだ更新できるなら、出発点から到達可能な負閉路があります。

## 18 ダイクストラ法とベルマン・フォード法の選択

| 条件 | 選びやすい方法 |
|---|---|
| 重みがなく、辺の本数を最少にする | BFS |
| 重みがすべて0以上 | ダイクストラ法 |
| 負の重みがあり得る | ベルマン・フォード法 |
| 負閉路の有無も調べたい | ベルマン・フォード法 |

「最短経路」と見ただけでダイクストラ法と決めず、重みの有無と符号を確認します。

## 19 全頂点間の最短距離

すべての出発点からすべての到着点までを求める問題を**全点対最短経路**と呼びます。

頂点を中継点として一つずつ許可する**ワーシャル・フロイド法**では、距離表を更新します。

```text
すべての中継点kについて
    すべての出発点iについて
        すべての到着点jについて
            dist[i][j] = min(
                dist[i][j],
                dist[i][k] + dist[k][j]
            )
```

意味は、「iからjへ直接行く今の最良」と「kを経由する道」を比べて短い方にする、です。

三重の繰返しなのでO(V³)、距離表はO(V²)です。負の辺は扱えますが、負閉路があると通常の最短距離は定まりません。計算後に`dist[i][i] < 0`となる頂点があれば負閉路を検出できます。

## 20 最小全域木――全地点を安くつなぐ

最短経路とは別の問題もあります。全頂点をつなぎ、辺の重みの合計を最小にした木を**最小全域木**と呼びます。

たとえば複数の建物へ通信ケーブルを引く総工事費を小さくする問題です。ある一地点からの道を短くするのではなく、ネットワーク全体の辺の合計を小さくします。

- **クラスカル法**は、重みの小さい辺から、輪を作らないものを選ぶ。
- **プリム法**は、一頂点から始め、現在の木と外側を結ぶ最小辺を選ぶ。

クラスカル法では、二頂点がすでに同じ集まりかを調べる**Union-Find**、または**素集合データ構造**が役立ちます。

```text
find(x)   : xが属する集まりの代表を返す
union(a,b): aとbの集まりを結合する
```

経路圧縮とランク・サイズによる併合を使うと、非常に高速に動きます。

## 21 よくある取り違え

### 21.1 visitedを忘れる

輪のあるグラフで終わらないか、同じ頂点を大量に処理します。

### 21.2 BFSで重み付き距離を求める

辺の本数が少なくても、重みの合計が小さいとは限りません。

### 21.3 ダイクストラ法へ負の辺を渡す

確定済みの距離が後で小さくなり得るため、正しさの根拠が崩れます。

### 21.4 到達不能な∞へ重みを足す

プログラムで∞の代わりに大きな整数を使うと、加算で桁あふれする場合があります。`dist[u]`が未到達でないことを確かめてから足します。

### 21.5 有向辺を両方向へ登録する

一方通行が双方向道路へ変わってしまいます。無向グラフだけ、u→vとv→uの両方を登録します。

### 21.6 最短距離だけ保存して経路を失う

道順も必要なら、更新時に`parent`を保存します。

## 有向非巡回グラフ（DAG: Directed Acyclic Graph）と最小全域木の補足

**有向非巡回グラフ（DAG: Directed Acyclic Graph）**は、向き付きの辺をたどって元へ戻る有向閉路がないグラフです。本文で初出時に略語まで定義し、解答だけで突然使わないようにします。

同じ無向グラフ`AB=1, AC=4, BC=2, BD=5, CD=3`で最小全域木を作ります。クラスカル法は辺を1,2,3,4,5の順に見て、AB、BCを採用し、CDを採用して全頂点を接続します。ACはAとCが既に同じ集合なので閉路を作り不採用です。総重みは`1+2+3=6`です。Union-Findは頂点の属する集合を管理し、両端の根が同じかで閉路を判定します。

プリム法をAから始めると、Aに接する最小AB、接続済み集合から外へ出る最小BC、次にCDを選び、同じ総重み6になります。途中の選択順は違っても、得られる最小総重みは一致します。
