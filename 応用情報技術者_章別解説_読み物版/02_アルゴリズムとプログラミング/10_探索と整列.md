# 第2章・第10話　探索と整列――探す前に並べるべきか、並べず探すべきか


## このファイルで初めて使う用語

本文で使う前に、ここでは次の意味を置きます。略語は正式名、日本語名、本文での役割の順です。

- **整列（ソート）**：値を大小や文字順などに並べ直すこと。（[詳説](<#13 整列の目的>)）
- **主キー**：表の各行を一意に識別する列または列の組。（[詳説](<../06_データベース/03_関係モデルとキー.md#9 主キーと代替キー>)）


名簿から一人を探します。

- 一回だけなら、上から順に見る方が準備なしで済む。
- 何度も探すなら、先に整列する費用を払って二分探索する方がよい場合がある。
- 完全一致だけなら、ハッシュ表を作る選択もある。

アルゴリズムは、一回の速さだけでなく、準備、更新、記憶量、順序の必要性を含めて選びます。

---

## 1 探索問題を定義する

入力は、

- データ列。
- 探したいキー。

です。

出力は、例えば、

- 見つかった位置。
- 見つからないことを示す特別値。
- 該当する全要素。
- 最初または最後の該当位置。

です。

重複キーがあるとき、どれを返すか決めます。

## 2 線形探索

先頭から一つずつ比較します。

```text
関数 linearSearch(a, target)
    for i = 0 から length(a)-1 まで
        もし a[i] == target なら
            iを返す
    -1を返す
```

`-1`は有効添字にないことを利用した「見つからない」の印です。戻り型で有無を分ける方法もあります。

## 3 線形探索の計算量

- 最良：先頭にあり、1回。`O(1)`。
- 最悪：末尾または存在せず、n回。`O(n)`。
- 一様にどこかへあるなら、平均は約`(n+1)/2`回で`O(n)`。

未整列でも使え、リストでも使えます。

## 4 番兵法

配列末尾へ探す値を番兵として一時的に置き、ループ内の範囲検査を減らす方法があります。

```text
末尾へtargetを置く
i=0
while a[i] != target
    i=i+1
元の範囲内なら発見、番兵位置なら不在
```

元の値を退避・復元し、追加枠や変更権限が必要です。現代の最適化処理系では必ず速いとは限りません。正しさと安全性を優先します。

## 5 二分探索の前提

データがキーで昇順に整列済みで、中央位置へ直接アクセスできることが基本です。

```text
[3, 8, 12, 20, 31, 44, 57]
```

31を探します。

1. 中央20。31は大きいので左半分を捨てる。
2. 残り`[31,44,57]`の中央44。31は小さいので右を捨てる。
3. 31と一致。

## 6 二分探索の擬似コード

両端を含む区間`low..high`を使います。

```text
関数 binarySearch(a, target)
    low = 0
    high = length(a)-1

    while low <= high
        mid = low + floor((high-low)/2)

        もし a[mid] == target なら
            midを返す
        そうでなく a[mid] < target なら
            low = mid + 1
        そうでなければ
            high = mid - 1

    -1を返す
```

## 7 中央値計算のオーバフロー

```text
mid = (low+high)/2
```

では、`low+high`が整数上限を越える可能性があります。

```text
mid = low + (high-low)/2
```

なら、範囲内の差を使い、危険を減らせます。

## 8 二分探索の不変条件

各回の先頭で、

```text
targetが配列にあるなら、必ずlowからhighの範囲内にある
```

とします。

中央より小さい・大きい側を、整列済みという前提から安全に捨てます。

更新で`mid`自身を除く`mid+1`、`mid-1`にしないと、範囲が縮まず無限ループになる場合があります。

## 9 二分探索の計算量

候補数を半分ずつにします。

```text
n → n/2 → n/4 → ... → 1
```

回数は約`log₂n`なので`O(log n)`です。

1024要素なら最悪約11回前後の比較で、不在も確認できます。

## 10 最初の一致を探す

重複値があると、普通の二分探索はどれか一つを返します。

```text
[1,2,2,2,3]
```

最初の2が必要なら、一致しても答え候補を保存し、さらに左を探します。

```text
もし a[mid] == target
    answer = mid
    high = mid - 1
```

最後の一致なら右を探します。

## 11 下限位置と挿入位置

`target`以上の最初の位置をlower boundと呼ぶことがあります。

整列を保ったままtargetを挿入する位置や、範囲検索の開始に使えます。

探索は`O(log n)`でも、配列へ実際に挿入するには後ろをずらすので`O(n)`です。

## 12 探索方法を比べる

| 方法 | 前提 | 平均・代表 | 得意 |
|---|---|---:|---|
| 線形探索 | なし | O(n) | 小規模、一回、未整列 |
| 二分探索 | 整列、直接参照 | O(log n) | 順序・範囲、変更少ない |
| ハッシュ | ハッシュ表構築 | 平均O(1) | 完全一致 |
| 平衡木 | 木を維持 | O(log n) | 更新と順序・範囲 |

準備と更新費用も含めます。

## 13 整列の目的

データをキーの昇順・降順へ並べることを整列、ソートと呼びます。

```text
[4,2,3,1] → [1,2,3,4]
```

整列すると、

- 二分探索。
- 重複の発見。
- 範囲抽出。
- 二つの列の併合。
- 順位付け。

がしやすくなります。

## 14 ソートを比べる観点

- 時間計算量：最良・平均・最悪。
- 追加領域。
- 安定性。
- 配列内で行うin-placeか。
- ほぼ整列済みで速いか。
- 外部記憶の大データへ使えるか。
- 並列化しやすいか。

安定ソートは、同じキーの要素の元順を保ちます。

## 15 選択ソート

未整列部分から最小値を探し、先頭と交換します。

```text
[4,2,3,1]
最小1と先頭4を交換 → [1,2,3,4]
残り[2,3,4]の最小2はそのまま
残り[3,4]の最小3はそのまま
```

擬似コードです。

```text
for i = 0 から n-2
    minIndex = i
    for j = i+1 から n-1
        もし a[j] < a[minIndex]
            minIndex = j
    a[i]とa[minIndex]を交換
```

比較回数は、

```text
(n-1)+(n-2)+...+1 = n(n-1)/2
```

で`O(n²)`です。交換回数は最大n-1回と少ないです。普通の交換実装は安定ではありません。

## 16 バブルソート

隣り合う二要素を比べ、逆なら交換します。一巡で最大値が末尾へ「泡のように」移ります。

```text
[4,2,3,1]
4と2交換 [2,4,3,1]
4と3交換 [2,3,4,1]
4と1交換 [2,3,1,4]
```

次の巡回で残りを整列します。

最悪`O(n²)`です。同値では交換しない実装なら安定です。

一巡で交換が一度もなければ既に整列済みなので終了できます。この改良で最良`O(n)`になります。

## 17 挿入ソート

左側を整列済みに保ち、次要素を正しい位置へ挿入します。

```text
[4 | 2,3,1]
2を4の前へ [2,4 | 3,1]
3を2と4の間へ [2,3,4 | 1]
1を先頭へ [1,2,3,4]
```

トランプを手札へ一枚ずつ差す動きです。

最悪`O(n²)`ですが、ほぼ整列済みなら移動が少なく、最良`O(n)`です。同値の後ろへ挿入すれば安定です。

小さな部分配列では、高速なソートの補助にも使われます。

## 18 シェルソート

離れた要素を一定間隔ごとに挿入ソートし、間隔を小さくして最後に1にします。

```text
間隔4 → 間隔2 → 間隔1
```

遠くにある小さい値を早めに前へ動かし、最後の挿入ソートを速くします。

計算量は間隔列に依存します。単純な説明では最悪`O(n²)`となる間隔もあり、実用的な列で改善します。一般には安定ではありません。追加領域は少なくできます。

## 19 併合――整列済み二列を一列へする

```text
A=[2,5,8]
B=[1,4,9]
```

各列の先頭を比べ、小さい方を出力します。

```text
2と1 → 1
2と4 → 2
5と4 → 4
5と9 → 5
8と9 → 8
A終了 → Bの9
結果 [1,2,4,5,8,9]
```

各要素を一度ずつ出すので`O(n+m)`です。

## 20 マージソート

1. 配列を半分へ分ける。
2. 各半分を再帰的に整列する。
3. 二つの整列済み列を併合する。

```text
[4,2,3,1]
→ [4,2] [3,1]
→ [4][2][3][1]
→ [2,4] [1,3]
→ [1,2,3,4]
```

分割段数が`log n`、各段で合計n要素を併合するため、最良・平均・最悪とも`O(n log n)`です。

配列版は通常`O(n)`の補助配列を使います。正しく併合すれば安定です。

## 21 外部マージソート

主記憶へ入り切らない巨大ファイルを整列します。

1. 主記憶へ入る大きさずつ読み、内部で整列して一時ファイルへ書く。これをラン作成と呼ぶ。
2. 複数の整列済みランを順次併合する。

ディスクでは比較回数より、連続読書きと入出力回数が重要です。複数ランを一度に併合する多方向マージを使います。

## 22 クイックソート

基準値pivotを選び、

- pivotより小さい群。
- pivotと等しい群。
- pivotより大きい群。

へ分け、左右を再帰的に整列します。

```text
[4,2,3,1], pivot=3
小 [2,1] | 3 | 大 [4]
小を [1,2]へ
結果 [1,2,3,4]
```

分割が均等なら`O(n log n)`、毎回0個とn-1個へ偏ると`O(n²)`です。

配列内で行う実装は追加領域が少なく、キャッシュ効率もよい傾向があります。一般には安定ではありません。

## 23 pivotの選び方

整列済み配列で毎回先頭をpivotにすると、極端に偏ります。

- ランダムに選ぶ。
- 先頭・中央・末尾の中央値を使う。
- 小さい配列では挿入ソートへ切り替える。

などで実用性能を安定させます。

再帰の深さが大きくなりすぎないよう、片側をループ処理する、深さ上限でヒープソートへ切り替えるイントロソートなどがあります。

## 24 分割処理を追う

左右から走査する方式、末尾pivot方式など複数実装があります。境界条件を混ぜると、要素を飛ばす、無限ループ、pivot重複処理が起きます。

確認する不変条件の例は、

```text
pivot未満の領域 | 未分類領域 | pivot以上の領域
```

が各回で保たれることです。

同値が大量にあるデータでは、三分割が有効です。

## 25 ヒープソート

1. 配列を最大ヒープへ構築する。
2. 根の最大値を末尾と交換する。
3. 整列済み末尾を除き、残りをヒープへ戻す。
4. 繰り返す。

最悪でも`O(n log n)`、追加領域`O(1)`にできます。一般には安定ではありません。

クイックソートより実測定数が大きい場合がありますが、最悪時間の上限が必要な場面で利点があります。

## 26 安定性の具体例

元データを受付順に並べます。

```text
(点数80, アキ先着)
(点数70, イチ)
(点数80, ウメ後着)
```

点数降順へ安定ソートすると、80点の中でアキがウメより先のままです。

複数キーで整列するとき、先に副キー、後に主キーを安定ソートすれば、副キー順を残せます。

## 27 in-placeの意味

入力配列とは別に、入力サイズへ比例する大きな領域を使わず、主に配列内の交換で整列する性質です。

一般的な例では、

- 選択、バブル、挿入、シェル、ヒープ：in-placeにできる。
- 配列のマージソート：O(n)補助領域を使う。
- クイック：配列内分割だが再帰スタックを使う。

です。

「O(1)追加領域」と「再帰スタックも含めて完全に一定」を区別します。

## 28 比較ソートの下限

要素の大小比較だけで任意データを整列する比較ソートは、一般に最悪`Ω(n log n)`回程度の比較が必要です。

選択肢となる`n!`通りの並びを、真偽の比較で区別する決定木の高さが`log₂(n!)`必要だからです。

キーが小さな整数範囲など追加条件があれば、計数ソートや基数ソートで別の計算量を得られます。

## 29 整列済みか検査する

```text
for i = 1 から n-1
    もし a[i-1] > a[i]
        falseを返す
trueを返す
```

`O(n)`です。

整列アルゴリズムのテストでは、

- 昇順になったか。
- 元要素が一個も失われず増えていないか。
- 安定性を約束するなら同値順が保たれたか。

を確認します。

## 30 代表ソートの比較

| 方法 | 最良 | 平均 | 最悪 | 安定性 | 追加領域の代表 |
|---|---:|---:|---:|---|---:|
| 選択 | n² | n² | n² | 通常不安定 | O(1) |
| バブル | n | n² | n² | 安定に可能 | O(1) |
| 挿入 | n | n² | n² | 安定に可能 | O(1) |
| シェル | 間隔依存 | 間隔依存 | 間隔依存 | 不安定 | O(1) |
| マージ | n log n | n log n | n log n | 安定に可能 | O(n) |
| クイック | n log n | n log n | n² | 通常不安定 | 再帰分 |
| ヒープ | n log n | n log n | n log n | 不安定 | O(1) |

表の`n²`などはBig-Oを省略した表記です。

## 31 方法を選ぶ例

### 小さく、ほぼ整列済み

挿入ソートが単純で速い場合があります。

### 安定性が必要で主記憶に入る

マージソートや安定なライブラリソート。

### 追加記憶が厳しく最悪時間も抑える

ヒープソート。

### 一般の配列で平均的な実測速度

改良クイックソートや複合アルゴリズム。

### 巨大ファイル

外部マージソート。

実務では、十分に検証・最適化された標準ライブラリを使い、必要な安定性と比較関数を指定します。

## 32 比較関数の危険

ソートへ渡す比較規則は、

- `a<a`は偽。
- a<bかつb<cならa<c。
- aとbが同等なら、両方向で矛盾しない。

など一貫した順序を作る必要があります。

比較中に値を変更したり、時刻や乱数で結果を変えたりすると、ソートが正しく動きません。

浮動小数点のNaNや、NULLをどこへ置くかも決めます。

## 比較回数の和と下界を導く

```text
S=(n-1)+(n-2)+…+2+1
S=1+2+…+(n-2)+(n-1)
2S=n+n+…+n  （n-1組）
S=n(n-1)/2
```

`n=4`なら`3+2+1=6`、式も`4×3/2=6`です。

比較ソートは、n個の異なる値の`n!`通りの順列を、比較結果「小さい／大きい」の二分岐で区別します。n=3なら6通りなので、二分木の葉が6枚必要で高さは少なくとも`ceil(log₂6)=3`です。一般に高さは`Ω(log₂(n!))`で、`log₂(n!)=log₂1+…+log₂n`は`Ω(n log n)`になります。`Ω`は漸近的な下界を表します。


## 応用情報技術者試験での扱われ方

- **典型設問:** 「線形探索の最良・最悪計算量を答えてください。」
- **条件語:** `整列（ソート）`を本文の定義と対応させます。
- **最初の着眼点:** 求める量と単位を先に書き、問題文の数値を同じ単位へそろえます。
- **途中の組立て・式:** 既知量→使用する関係式→代入→単位付き結果の順に進めます。 本文の `-1` を使います。記号、単位、成立条件を置いてから代入し、結果の意味まで答えます。
- **典型誤答と理由:** 途中式を飛ばすと、切上げ・分母・時間換算・2進/10進接頭辞のどこで値が変わったか検算できません。

## 解答と考え方

1. **解法の入口:** 求める量と単位を先に書き、問題文の数値を同じ単位へそろえます。 問題は「線形探索の最良・最悪計算量を答えてください。」です。
   **途中手順:** 既知量→使用する関係式→代入→単位付き結果の順に進めます。 結果は「最良O1、最悪Onです。」と照合します。
   **結論:** 最良O(1)、最悪O(n)です。
   **この誤答が起きる理由:** 途中式を飛ばすと、切上げ・分母・時間換算・2進/10進接頭辞のどこで値が変わったか検算できません。
