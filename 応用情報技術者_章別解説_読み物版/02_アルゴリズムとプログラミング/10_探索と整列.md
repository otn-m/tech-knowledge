# 第2章・第10話　探索と整列――探す前に並べるべきか、並べず探すべきか

整列済みの列を二分探索すると、比較のたびに探索候補を半分へ絞り込めます。
ただしその速さは、探索するキーの順にデータが整列済みという前提に支えられた設計です。
一度だけ値を探す列をわざわざ並べ替えると、探索そのものより整列の所要時間が大きくなりかねません。
そのため探索と整列の手法は、1回の操作の速さだけでなく、事前の準備やデータ更新にかかる費用まで含めて選ぶ必要があります。

## 探索で返す値と前提を決める

### 1 探索問題を定義する

探索の入力は、データ列と探したいキーです。
出力には、目的に応じて次のような値を用います。

- 見つかった位置の添字
- 見つからない事実を示す特別値
- 条件に合致する全要素の集合
- 最初または最後の一致位置

重複するキーが存在するときは、どの位置の要素を返すかをあらかじめ取り決めておく設計が求められます。

### 2 線形探索

線形探索は、配列の先頭から末尾に向かって要素を1つずつ順番に比較する手法です。

```text
関数 linearSearch(a, target)
    for i = 0 から length(a)-1 まで
        もし a[i] == target なら
            iを返す
    -1を返す
```

`-1`は有効添字の範囲外であることを利用した、未検出を表す目印です。
言語によっては、戻り値の型としてオプショナル型を用いて有無を区別する実装も見られます。

### 3 線形探索の計算量

- 最良――先頭に見つかる場合で1回。計算量は`O(1)`です。
- 最悪――末尾に存在するか不在の場合でn回。計算量は`O(n)`です。
- 平均――一様に散らばっているなら約`(n+1)/2`回の比較となり、計算量は`O(n)`です。

この手法は要素が未整列のままでも適用でき、配列だけでなく連結リストでもそのまま利用可能です。

### 4 番兵法

ループ内の範囲終了判定を省略する工夫として、配列の末尾に探索対象の値を番兵として一時配置する手法が知られています。

```text
末尾へtargetを置く
i=0
while a[i] != target
    i=i+1
元の範囲内なら発見、番兵位置なら不在
```

ただし番兵を配置するには、元の値を退避・復元する処理や配列末尾の空き領域、配列への書き込み権限が欠かせません。
近年の最適化コンパイラのもとでは、番兵を置いても実行速度が向上するとは限らないのが実情です。
そのため現代の設計では、特殊な番兵を用いるよりも、境界検査を含む安全で明快なコードを優先する方針が一般的です。

## 候補の半分を安全に除く

### 5 二分探索の前提

二分探索は、データがキーの昇順に並んでおり、中央の位置へ即座にアクセスできる配列構造を前提とします。

```text
[3, 8, 12, 20, 31, 44, 57]
```

値31を探す手順を追ってみましょう。

1. 中央の値20と比較します。探す値31のほうが大きいため、中央を含む左半分を候補から除外します。
2. 残った`[31, 44, 57]`の中央値44と比較します。31のほうが小さいため、中央を含む右半分を除外します。
3. 最後に残った中央の値31と一致し、探索が完了します。

### 6 二分探索の擬似コード

中央の値と一致しなかった場合、その中央位置の要素自身は次の探索候補から外すのが鉄則です。
この1要素を候補から確実に除外しないと探索区間が縮まらず、探索対象が存在しない状況でループが終了しなくなります。
探索範囲の管理には、両端の添字を含む閉区間`low..high`を保持する設計が一般的です。

```text
関数 binarySearch(a, target)
    low = 0
    high = length(a)-1

    while low <= high
        mid = low + floor((high-low)/2)

        もし a[mid] == target なら
            midを返す
        そうでなく a[mid] < target なら
            low = mid + 1
        そうでなければ
            high = mid - 1

    -1を返す
```

### 7 中央値計算のオーバフロー

中央の添字を求める際に次の式を用いると、`low + high`の加算結果が整数型の上限値を超えてオーバフローを引き起こす恐れがあります。

```text
mid = (low+high)/2
```

安全に中央を計算するには、幅の差分を加える次の式を用いるのが確実です。

```text
mid = low + (high-low)/2
```

### 8 二分探索の不変条件

各ループの先頭では、アルゴリズムの正しさを保証する次の性質が常に維持されている点を確認します。

```text
targetが配列にあるなら、必ずlowからhighの範囲内にある
```

配列が昇順に整列している前提があるからこそ、中央と比較した片側の領域を安全に切り捨てることが可能です。
探索範囲を更新する際に`mid`を除外して`mid + 1`や`mid - 1`へ移動させないと、候補数が減らず処理が停止しなくなる事態を招くため、境界値の操作には細心の注意が欠かせません。

### 9 二分探索の計算量

二分探索では、1回の比較ごとに探索候補の要素数が半分に減少します。

```text
n → n/2 → n/4 → ... → 1
```

候補が1個に絞り込まれるまでの縮小回数は約`log₂n`回となるため、全体の計算量は`O(log n)`です。
例えば1,024要素の配列であっても、最悪11回前後の比較を行うだけで目的の値の有無を確定できます。

## 重複と挿入位置を扱う

### 10 最初の一致を探す

配列内に同じキーが複数存在する場合、標準的な二分探索はいずれか1つの添字を見つけた時点で終了するのが通常の挙動です。

```text
[1, 2, 2, 2, 3]
```

最も左側にある値2の位置を特定したいときは、一致を確認したあとも暫定位置を保持したまま、さらに左側の区間へ探索を継続します。

```text
もし a[mid] == target
    answer = mid
    high = mid - 1
```

逆に最も右側の位置を求めたいケースでは、一致確認後に右側区間を絞り込む形を取るのが自然です。

### 11 下限位置と挿入位置

指定したキー以上となる最小の位置を求める操作は、lower bound（下限探索）と呼ばれます。
この探索結果は、配列の整列順を崩さずに新しい要素を挿入すべき位置の決定や、一定範囲の要素を取り出す範囲検索の基点として活用できます。
ただし探索自体が`O(log n)`で済むとしても、配列へ要素を実際に挿入する操作は後続要素のシフトを伴うため、`O(n)`の移動時間がかかる点に留意が必要です。

### 12 探索方法を比べる

| 方法 | 前提 | 平均・代表 | 得意な場面 |
|---|---|---:|---|
| 線形探索 | なし | O(n) | 小規模、1回のみの探索、未整列データ |
| 二分探索 | 整列済み、直接参照 | O(log n) | 順序・範囲検索、更新頻度が低い配列 |
| ハッシュ表 | ハッシュ表の構築 | 平均O(1) | キーによる完全一致検索 |
| 平衡二分探索木 | 木構造の維持 | O(log n) | 頻繁な挿入・削除と順序・範囲検索の両立 |

探索手法を選定する際は、1回の探索コストだけでなく、データ構造の構築や更新に要する総費用まで見極める視点が欠かせません。

## 整列の目的と比較の基準

### 13 整列の目的

データをキーの昇順や降順に並び替える操作が、整列（ソート）です。

```text
[4, 2, 3, 1] → [1, 2, 3, 4]
```

あらかじめ整列を済ませておくと、次のような各種処理を効率よく実行できるようになります。

- 二分探索の適用
- 重複要素の検出
- 指定範囲の要素抽出
- 2つの整列済み列の併合
- 順位付けの集計

### 14 ソートを比べる観点

整列アルゴリズムの得失を評価する観点は多岐にわたるものです。

- 時間計算量（最良・平均・最悪の各局面）
- 処理に必要な追加の記憶領域
- 同一キーの順序を保つ安定性
- 入力配列の内部だけで整列を完結できるか（in-place）
- ほぼ整列済みの入力に対して高速に動作するか
- 主記憶に収まらない大規模データに対応できるか
- 複数プロセッサによる並列化が容易か

特に安定ソートは、キーの値が同一である複数要素について、並び替え前の相対的な前後関係をそのまま維持する性質を指します。

## 要素を選び交換し挿入する

### 15 選択ソート

未整列部分から最小値を探し出し、先頭の要素と交換する処理を繰り返します。

```text
[4, 2, 3, 1]
最小1と先頭4を交換 → [1, 2, 3, 4]
残り[2, 3, 4]の最小2はそのまま
残り[3, 4]の最小3はそのまま
```

アルゴリズムの擬似コードは次の通りです。

```text
for i = 0 から n-2
    minIndex = i
    for j = i+1 から n-1
        もし a[j] < a[minIndex]
            minIndex = j
    a[i]とa[minIndex]を交換
```

最小値を探す比較回数は、未整列部分が1つ縮小するごとに1回ずつ減少します。
比較の合計回数は次の式で表され、時間計算量は`O(n²)`です。

```text
(n-1)+(n-2)+...+1 = n(n-1)/2
```

交換回数は最大でも`n - 1`回と少ない水準に留まります。
ただし離れた要素同士を入れ替えるため、標準的な実装では安定性が保たれません。

#### 比較回数の和の導出

```text
S=(n-1)+(n-2)+…+2+1
S=1+2+…+(n-2)+(n-1)
2S=n+n+…+n  （n-1組）
S=n(n-1)/2
```

`n = 4`の場合であれば`3 + 2 + 1 = 6`となり、計算式`4 × 3 / 2 = 6`とも整合します。

### 16 バブルソート

バブルソートは、隣接する2要素を比較して順序が逆であれば交換する処理を繰り返す手法です。
一巡の走査を行うごとに、未整列領域の最大値が泡のように末尾へと運ばれていきます。
この走査を残りの未整列領域に対して順次適用していく設計です。

```text
[4, 2, 3, 1]
4と2を交換 [2, 4, 3, 1]
4と3を交換 [2, 3, 4, 1]
4と1を交換 [2, 3, 1, 4]
```

時間計算量は最悪の場合で`O(n²)`に達します。
同値の要素同士を交換しない実装にすれば、元の順序関係を壊さない安定ソートとして動作します。
さらに、一巡の走査で交換が一度も生じなければ整列済みと判断して処理を打ち切る改良が可能です。
この判定を導入すると、すでに並んでいるデータに対して最良`O(n)`の計算量で素早く処理を完了できます。

### 17 挿入ソート

配列の左側を整列済み領域として維持し、未整列領域の要素を適切な位置へ順次挿入していく手法です。

```text
[4 | 2, 3, 1]
2を4の前へ [2, 4 | 3, 1]
3を2と4の間へ [2, 3, 4 | 1]
1を先頭へ [1, 2, 3, 4]
```

これは配られたトランプのカードを手札へ順番に差し込んで並べる動作に相当します。

最悪の時間計算量は`O(n²)`に達するものの、データがほぼ整列している状態であれば要素の移動が極めて少なく、最良`O(n)`で軽快に完了します。
同値の要素が見つかった場合はその直後へ挿入する規則を守ることで、安定性を容易に担保できる設計です。
要素数が少ない小さな部分配列に対してはオーバヘッドが小さいため、後述する高度なソートアルゴリズムの仕上げ処理としても頻繁に併用されます。

### 18 シェルソート

シェルソートは、ある程度離れた位置にある要素同士を一定の間隔ごとに取り出して挿入ソートを行い、その間隔を段階的に狭めて最終的に間隔1の挿入ソートへ持ち込む手法です。

```text
間隔4 → 間隔2 → 間隔1
```

遠方に存在する小さな値をあらかじめ前方へと大きく移動させておくことで、仕上げとなる間隔1の挿入ソートにかかる移動回数を大幅に削減します。

計算量は採用する間隔列の選び方に大きく左右される性質を持ちます。
単純な間隔設定では最悪`O(n²)`にとどまる構成も見られますが、工夫された間隔列を用いることで計算量を実用的な水準へ改善することが可能です。
離れた位置との間で要素を飛び越えて交換するため、一般に安定ソートの性質は保たれません。
一方で、入力配列内で処理が完結するため追加領域はごくわずかで済む利点を備えています。

## 分割した列を整列する

### 19 併合――整列済み二列を一列へまとめる

```text
A=[2, 5, 8]
B=[1, 4, 9]
```

各列の先頭要素同士を比較し、小さい方の要素を順次出力配列へと取り出していく手順です。

```text
2と1を比較 → 1を出力
2と4を比較 → 2を出力
5と4を比較 → 4を出力
5と9を比較 → 5を出力
8と9を比較 → 8を出力
列Aが終了 → 列Bの9を出力
結果 [1, 2, 4, 5, 8, 9]
```

各要素を高々1回ずつ取り出す走査となるため、併合にかかる計算量は要素数の和である`O(n + m)`で済みます。

### 20 マージソート

マージソートは、配列の二分割、部分配列の再帰的な整列、そして整列済み配列同士の併合を繰り返す分割統治法に基づくアルゴリズムです。

1. 配列を中央で2つに二分割する。
2. 分割した各部分配列に対して再帰的にマージソートを適用する。
3. 整列を終えた2つの部分配列を1つに併合する。

```text
[4, 2, 3, 1]
→ [4, 2] [3, 1]
→ [4] [2] [3] [1]
→ [2, 4] [1, 3]
→ [1, 2, 3, 4]
```

分割の深さは常に`log n`段となり、各段で合計n個の要素を併合するため、最良・平均・最悪のいずれの状況でも計算量は`O(n log n)`を維持します。
配列を対象とする標準的な実装では、併合処理の作業領域として`O(n)`の補助配列が必要です。
同値の要素を比較する際に左側の要素を優先して出力すれば、安定ソートとしての要件を満たせます。

### 21 外部マージソート

主記憶（メインメモリ）に収まりきらない巨大なファイルを外部ストレージ上で整列する用途には、外部マージソートが有力な選択肢です。

1. 主記憶に収まるサイズごとにデータを読み込み、内部ソートを行って整列済みの小ファイルとして書き出します。これをランの作成と呼びます。
2. 出来上がった複数の整列済みランを順次併合していきます。

外部ストレージを扱う処理では、CPUによる比較回数よりもストレージの連続アクセス効率や入出力回数が性能を決定づけます。
そのため、多数のランを1度にまとめて併合する多方向マージ（k-wayマージ）を活用するのが定石です。

### 22 クイックソート

クイックソートは、基準値となる要素（ピボット）を1つ定め、全体のデータを基準値未満、基準値と同値、基準値超過の各領域へ振り分ける分割統治アルゴリズムです。

ピボットより小さいグループと大きいグループのそれぞれに対して、再帰的に同じ整列処理を適用していきます。

```text
[4, 2, 3, 1], pivot = 3
小さい群 [2, 1] | 基準 3 | 大きい群 [4]
小さい群を整列して [1, 2] へ
結果 [1, 2, 3, 4]
```

ピボットによってデータが均等に二分されれば計算量は`O(n log n)`に収まりますが、毎回0個と`n - 1`個のように極端に偏る最悪ケースでは`O(n²)`に劣化します。
配列内で要素を交換するインプレース実装であれば余分な記憶領域をほとんど消費せず、局所的なメモリアクセスによってCPUキャッシュを効率よく活用できるのが強みです。
ただし離れた要素同士を交換する手順を含むため、一般的な実装では安定ソートになりません。

### 23 ピボットの選び方

すでに整列している配列に対して毎回先頭の要素をピボットに選んでしまうと、分割が最悪の偏りを示して性能が著しく低下します。
こうした極端な偏りを防ぐ手法として、次のような対策が実践されています。

- 範囲内から乱数でピボットを抽出する
- 先頭・中央・末尾の3要素から中央値を求めてピボットとする
- 要素数が一定以下に縮小した段階で挿入ソートへ切り替える

こうした多様な工夫を取り入れることで、実用環境におけるクイックソートの処理性能を安定した水準に保つ設計が主流です。
さらに再帰呼び出しの深さが過大になる事態を避けるため、片側の部分配列をループ構造で処理したり、再帰の深さ上限に達した時点でヒープソートへ切り替えたりするイントロソートなどの発展的な手法も広く採用されています。

### 24 分割処理を追う

配列を左右から走査する方式や末尾の要素をピボットとする方式など、分割には複数の実装形態が存在します。
ループの境界条件を誤ると、要素の処理漏れや無限ループ、あるいはピボットの重複処理といった不具合を招きかねません。

例えば走査の各段階において、次の領域区分が常に維持されているかをループ不変条件として点検します。

```text
pivot未満の領域 | 未分類領域 | pivot以上の領域
```

同じキーを持つ要素が大量に含まれるデータに対しては、未満・同値・超過の3つに明確に分ける三分割方式が有効なアプローチとなります。

### 25 ヒープソート

1. 対象配列全体を最大ヒープ構造へと再構成する。
2. 根に位置する最大値を取り出し、未整列領域の末尾要素と交換する。
3. 整列済みとなった末尾を除外し、残りの領域でヒープ条件を復元する。
4. この交換と復元を要素がなくなるまで反復する。

ヒープソートは最悪ケースであっても計算量`O(n log n)`を保証し、追加領域も`O(1)`で完結させることが可能です。
要素の親子関係を飛び越えて交換を行うため、一般的な実装は安定ソートになりません。
平均的な実行速度ではクイックソートの実測定数に及ばない場面も見られますが、最悪実行時間の上限を厳密に保証したい安全重視のシステムにおいて大きな価値を発揮します。

## 順序と記憶量の条件を確かめる

### 26 安定性の具体例

安定ソートでは、同一キーを持つ要素同士の入力時点での相対順序がそのまま保存されます。
具体例として、受付順に登録された次のデータを点数の降順で安定ソートする場面を考えてみましょう。

```text
(点数80, アキ先着)
(点数70, イチ)
(点数80, ウメ後着)
```

点数の降順で安定ソートを施した場合、同点である80点のデータにおいて、先着のアキが後着のウメよりも前方に並ぶ関係性が崩れません。
この安定性を利用すると、複数キーによる複合整列を行う際に、まず優先度の低い副キーで整列した後に優先度の高い主キーで安定ソートをかけることで、副キーの並び順を壊さずに多段整列を完了できます。

### 27 in-placeの意味

入力データ配列とは別に、入力サイズに比例するような大きな追加記憶領域を確保せず、元の配列内の要素交換を主体として整列を完了する性質のことです。

代表的な整列手法が要求する追加領域には、次のような差異が存在します。

- 選択、バブル、挿入、シェル、ヒープ――インプレースとして実装可能
- 配列版マージソート――`O(n)`の補助配列領域を要求
- クイックソート――配列内交換だが再帰呼び出しに応じたスタック領域を消費

アルゴリズムを評価する際は、単純なデータ格納領域としての「`O(1)`追加領域」と、関数の呼び出しスタックまで含めた「完全に一定の作業領域」とを厳密に区別して捉える視点が大切です。

### 28 比較ソートの下限

要素同士の大小比較のみを手がかりとして順序を決定する一般的な整列アルゴリズムでは、最悪ケースにおける比較回数の下限が`Ω(n log n)`となることが数学的に証明されています。

異なるn個の要素からなる並び順は全部で`n!`通り存在し、1回の真偽比較で得られる二分岐によってこれらの候補を完全に区別するためには、決定木の高さとして少なくとも`log₂(n!)`の深さが必要となるためです。

もし要素の値が小さな整数値の範囲に収まっているなど特定の前提条件が満たされる場合には、計数ソートや基数ソートのように要素比較を伴わないアルゴリズムを用いることで、より小さな計算量を達成できる道も開かれています。

比較ソートの枠組みでは、相異なるn個の値が取り得る`n!`通りの順列を、大小比較という二分岐の決定木によって1つに特定していきます。
例えば`n = 3`であれば順列は6通りとなるため、決定木には少なくとも6枚の葉が求められ、その高さは`ceil(log₂6) = 3`以上に達する計算です。
一般のnに対して必要な木の高さは`Ω(log₂(n!))`であり、対数の和`log₂(n!) = log₂1 + … + log₂n`を評価することで`Ω(n log n)`の下界が導出されます。
なお、ここで用いられる記号`Ω`は計算量の漸近的な下界を指し示す表記法です。

## 結果を検証して方法を選ぶ

### 29 整列済みか検査する

配列が正しく昇順に並んでいるかを確認する走査は、隣接要素を順次比較することで`O(n)`の計算量で実現できます。

```text
for i = 1 から n-1
    もし a[i-1] > a[i]
        falseを返す
trueを返す
```

整列処理の正当性を自動テストなどで検証する際には、次の3つの要件を漏れなく確認する姿勢が求められます。

- 全要素が昇順の規則を満たしているか
- 元の要素が欠落したり余分に追加されたりせず完全に維持されているか
- 安定ソートを謳う場合、同値要素の相対的な初期順序が保持されているか

### 30 代表ソートの比較

| 方法 | 最良 | 平均 | 最悪 | 安定性 | 追加領域の代表 |
|---|---:|---:|---:|---|---:|
| 選択ソート | n² | n² | n² | 通常不安定 | O(1) |
| バブルソート | n | n² | n² | 安定に実装可能 | O(1) |
| 挿入ソート | n | n² | n² | 安定に実装可能 | O(1) |
| シェルソート | 間隔依存 | 間隔依存 | 間隔依存 | 不安定 | O(1) |
| マージソート | n log n | n log n | n log n | 安定に実装可能 | O(n) |
| クイックソート | n log n | n log n | n² | 通常不安定 | 再帰スタック分 |
| ヒープソート | n log n | n log n | n log n | 不安定 | O(1) |

表中の`n²`や`n log n`といった表記は、Big-O記法における主要項を簡潔に示したものです。

### 31 実務における選定の指針

#### 小規模でほぼ整列済みのデータ
挿入ソートが極めて軽量であり、最良の選択肢となる場合があります。

#### 安定性が必須で全データが主記憶に収まる場合
マージソートや言語処理系の安定ソートライブラリを採用するのが確実です。

#### 追加メモリの制約が厳しく最悪時間を抑えたい環境
最悪でも`O(n log n)`が保証されインプレースで完結するヒープソートが強みを発揮します。

#### 一般的な配列に対する平均実行速度を最優先する場合
最適化されたクイックソートや、複数アルゴリズムを組み合わせたハイブリッドソートが有力です。

#### 主記憶を超過する巨大ファイルを整列する場合
ディスクや外部ストレージへの分割アクセスを前提とした外部マージソートを選択します。

実務の開発現場では、十分に検証と最適化が行われた標準ライブラリのソート関数を活用し、要求仕様に応じた比較関数や安定性の有無を正しく指定するのが基本方針です。

### 32 比較関数の設計上の注意

ソート関数に渡す比較述語（比較関数）は、数学的に一貫した狭義の弱順序（Strict Weak Ordering）を満たす設計が必須です。

- 自己比較の偽判定：すべての要素aに対して`a < a`は常に偽
- 推移律：`a < b`かつ`b < c`であれば必ず`a < c`
- 同等の対称性：aとbが等しいと判定される関係において矛盾を生じさせない

ソートの実行途中に比較対象のオブジェクトの内部状態を書き換えたり、比較処理の中で現在時刻や乱数などの非決定的な要素を参照したりすると、アルゴリズムの前提が崩壊して異常終了や無限ループの原因となります。
また、浮動小数点数の非数（NaN）やデータベース由来のNULL値といった特殊なデータを先頭と末尾のどちらに寄せるかについても、あらかじめ厳密な順序規則を定めておく配慮が欠かせません。

整列済みの7要素から値31を探し出す二分探索では、1回の比較ごとに候補領域を半分ずつ安全に削ぎ落とせます。
しかしその高速性を享受するためには事前の整列処理に一定の計算コストが伴い、要素の挿入や削除が発生するたびに順序構造を維持し続ける運用費用も発生します。
システム全体の処理効率を高めるためには、探索を行う頻度とデータを更新する頻度の比率を冷静に見積もったうえで、実行時間、所要メモリ、安定性の要求条件を満たす最適なアルゴリズムを選択する判断が肝要です。
