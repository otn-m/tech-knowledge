# 第2章・第2話　データ型と式――同じ0と1でも、整数・文字・日付では意味が違う

コンピュータの中では、値は最終的にビット列として保存されます。しかし、プログラムはすべてを「ただの0と1」として扱いません。

```text
20 + 5        → 数の加算なら25
"20" + "5"  → 文字列の連結なら"205"
```

同じように見える記号でも、値の種類によって意味が変わります。

値の種類、表現範囲、許される操作をまとめた規則をデータ型、短く型と呼びます。

---

## 1 型が必要な理由

型には三つの役割があります。

1. **保存方法を決める**
   - 何ビット使うか。
   - 符号や小数をどう表すか。
2. **許される操作を決める**
   - 数なら加算、文字列なら連結など。
3. **意味の取り違えを見つける**
   - 日付へ人数を足すなど、不自然な操作をエラーにする。

型は単なる記憶域の箱サイズではありません。「これは円」「これは利用者ID」という業務上の意味も表せます。

## 2 整数型

小数部分を持たない数を扱います。

```text
-3, 0, 42, 1000000
```

ビット数と符号の有無で範囲が決まります。

八ビットなら、

- 符号なし：0から255。
- 二の補数の符号付き：-128から127。

です。

範囲を越えるとオーバフローします。言語により、

- エラーにする。
- 下位ビットだけ残して回り込む。
- 自動的に大きな整数へ広げる。

などが違います。

## 3 実数型――コンピュータでは多くが浮動小数点

小数を含む値を扱います。

```text
3.14
-0.25
1.0e6
```

多くの言語の実数型は、IEEE 754の単精度・倍精度などの二進浮動小数点です。

```text
単精度  主に32ビット
倍精度  主に64ビット
```

倍精度は、単精度より広い範囲と多い有効桁を持ちますが、どちらも有限です。

0.1のように正確に表せない値があり、丸め、桁落ち、オーバフロー、アンダーフローがあります。

## 4 十進型と固定小数点型

金額のように十進の桁を正確に扱いたい場合、十進型や固定小数点型を使います。

```text
12.34円を、小数点以下2桁の固定小数として持つ
内部では1234という整数に近い形で持つ
```

それでも、

- 端数をいつ丸めるか。
- 切上げ、切捨て、四捨五入のどれか。
- 消費税を商品ごとか合計後に掛けるか。

は業務仕様として決める必要があります。

## 5 論理型

真と偽の二値を扱います。

```text
true
false
```

比較式の結果です。

```text
age >= 18  → trueまたはfalse
```

0を偽、0以外を真として扱える言語もありますが、数値と論理を混ぜると意図が分かりにくくなります。

データベースではNULLを含む三値論理を使うことがあり、普通の真偽と違います。

## 6 文字型と文字列型

### 文字型

一つの文字や符号単位を扱う型です。

```text
'A'
'あ'
```

ただし、言語の文字型が、Unicodeコードポイント一個、人が見る一文字、UTF-16符号単位一個のどれかは確認が必要です。

### 文字列型

文字の並びを扱います。

```text
"こんにちは"
"A12"
""
```

`""`は長さ0の空文字列です。値が存在しないNULLとは違います。

## 7 NULL――値がない、または分からない

NULLは、値そのものがないことを表す特別な状態として使われます。

```text
空文字列 ""   文字列は存在し、文字数0
数値0          数値は存在し、値が0
NULL           値がない、未設定、不明など
```

NULLが何を意味するかは設計で決めます。

- まだ入力されていない。
- 対象外である。
- 分からない。
- 意図的に削除した。

複数の意味を一つのNULLへ詰めると、後で区別できません。

NULLへ普通の演算をするとNULLが広がる言語や、エラーになる言語があります。

## 8 列挙型

許された値を名前付きで列挙します。

```text
OrderStatus = {受付, 支払済, 発送済, 取消}
```

単なる整数0、1、2、3より、意味が分かり、許されない状態を防ぎやすくなります。

ただし、新しい状態を追加したとき、すべての分岐が対応しているか確認します。

## 9 配列型と構造型

### 配列型

同じ型の値を、番号付きで複数持ちます。

```text
scores = [70, 85, 90]
```

### 構造型

異なる意味・型の項目を一つにまとめます。レコード、構造体などと呼びます。

```text
Student
  id: 整数
  name: 文字列
  score: 整数
```

「配列は同じ種類を番号で」「構造は異なる役割を名前で」まとめるのが基本です。

## 10 抽象データ型

内部の保存方法ではなく、利用者から見える値と操作で型を定めます。

スタックなら、

- 空のスタックを作る。
- pushで上へ積む。
- popで上から取り出す。
- topで一番上を見る。
- 空か調べる。

という操作を定めます。

内部を配列で作るか連結リストで作るかは、利用者へ隠せます。このような「何ができるか」と「どう作るか」の分離が抽象化です。

## 11 静的型付けと動的型付け

### 静的型付け

変数や式の型の多くを、実行前に検査します。

```text
整数 total
total = "abc"  → 実行前に型誤り
```

早く誤りを見つけ、最適化しやすい利点があります。

### 動的型付け

実行中の値が型を持ち、操作時に検査します。

```text
x = 10
x = "abc"
```

柔軟に書けますが、特定経路を実行したとき初めて型誤りが見つかることがあります。

静的か動的かだけで、安全性や品質は決まりません。型システム、テスト、設計、道具を合わせて考えます。

## 12 型推論

明示的に型名を書かなくても、初期値や使われ方から処理系が型を決めることを型推論と呼びます。

```text
x = 3
```

から、`x`を整数だと推論します。

型を書かないことと、型が存在しないことは違います。

## 13 暗黙の型変換

処理系が自動で型を変えることがあります。

```text
整数3 + 実数0.5
→ 整数3を実数3.0へ変換
→ 3.5
```

便利ですが、意図しない変換もあります。

```text
"10" + 2
```

が`"102"`になるか、12になるか、エラーかは言語によります。

暗黙変換を前提にせず、重要な境界では型を明確にします。

## 14 明示的な型変換

人が変換を指定することをキャスト、型変換と呼びます。

```text
整数へ変換("123") → 123
文字列へ変換(123) → "123"
```

入力`"12x"`を整数へできない場合を処理します。

```text
変換できたか
範囲内か
余分な文字はないか
単位は正しいか
```

を確認します。

## 15 狭い型へ変えると情報を失う

```text
実数3.9 → 整数3
```

のように小数を捨てる場合があります。四捨五入とは限りません。

```text
大きな整数1000 → 八ビット整数
```

では範囲を越えます。

```text
倍精度 → 単精度
```

では有効桁を失うことがあります。

変換前に範囲を確認し、丸め規則を指定します。

## 16 整数除算

整数どうしの除算で、小数を捨てる言語があります。

```text
5 / 2 → 2
```

実数として割れば、

```text
5.0 / 2.0 → 2.5
```

です。

平均を求めるとき、合計も件数も整数だと、端数が失われることがあります。

```text
average = real(total) / count
```

のように、意図的に実数へします。

負の整数除算で、0方向へ切り捨てるか、負の無限大方向へ床を取るかは言語により違います。

## 17 演算のオーバロード

同じ記号や関数名が、型によって違う操作を行うことがあります。

```text
2 + 3          → 整数加算
2.0 + 3.0      → 浮動小数点加算
"a" + "b"    → 文字列連結
```

これをオーバロードと呼びます。

関数名が同じで、引数の個数や型が違う複数定義を選ぶこともオーバロードです。

後で学ぶオーバーライドは、子クラスが親クラスの操作を置き換えることで、別の概念です。

## 18 評価順序と短絡評価

ANDでは、左が偽なら、右を見なくても全体が偽です。ORでは、左が真なら、右を見なくても全体が真です。

右側を評価しないことを短絡評価と呼びます。

```text
x != 0 AND 10/x > 2
```

`x=0`のとき、左が偽なので右の0除算を行わずに済みます。

ただし、右側に関数呼出しなどの副作用があると、「実行されると思った処理が行われない」ことがあります。条件式へ不要な副作用を入れません。

## 19 参照型と値型という見方

値そのものを変数に持つ型と、別の場所にある対象への参照を持つ型を区別する言語があります。

```text
a = [1,2]
b = a
bへ3を追加
```

`a`と`b`が同じ配列を参照しているなら、`a`から見ても`[1,2,3]`になります。

値を複製したと思っていたのに同じ対象を共有していると、思わぬ変更が伝わります。

```text
同じ対象を共有する代入か
中身を複製するコピーか
入れ子の中まで複製するか
```

を確認します。

## 20 等価性――同じ対象か、同じ内容か

二つの比較があります。

- 同一性：まったく同じ一個の対象を参照しているか。
- 値の等価性：中身の値が同じか。

別々に作った二つの`[1,2]`は、中身は同じでも、別の対象です。

言語の`==`がどちらを比べるかは型によって違う場合があります。

## 21 型を設計するときの問い

1. 取り得る最小値と最大値は何か。
2. 小数は必要か。十進で正確に扱う必要があるか。
3. 値がない状態は必要か。何種類の理由があるか。
4. 単位や通貨を区別すべきか。
5. 変更可能か、不変にするか。
6. 外部入力をどう検証するか。
7. 保存・通信時の形式は何か。
8. 将来、新しい状態を追加するか。

単に「一番大きい型」を使えばよいとは限りません。意味、性能、保存形式、他システムとの互換性を考えます。

## 8ビット整数と継承を最初から導く

8ビット列は各桁2通りなので`2⁸=256`通りです。符号なしは`00000000₂=0`から`11111111₂=255`です。二の補数の符号付き整数では、先頭0側が0〜127、先頭1側が−128〜−1を表すため範囲は−128〜127です。最小列`10000000₂=-128`、最大列`01111111₂=127`です。

**クラス**は同種オブジェクトのデータと操作を定める設計図です。親クラス`Animal`の操作`speak()`を子クラス`Dog`が引き継ぎ、Dog向け実装へ置き換えるのがオーバーライドです。

```text
Animal
  └─ Dog: speak()を「ワン」と実装
```


## 22 確認問題

1. 型の三つの役割を説明してください。
2. 八ビット符号なし整数と符号付き整数の範囲を答えてください。
3. 単精度と倍精度の違いを説明してください。
4. 金額に二進浮動小数点でなく、十進型や最小単位整数を使う理由を説明してください。
5. 論理型はどのような値を持ちますか。
6. 空文字列、数値0、NULLを区別してください。
7. 列挙型を使う利点を説明してください。
8. 配列型と構造型の違いを説明してください。
9. 抽象データ型は、内部実装ではなく何で定義しますか。
10. 静的型付けと動的型付けの違いを説明してください。
11. 型推論とは何ですか。
12. 暗黙変換が危険な例を一つ挙げてください。
13. `3.9`を整数へ変換するとき、何を確認しますか。
14. 整数`5/2`が2になる環境で、2.5を得るにはどうしますか。
15. オーバロードとオーバーライドを区別してください。
16. 短絡評価により、`x!=0 AND 10/x>2`が安全になる理由を説明してください。
17. `a`と`b`が同じ配列を参照するとき、bの変更がaから見える理由を説明してください。
18. 同一性と値の等価性の違いを説明してください。
19. 温度を整数型へする前に考えることを三つ挙げてください。
