# 第2章・第5話　配列と文字列――同じ種類の値を、番号付きで並べる

値を順番に並べておけば、読むのも増やすのも簡単そうです。
実際、添字が分かれば目的の要素へ直接移れます。
途中へ値を差し込むと事情が変わり、その後ろの要素をまとめて動かさなければなりません。

配列の速さは、操作によって変わります。


## 1 要素と添字

```text
scores = [70, 85, 90]
```

- 配列全体の名前：`scores`
- 各値：要素。
- 位置を示す番号：添字、インデックス。

0から始まる書き方では、

```text
scores[0] = 70
scores[1] = 85
scores[2] = 90
```

です。

3要素の最後は2です。

```text
要素数nなら、有効添字は0からn-1
```

試験の擬似言語では1から始まる場合もあります。
問題文の宣言を最初に確認します。

## 2 なぜ0から始める言語が多いのか

要素を数えるなら、最初を1とする方が自然です。
配列の添字を先頭からの距離と考えると、最初の要素までの距離は0になります。

配列の先頭アドレスを1000、各要素を4バイトとします。

```text
0番目のアドレス = 1000 + 4×0 = 1000
1番目のアドレス = 1000 + 4×1 = 1004
i番目のアドレス = 1000 + 4×i
```

添字を先頭からのずれ、offsetとして使えます。

0開始だけが正しいわけではありません。
1開始の言語や、任意の下限を持てる言語もあります。

## 3 ランダムアクセス

先頭アドレス、要素サイズ、添字から目的位置を計算できるため、途中を1つずつたどらず直接到達できます。

これをランダムアクセスと呼びます。

ここでのrandomは無作為という意味ではなく、任意の位置に直接という意味です。

配列の要素参照は、通常`O(1)`です。

## 4 配列の走査

全要素を順に見ることを走査と呼びます。

```text
for i = 0 から length(scores)-1 まで
    scores[i]を表示
```

要素を直接受け取れるなら、

```text
for each score in scores
    scoreを表示
```

です。

添字が必要な処理か、値だけでよいかで選びます。

## 5 合計と平均

```text
total = 0
for each score in scores
    total = total + score

もし length(scores) > 0 なら
    average = real(total) / length(scores)
```

空配列で0除算しないようにします。
整数除算で小数が失われないよう、型も確認します。

計算量は全要素を1回見るので`O(n)`です。

## 6 最大値と最小値

```text
もし配列が空なら
    データなし

maxValue = scores[0]
for i = 1 から length(scores)-1 まで
    もし scores[i] > maxValue なら
        maxValue = scores[i]
```

最初の要素を初期値に使ったので、走査は1番から始めます。

最大値だけでなく位置も必要なら、`maxIndex`も同時に更新します。

## 7 固定長配列

作成時に長さを決め、後から変えない配列です。

```text
整数 scores[30]
```

必要容量が分かる場合は単純で、要素を連続配置しやすいです。

容量を超えて追加できず、使わない枠は無駄になります。

## 8 動的配列

要素の追加に応じて長さを変えられるように見える配列です。

内部には、

- 現在の要素数、size。
- 確保済みの枠数、capacity。

があります。

```text
size=3, capacity=4
[A][B][C][空]
```

満杯で追加すると、より大きな連続領域を確保し、既存要素を移します。

```text
[A][B][C][D]  満杯
↓ 例えば容量8を新規確保してコピー
[A][B][C][D][空][空][空][空]
```

## 9 償却計算量

動的配列の末尾追加は、普段なら空きへ置くだけで`O(1)`です。
「普段なら」という条件を落とすと、容量拡張で全要素をコピーする1回を説明できません。
拡張時は全要素コピーで`O(n)`です。

容量を毎回1個だけ増やすと、追加のたびにコピーします。
容量を2倍など幾何的に増やせば、高価な拡張はまれです。

多数回の操作全体で平均した1回当たりの費用を償却計算量と呼び、末尾追加は償却`O(1)`と評価できます。

これは「どの1回も必ずO(1)」という意味ではありません。
リアルタイム処理では、拡張が起きる最悪時間も重要です。

## 10 末尾への追加と途中への挿入

動的配列の末尾追加は、空きがあれば速いです。

途中に挿入するには、後ろの要素を1つずつずらします。

```text
[A][B][C][D]
位置1へXを挿入
[A][X][B][C][D]
       ↑ B,C,Dを移動
```

最悪`O(n)`です。

削除も、空きを詰めて順序を保つなら後ろを移動します。

## 11 範囲外アクセス

3要素で`array[3]`を読むと範囲外です。

言語により、

- 例外やエラーにする。
- 未定義動作になる。
- 隣の記憶域を誤って読む・書く。

違いがあります。

境界検査のない環境では、情報漏えい、データ破壊、攻撃につながります。

## 12 多次元配列

行と列を持つ表を2次元配列で表します。

```text
matrix = [
  [1,2,3],
  [4,5,6]
]
```

```text
matrix[0][0]=1
matrix[1][2]=6
```

行番号と列番号を取り違えないようにします。

## 13 行優先と列優先

2次元配列を主記憶の1列に並べる方法があります。

### 行優先

1行目を全部置き、次に2行目を置きます。

```text
1,2,3,4,5,6
```

### 列優先

1列目を全部置き、次に2列目を置きます。

```text
1,4,2,5,3,6
```

保存順に近い方向にループすると、キャッシュを効率よく使える場合があります。

## 14 二次元配列のアドレス計算

行優先で、列数`C`、1要素`S`バイト、先頭アドレス`B`、0開始の`[r][c]`なら、

```text
アドレス = B + (r×C+c)×S
```

です。

まず、前にある完全な行が`r`行、各行`C`要素なので`r×C`要素あります。
同じ行の前に`c`要素あります。

## 15 不規則な二次元配列

各行の長さが違う配列をジャグ配列と呼ぶことがあります。

```text
[
 [1,2],
 [3,4,5,6],
 [7]
]
```

長方形の連続領域ではなく、各行への参照の配列として実装されることがあります。
行ごとに長さを確認します。

## 16 配列のコピー

配列をコピーしたのだから、片方の変更はもう片方へ影響しないと考えたくなります。
しかし、要素が参照なら、外側の配列だけを複製しても内側の対象は共有されたままです。

```text
b = a
```

が、

- 配列全体を複製する。
- 同じ配列への参照だけを複製する。

のどちらかは言語によります。

### 浅いコピー

一番外側だけ複製し、中の参照先は共有します。

### 深いコピー

入れ子の対象もたどって複製します。

循環参照、共有すべき対象、大きなデータでは、単純な深いコピーに費用や意味の問題があります。

## 17 スライス

配列の一部分を表します。

```text
a[2:5]
```

が添字2、3、4を表し、上端5を含まない言語があります。

```text
開始を含む、終了を含まない
要素数 = 終了 - 開始
```

なので扱いやすい形です。

スライスが新しいコピーか、元配列を参照する窓かも言語により違います。

## 18 文字列は文字の並び

```text
text = "ABC"
```

文字列では、

- 長さを求める。
- 位置の文字を読む。
- 部分文字列を取る。
- 検索する。
- 連結する。
- 分割する。

などを行います。

## 19 文字列の不変性

多くの言語では、作成済みの文字列内容をその場で変更できない不変オブジェクトにします。

```text
s = "A"
s = s + "B"
```

は、元の`"A"`を書き換えるのでなく、新しい`"AB"`を作り、`s`の参照を付け替える場合があります。

ループで1文字ずつ連結すると、毎回大きなコピーが起きて`O(n²)`相当になる場合があります。
文字列ビルダや配列に集めて最後に結合します。

## 20 文字列の長さは何を数えるか

画面に5文字見えれば、長さも5だと答えたくなります。
実際には、バイト数、符号単位数、コードポイント数、人が見る文字数のどれを返すかで値が変わります。

`"A"`は単純ですが、絵文字や結合文字があります。

「長さ」が、

- バイト数。
- UTF-16符号単位数。
- Unicodeコードポイント数。
- 人が1文字と感じる書記素クラスタ数。

のどれかを確認します。

画面の文字数制限をバイト数で行うと、多言語利用者だけ短くなることがあります。
通信容量にはバイト数、表示には書記素数など、目的で選びます。

## 21 終端文字を持つ文字列

C言語などでは、文字列の終わりを値0のNUL文字で示す方式があります。

```text
'A' 'B' 'C' NUL
```

長さを知るにはNULまで数えます。
途中にNULを含められず、終端を書き忘れると範囲外まで読む危険があります。

別方式では、長さを別に保存します。

## 22 文字列比較

単純なコードポイント順、言語別辞書順、大文字小文字を無視、正規化後など、比較規則が違います。

```text
"10" < "2"
```

を文字列として先頭から比べると、`"1"`が`"2"`より先なので真になる場合があります。
数値10と2なら偽です。

数値の文字列は数値に検証変換してから比較します。

## 23 文字列入力の検証

利用者入力には、

- 空白だけ。
- 前後の余分な空白。
- 想定外の改行。
- 異なる正規化形。
- 非常に長い文字列。
- 制御文字。
- 見た目の似た文字。

があります。

勝手にすべて削除・変換すると、名前やパスワードの意味を変えることがあります。
項目ごとに規則を決め、元入力と正規化値を分けます。

## 24 配列を選ぶときの問い

1. 要素数は固定か変わるか。
2. 任意位置を頻繁に直接読むか。
3. 途中への挿入・削除が多いか。
4. 順序を保つか。
5. 同じ型だけか。
6. 連続領域を確保できるか。
7. 最悪時の拡張時間を許容できるか。
8. コピーか共有か。
9. 多次元なら保存順は何か。
10. 文字列なら何を1文字と数えるか。
