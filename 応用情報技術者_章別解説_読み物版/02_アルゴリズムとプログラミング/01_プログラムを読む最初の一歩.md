# 第2章・第1話　プログラムを読む最初の一歩――一行の記号を、日本語の手順へ戻す

第1章では、数、論理、データの表し方を学びました。ここからは、コンピュータへ実際の手順を伝えます。

プログラムを見たことがない人にとって、次の一行は暗号に見えます。

```text
total = price * count
```

しかし、部品へ分ければ、

```text
priceという箱の値と
countという箱の値を掛け、
結果をtotalという箱へ保存する
```

という指示です。

この授業では、特定の実在言語を先に暗記しません。応用情報試験で使われる擬似言語に近い、説明用の書き方を使います。記号ごとに日本語へ戻す練習をします。

---

## 1 アルゴリズムは、問題を解く有限の手順

カップ麺を作る手順も、広い意味ではアルゴリズムに似ています。

1. ふたを開ける。
2. 粉末スープを入れる。
3. 熱湯を線まで入れる。
4. ふたを閉める。
5. 三分待つ。

コンピュータ科学でいうアルゴリズムには、次の性質が必要です。

- 入力：何を受け取るかが決まる。
- 出力：何を答えるかが決まる。
- 明確性：各手順を一意に実行できる。
- 有限性：いつか終わる。
- 有効性：実際に行える基本操作で書かれる。

「いい感じになるまで混ぜる」は、人間には通じても、どの状態で止めるか曖昧です。

## 2 プログラムは、アルゴリズムを言語で記したもの

アルゴリズムは考え方としての手順です。それを、あるプログラム言語の文法に従って書いたものがプログラムです。

同じアルゴリズムを、Python、Java、Cなど違う言語で書けます。

```text
問題         二つの数の大きい方を返す
アルゴリズム 二つを比べ、大きい方を答える
プログラム   特定言語のif文などで記述する
```

言語が違っても、比較と分岐という考えは共通します。

## 3 入力・処理・出力へ分ける

消費税込み価格を求めます。

```text
入力：税抜価格1000円、税率10%
処理：1000×(1+0.10)
出力：1100円
```

プログラムを読むとき、最初に、

1. 何を受け取るか。
2. 何を計算・判定するか。
3. 何を返す・表示・保存するか。

へ分けます。

入力はキーボードだけではありません。ファイル、ネットワーク、センサ、別の関数も入力元です。出力も画面だけでなく、戻り値、ファイル、通信、モータ操作などがあります。

## 4 ソースコードと機械語

人が読むためのプログラム文をソースコードと呼びます。

CPUが直接実行するのは、CPUの命令規則に従う機械語です。コンパイラやインタプリタなどの処理系が、ソースコードを実行可能な形へつなぎます。

```text
人が書くソースコード
       ↓ 言語処理系
CPUが実行できる命令、または解釈実行
```

ソースコードを保存したファイルをソースファイルと呼びます。

## 5 一行、文、式は同じではない

### 式

値を作る記述です。

```text
3 + 4
price * count
age >= 18
```

式を評価すると、値が得られます。

### 文

コンピュータへ一つの処理を指示する単位です。

```text
total = price * count
totalを表示する
```

### 行

画面やファイル上の見た目の一列です。一つの文を複数行へ書く言語も、一行へ複数文を書く言語もあります。

したがって「一行」と「一文」は必ず同じではありません。

## 6 リテラル――ソースへ直接書いた値

次の`100`、`3.14`、`"こんにちは"`、`true`は、値を直接表しています。このような記述をリテラルと呼びます。

```text
100             整数リテラル
3.14            実数リテラル
"こんにちは"    文字列リテラル
true            真偽値リテラル
```

文字列は引用符で囲みます。引用符自体は、通常は文字列の内容ではなく、どこからどこまでが文字列かを示す印です。

```text
"123"  文字列
123    数値
```

見た目が似ていても、できる操作が違います。

## 7 変数――値へ名前を付ける箱

変数は、値を保存・参照するための名前です。初めは「名前の付いた箱」と考えます。

```text
price = 120
count = 3
```

実行後の状態は、

```text
priceの箱  120
countの箱  3
```

です。

変数名は、その値の意味が分かるようにします。

```text
x       文脈がなければ意味が分かりにくい
price   価格だと分かる
```

短い数式では`x`が自然な場合もあります。長い業務プログラムでは意図を表す名前を優先します。

## 8 代入――右の値を、左の変数へ保存する

```text
total = price * count
```

多くの手続型言語で`=`は、数学の等号ではなく代入を表します。

読む順は右から左です。

1. `price`の現在値を読む。
2. `count`の現在値を読む。
3. 二つを掛ける。
4. 結果を`total`へ保存する。

### `x=x+1`は矛盾ではない

```text
x = x + 1
```

右側の古い`x`へ1を足し、その結果で左側の`x`を更新します。

```text
実行前 x=5
右側 5+1=6
実行後 x=6
```

数学の等式として読むと`5=6`で矛盾しますが、代入命令としては「一つ増やす」です。

擬似言語では、混同を避けて`x ← x+1`のように左向き矢印で代入を書くこともあります。

## 9 初期化――使う前の最初の値を決める

合計を求める変数は、足し始める前に0へします。

```text
total = 0
```

この最初の値を設定することを初期化と呼びます。

初期化していない変数を読むと、

- 言語がエラーにする。
- 自動的に0などを入れる。
- 以前その場所にあった不定な値を読む。

など、言語や場所により違います。初期値を意図的に決めます。

## 10 演算子――値へ操作を行う記号

代表的な算術演算子です。

```text
+  加算
-  減算
*  乗算
/  除算
%  剰余
```

`17 % 5`は、17を5で割った余り2です。

剰余は、

- 偶数か調べる：`n % 2 == 0`
- 一定個ごとに繰り返す。
- 配列の位置を循環させる。

などに使います。

負数の剰余規則は言語により違う場合があります。

## 11 比較演算子――真か偽を作る

```text
==  等しい
!=  等しくない
<   より小さい
<=  以下
>   より大きい
>=  以上
```

```text
age >= 18
```

は、`age`が18以上なら真、そうでなければ偽という値になります。

代入の`=`と、等しいか比べる`==`を区別します。言語によって記号は違います。

## 12 論理演算子――条件を組み合わせる

```text
AND  両方が真
OR   少なくとも一方が真
NOT  真偽を反転
```

```text
age >= 18 AND hasTicket == true
```

は、「18歳以上であり、かつ、券を持っている」です。

日常語の「または」は曖昧ですが、普通のORは両方真も含みます。

## 13 括弧と優先順位

```text
2 + 3 * 4
```

は通常、乗算を先にして14です。

```text
(2 + 3) * 4
```

なら20です。

長い式では、規則を知っていても括弧で意図を明確にします。ただし、括弧を増やしすぎても読みにくくなります。途中の式へ名前を付ける方法もあります。

```text
subtotal = price * count
total = subtotal + shipping
```

## 14 関数呼出しの形

名前の後ろに丸括弧を書き、中へ渡す値を書く形がよく使われます。

```text
max(3, 8)
```

`max`という関数へ3と8を渡し、大きい方8を受け取ります。

```text
result = max(3, 8)
```

なら、返った8を`result`へ保存します。

括弧は、計算順をまとめる括弧と、関数へ値を渡す括弧の両方に使われます。前に名前があれば関数呼出しの可能性があります。

## 15 表示と戻り値は違う

```text
print(8)
```

は画面などへ8を表示します。

```text
return 8
```

は、呼出し元へ結果8を返します。

表示した値を、呼出し元が自動的に計算へ使えるとは限りません。

```text
表示：人へ見せる副作用
戻り値：別の処理へ渡す値
```

デバッグ用の表示が消えても、関数の結果は返るように設計します。

## 16 コメント――人へ説明し、実行しない部分

コメントは、処理系が実行しない、人向けの注記です。

```text
# 税率は設定ファイルから受け取る
tax = price * rate
```

良いコメントは、コードを読めば分かる「何を」を繰り返すより、

- なぜこの方法か。
- どの前提があるか。
- どの仕様や判断に基づくか。
- 何に注意するか。

を補います。

コードを変更したのに古いコメントを残すと、かえって危険です。

## 17 空白と字下げ

演算子の周りへ空白を置くと読みやすくなります。

```text
total=price*count
total = price * count
```

行の先頭の空白を字下げ、インデンテーションと呼びます。条件や繰返しの内側を示します。

```text
もし age >= 18 なら
    "成人"を表示する
```

Pythonのように字下げ自体が文法の言語もあれば、波括弧で範囲を示し字下げは人向けという言語もあります。どちらでも、一貫した字下げが構造を見せます。

## 18 実行トレース――一行ずつ状態を追う

次を実行します。

```text
x = 2
y = x + 3
x = y * 2
```

表へします。

| 実行後 | x | y |
|---|---:|---:|
| 開始 | 未定 | 未定 |
| `x=2` | 2 | 未定 |
| `y=x+3` | 2 | 5 |
| `x=y*2` | 10 | 5 |

大切なのは、各行で右側を古い状態から評価し、その後で左側を更新することです。

頭だけで追わず、変数表を書きます。配列やスタックは別の図にします。

## 19 三種類の誤り

### 構文誤り

言語の文法に合わない記述です。

```text
total = price *
```

### 実行時誤り

文法は正しいが、実行中の値や環境で失敗します。

```text
10 / 0
存在しないファイルを開く
```

### 論理誤り

プログラムは動くが、望んだ答えを出しません。

```text
税込価格を price * rate とし、元価格を足し忘れる
```

処理系が止めない論理誤りは、テストやレビュー、仕様確認で見つけます。

## 20 擬似コード――特定言語の細部を減らして手順を書く

応用情報では、試験用の擬似言語や文章的な手順が出ます。

```text
関数 max(a, b)
    もし a > b なら
        aを返す
    そうでなければ
        bを返す
```

擬似コードでも、

- 代入か比較か。
- 範囲の端を含むか。
- 配列番号は0からか1からか。
- 整数除算の端数をどうするか。
- 値渡しか参照渡しか。

を確認します。

## 21 アルゴリズムを作る基本手順

1. 入力と出力を例付きで書く。
2. 正常・境界・異常な例を作る。
3. 人間が手で解く手順を書く。
4. 一つの手順を、比較・代入・分岐・繰返しへ分ける。
5. 途中で何を覚えるか決める。
6. 必ず終わる理由を確認する。
7. すべての許された入力で正しい理由を確認する。
8. 入力が増えたときの時間と記憶量を見積もる。

コードから始めると、何を解くかを見失うことがあります。まず入出力と小例を紙に書きます。

## 税込み式を単位から作る

10%は「100分の10」なので`10÷100=0.10`です。税抜価格を`p円`とすると、税額は`p円×0.10=0.10p円`、元価格分は`1.00p円`です。

```text
税込価格 = 元価格 + 税額
         = p×1.00 + p×0.10
         = p×(1+0.10)
         = p×1.10 円
```

`1`を足すのは元価格100%分を残すためです。問題では端数処理の単位も確認します。


## 22 確認問題

1. アルゴリズムとプログラムの違いを説明してください。
2. アルゴリズムに有限性が必要なのはなぜですか。

4. 式、文、行の違いを説明してください。
5. 数値`123`と文字列`"123"`の違いを説明してください。
6. 変数とリテラルの違いを説明してください。
7. `x=5`の後に`x=x+2`を実行すると、xはいくつですか。手順も書いてください。
8. 初期化とは何ですか。
9. `17%5`はいくつですか。剰余の用途も一つ挙げてください。
10. 代入`=`と比較`==`の違いを説明してください。
11. `2+3*4`と`(2+3)*4`を計算してください。
12. 関数の表示と戻り値の違いを説明してください。
13. 良いコメントには何を書くと役立ちますか。
14. 字下げにはどのような役割がありますか。
15. 次をトレースしてください。

```text

```

16. 構文誤り、実行時誤り、論理誤りの例を一つずつ挙げてください。
17. 擬似コードでも確認すべき細部を三つ挙げてください。

## 解答と考え方

1. **解法の入口:** 二つの語を、対象・目的・成立条件・失敗時の四列に置いて比べます。 問題は「アルゴリズムとプログラムの違いを説明してください。」です。
   **途中手順:** 共通点を一つ、相違点を一つ示し、問題の条件へ合う側を選びます。 結論「アルゴリズムは問題を解く明確で有限な手順、プログラムはその手順を特定言語の文法で記したものです。」の比較軸を確認します。
   **結論:** アルゴリズムは問題を解く明確で有限な手順、プログラムはその手順を特定言語の文法で記したものです。
   **この誤答が起きる理由:** 名称や長所だけで選ぶと、守る対象・処理時点・前提条件が違う方式を交換可能だと誤認します。

2. **解法の入口:** 理由を求める対象を特定し、原因→仕組み→観測される結果の鎖を作ります。 問題は「アルゴリズムに有限性が必要なのはなぜですか。」です。

   **結論:** 結果を出す手順として、許された入力でいつか終了する必要があるからです。
   **この誤答が起きる理由:** 『速い』『安全』など結果だけを書くと、どの仕組みがなぜ効くのか、例外条件が説明できません。
