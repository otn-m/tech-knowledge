# 第2章・第1話　プログラムを読む最初の一歩――一行の記号を、日本語の手順へ戻す

第1章で学んだ数、論理、データの表し方を使い、コンピュータに実行する手順を伝えます。
たとえば、次の1行は、価格と個数から合計を求める記述です。

```text
total = price * count
```

部品に分けると、次の指示になります。

```text
priceという箱の値と
countという箱の値を掛け、
結果をtotalという箱へ保存する
```

記号を一つずつ覚えても、同じ記号が置かれた位置や値の型によって働きは変化します。
何を計算し、どの値を保存したかを順に追うことで、文としての意味が明確になるわけです。

特定の実在言語をあらかじめ暗記する必要はありません。
応用情報試験の擬似言語に近い表記を使い、記号を日本語の手順に戻しながら読み解いていきましょう。

## 手順を実行できる記述にする

### 1 アルゴリズムは、問題を解く有限の手順

カップ麺を作る手順も、広い意味ではアルゴリズムに似ています。

1. ふたを開ける。
2. 粉末スープを入れる。
3. 熱湯を線まで入れる。
4. ふたを閉める。
5. 3分待つ。

ただし、手順を細かく書くだけでは、コンピュータ科学でいうアルゴリズムの条件を満たすとは限りません。
次の性質が必要です。

- 入力――何を受け取るかが決まる。
- 出力――何を答えるかが決まる。
- 明確性――各手順を一意に実行できる。
- 有限性――いつか終わる。
- 有効性――実際に行える基本操作で書かれる。

「いい感じになるまで混ぜる」は、人間には通じても、どの状態で止めるか曖昧です。

### 2 プログラムは、アルゴリズムを言語で記したもの

明確で有限な手順を決めても、そのままCPUが実行できるわけではありません。
アルゴリズムは、考え方としての手順です。
それを、あるプログラム言語の文法に従って書いたものがプログラムです。

同じアルゴリズムを、Python、Java、Cなど違う言語で書けます。

```text
問題         二つの数の大きい方を返す
アルゴリズム 二つを比べ、大きい方を答える
プログラム   特定言語のif文などで記述する
```

言語が異なっていても、比較や分岐といった根底にある考え方は共通です。

## 入力から出力までの処理を定める

### 3 入力・処理・出力へ分ける

税込価格を求める処理では、受け取る価格と税率、計算手順、計算後の金額という3要素に整理できます。

```text
入力：税抜価格1000円、税率10%
処理：1000×(1+0.10)
出力：1100円
```

プログラムを読む際も同様に、何を受け取り、何を計算・判定し、何を保存・返却するかを分解して把握することが重要です。
ただし、入出力をキーボードや画面だけに限定してしまうと、ファイルを読み出す処理や値を返す関数が枠組みから外れてしまいます。
ファイルやネットワーク、センサ、別の関数も立派な入力元に他なりません。
出力についても、画面表示だけでなく戻り値やファイル保存、通信送信、モータ制御などが含まれる仕様です。
処理の前後で受け渡されるあらゆる対象を、広い意味での入出力として捉える姿勢が欠かせません。

#### 税込み式を単位から作る

10%は「100分の10」ですから、小数表記では`10÷100=0.10`です。
税抜価格を`p円`と置けば、税額は`p円×0.10=0.10p円`、元価格分は`1.00p円`となります。

```text
税込価格 = 元価格 + 税額
         = p×1.00 + p×0.10
         = p×(1+0.10)
         = p×1.10 円
```

`1`を足しているのは、元価格の100%分を確実に残すためです。
実際の試験問題では、端数処理の指定や計算単位にも注意を払う必要があります。

### 4 ソースコードと機械語

入出力と処理を、人が読めるプログラム文にしたものを**ソースコード**と呼びます。

CPUが直接実行するのは、CPUの命令規則に従う機械語です。
コンパイラやインタプリタなどの処理系が、ソースコードを実行可能な形式へと変換します。

```text
人が書くソースコード
       ↓ 言語処理系
CPUが実行できる命令、または解釈実行
```

ソースコードを保存したファイルがソースファイルです。

## 値を作る式と、状態を変える文

### 5 一行、文、式は同じではない

画面上で改行されていれば、そこで一つの処理が完結すると捉えたくなるかもしれません。
しかし、改行はあくまで視覚的な区切りにすぎず、値を作る式や処理を命じる文の境界と一致するとは限らないのです。

#### 式

値を作る記述です。

```text
3 + 4
price * count
age >= 18
```

式を評価すると、値が得られます。

#### 文

コンピュータに1つの処理を指示する単位です。

```text
total = price * count
totalを表示する
```


#### 行

画面やファイル上の見た目の1列です。
1つの文を複数行に書く言語も、1行に複数文を書く言語もあります。

したがって「1行」と「1文」は必ず同じではありません。

### 6 リテラル――ソースへ直接書いた値

次の`100`、`3.14`、`"こんにちは"`、`true`は、値を直接表しています。
このような記述をリテラルと呼びます。

```text
100             整数リテラル
3.14            実数リテラル
"こんにちは"    文字列リテラル
true            真偽値リテラル
```

プログラム中の文字列は二重引用符などで囲むのが通例です。
引用符そのものは文字列のデータ本体というより、文字列の開始と終了を示す境界の目印として機能します。

```text
"123"  文字列
123    数値
```

見た目が数字に似ていても、データ型が異なれば適用できる演算もまったく違ってくるわけです。

### 7 変数――値へ名前を付ける箱

ソースコードに直接書かれた値だけでなく、計算結果を保存して後から参照したい場面も多く存在します。
その際に活躍する**変数**とは、値を保持・参照するための識別名に他なりません。
初学の段階では「名前ラベルが貼られた箱」とイメージすると理解しやすいでしょう。

```text
price = 120
count = 3
```

この2つの代入を実行した場合、メモリ上に保持される値は次の通りです。

```text
priceの箱  120
countの箱  3
```

変数名を決める際は、保持される値の意味が一目で伝わる単語を選定します。

```text
x       文脈がなければ意味が分かりにくい
price   価格だと分かる
```

短い数学的アルゴリズムであれば`x`のような1文字でも自然に読めます。
一方、実務の大規模なプログラムでは、変数の意図を明確に示す命名規則が何より重要となるのです。

### 8 代入――右の値を、左の変数へ保存する

```text
total = price * count
```

多くの手続型言語において、記号`=`は数学的な等号というよりも「代入」の操作を意味します。

代入文では、まず右側の式を完全に評価した上で、得られた値を左側の変数へと格納する順序をとる仕組みです。

1. `price`の現在値を読む。
2. `count`の現在値を読む。
3. 2つを掛ける。
4. 結果を`total`に保存する。

#### `x=x+1`は矛盾ではない

```text
x = x + 1
```

右側の式にある古い`x`の値へ1を加え、その計算結果で左側の`x`を上書き更新します。

```text
実行前 x=5
右側 5+1=6
実行後 x=6
```

数学の等式として読むと`5=6`という矛盾が生じますが、代入命令としては「現在の値を1増やす」という操作を意味しているのです。

擬似言語においては、こうした混同を避けるために`x ← x+1`のように左向き矢印で代入を記述するのが一般的といえます。

### 9 初期化――使う前の最初の値を決める

変数を宣言した直後の状態では、安全な値があらかじめ入っている保証はありません。
初期値を設定する際は、その後の処理や演算に適した値を選ぶ必要があります。

たとえば合計値を集計していく変数であれば、加算を始める前にあらかじめ0をセットしておく形をとります。

```text
total = 0
```

このように、変数を使う直前に最初の値を設定する操作が「初期化」です。

未初期化の変数を読み出した場合の挙動は、プログラミング言語の仕様や実行環境によって様々に分かれます。

- 言語がエラーにする。
- 自動的に0などを入れる。
- 以前その場所にあった不定な値を読む。

環境ごとの差異に惑わされないためにも、使う変数は常に意図を持って明示的に初期化しておくべきです。

## 記号を組み合わせて値を求める

### 10 演算子――値へ操作を行う記号

値に対して四則演算などの処理を加える記号を**演算子**と呼びます。
代表的な算術演算子の構成は次の通りです。

```text
+  加算
-  減算
*  乗算
/  除算
%  剰余
```

`17 % 5`であれば、17を5で割った余りである2が評価結果となります。

剰余の演算は、実務において次のような場面で重宝される技法です。

- 偶数か調べる――`n % 2 == 0`
- 一定個ごとに繰り返す。
- 配列の位置を循環させる。

なお、負の数に対する剰余の丸め規則は言語によって仕様が異なる点に注意してください。

### 11 比較演算子――真か偽を作る

数値を計算する式とは異なり、大小関係や一致を調べる式は「真」または「偽」という真偽値を生み出す式です。
代表的な**比較演算子**は次のとおりです。

```text
==  等しい
!=  等しくない
<   より小さい
<=  以下
>   より大きい
>=  以上
```

たとえば次の式では、`age`が18以上であれば真、18未満であれば偽と評価されます。

```text
age >= 18
```

ここで注意したいのが、値を代入する記号`=`と、等しいかを判定する比較演算子`==`の明確な区別です。
言語によって比較に使う記号は異なるものの、役割の違いは共通しています。

### 12 論理演算子――条件を組み合わせる

年齢の条件だけでなく入場券の有無も同時に調べたい場合は、複数の条件を論理演算子で結合する設計をとるわけです。

```text
AND  両方が真
OR   少なくとも一方が真
NOT  真偽を反転
```

次の式は、「18歳以上であり、かつ券を所持している」という複合条件を表しています。

```text
age >= 18 AND hasTicket == true
```

日常会話の「または」はどちらか一方を指しがちですが、論理演算のORは両方が真であるケースも当然に含む設計です。

### 13 括弧と優先順位

同じ数値と演算子を並べた式であっても、どの演算を優先して評価するかによって得られる結果は一変します。
たとえば次の式では、通常の数学と同様に乗算が優先されるため、計算結果は14となる仕組みです。

```text
2 + 3 * 4
```

括弧で加算を先に囲めば、計算結果は20へと変化します。

```text
(2 + 3) * 4
```

複雑な式においては、優先順位の暗記に依存せず、括弧を用いて計算の意図を明示するのが確実です。
ただし、過剰に括弧を重ねるとかえって可読性を損ねてしまいます。
そのような場合は、途中の計算結果を変数に受けて式を分割する設計が有効といえます。

```text
subtotal = price * count
total = subtotal + shipping
```


### 14 関数呼出しの形

プログラミングにおける丸括弧は、演算順序の制御にとどまらず、関数へ引数を渡す役割も担う重要な記号です。
関数名の直後に丸括弧を配置し、その内側に渡したい値をカンマで並べる記法が標準的です。

```text
max(3, 8)
```

この式では、`max`という関数に3と8を渡すことで、大きい方の値である8を受け取っています。
得られた計算結果を後続の処理で使いたい場合は、関数呼出しの式を代入文の右辺に配置すればよいのです。

```text
result = max(3, 8)
```

これにより、返却された8が変数`result`に無事保存されます。
丸括弧の手前に名前が置かれていれば、そこに関数呼出しが存在することを示唆しているわけです。

## 結果の受け渡しと、記述の読みやすさ

### 15 表示と戻り値は違う

関数を正しく扱う上では、「画面への表示」と「呼出し元への戻り値」の役割を厳密に区別しなければなりません。
画面に所望の数値が出力されると、あたかも関数が正常に値を返したかのように錯覚しがちです。
しかし、画面表示は外部環境に対する作用（副作用）にすぎず、呼出し元のプログラムが次の計算に活用できる戻り値とは根本的に異なるものです。

```text
print(8)
```

この命令は、画面などに8を表示します。
一方、次の命令は呼出し元に結果8を返します。

```text
return 8
```

画面に出力された文字を、呼出し側が自動的に数値データとして再利用できるわけではありません。

```text
表示：人へ見せる副作用
戻り値：別の処理へ渡す値
```

デバッグ用の表示行を削除したとしても、関数の戻り値によって後続の処理が破綻なく進行するよう設計しておく必要があります。

### 16 コメント――人へ説明し、実行しない部分

コメントは、処理系が実行しない、人向けの注記です。

```text
# 税率は設定ファイルから受け取る
tax = price * rate
```

良いコメントは、コードを読めば分かる「何を」を繰り返すより、次の情報を補います。

- なぜこの方法か。
- どの前提があるか。
- どの仕様や判断に基づくか。
- 何に注意するか。

コードを変更したのに古いコメントを残すと、かえって危険です。

### 17 空白と字下げ

演算子の前後に適切な半角空白を設けると、式の構造を素早く見通せるようになります。

```text
total=price*count
total = price * count
```

また、行頭に設ける空白の深さを「字下げ（インデンテーション）」と呼びます。
字下げは、条件分岐やループ処理の内側にあるブロック構造を視覚化するための重要な道具です。

```text
もし age >= 18 なら
    "成人"を表示する
```

Pythonのように字下げの深さそのものが文法規則を成す言語もあれば、C言語やJavaのように波括弧で範囲を区切り、字下げは人間用の補助とする言語も存在します。
どのような言語であれ、一貫した字下げを維持することがコードの構造を誰の目にも明快にするのです。

## 状態を追って手順を確かめる

### 18 実行トレース――一行ずつ状態を追う

単一の代入文を理解できたら、次は複数の文が連続して実行された際の状態変化を追跡してみましょう。
例として、次のコードを上から順に実行してみます。

```text
x = 2
y = x + 3
x = y * 2
```

各行の実行完了時点における変数の値を整理したものが、次のトレース表です。

| 実行後 | x | y |
|---|---:|---:|
| 開始 | 未定 | 未定 |
| `x=2` | 2 | 未定 |
| `y=x+3` | 2 | 5 |
| `x=y*2` | 10 | 5 |

大切なのは、各行で右側を古い状態から評価し、その後で左側を更新することです。

頭だけで追わず、変数表を書きます。
配列やスタックは別の図にします。

### 19 三種類の誤り

#### 構文誤り

言語の文法に合わない記述です。

```text
total = price *
```


#### 実行時誤り

文法は正しいが、実行中の値や環境で失敗します。

```text
10 / 0
存在しないファイルを開く
```


#### 論理誤り

プログラムは動くが、望んだ答えを出しません。

```text
税込価格を price * rate とし、元価格を足し忘れる
```

コンパイラや実行時環境が警告してくれない論理誤りは、テストコードの実行やコードレビュー、丁寧な机上トレースによって洗い出す必要があります。

### 20 擬似コード――特定言語の細部を減らして手順を書く

応用情報技術者試験では、特定の商用言語に偏らないよう、専用の擬似言語や文章によるアルゴリズム記述が頻出します。

```text
関数 max(a, b)
    もし a > b なら
        aを返す
    そうでなければ
        bを返す
```

実在の言語から瑣末な文法規則を削ぎ落とした擬似コードを読む際も、次の観点を丁寧に確認する姿勢が欠かせません。

- 代入か比較か。
- 範囲の端を含むか。
- 配列番号は0からか1からか。
- 整数除算の端数をどうするか。
- 値渡しか参照渡しか。

### 21 アルゴリズムを作る基本手順

1. 入力と出力を例付きで書く。
2. 正常・境界・異常な例を作る。
3. 人間が手で解く手順を書く。
4. 1つの手順を、比較・代入・分岐・繰返しに分ける。
5. 途中で何を覚えるか決める。
6. 必ず終わる理由を確認する。
7. すべての許された入力で正しい理由を確認する。
8. 入力が増えたときの時間と記憶量を見積もる。

いきなりプログラムコードを書き始めると、本来解くべき問題の全体像を見失ってしまう危険があります。
まずは期待される入出力と具体例を紙の上に書き出し、解法の手順を整理することから始めましょう。

冒頭の`total = price * count`は、2つの現在値から式を評価し、その結果を変数へ保存する文でした。
同様に、各行が受け取る値、更新する内部状態、そして外部へ渡す結果を丁寧に追跡していくことで、一見難解な記号の連なりも、確実に動作する明快な手順として読めるようになるのです。
