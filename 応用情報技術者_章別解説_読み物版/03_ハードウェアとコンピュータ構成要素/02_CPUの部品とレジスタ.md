# 第3章 第2話 CPUの部品とレジスタ

`ADD R1, R2`は、外から見ればわずか1行の命令に見えます。
ところがCPUの内部では、命令の位置を示し、命令を保持し、値を運び、計算結果を受け取る複数の回路が細かく連動して動く形です。

CPUは、Central Processing Unit（中央処理ユニット）の略称に他なりません。
外見は1つの黒い半導体チップに見えても、その内側を「単に計算する回路」だけで説明することはできないわけです。

```text
CPU
├─制御機構
├─演算機構 ALU・FPUなど
├─レジスタ
├─キャッシュ
└─内部の伝送路
```

プログラムの命令を取り出し、解釈し、計算し、ほかの周辺回路を制御するには、これらの部品が同じ1命令の中で密接に協力しなければなりません。
レジスタの名前は数多く存在しますが、「何を一時的に記憶するか」という観点で追えば、その役割をすっきりと区別できます。

## CPUの近くで値を保持し、計算する

### 1 CPUは主記憶へ直接何でも置かない

主記憶はCPUのコアから物理的に離れており、読み書きには無視できない時間がかかります。
演算を行うたびに遠い主記憶との間を往復していては、処理速度が大幅に低下してしまう形です。

そこでCPUの内部に、今すぐ使う値やメモリアドレスを保持する極めて小さな超高速記憶領域を用意します。
これが**レジスタ**です。

```text
主記憶から値をレジスタへ読む
       ↓
レジスタ同士で計算する
       ↓
結果をレジスタへ置く
       ↓
必要なら主記憶へ書く
```

レジスタは極めて高速である反面、回路規模の制約から搭載できる総数が厳しく限られます。
そのためコンパイラは、どの変数をどのレジスタに割り当てて高速化を図るかを綿密に最適化するわけです。

### 2 制御機構

命令を取り出す段階では、次に実行すべき命令が格納された番地を示し、主記憶に対して読出しを指示します。
取り出した命令を解読した後は、演算部、各種レジスタ、入出力回路へ制御信号を送り、処理を着実に進める形です。
プログラムに分岐や割込みが発生した場合には、次に実行する命令の位置も柔軟に変更します。
この一連の動作を司る司令塔が制御部（制御機構）に他なりません。

命令のビット列を解釈して回路ごとの制御信号へと変換するデコーダ（命令解読器）は、制御部の中核をなす回路です。

### 3 演算機構

#### 3.1 ALU

`ALU`は整数の算術演算、論理演算、比較、ビットシフトなどを一手に引き受けます。
内部には次のような専門回路が組み込まれている形です。

- 加算器は、数値同士の足し算を実行します。
- 補数器は、負数表現や引き算を行うために2の補数を生成します。
- 乗算器は、掛け算を専門に処理します。
- シフタは、ビット列を左右へずらす操作を担当します。

引き算`A-B`を計算する際にも、補数器でBの2の補数を作って`A+(-B)`という加算に帰着させる回路構成が広く用いられています。
第1章で学んだ補数の論理が、そのまま物理的な演算回路の工夫に直結しているわけです。

#### 3.2 FPU

整数の演算とは別に、実数を扱う浮動小数点数の加減乗除などを専門に受け持つのが`FPU`（Floating-Point Unit）です。

浮動小数点の計算では、指数部を揃え、仮数部を演算し、正規化と丸めを行う複雑な手順を踏むため、整数加算器とは独立した回路構造を必要とします。
現代のCPUではチップ内部に統合されるのが通例ですが、機能の役割としては整数のALUと明確に区別して理解する方針です。

#### 3.3 積和演算器

さらに、掛け算の結果を累積値に加算する処理を1ステップで高速に実行する回路を`積和演算器`（MAC：Multiply-Accumulate）と呼びます。

```text
accumulator = accumulator + a × b
```

音声や画像のデジタル信号処理、行列計算、機械学習の推論ではこの積和計算が天文学的な回数繰り返されるため、専用回路による高速化が不可欠です。

## 演算対象と結果を置く

### 4 アキュムレータ

演算回路で算出した計算結果も、次の計算ステップで再利用するために一時保持しなければなりません。
演算結果を次々と累積して保持する特殊なレジスタを**アキュムレータ**（累算器）と呼びます。

1つのアキュムレータを中心として設計されたプロセッサにおいて、`A+B+C`を計算する流れを見てみましょう。

```text
ACC ← A
ACC ← ACC + B
ACC ← ACC + C
```

このような構成で使われる1オペランド命令は、アキュムレータを暗黙の演算対象および結果の格納先として利用し、命令コード側にはもう一方のオペランド番地だけを記述する方式です。
命令コード側で明示するオペランドを1つに絞り込み、もう一方の演算対象をアキュムレータとして固定的に割り当てる仕組みを指します。
現代のプロセッサは複数の汎用レジスタを用いる設計が主流ですが、計算の原初的なモデルを理解するうえでアキュムレータの動作原理は極めて有益です。

### 5 汎用レジスタ

特定の結果の累積だけでなく、数値データ、メモリアドレス、計算の途中経過など、多彩な用途に自由に割り当てて利用できる記憶領域が**汎用レジスタ**（GR：General Register）です。

```text
R1 ← 5
R2 ← 7
R3 ← R1 + R2
```

プロセッサの命令セットアーキテクチャによって、搭載されるレジスタの本数、ビット幅、特定の命令で課される制約などはそれぞれ異なります。

## 命令と主記憶の間をつなぐ

### 6 プログラムカウンタ

計算に使う数値データだけであれば、汎用レジスタの中に保持しておけば事足ります。
しかし、プログラムを正しい順序で実行していくためには、「処理がどこまで進んだか」と「いまどの命令を処理しているか」を正確に記憶し続けなければなりません。

次に取り出すべき命令が格納されている主記憶の番地を保持するレジスタが**プログラムカウンタ**（PC）です。
命令アドレスレジスタ、命令カウンタ、逐次制御カウンタと表記される資料も存在します。

```text
PC = 100
番地100の命令を取る
PC = 104  ← 次の命令へ
```

通常の逐次処理では、1命令を取り出すたびに次の命令のアドレスへと値が自動的に更新されていく形です。
ただし、条件分岐命令が成立した場合には、PCにジャンプ先の番地が直接上書きされます。
サブルーチンの呼出しや復帰、割込み処理の発生時にも、このPCの値を書き換えることで実行の流れが制御されるわけです。

なお、ここでのPCは`Program Counter`の略称であり、パソコン（Personal Computer）や特定メーカー固有の用語ではない点に留意してください。
x86系プロセッサでは、同等の役割を担うポインタレジスタを通例としてIP、EIP、RIPなどと呼称します。

### 7 命令レジスタ

PCが「次の命令の番地」を指し示すのに対して、主記憶からフェッチしてきた「命令コードそのもの」を保持するのが**命令レジスタ**（IR：Instruction Register）です。
プロセッサが現在解読し、まさに実行しようとしている命令ビット列がここに格納されます。

```text
主記憶[PC] → IR
```

IRに読み込まれた命令語のうち、処理内容を示す命令部がデコーダに渡され、「加算」「メモリアクセス」「分岐」といった具体的な制御信号へと変換される仕組みです。
「PCは次の命令の住所」「IRは現在解読中の命令の内容」と対比して整理しておけば、両者の役割を取り違える心配はありません。

### 8 メモリアドレスレジスタ

プログラムの命令や各種データを主記憶から取得するためには、アクセス対象となる番地をメモリ側へ正確に提示する必要があります。
このアクセス対象番地を保持してアドレスバスへと送出するレジスタが、メモリアドレスレジスタ（MAR：Memory Address Register）です。

```text
MAR ← 1000
主記憶へ読出し信号
```

PCが保持するのはあくまで「次の命令のアドレス」ですが、MARはデータ読出しや書込みも含めた「主記憶にアクセスする瞬間のあらゆる番地」を一時的に受け持ちます。

### 9 データレジスタとメモリレジスタ

主記憶へ番地を送出した後、メモリから読み出されて返ってきたデータや、逆に主記憶へ書き込むべきデータを一時的に保持する窓口も欠かせません。
この受渡し役を果たすのが、データレジスタ（DR：Data Register）またはメモリレジスタ（MR）です。
アーキテクチャによっては、MDR（Memory Data Register）という名称を採用している場合もあります。

```text
読出し: 主記憶[MAR] → DR
書込み: DR → 主記憶[MAR]
```

MARが郵便物の「宛先住所」に相当するならば、DRは箱の中に入っている「荷物の実体」に相当するわけです。
番地を運ぶ経路と、データそのものを運ぶ経路を独立して追うことで、メモリアクセスの全体像が鮮明に見えてきます。

## 番地と実行状態を管理する

### 10 インデックスレジスタ

配列データを先頭から順番に走査する場合、配列全体の基準アドレスは固定したまま、そこからの相対的なオフセット距離を増減させると効率よく次の要素へアクセスできます。
この反復処理におけるオフセット値を保持し、命令内のアドレス部に加算して実際のアドレスを割り出すレジスタが**インデックスレジスタ**（指標レジスタ）です。

配列の先頭番地が1000、1要素のサイズが4バイト、添字`i=3`である場合、先頭からのオフセットは`3要素×4バイト=12バイト`となり、目的のアドレスは`1000+12=1012`と求まります。

```text
基準番地1000 + (添字3×4バイト/要素) = 1000 + 12バイト = 1012
```

プログラムコード内の命令語を直接書き換えることなく、レジスタの値だけを1つ加算してループを回せる点が大きな利点です。

### 11 ベースレジスタ

配列の要素を走査する用途とは別に、プログラムコード全体やデータ領域が主記憶上のどの位置にロードされたかを基準化する用途も存在します。
メモリ再配置の基準となる先頭番地を保持するのが**ベースレジスタ**です。
命令語の中には、基準点からの相対変位（ディスプレイスメント）だけを記録しておきます。

```text
ベース = 8000
変位   = 120
実効番地 = 8120
```

プログラムが主記憶の別の番地に配置された場合でも、ベースレジスタの初期値を差し替えるだけで、命令コード内の相対的な指定をそのまま流用できる仕組みです。

### 12 スタックポインタ

サブルーチンや関数を呼び出した後に元の処理へ正しく復帰するためには、呼出し元の戻り番地やレジスタの退避データを安全に保存しておかなければなりません。
関数の呼出し時には、これらの復帰情報やローカル変数がスタックと呼ばれる後入れ先出し（LIFO）のメモリ領域に順次積み上げられます。
このスタック領域における現在の最上位アドレスを常に指し示しているのが、スタックポインタ（SP：Stack Pointer）です。

```text
push 値 → SPを動かして保存
pop      → 値を読みSPを戻す
```

スタックがメモリの高位番地から低位番地に向かって伸びるか、その逆向きに確保されるかは、CPUアーキテクチャやOSの呼出し規約によって定められています。

### 13 フラグレジスタ

ALUで演算を実行した後は、得られた数値そのものだけでなく、計算結果の性質を表す状態情報もその後の条件分岐で利用されます。
演算結果のステータスを示すビット群をまとめたレジスタが**フラグレジスタ**（ステータスレジスタ）です。

- ゼロフラグは、演算結果がちょうど0になった場合にセットされます。
- キャリーフラグは、最上位ビットからの桁上がりや桁下がりが発生したことを示します。
- 符号フラグは、演算結果の最上位ビットを参照して結果が負数であるかを表します。
- オーバフローフラグは、符号付き演算において表現可能な数値範囲を超過したことを通知します。

比較命令（CMP）は内部的に引き算を行ってこれらのフラグを更新し、直後の条件分岐命令がフラグの状態を判定してジャンプ先を決定する形です。

```text
CMP R1, R2
BEQ equalLabel  // 等しければ分岐
```

## 処理する幅と演算器の用途を分ける

### 14 ワード

CPUが内部で自然に一括処理できる基本のビット幅を**ワード**（語）と呼びます。
32ビットCPUや64ビットCPUという表現は、汎用レジスタのビット幅、内部バスの幅、扱えるメモリアドレス空間の広さなどを総合した特徴を指すものです。
ただし、あらゆる命令やデータが常にワード幅そのもので扱われるとは限りません。

- ビットは、0または1を表す情報の最小単位です。
- バイトは、通例として8個のビットを束ねた単位です。
- キャラクタは、文字コードの1文字を表す単位であり、符号化方式によって必要なバイト数が変化します。
- ワードは、特定のCPU設計において標準的に扱われる処理の基本単位です。

### 15 プロセッサの種類

各種レジスタは、命令実行に必要な一時記憶の役割を機能ごとに分担した機構でした。
これに対し、どのような演算回路を重点的に搭載し、何を並列に処理するかという点では、プロセッサそのものの用途に応じた設計の分岐が生じます。

#### 15.1 CPU

多様な命令体系と複雑な制御ロジックを柔軟にこなす万能型のプロセッサです。
OSの基本制御から一般的なアプリケーションの実行まで、システム全体のオーケストレーションを担います。

#### 15.2 GPU

これに対して`GPU`（Graphics Processing Unit）は、無数の画素や3次元ポリゴンの頂点計算など、同一パターンの単純な浮動小数点演算を大量並列で処理することに特化したプロセッサです。
構造が比較的シンプルなコアを数千個単位で並列配置しており、膨大なデータに対して同一の演算を一斉に適用する処理で圧倒的なスループットを叩き出します。
一方で、複雑な条件分岐が入り乱れる処理では性能が落ちやすいため、CPUとの得意分野の棲み分けが成り立っている形です。

#### 15.3 GPGPU

この超並列演算能力をグラフィックス以外の汎用科学計算に転用する技術体系を`GPGPU`（General-Purpose computing on GPU）と呼びます。
大規模な行列積、物理シミュレーション、深層学習のモデル訓練などで標準的な計算基盤として定着しているわけです。
ただし、CPUとGPUの間でデータを送受信する転送遅延や、アルゴリズムの並列化可能比率がシステム全体の処理速度を制約する点には注意を要します。

#### 15.4 DSP

音声信号、画像フィルタ、無線通信の電波処理といったデジタル信号処理に特化したプロセッサが`DSP`（Digital Signal Processor）です。
積和演算のハードウェアアクセラレータ、リングバッファを効率よく巡回するメモリアドレッシング、一定周期で確実に処理を終えるリアルタイム性を備えています。

#### 15.5 AIチップとTPU

深層学習（ディープラーニング）で行われる膨大な行列演算やテンソル計算を専門に引き受けるのが、AIアクセラレータ（AIチップ）です。
代表例である`TPU`（Tensor Processing Unit）は、多次元配列であるテンソルの演算に最適化された専用設計のプロセッサとして知られています。
演算精度を意図的に低減させて処理量を稼ぐ工夫や、メモリ間のデータ転送を極限まで削減するシストリックアレイ構造などを採用し、電力効率を飛躍的に高めているわけです。

### 16 専用化の利点と代償

特定の計算に特化した専用ハードウェアを組み込むと、同じ消費電力や半導体面積の中で桁違いの処理速度を引き出しやすくなります。
その一方で、設計対象外の一般的な処理には柔軟に対応できず、専用のAPIやCPUとのデータ受け渡しコストが新たな足かせとなりかねません。
負荷が途切れて専用回路が遊休状態に陥れば、投じたハードウェア資源の利用効率も悪化してしまいます。

現代のシステムアーキテクチャでは、汎用CPUに加えてGPU、画像処理エンジン、暗号化アクセラレータ、AI推論コアなど、異なる特性のプロセッサを適材適所で協調動作させる設計が一般的です。
このような異種混合のアーキテクチャを**ヘテロジニアス**構成と呼びます。
特定回路のピーク性能だけでなく、プロセッサ間でデータをやり取りする遅延や各回路の稼働率までをトータルで見渡す視野が求められるわけです。

## 一つの読込み命令を追う

### 17 一命令の中で部品が協力する

「主記憶1000番地のデータを汎用レジスタR1に読み込む」という基本的な命令を例にとり、各部品の連動を順を追って確認してみましょう。

1. プログラムカウンタ（PC）が指す番地から命令コードをフェッチし、命令レジスタ（IR）へ格納する。
2. デコーダがIRの命令部を読み解き、「主記憶からの読込み命令」であると判断する。
3. 命令内のオペランドで指定されたアドレス1000を、メモリアドレスレジスタ（MAR）にセットする。
4. MARのアドレス信号とともに、主記憶に対して読出し制御信号を送出する。
5. 主記憶から読み出されたデータがデータバスを経由してデータレジスタ（DR）に到着する。
6. DRに保持されたデータを汎用レジスタR1へと転送する。
7. PCの値をインクリメントし、次の命令のアドレスを指し示す。

レジスタの名前を個別に暗記する作業から一歩進めて、「次の命令の住所」「現在実行中の命令」「メモリの住所」「運ばれる荷物」「計算途中の作業台」という役割の有機的な連携として捉える視点が大切です。
