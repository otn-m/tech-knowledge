# 第3章・第2話　CPUの部品とレジスタ――一番近い小さな作業机

CPUは、Central Processing Unit、中央処理装置です。プログラムの命令を取り出し、解釈し、計算し、ほかの装置を制御します。

一つの黒い部品に見えても、内部には役割の違う回路があります。

```text
CPU
├─制御装置
├─演算装置 ALU・FPUなど
├─レジスタ
├─キャッシュ
└─内部の伝送路
```

この授業では、特にレジスタを「何を一時的に覚える箱か」で区別します。

---

## 1 CPUは主記憶へ直接何でも置かない

主記憶はCPUより遠く、読み書きに時間がかかります。演算のたびに遠い主記憶へ往復すると遅くなります。

そこでCPU内部に、今すぐ使う値や住所を置くごく小さな高速記憶を持ちます。これが**レジスタ**です。

```text
主記憶から値をレジスタへ読む
       ↓
レジスタ同士で計算する
       ↓
結果をレジスタへ置く
       ↓
必要なら主記憶へ書く
```

レジスタは速い代わりに数が限られます。コンパイラは、どの値をどのレジスタへ置くか割り当てます。

## 2 制御装置

制御装置は命令の進行役です。

- 次の命令がある番地を示す。
- 主記憶へ読出しを指示する。
- 取り出した命令を解読する。
- 演算装置、レジスタ、入出力へ制御信号を送る。
- 分岐、割込みなどで次の命令位置を変える。

制御装置の一部に、命令のビット列を意味ある制御信号へ変える**デコーダ**、命令解読器があります。

## 3 演算装置

### 3.1 ALU

**ALU**は整数の算術演算、論理演算、比較、シフトなどを行います。

内部には次の回路があります。

- 加算器――足し算をする。
- 補数器――負数表現や引き算のため補数を作る。
- 乗算器――掛け算をする。
- シフタ――ビットを左右へずらす。

引き算`A-B`を、Bの2の補数を作って`A+(-B)`という加算で行う回路があります。第1章の補数が、実際の演算回路へつながります。

### 3.2 FPU

**FPU**、Floating-Point Unitは、浮動小数点数の加減乗除などを行う演算回路です。

整数加算とは、指数をそろえ、仮数を計算し、正規化し、丸める必要があるため処理が違います。CPUに内蔵されるのが一般的ですが、概念上は役割を区別します。

### 3.3 積和演算器

掛け算の結果を累積値へ足す処理を一まとまりで行う回路を**積和演算器**、MACと呼びます。

```text
accumulator = accumulator + a × b
```

信号処理、行列計算、機械学習ではこの形を大量に使うため、専用回路で高速化します。

## 4 アキュムレータ

演算結果を累積して置くレジスタを**アキュムレータ**、累算器と呼びます。

一つのアキュムレータを中心にするCPUで、`A+B+C`を計算するイメージです。

```text
ACC ← A
ACC ← ACC + B
ACC ← ACC + C
```

**一オペランド命令**は、ACCを暗黙の演算対象・結果格納先として使い、命令へはもう一方の対象だけを明示する形式です。数値を一つしか使えないという意味ではありません。現在のCPUは複数の汎用レジスタを使うことが多いですが、この形式の理解にアキュムレータが役立ちます。

## 5 汎用レジスタ

数値、住所、途中結果など、さまざまな用途へ使えるレジスタが**GR**、General Register、汎用レジスタです。

```text
R1 ← 5
R2 ← 7
R3 ← R1 + R2
```

命令セットによって、レジスタ数、幅、特別な役割が違います。

## 6 プログラムカウンタ

次に取り出す命令の番地を持つレジスタが**プログラムカウンタ**、PCです。

命令アドレスレジスタ、命令カウンタ、逐次制御カウンタと呼ぶ資料もあります。

```text
PC = 100
番地100の命令を取る
PC = 104  ← 次の命令へ
```

通常は次へ進みます。分岐命令なら、PCへ別の番地を入れます。関数呼出し、戻り、割込みもPCを変えます。

ここでPCは**Program Counter**の略です。Personal Computerと略語が同じだけで、Intel系CPU固有の名称ではありません。x86系では同じ役割の命令ポインタを通常IP、EIP、RIPと呼びます。

## 7 命令レジスタ

現在解読・実行している命令を持つレジスタが**IR**、Instruction Register、命令レジスタです。

```text
主記憶[PC] → IR
```

IRの命令部をデコーダが読み、「加算」「転送」「分岐」などの制御信号を作ります。

PCが「次の命令の住所」、IRが「今扱っている命令そのもの」です。

## 8 メモリアドレスレジスタ

主記憶のどの番地を読み書きするかを持つものが**MAR**、Memory Address Register、メモリアドレスレジスタです。

```text
MAR ← 1000
主記憶へ読出し信号
```

住所を載せる箱です。

## 9 データレジスタ・メモリレジスタ

主記憶との間で読み書きするデータを一時的に持つものが**DR**、Data Register、または**MR**、Memory Registerです。Memory Data Register、MDRと呼ぶ構成もあります。

```text
読出し: 主記憶[MAR] → DR
書込み: DR → 主記憶[MAR]
```

MARが宛先住所、DRが運ぶ荷物です。

## 10 インデックスレジスタ

配列などの繰返し位置を表す値を置き、命令中の住所へ足して実際の住所を作るものが**インデックスレジスタ**、指標レジスタです。

配列先頭が1000、一要素4バイト、i=3なら、先頭からの距離は`3要素×4バイト/要素=12バイト`、目的番地は`1000+12=1012`です。

```text
基準番地1000 + (添字3×4バイト/要素) = 1000 + 12バイト = 1012
```

命令側の住所を書き換えず、レジスタ値を更新して次要素へ進めます。

## 11 ベースレジスタ

プログラムやデータ領域の基準となる先頭番地を持つものが**ベースレジスタ**です。

命令には基準からの差、変位だけを書きます。

```text
ベース = 8000
変位   = 120
実効番地 = 8120
```

プログラムを主記憶の別位置へ移しても、ベース値を変えれば、命令中の相対的な差をそのまま使えます。

## 12 スタックポインタ

スタックの現在の先頭位置を示すレジスタが**スタックポインタ**、SPです。

関数呼出しでは、戻り番地、保存するレジスタ、局所変数などをスタックへ積みます。

```text
push 値 → SPを動かして保存
pop      → 値を読みSPを戻す
```

スタックが高番地から低番地へ伸びるか、その逆かはCPU・規約によります。

## 13 フラグレジスタ

演算結果の状態を表す小さな印を持つレジスタがあります。

- ゼロフラグ――結果が0。
- キャリーフラグ――最上位から桁上がり。
- 符号フラグ――結果の符号を示す。
- オーバーフローフラグ――符号付き範囲を超えた。

比較命令は実質的に引き算相当を行い、フラグを設定します。後の条件分岐がフラグを見て進む道を変えます。

```text
CMP R1, R2
BEQ equalLabel  // 等しければ分岐
```

## 14 ワード

CPUが自然に一まとまりとして扱うビット幅を**ワード**と呼びます。

32ビットCPU、64ビットCPUという表現は、汎用レジスタ幅や住所幅など複数の特徴と関係します。すべての命令・データが必ずその幅だけとは限りません。

- ビットは0か1の一桁。
- バイトは通常8ビット。
- キャラクターは文字符号の一単位として使われる語で、必要バイト数は符号化方式による。
- ワードはCPU設計上の基本処理幅。

## 15 CPUの種類

### 15.1 CPU

多様な命令と制御を扱う汎用的な処理装置です。OSやアプリケーションの主な制御を担います。

### 15.2 GPU

**GPU**、Graphics Processing Unitは、もともと多数の画素・頂点へ似た計算を並列に行う画像処理を得意とする演算装置です。

多数の比較的単純な演算器を持ち、同じ形の計算を大量データへ行うのに向きます。複雑な分岐を一つずつ行う仕事では、CPUが向く場合があります。

### 15.3 GPGPU

GPUを画像以外の汎用計算へ利用することを**GPGPU**、General-Purpose computing on GPUと呼びます。

行列計算、科学計算、機械学習などで使います。CPUとGPU間のデータ転送、並列化できる割合、分岐のばらつきが性能を左右します。

### 15.4 DSP

**DSP**、Digital Signal Processorは、音声、画像、通信波形などのデジタル信号処理へ最適化したプロセッサです。

積和演算、循環バッファ、固定時間処理などを効率よく行う命令・構造を持ちます。

### 15.5 AIチップ・TPU

ニューラルネットワークで大量に行う行列・テンソル演算へ特化したものをAIアクセラレータ、AIチップなどと呼びます。

**TPU**、Tensor Processing Unitは、テンソル演算へ最適化した専用プロセッサの名称です。テンソルは多次元の数値配列だと考えてください。

低い精度の数値を大量に高速計算する、データ移動を減らすなど、機械学習向けの工夫があります。

## 16 専用化の利点と代償

ある計算へ専用化すると、同じ電力や面積で高速化しやすくなります。しかし次の代償があります。

- 得意でない処理へ柔軟に使えない。
- 専用のプログラミング環境が必要。
- CPUとのデータ転送が必要。
- 利用率が低いと部品が待つ。

実際のコンピュータはCPUだけでなく、GPU、動画処理、暗号、AIなど異なる演算器を組み合わせます。これを**ヘテロジニアス**、異種混合の構成と呼びます。

## 17 一命令の中で部品が協力する

「主記憶1000番地の値をR1へ読む」を概念的に追います。

1. PCの番地から命令を取り、IRへ入れる。
2. デコーダが「読込み命令」と判断する。
3. 命令の住所1000をMARへ入れる。
4. 主記憶へ読出し信号を送る。
5. 返った値をDRへ受ける。
6. DRの値をR1へ移す。
7. PCは次の命令を指す。

レジスタ名を丸暗記するより、「次の命令」「今の命令」「記憶の住所」「運ぶデータ」「計算途中」という役割で追います。


## 応用情報技術者試験での扱われ方

- **典型設問:** 「レジスタをCPU内部へ置く理由は何ですか。」
- **条件語:** `レジスタ`を本文の定義と対応させます。
- **最初の着眼点:** 理由を求める対象を特定し、原因→仕組み→観測される結果の鎖を作ります。
- **途中の組立て・式:** 本文の成立条件を原因へ、処理や構造を仕組みへ、利点・欠点を結果へ対応させます。 本文の `A-B` を使います。記号、単位、成立条件を置いてから代入し、結果の意味まで答えます。
- **典型誤答と理由:** 『速い』『安全』など結果だけを書くと、どの仕組みがなぜ効くのか、例外条件が説明できません。
