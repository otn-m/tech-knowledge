# 第3章 第3話 命令とアドレス指定

命令の中に`1000`と書かれていても、CPUが実際に受け取る値は1000とは限りません。

```text
1000を値として使う              → 1000
1000番地を読む                  → memory[1000]
1000番地にある住所をさらに読む  → memory[memory[1000]]
```

同じ数値であっても、即値として扱うか、メモリアドレスとして扱うか、あるいはアドレスが格納された場所として扱うかによって意味が激変します。
CPUは、その数値を何段階たどるべきかを命令のフォーマットから正しく判断しなければならないわけです。

## 処理と対象を命令に指定する

### 1 命令語

CPUが1つの命令として読み込むビット列を**命令語**と呼びます。
命令を正しく実行するには、何の処理を行うのか、そしてどのデータを対象とするのかを明確に指定しなければなりません。
概念的には、命令語は大きく次の2つの領域で構成される形です。

```text
┌──────────┬──────────────┐
│ 命令部       │ アドレス部       │
│ opcode       │ operand field  │
└──────────┴──────────────┘
```

加算、転送、分岐など、処理の種別を指定する領域が命令部（オペコード）です。
これに対し、演算対象となるレジスタ番号、即値データ、メモリアドレスなどを指定する領域がアドレス部（オペランド部）に当たります。
命令語の厳密なビット幅や内部構造は、CPUの命令セットアーキテクチャによって規定されているわけです。

### 2 オペランド

命令が指定する演算の対象実体を**オペランド**と呼びます。
日常的な算術式と対比してみると、次の式における5と3がオペランドであり、中央の`+`が演算子に相当する形です。

```text
5 + 3
```

機械語におけるオペランドは、定数値そのものであったり、特定のレジスタ番号であったり、主記憶上のアドレスであったりと多様な形態を取ります。
同じ加算処理を実行する場合でも、対象データをどこから調達してくるのかを指定するルールが欠かせません。

### 3 オペランド数による命令形式

命令内で明示的に指定するオペランドの数を減らせば、命令コードのビット長を短縮できる反面、暗黙のうちに利用されるレジスタやスタックが増えることになります。
加算処理を題材として、各形式の特徴を比較してみましょう。

#### 3.1 三オペランド形式

```text
ADD R3, R1, R2
```

`R3 = R1 + R2`のように、2つの入力元レジスタと1つの出力先レジスタを完全に独立して指定できる形式です。
元のレジスタR1やR2の値を上書きせずに保持できる利点があるものの、命令コード内に3つのレジスタ番号を収める領域が必要となります。

#### 3.2 二オペランド形式

```text
ADD R1, R2
```

`R1 = R1 + R2`のように、一方のレジスタを入力元と出力先で兼任させる形式です。
命令長を三オペランドより短く抑えられますが、R1の元データは計算結果によって上書きされてしまいます。

#### 3.3 一オペランド形式

アキュムレータ（ACC）を暗黙の演算対象兼出力先として固定する設計です。

```text
ADD X
```

`ACC = ACC + memory[X]`という動作を意味します。
命令コード内にアキュムレータを記述する必要がなく、メモリ番地Xだけを指定すればよいため、命令語をコンパクトに保てるわけです。

#### 3.4 ゼロオペランド形式

スタック領域の最上位に置かれたデータを暗黙のうちにポップして演算を行う方式です。

```text
PUSH 5
PUSH 3
ADD
```

この場合、ADD命令自体にはオペランドの指定が一切含まれず、スタックから2つの値を自動的に取り出して加算し、結果を再びスタックへプッシュします。
「1オペランド」や「ゼロオペランド」という呼称は、扱えるデータ数の上限というより、命令コードの中に明示的に記述するオペランドの個数に着目した分類です。

### 4 代表的な命令種類

主記憶やレジスタから取り出したデータを演算する際には、加算、減算、乗算、除算、符号反転などの算術演算命令を活用します。
ビット単位のAND、OR、XOR、NOTを施す処理は、論理演算命令の範疇です。
レジスタ同士の間や、主記憶とレジスタとの間でデータを転送する命令群は、転送命令（LOAD、STORE、MOVEなど）と呼ばれます。
処理の流れを条件に応じて切り替える際には、比較命令と分岐命令を巧みに組み合わせる構成です。
比較命令は2つの値を内部的に引き算してゼロフラグや符号フラグを設定し、データ自体は破棄する動作を取ります。
分岐命令はプログラムカウンタの値を書き換えることでジャンプを実現し、常に分岐する無条件分岐と、フラグの状態を判定して分岐する条件付き分岐に分かれる形です。
ビット列を左右にシフトさせる命令には、論理シフト、算術シフト、ローテーションが存在し、2倍や1/2倍の乗除算の代用やビットマスク処理で重宝されます。
入出力命令は周辺機器の状態を監視してデータを送受信しますが、主記憶と同じアドレス空間に各機器のレジスタをマッピングして通常命令で制御する方式も一般的です。
サブルーチン呼出し、復帰、割込みマスクの制御、プロセッサの停止などは、すべて制御命令に分類されます。

## ビット列から命令を実行する

### 5 機械語とアセンブリ表記

プロセッサの回路が直接解釈するのは0と1からなるビット列に他なりません。
しかし人間にとってビット列を直読することは困難であるため、意味の通る英単語や記号を用いたニーモニック表現を用います。

```text
機械語の例      0010 0001 0010
アセンブリ例    ADD R1, R2
```

アセンブラと呼ばれる変換プログラムが、`ADD`や`R1`といった記号を対応する機械語のビットパターンへと翻訳する仕組みです。
機械語のフォーマットやオペコードの割り当てはCPUアーキテクチャごとに完全に異なります。
同一の`ADD`というアセンブリ記述であっても、異なるISA上では全く別のビット列にエンコードされるわけです。

### 6 命令実行の四つの大段階

1つの命令が処理されるプロセスは、一般に次の4つの段階に分解できます。

1. フェッチ：命令コードを主記憶からCPU内部へ読み出す。
2. デコード：命令部を解読して制御信号を生成する。
3. オペランドフェッチ：命令実行に必要なデータを主記憶やレジスタから取得する。
4. 実行：演算器による計算、データの転送、分岐先アドレスの更新を行う。

演算結果をレジスタやメモリへ書き戻すライトバックを独立した段階として数える場合もあります。

### 7 フェッチをレジスタで追う

PC=100、命令長4バイトと仮定して各レジスタの推移を追ってみましょう。

```text
1. MAR ← PC          // 100
2. 主記憶読出し
3. DR ← memory[MAR]  // 番地100の命令
4. IR ← DR
5. PC ← PC + 4       // 104
```

内部実装の細部はプロセッサによって異なりますが、PCが次の番地を指し、MARがアドレスを送り、DRがデータを受け、IRに命令が保持されるという基本原則は一貫している形です。
条件分岐命令が成立した場合には、インクリメントされたPCに対して新たなジャンプ先アドレスが上書きされることになります。

## オペランドの数値から参照先を求める

### 8 有効アドレス

命令を取り出して解読したとしても、オペランド部に書かれた数値をそのままメモリアドレスとしてアクセスしてよいとは限りません。
レジスタの値をオフセットとして加算するのか、あるいはメモリ上に書かれたポインタをさらに参照するのかによって、アクセス先は劇的に変化します。
命令のアドレス部やレジスタの値を計算し、最終的に目的のデータが存在する主記憶上の実際のアドレスを**有効アドレス**（実効アドレス：EA）と呼ぶわけです。

```text
命令中の値 + レジスタ値など
          ↓ アドレス計算
有効アドレス
          ↓
主記憶のデータ
```

採用するアドレス指定方式の違いによって、有効アドレスを算出するための計算式がそれぞれ異なります。

### 9 共通の主記憶表

以後の具体例では、次の主記憶およびレジスタの値を共通の前提として使用する方針です。

| 番地 | 内容 |
|---:|---:|
| 1000 | 2000 |
| 1004 | 35 |
| 1012 | 80 |
| 2000 | 50 |
| 2020 | 99 |

レジスタの初期状態は次のように設定されているものとします。

```text
INDEX = 12
BASE  = 2000
PC    = 3000
```

### 10 即値アドレス指定

命令コード内のオペランドに書かれた数値1000を、外部のメモリを参照せずに定数データそのものとして直接扱う方式が**即値アドレス指定**です。

```text
LOAD R1, #1000
```

`#`を即値の識別子とする表記法であれば、レジスタR1には即座に数値1000が代入されます。
主記憶へのアクセスが一切発生しないため極めて高速ですが、命令コードの限られたビット幅に収まる小さな定数しか扱えません。

### 11 直接アドレス指定

オペランドに記述された数値1000を主記憶のアドレスとして解釈し、その番地に格納されているデータを読み出すのが**直接アドレス指定**（絶対アドレス指定）です。

```text
LOAD R1, [1000]
```

```text
EA = 1000
R1 = memory[1000] = 2000
```

この例では、1000番地を読み出して格納されている値2000をR1にロードします。
命令内に絶対的な番地を直接書き込むため分かりやすい反面、参照可能なメモリ範囲がオペランド部のビット数によって物理的に制約される形です。

### 12 間接アドレス指定

同じ1000という数値であっても、そこに「目的データの番地」が格納されているものとして2段階でメモリをたどる方式が**間接アドレス指定**です。

```text
LOAD R1, [[1000]]
```

この例では、次の順序でアクセスを実行します。

```text
memory[1000] = 2000  // ここに住所
EA = 2000
R1 = memory[2000] = 50
```

この方式では、まず1000番地を読み出してアドレス値2000を取得し、続いて2000番地にアクセスして目的データ50を取り出します。
主記憶への読出しが2回発生するため実行時間は長くなりますが、プログラム実行中に参照先を動的に切り替えるポインタ操作を実現できるわけです。

## レジスタを使って対象を指定する

### 13 レジスタアドレス指定

オペランドの参照先として外部の主記憶を介さず、プロセッサ内部のレジスタそのものを直接指定するのが、レジスタアドレス指定です。

```text
ADD R1, R2
```

主記憶バスを経由せずにCPU内部の超高速回路だけで完結するため、最も高い処理速度を誇ります。
これに対し、レジスタ内に保持されている数値をメモリアドレスとして解釈し、主記憶からデータを取得する方式をレジスタ間接アドレス指定と呼ぶ形です。

```text
R2 = 2000
LOAD R1, [R2]
```

レジスタR2に格納された番地2000を参照し、主記憶2000番地から値50を取り出してR1へ転送します。
ポインタ変数をレジスタ上に保持しておけば、メモリアクセスの回数を最小限に抑えつつ柔軟な間接参照を展開できるわけです。

### 14 インデックスアドレス指定

命令コード内の基準アドレスに対して、インデックスレジスタの保持するオフセット値を加算して有効アドレスを算出する方式を、インデックスアドレス指定と呼びます。

```text
LOAD R1, [1000 + INDEX]
```

INDEXレジスタの値が12であれば、計算の展開は次の通りです。

```text
EA = 1000 + 12 = 1012
R1 = memory[1012] = 80
```

インデックスレジスタの値が12であれば、`1000 + 12 = 1012`番地が有効アドレスとなり、その場所に格納されている値80が読み出されます。
配列の連続した要素をループ処理で順番にアクセスする場面で威力を発揮する仕組みに他なりません。

### 15 ベースアドレス指定

一方、配列要素の巡回に適したインデックス指定と対比され、プログラムやデータ領域全体の配置先を基準化する目的で使われるのがベースアドレス指定です。
ベースレジスタが保持する先頭番地に対して、命令コード内に記述された変位（ディスプレイスメント）を加算してアクセス先を求めます。

```text
LOAD R1, [BASE + 20]
```

BASE=2000、変位=20であるため、EA=2020、R1=99という結果が得られる形です。
プログラムがメモリ上のどの位置にロードされた場合でも、ベースレジスタの初期値を差し替えるだけでコード内の相対参照を完全に維持できます。
このアドレス調整処理はベース修飾と呼ばれ、マルチプログラミング環境での再配置を支える根幹技術に他なりません。

## 命令の位置を基準にする

### 16 相対アドレス指定

プログラムカウンタ（PC）が保持する現在のアドレスを基準とし、命令内の変位を加算して有効アドレスを導き出す方式が相対アドレス指定です。

```text
PC = 3000
変位 = -40
EA = 3000 + (-40) = 2960
```

PCが3000で変位が-40であれば、有効アドレスは2960となり、後方への条件分岐などがスムーズに記述できます。
プログラム全体がメモリの異なる番地へ再配置されたとしても、命令同士の相対的な距離関係は不変であるため、コードを一切書き換えることなくそのまま実行できる利点をもたらす形です。
基準となるPCの値が命令フェッチ後の次命令アドレスを指すのか、現在実行中の命令アドレスを指すのかは、各アーキテクチャの仕様書で確認する必要があります。

### 17 絶対アドレス指定

相対指定が基準点からの差分情報を用いるのに対し、分岐先などの完全なメモリアドレスを命令内に直接記述する方式が絶対アドレス指定です。

```text
JUMP 5000
PC = 5000
```

主記憶上の配置場所が動的に変更された場合には、命令内のアドレス記述を修正しなければ正しく動作しません。
相対指定が「ここから何歩進むか」を指定するのに対し、絶対指定は「何丁目何番地」を直接指定する方式だと捉えられます。
両者の違いを意識することが大切です。

## 住所の計算と読出しを分けて追う

### 18 アドレス修飾を組み合わせる

高度なプロセッサでは、ベースアドレス、インデックス、倍率（スケールファクタ）、変位を単一の命令内で組み合わせて有効アドレスを算出できます。

```text
EA = BASE + INDEX × SCALE + DISPLACEMENT
```

BASE=1000、INDEX=3、SCALE=4、変位=8なら、計算は次の通りです。

```text
EA = 1000 + 3×4 + 8 = 1020
```

構造体の配列に格納された特定メンバへのアクセスなどを、わずか1命令でスマートに指定できる強力な表現力を持つ形です。

### 19 ポインタを二回たどる例

間接アドレス指定の構造を、日常的な案内にたとえて整理してみましょう。

```text
封筒Aに「鍵は引出しB」と書いてある。
引出しBに鍵がある。
```

封筒Aに記されているのは、鍵の実体というより、鍵が保管されている別の場所を示す情報です。
同様に、1000番地に格納されている数値2000は、間接指定においては最終データそのものというより、次に開くべきメモリの番地として扱われるわけです。
直接指定と間接指定の混同は、2000という数値を受け取るのか、それとも2000番地に保管されている値50を受け取るのかという決定的な違いとなって現れます。

## 命令形式の便利さと実装の負担を比べる

### 20 RISCとCISC

多彩で柔軟なアドレス指定方式を用意すれば、わずか1命令で複雑なメモリアクセスを完結できる利便性が得られます。
しかしその利便性は、命令語長の肥大化や、命令デコード回路の複雑化という重いトレードオフを伴わざるを得ません。
この設計思想の対立が、**RISC**と**CISC**という2大アーキテクチャの分岐点となったわけです。

#### 20.1 RISC

**RISC**（Reduced Instruction Set Computer）は、命令の種類を絞り込んで規則正しい固定長フォーマットを採用し、パイプライン処理の効率化を極限まで追求する設計思想です。

- 命令の長さが均一な固定長フォーマットを採用する。
- 豊富な汎用レジスタを備える。
- 主記憶へのアクセスをLOAD命令とSTORE命令に限定する（ロード・ストアアーキテクチャ）。
- 単純なアドレス指定方式を中心とする。

1つの処理を完結させるために必要な命令のステップ数は増加しやすい傾向があります。

#### 20.2 CISC

**CISC**（Complex Instruction Set Computer）は、1つの命令で多彩かつ高度な処理を表現できるように工夫された命令セットです。

- 1バイトから複数バイトまで長さが異なる可変長命令を多用する。
- 複雑なアドレス修飾や高機能な複合命令を標準搭載する。
- 単一の命令内で主記憶アクセスと演算を同時に完結できる。

命令デコード回路が複雑になりやすい反面、プログラム全体のコードサイズを小さく抑えられる利点があります。

### 21 固定長命令と可変長命令

すべての命令が同一のビット長で設計されている体系が固定長命令です。
次の命令の格納位置を即座に計算できるため先読みや並列デコードが容易になりますが、単純な命令であっても常に最大のビット長を消費してしまう側面があります。
これに対し、命令の種類や指定するオペランドの数に応じて長さが変動する体系が可変長命令です。
必要な情報だけを無駄なく詰め込めるためメモリ効率に優れますが、命令の区切りを判定するデコーダの実装負荷が高くなります。

### 22 エンディアンとの区別

ビッグエンディアンやリトルエンディアンは、複数バイトで表される数値を主記憶の連続した番地に配置する際のバイトの並び順を定めた規約です。
オペランドの記述から有効アドレス（EA）を導き出す計算規則とは全く別次元の話である点に注意しなければなりません。
アドレス指定方式は「どの番地をアクセス先として求めるか」を決定し、エンディアンは「その番地を起点として複数バイトをどういう順序で読み書きするか」を定めます。
両者の概念を混同しないことが肝要です。

### 23 アドレス計算の解き方

試験問題や実践的な計算に挑む際は、必ず次の3ステップを段階的に記述し、番地を求める計算とデータ自体を取得する操作を明確に切り分けましょう。

1. 適用するアドレス指定方式の計算式を立てる。
2. 有効アドレス（EA）の数値を正確に計算する。
3. 必要に応じて主記憶の`memory[EA]`からデータを読み出す。

即値指定であれば主記憶の読出しステップは存在しません。
間接指定であれば、アドレスを取得するメモリアクセスと、データ本体を取得するメモリアクセスの2段階を明確に意識して追跡することが確実な理解へとつながります。
