# 第3章 第3話 命令とアドレス指定

命令の中に`1000`と書かれていても、CPUが受け取る値は1000とは限りません。

```text
1000を値として使う              → 1000
1000番地を読む                  → memory[1000]
1000番地にある住所をさらに読む  → memory[memory[1000]]
```

同じ数が、値にも、住所にも、住所を置いた場所にもなります。
CPUは、その数をどこまでたどるべきか、命令の形式から判断しなければなりません。

## 処理と対象を命令に指定する

### 1 命令語

CPUが1命令として読むビット列を**命令語**と呼びます。
命令を実行するには、何をするかと、何を対象にするかを指定します。
概念的には、命令語を次の2つに分けます。

```text
┌──────────┬──────────────┐
│ 命令部       │ アドレス部       │
│ opcode       │ operand field  │
└──────────┴──────────────┘
```

加算、転送、分岐など、処理の種類を示すのが**命令部**、オペコードです。
対象のレジスタ、値、住所などを示す部分は、**アドレス部**、オペランド部です。
命令の形式はCPUの命令セットで決まります。

### 2 オペランド

命令が指定する演算の対象を**オペランド**と呼びます。
普通の式で比べると、次の式では5と3がオペランド、+が演算子です。

```text
5 + 3
```

機械語命令のオペランドは、数値そのもの、レジスタ、主記憶上のデータなどです。
同じ加算でも、対象をどこから得るかを指定する必要があります。

### 3 オペランド数による命令形式

明示する対象を減らすと、命令内の指定部分を減らせる一方、暗黙に使う場所が増えます。
加算で、この関係を比べます。

#### 3.1 三オペランド形式

```text
ADD R3, R1, R2
```

`R3 = R1 + R2`のように、2入力と出力を別々に指定できます。
元のR1、R2を残せますが、命令内の指定部分が増えます。

#### 3.2 二オペランド形式

```text
ADD R1, R2
```

`R1 = R1 + R2`のように、一方を入力と出力で兼ねます。
R1の元の値は上書きされます。

#### 3.3 一オペランド形式

アキュムレータACCを暗黙の入力、出力にします。

```text
ADD X
```

`ACC = ACC + memory[X]`のような意味です。
命令にACCを書く必要がありません。

#### 3.4 ゼロオペランド形式

スタック最上部の値を暗黙に使います。

```text
PUSH 5
PUSH 3
ADD
```

ADDが2値を取り出して足し、結果を積みます。

「1オペランド」は数値を1個しか使えないという意味ではなく、命令に明示する対象が1個です。

### 4 代表的な命令種類

取り出した値を計算するときには、加算、減算、乗算、除算、符号反転などの算術演算命令を使います。
ビット単位のAND、OR、XOR、NOTなどは論理演算命令です。

計算する値をレジスタ間や主記憶とレジスタの間で移すのが、転送命令です。
`LOAD`、`STORE`、`MOVE`などの名前があります。

処理の順序を変えるときは、比較と分岐を組み合わせます。
比較命令は2値を比べてゼロや符号などのフラグを設定し、値自体を保存しない場合もあります。
分岐命令は次に実行する命令番地を変え、無条件分岐と、フラグなどの条件付き分岐があります。
ビット列を左右へずらすシフト命令には、論理シフト、算術シフト、回転があり、2倍や2分の1相当の計算、ビット抽出に使います。

入出力命令は入出力装置の状態を読み、データを送受信しますが、主記憶と同じ命令で装置レジスタを扱う方式もあります。
関数呼出し、戻り、割込みの許可と禁止、停止など、実行状態を制御するものは制御命令です。

## ビット列から命令を実行する

### 5 機械語とアセンブリ表記

CPUが読むのはビット列です。
人間は記号を使います。

```text
機械語の例      0010 0001 0010
アセンブリ例    ADD R1, R2
```

`ADD`や`R1`の記号を、アセンブラがオペコード番号とレジスタ番号に変換します。

機械語のビット配置はCPUごとに違います。
同じ`ADD`という記号でも、別ISAでは命令形式、ビット列が違います。

### 6 命令実行の四つの大段階

1命令の処理を大きく分けます。

1. **フェッチ**：命令を主記憶から取り出す。
2. **デコード**：命令部を解読する。
3. **オペランドフェッチ**：必要なデータを取る。
4. **実行**：演算、転送、分岐などを行う。

結果を主記憶に書く書戻しを別段階として数える説明もあります。

### 7 フェッチをレジスタで追う

PC=100、命令長4バイトとします。

```text
1. MAR ← PC          // 100
2. 主記憶読出し
3. DR ← memory[MAR]  // 番地100の命令
4. IR ← DR
5. PC ← PC + 4       // 104
```

CPUによって内部動作は違いますが、PCが次命令を示し、MARで住所を送り、DRで受け、IRに命令を置く関係を追えます。

分岐命令を実行すれば、増やしたPCを分岐先に上書きします。

## オペランドの数値から参照先を求める

### 8 有効アドレス

命令を取り出して解読できても、オペランド欄の数値をそのまま主記憶番地としてよいとは限りません。
レジスタの値を足すのか、主記憶にある住所をもう一度たどるのかによって、実際に読む場所が変わります。

命令のアドレス部やレジスタから計算し、実際にデータにアクセスする主記憶番地を**有効アドレス**、実効アドレス、EAと呼びます。

```text
命令中の値 + レジスタ値など
          ↓ アドレス計算
有効アドレス
          ↓
主記憶のデータ
```

アドレス指定方式ごとに、EAの求め方が違います。

### 9 共通の主記憶表

以後、同じ表を使います。

| 番地 | 内容 |
|---:|---:|
| 1000 | 2000 |
| 1004 | 35 |
| 1012 | 80 |
| 2000 | 50 |
| 2020 | 99 |

レジスタは次とします。

```text
INDEX = 12
BASE  = 2000
PC    = 3000
```

### 10 即値アドレス指定

命令の中の1000を、そのまま値として使うのが即値アドレス指定です。

```text
LOAD R1, #1000
```

`#`を即値の印とする表記なら、R1に数値1000を入れます。
1000番地は読まないため、結果は1000です。
小さな定数をすぐ使えますが、命令の値欄に入る範囲に制限があります。

### 11 直接アドレス指定

1000を値ではなくデータの番地として使うのが、直接アドレス指定です。
命令のアドレス部を、そのまま参照先にします。

```text
LOAD R1, [1000]
```

```text
EA = 1000
R1 = memory[1000] = 2000
```

命令が住所を直接指定するため、住所範囲はアドレス部のビット数に制約されます。

### 12 間接アドレス指定

同じ1000でも、そこに参照先の住所が入っていると解釈すれば、もう1段たどります。
間接アドレス指定では、命令で示した場所にデータそのものではなく、データの住所が入っています。

```text
LOAD R1, [[1000]]
```

この例では、次の順序で読みます。

```text
memory[1000] = 2000  // ここに住所
EA = 2000
R1 = memory[2000] = 50
```

主記憶を1回余分に読む代わりに、ポインタや動的な参照先を扱えます。

## レジスタを使って対象を指定する

### 13 レジスタアドレス指定

ここまでの指定では、命令中の値や主記憶の内容を使いました。
オペランドにレジスタそのものを指定する方法もあります。

```text
ADD R1, R2
```

主記憶に行かずCPU内のレジスタを使うため高速ですが、使えるレジスタ数は限られます。

### 14 レジスタ間接アドレス指定

レジスタに値そのものを置く代わりに、データの住所を入れると、レジスタ間接アドレス指定になります。

```text
R2 = 2000
LOAD R1, [R2]
```

EA=2000、R1=50です。
配列やポインタを順にたどるときは、R2を更新して参照先を変えます。

### 15 インデックスアドレス指定

レジスタの値をそのまま住所にする方法とは別に、命令中の基準住所へ足す方法もあります。
インデックスアドレス指定は、インデックスレジスタの値を足して参照先を求めます。

```text
LOAD R1, [1000 + INDEX]
```

INDEX=12なので、

```text
EA = 1000 + 12 = 1012
R1 = memory[1012] = 80
```

配列のi番目にアクセスするのに向きます。
要素幅4なら、INDEXに`i×4`を入れるか、CPUが倍率を指定できる場合があります。

この加算を**インデックス修飾**と呼びます。

### 16 ベースアドレス指定

インデックス指定が繰返し位置の変化に向くのに対し、ベース指定では領域の配置先を基準にします。
ベースレジスタに命令中の変位を足して参照先を求めます。

```text
LOAD R1, [BASE + 20]
```

BASE=2000なので、EA=2020、R1=99です。

プログラムやデータの配置先が変わっても、ベースレジスタを直せば相対位置20を使えます。
この住所調整を**ベース修飾**と呼びます。

## 命令の位置を基準にする

### 17 相対アドレス指定

現在の命令位置付近を基準に、PCと変位を足して分岐先などを求めます。

```text
PC = 3000
変位 = -40
EA = 3000 + (-40) = 2960
```

近くの分岐先を小さな差で表せます。
プログラム全体を別住所に移しても、命令間の差が同じなら動かしやすくなります。

PCがフェッチ後の次命令を指すか、現在命令を指すかなど、基準はISA仕様で確認します。

### 18 絶対アドレス指定

相対指定が基準からの差を使うのに対し、絶対指定では、分岐先などの絶対的な番地を命令で指定します。

```text
JUMP 5000
PC = 5000
```

配置が変わると住所を修正する必要があります。
相対指定は差、絶対指定は番地そのものです。

## 住所の計算と読出しを分けて追う

### 19 アドレス修飾を組み合わせる

CPUによっては、ベース、インデックス、倍率、変位を組み合わせます。

```text
EA = BASE + INDEX × SCALE + DISPLACEMENT
```

BASE=1000、INDEX=3、SCALE=4、変位=8なら、

```text
EA = 1000 + 3×4 + 8 = 1020
```

構造体中の配列などを1命令で指定できますが、式の各項が何を表すか分けます。

### 20 ポインタを二回たどる例

間接指定を日常の案内で考えます。

```text
封筒Aに「鍵は引出しB」と書いてある。
引出しBに鍵がある。
```

封筒Aの文字は鍵ではなく場所です。
同様に、1000番地の2000は、間接指定では値として使わず次の住所として使います。

直接指定と間接指定の取り違えは、2000という数を得るか、2000番地の50を得るかという明確な違いです。

## 命令形式の便利さと実装の負担を比べる

### 21 RISCとCISC

アドレス指定を豊富にすれば、1命令で複雑な場所へ到達できます。
その便利さは、命令の長さや解読回路の複雑さと引換えです。
命令セット全体の設計では、この交換条件がRISCとCISCの違いとして現れます。

命令セット設計の代表的な考えです。
現代の実装は両者の特徴を取り入れ、単純な二分が難しい場合もあります。

#### 21.1 RISC

**RISC**、Reduced Instruction Set Computerは、比較的単純で規則的な命令を中心にし、パイプライン化や高速実行をしやすくする考えです。

- 固定長命令が多い。
- レジスタ数を多く持つ設計がある。
- 主記憶アクセスをロード、ストア命令に分ける。
- 単純なアドレス方式を中心にする。

一仕事に必要な命令数は増える場合があります。

#### 21.2 CISC

**CISC**、Complex Instruction Set Computerは、多様で複雑な処理を1命令で表せる命令セットを持つ考えです。

- 可変長命令を含むことが多い。
- 多様なアドレス指定や複合命令を持つ。
- 1命令で多くの処理を行える。

命令解読が複雑になりやすい一方、コードを短く表せる場合があります。

### 22 固定長命令と可変長命令

すべて同じバイト数なら**固定長命令**です。
次の命令位置を計算しやすく、並列解読しやすい特徴がありますが、簡単な命令でも一定長を使います。

命令ごとに長さが違うものが**可変長命令**です。
必要情報だけを詰めてコードを小さくできる一方、命令境界の判定と解読が複雑です。

命令長とCPUの「32ビット、64ビット」は同じ意味ではありません。

### 23 エンディアンとは別の話

ビッグエンディアンとリトルエンディアンは、多バイト数を主記憶の連続番地へ置くときのバイト順を定めます。
命令のオペランドから実効アドレスを求める規則とは別です。

命令中のアドレス方式は「どの番地を求めるか」、エンディアンは「複数バイトをその番地からどの順に置くか」です。
混同しません。

### 24 アドレス計算の解き方

ここまでの例で、命令中に同じ数値があっても、指定方式によって得られる値が変わることを見ました。
計算では必ず次の3行に分け、住所を求める段階と、その中身を読む段階を区別します。

```text
1. アドレス方式の式を書く。
2. 有効アドレスEAを計算する。
3. 必要ならmemory[EA]を読む。
```

即値指定なら主記憶を読みません。
間接指定なら、住所を得る読出しと、データを得る読出しを分けます。
