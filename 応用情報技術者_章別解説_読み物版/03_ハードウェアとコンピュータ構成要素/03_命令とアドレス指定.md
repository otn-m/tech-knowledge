# 第3章・第3話　命令とアドレス指定――その数は値か、住所か


## このファイルで初めて使う用語

本文で使う前に、ここでは次の意味を置きます。略語は正式名、日本語名、本文での役割の順です。

- **EA**：Enterprise Architecture（エンタープライズアーキテクチャ）。企業全体の業務、データ、アプリ、技術を体系化し、現状から将来像へ導く設計・管理方法。（[詳説](<../02_アルゴリズムとプログラミング/20_マークアップ・データ記述・UML.md#36 DDL>)）


CPUの命令には、「足せ」「読め」「分岐せよ」という操作と、「何を対象にするか」が必要です。

```text
ADD R1, R2
```

これは概念的に「R1へR2を足せ」です。`ADD`が操作、`R1`と`R2`が対象です。

難しいのは、命令中に`1000`と書かれていたとき、それが数値1000そのものなのか、主記憶1000番地の値なのか、1000番地に書かれた別の住所なのかが、命令の方式で変わることです。

先に日常の封筒で三つを分けます。「1000円」と書いた紙そのものを使うのが即値、「1000番の引出しを開け、中の品を使う」のが直接指定、「1000番の引出しに書かれた2000番を読み、2000番の引出しを開ける」のが間接指定です。値、住所、住所を入れた場所を区別してから、命令表記へ進みます。

## 1 命令語

CPUが一命令として読むビット列を**命令語**と呼びます。

概念的には二部分へ分かれます。

```text
┌──────────┬──────────────┐
│ 命令部       │ アドレス部       │
│ opcode       │ operand field  │
└──────────┴──────────────┘
```

- **命令部**、オペコードは、加算、転送、分岐など何をするか。
- **アドレス部**、オペランド部は、対象のレジスタ、値、住所など。

命令の形式はCPUの命令セットで決まります。

## 2 オペランド

演算の対象を**オペランド**と呼びます。

```text
5 + 3
```

では5と3がオペランド、+が演算子です。

機械語命令のオペランドは、数値そのもの、レジスタ、主記憶上のデータなどです。

## 3 オペランド数による命令形式

### 3.1 三オペランド形式

```text
ADD R3, R1, R2
```

`R3 = R1 + R2`のように、二入力と出力を別々に指定できます。元のR1、R2を残せますが、命令内の指定部分が増えます。

### 3.2 二オペランド形式

```text
ADD R1, R2
```

`R1 = R1 + R2`のように、一方を入力と出力で兼ねます。R1の元の値は上書きされます。

### 3.3 一オペランド形式

アキュムレータACCを暗黙の入力・出力にします。

```text
ADD X
```

`ACC = ACC + memory[X]`のような意味です。命令へACCを書く必要がありません。

### 3.4 ゼロオペランド形式

スタック最上部の値を暗黙に使います。

```text
PUSH 5
PUSH 3
ADD
```

ADDが二値を取り出して足し、結果を積みます。

「一オペランド」は数値を一個しか使えないという意味ではなく、命令へ明示する対象が一個です。

## 4 代表的な命令種類

### 4.1 算術演算命令

加算、減算、乗算、除算、符号反転などです。

### 4.2 論理演算命令

AND、OR、XOR、NOTなど、ビット単位の論理演算です。

### 4.3 転送命令

レジスタ間、主記憶とレジスタ間で値を移します。`LOAD`、`STORE`、`MOVE`などの名前があります。

### 4.4 比較命令

二値を比べ、ゼロ・符号などのフラグを設定します。値自体を保存しない場合もあります。

### 4.5 分岐命令

次に実行する命令番地を変えます。無条件分岐と、フラグなどの条件付き分岐があります。

### 4.6 シフト命令

ビット列を左・右へずらします。論理シフト、算術シフト、回転があります。2倍・2分の1相当の計算やビット抽出に使います。

### 4.7 入出力命令

入出力装置の状態を読み、データを送受信します。主記憶と同じ命令で装置レジスタを扱う方式もあります。

### 4.8 制御命令

関数呼出し、戻り、割込み許可・禁止、停止など、実行状態を制御します。

## 5 機械語とアセンブリ表記

CPUが読むのはビット列です。人間は記号を使います。

```text
機械語の例      0010 0001 0010
アセンブリ例    ADD R1, R2
```

`ADD`や`R1`の記号を、アセンブラがオペコード番号とレジスタ番号へ変換します。

機械語のビット配置はCPUごとに違います。同じ`ADD`という記号でも、別ISAでは命令形式・ビット列が違います。

## 6 命令実行の四つの大段階

一命令の処理を大きく分けます。

1. **フェッチ**――命令を主記憶から取り出す。
2. **デコード**――命令部を解読する。
3. **オペランドフェッチ**――必要なデータを取る。
4. **実行**――演算、転送、分岐などを行う。

結果を主記憶へ書く書戻しを別段階として数える説明もあります。

## 7 フェッチをレジスタで追う

PC=100、命令長4バイトとします。

```text
1. MAR ← PC          // 100
2. 主記憶読出し
3. DR ← memory[MAR]  // 番地100の命令
4. IR ← DR
5. PC ← PC + 4       // 104
```

CPUによって内部動作は違いますが、PCが次命令を示し、MARで住所を送り、DRで受け、IRへ命令を置く関係を追えます。

分岐命令を実行すれば、増やしたPCを分岐先へ上書きします。

## 8 有効アドレス

命令のアドレス部やレジスタから計算し、実際にデータへアクセスする主記憶番地を**有効アドレス**、実効アドレス、EAと呼びます。

```text
命令中の値 + レジスタ値など
          ↓ アドレス計算
有効アドレス
          ↓
主記憶のデータ
```

アドレス指定方式ごとに、EAの求め方が違います。

## 9 共通の主記憶表

以後、同じ表を使います。

| 番地 | 内容 |
|---:|---:|
| 1000 | 2000 |
| 1004 | 35 |
| 1012 | 80 |
| 2000 | 50 |
| 2020 | 99 |

レジスタは次とします。

```text
INDEX = 12
BASE  = 2000
PC    = 3000
```

## 10 即値アドレス指定

命令中に値そのものを書きます。

```text
LOAD R1, #1000
```

`#`を即値の印とする表記なら、R1へ数値1000を入れます。1000番地を読まないので、結果は1000です。

小さな定数をすぐ使えますが、命令の値欄へ入る範囲に制限があります。

## 11 直接アドレス指定

命令のアドレス部を、そのままデータ番地にします。

```text
LOAD R1, [1000]
```

```text
EA = 1000
R1 = memory[1000] = 2000
```

命令が直接住所を書きます。住所範囲が命令のアドレス部のビット数に制約されます。

## 12 間接アドレス指定

命令で示した場所に、データそのものではなく、データの住所が入っています。

```text
LOAD R1, [[1000]]
```

概念的には次です。

```text
memory[1000] = 2000  // ここに住所
EA = 2000
R1 = memory[2000] = 50
```

主記憶を一回余分に読む代わりに、ポインタや動的な参照先を扱えます。

## 13 レジスタアドレス指定

オペランドがレジスタそのものです。

```text
ADD R1, R2
```

主記憶へ行かずCPU内のレジスタを使うため高速です。使えるレジスタ数は限られます。

## 14 レジスタ間接アドレス指定

レジスタにデータの住所を入れます。

```text
R2 = 2000
LOAD R1, [R2]
```

EA=2000、R1=50です。配列やポインタを順にたどるとき、R2を更新します。

## 15 インデックスアドレス指定

命令中の基準住所へ、インデックスレジスタの値を足します。

```text
LOAD R1, [1000 + INDEX]
```

INDEX=12なので、

```text
EA = 1000 + 12 = 1012
R1 = memory[1012] = 80
```

配列のi番目へアクセスするのに向きます。要素幅4なら、INDEXへ`i×4`を入れるか、CPUが倍率を指定できる場合があります。

この加算を**インデックス修飾**と呼びます。

## 16 ベースアドレス指定

ベースレジスタへ命令中の変位を足します。

```text
LOAD R1, [BASE + 20]
```

BASE=2000なので、EA=2020、R1=99です。

プログラムやデータの配置先が変わっても、ベースレジスタを直せば相対位置20を使えます。この住所調整を**ベース修飾**と呼びます。

## 17 相対アドレス指定

現在の命令位置付近を基準に、PCと変位を足して分岐先などを求めます。

```text
PC = 3000
変位 = -40
EA = 3000 + (-40) = 2960
```

近くの分岐先を小さな差で表せます。プログラム全体を別住所へ移しても、命令間の差が同じなら動かしやすくなります。

PCがフェッチ後の次命令を指すか、現在命令を指すかなど、基準はISA仕様で確認します。

## 18 絶対アドレス指定

分岐先などの絶対的な番地を命令で指定します。

```text
JUMP 5000
PC = 5000
```

配置が変わると住所を修正する必要があります。相対指定は差、絶対指定は番地そのものです。

## 19 アドレス修飾を組み合わせる

CPUによっては、ベース、インデックス、倍率、変位を組み合わせます。

```text
EA = BASE + INDEX × SCALE + DISPLACEMENT
```

BASE=1000、INDEX=3、SCALE=4、変位=8なら、

```text
EA = 1000 + 3×4 + 8 = 1020
```

構造体中の配列などを一命令で指定できますが、式の各項が何を表すか分けます。

## 20 ポインタを二回たどる例

間接指定を日常の案内で考えます。

```text
封筒Aに「鍵は引出しB」と書いてある。
引出しBに鍵がある。
```

封筒Aの文字は鍵ではなく場所です。同様に、1000番地の2000は、間接指定では値として使わず次の住所として使います。

直接指定と間接指定の取り違えは、2000という数を得るか、2000番地の50を得るかという明確な違いです。

## 21 RISCとCISC

命令セット設計の代表的な考えです。現代の実装は両者の特徴を取り入れ、単純な二分が難しい場合もあります。

### 21.1 RISC

**RISC**、Reduced Instruction Set Computerは、比較的単純で規則的な命令を中心にし、パイプライン化や高速実行をしやすくする考えです。

- 固定長命令が多い。
- レジスタ数を多く持つ設計がある。
- 主記憶アクセスをロード・ストア命令へ分ける。
- 単純なアドレス方式を中心にする。

一仕事に必要な命令数は増える場合があります。

### 21.2 CISC

**CISC**、Complex Instruction Set Computerは、多様で複雑な処理を一命令で表せる命令セットを持つ考えです。

- 可変長命令を含むことが多い。
- 多様なアドレス指定や複合命令を持つ。
- 一命令で多くの処理を行える。

命令解読が複雑になりやすい一方、コードを短く表せる場合があります。

## 22 固定長命令と可変長命令

すべて同じバイト数なら**固定長命令**です。次の命令位置を計算しやすく、並列解読しやすい特徴がありますが、簡単な命令でも一定長を使います。

命令ごとに長さが違うものが**可変長命令**です。必要情報だけを詰めてコードを小さくできる一方、命令境界の判定と解読が複雑です。

命令長とCPUの「32ビット・64ビット」は同じ意味ではありません。

## 23 エンディアンとは別の話

多バイト数を主記憶へどの順で置くかというビッグエンディアン・リトルエンディアンは、後のメモリ授業で扱います。

命令中のアドレス方式は「どの番地を求めるか」、エンディアンは「複数バイトをその番地からどの順に置くか」です。混同しません。

## 24 アドレス計算の解き方

問題では必ず次の三行へ分けます。

```text
1. アドレス方式の式を書く。
2. 有効アドレスEAを計算する。
3. 必要ならmemory[EA]を読む。
```

即値指定なら主記憶を読みません。間接指定なら、住所を得る読出しと、データを得る読出しを分けます。


## 応用情報技術者試験での扱われ方

- **典型設問:** 「命令語の命令部とアドレス部は何を表しますか。」
- **条件語:** `EA`、`命令語`、`命令部`、`アドレス部`を本文の定義と対応させます。
- **最初の着眼点:** 問われた語の上位概念、対象、役割、成立条件を分けて思い出します。
- **途中の組立て・式:** 『何であるか』に加え、『何へ何をするか』と、似た語との境界を一文にします。 本文の `R3 = R1 + R2` を使います。記号、単位、成立条件を置いてから代入し、結果の意味まで答えます。
- **典型誤答と理由:** 略語展開や日常語の印象だけでは、対象・役割・成立条件のいずれかが抜け、近い用語と区別できません。
