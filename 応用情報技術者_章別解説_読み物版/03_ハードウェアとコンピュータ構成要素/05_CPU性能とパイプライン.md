# 第3章 第5話 CPU性能とパイプライン

「3GHzのCPUだから速い」とは限りません。

周波数が高い方を選べばよいように思えます。
しかし、1命令に何クロック必要か、1つの仕事に何命令必要か、主記憶をどれほど待つか、同時に何命令進められるかによって、順位は逆転します。

処理時間は、次の式に分解できます。

```text
CPU実行時間
= 命令数 × 1命令当たり平均クロック数 ÷ 1秒当たりクロック数
```

周波数は式の一項にすぎません。
単位を追えば、どの要因を改善し、どの待ち時間が式の外にあるのかまで見分けられます。

## 1 クロック

CPU内部の多くの回路は、一定間隔の合図に合わせて状態を進めます。
この周期的な合図を**クロック**と呼びます。

```text
高 ┌─┐ ┌─┐ ┌─┐
   │ │ │ │ │ │
低 ┘ └─┘ └─┘ └─
    1   2   3   サイクル
```

一往復を**クロックサイクル**と呼びます。

## 2 周波数

1秒間に何回繰り返すかを**周波数**と呼び、単位はHz、ヘルツです。

- 1Hzは1秒に1回。
- 1kHzは1秒に1,000回。
- 1MHzは1秒に1,000,000回。
- 1GHzは1秒に1,000,000,000回。

3GHzなら1秒に30億クロックです。

## 3 サイクルタイム

一クロックにかかる時間を**サイクルタイム**、クロック周期と呼びます。

```text
サイクルタイム = 1 ÷ クロック周波数
```

1GHzなら、

```text
1 ÷ 1,000,000,000秒
= 1ナノ秒
```

ナノは10億分の1です。
2GHzなら0.5ns、4GHzなら0.25nsです。
周波数が2倍なら1周期は半分です。

## 4 CPI

1命令を実行するのに平均何クロック使うかを**CPI**、Cycles Per Instructionと呼びます。

```text
CPI = 総クロック数 ÷ 実行命令数
```

100命令を250クロックで実行したならCPI=2.5です。
平均なので小数になります。

CPIは命令種類、パイプライン停止、キャッシュミスなどで変わります。

## 5 CPU実行時間の式

命令数をI、平均CPIをC、周波数をfとします。

```text
必要クロック数 = I × C
一クロック時間 = 1/f

実行時間 = I × C × 1/f
         = I × C ÷ f
```

単位も確認します。

```text
命令 × クロック/命令 ÷ クロック/秒
= 秒
```

命令とクロックが消え、秒が残ります。

## 6 計算例

命令数6億、CPI=1.5、周波数3GHzとします。

```text
総クロック数 = 6億 × 1.5 = 9億
実行時間 = 9億 ÷ 30億/秒 = 0.3秒
```

同じ周波数でもCPIが2なら0.4秒です。
同じCPUでも命令数を4億に減らせば0.2秒です。

速さは周波数だけで決まりません。
また、この式が表すのは、平均CPIと周波数が対象区間を代表するとみなしたCPU処理時間です。
I/O待ちを含む経過時間とは区別し、動的に周波数が変わる場合は区間ごとに計算して足します。

## 7 命令ミックス

命令種類ごとに必要クロックが違います。
実際のプログラムで各命令が占める割合を**命令ミックス**と呼びます。

| 命令種類 | 割合 | CPI |
|---|---:|---:|
| 整数演算 | 50% | 1 |
| 主記憶アクセス | 30% | 3 |
| 分岐 | 20% | 2 |

平均CPIは重み付き平均です。

```text
0.5×1 + 0.3×3 + 0.2×2
= 0.5 + 0.9 + 0.4
= 1.8
```

単純に`(1+3+2)/3=2`とすると、出現割合を無視して誤ります。

## 8 MIPS

1秒に何百万命令を実行するかを**MIPS**、Million Instructions Per Secondと呼びます。

```text
MIPS = 1秒当たり命令数 ÷ 1,000,000
```

周波数3GHz、CPI=1.5なら、

```text
1秒当たり命令数 = 3,000,000,000 ÷ 1.5
                 = 2,000,000,000
MIPS = 2,000
```

## 9 MIPS比較の落とし穴

命令セットが違えば、1命令で行う仕事量が違います。

機械Aは複雑な1命令、機械Bは単純な3命令で同じ仕事をするかもしれません。
BのMIPSが高くても仕事全体が速いとは限りません。

同じプログラム、同じコンパイラ条件、同じ命令セットなど、比較条件をそろえます。
最終的には実際の仕事の実行時間が重要です。

## 10 FLOPS

1秒当たりの浮動小数点演算回数を**FLOPS**、Floating-point Operations Per Secondと呼びます。

- MFLOPSは毎秒100万演算。
- GFLOPSは毎秒10億演算。
- TFLOPSは毎秒1兆演算。

科学計算、画像、AIなどの演算能力を表します。

1命令がベクトルの8要素に積和演算を行うなら、掛算8回＋加算8回で16 FLOPと数える流儀があります。
ピーク性能と、実データで得る持続性能は、主記憶待ちや分岐で違います。

## 11 レイテンシとスループット

- **レイテンシ**は、1件が始まって終わるまでの時間。
- **スループット**は、一定時間に何件終えられるか。

洗濯機1台で1回60分ならレイテンシ60分です。
10台を同時に使えば、一着の時間は変わらなくても1時間の処理量は増えます。

CPU高速化でも、この2つを区別します。

## 12 パイプライン

実行時間の式でCPIを小さくできれば、同じ命令数と周波数でも処理は速くなります。
そこで、1命令が終わるまで次を止めるのではなく、複数命令の異なる段階を重ねます。

命令実行を複数段階に分け、異なる命令の段階を重ねる方式が**命令パイプライン**です。

5段階の例です。

```text
IF  命令取出し
ID  命令解読
EX  演算・アドレス計算
MEM 主記憶アクセス
WB  結果書戻し
```

## 13 パイプラインなし

各命令が5段階を全部終えてから次命令を始めます。

```text
命令1: IF ID EX MEM WB
命令2:                IF ID EX MEM WB
命令3:                               IF ID EX MEM WB
```

3命令で15段階分です。

## 14 パイプラインあり

各段階が別の回路を使えるなら重ねます。

```text
時刻     1  2  3   4   5   6   7
命令1   IF ID EX MEM  WB
命令2      IF ID  EX MEM  WB
命令3         IF  ID  EX MEM  WB
```

最初の命令は5サイクルかかりますが、その後は理想的に毎サイクル1命令完了します。

## 15 理想パイプラインのサイクル数

段数k、命令数nなら、理想的な必要サイクルは次です。

```text
k + n - 1
```

最初の命令がk段を満たすのにkサイクル、その後n-1命令が1サイクルずつ完了するからです。

5段、100命令なら104サイクルです。
非パイプラインで各命令5サイクルなら500サイクルです。

## 16 パイプラインは一命令を5倍速くしない

1命令のレイテンシは依然5段分です。
増えるのは主に多数命令のスループットです。

さらに実際には、各段の時間は完全に同じでなく、段間レジスタの費用、依存関係、分岐、主記憶待ちがあります。
理想倍率には届きません。

## 17 パイプラインハザード

理想計算では、段数を増やした後は1サイクルごとに命令を完了できます。
実際の命令列には、同じ回路を同時に使う要求、前の計算結果への依存、分岐先の未確定が混ざります。

重ねれば必ず速くなるのではなく、重ねられない箇所をどう処理するかが性能を決めます。

次命令を予定どおり進められない原因を**パイプラインハザード**と呼びます。

主に3種類です。

1. 構造ハザード
2. データハザード
3. 制御ハザード

## 18 構造ハザード

同じ時刻に2段階が同じ回路、記憶口を使おうとする資源競合です。

例として命令取出しとデータ読出しが、同じ一口の主記憶を同時に必要とします。

対策です。

- 命令用とデータ用のキャッシュを分ける。
- 複数ポートを持たせる。
- 片方を待たせる。

待たせる空きサイクルを**ストール**、泡のように空いたものをバブルと呼びます。

## 19 データハザード

前命令の結果を後命令が使うのに、まだ結果ができていません。

```text
命令1: R1 = R2 + R3
命令2: R4 = R1 + R5
```

命令2はR1を必要とします。

### 19.1 フォワーディング

結果がレジスタに正式に書き戻される前に、演算回路の途中から次命令に直接渡します。
**バイパス**とも呼びます。

### 19.2 ストール

結果が使えるまで後命令を待たせます。

### 19.3 命令スケジューリング

依存しない別命令を間に移し、待ち時間を埋めます。
コンパイラやCPUが行います。

データハザードには、読後書、書後読、書後書などの分類があります。
単純な順序実行パイプラインでは、まず「前の書込み結果を後が読む」RAW依存が中心です。

## 20 制御ハザード

条件分岐の結果が分かるまで、次に取る命令が決まりません。

```text
もしR1==0なら番地500へ
そうでなければ次へ
```

### 20.1 分岐予測

過去の傾向などから分岐する、しない、行先を予測し、先に命令を進めます。
正しければ待ちを減らせます。

### 20.2 予測失敗

間違った道で進めた命令を捨て、正しい道から取り直します。
パイプラインが深いほど、捨てる途中処理が増えます。

### 20.3 遅延分岐

分岐直後の一定数命令は分岐結果にかかわらず実行する仕様とし、その位置に有用命令を置く方式があります。
現在のすべてのISAが使うわけではありません。

## 21 スーパーパイプライン

各段階をさらに細かく分け、クロックを速くして多くの命令を重ねる方式を**スーパーパイプライン**と呼びます。

段が深いほど高周波数にしやすい一方、段間の費用、分岐予測失敗の損失、設計複雑さが増えます。

## 22 スーパースカラ

1サイクルに複数命令を取り出し、複数の演算器に発行して同時実行する方式を**スーパースカラ**と呼びます。

```text
サイクル1: 命令A→整数演算器、命令B→ロード装置
```

命令間依存と使う演算器をCPUが実行時に調べます。
幅4でも、毎回4命令実行できるとは限りません。

## 23 VLIW

**VLIW**、Very Long Instruction Wordは、同時実行できる複数操作を非常に長い1命令にまとめます。

どの操作を同時にするか、主にコンパイラが事前に計画します。
CPUの実行時制御を簡単にしやすい一方、コンパイラ性能、コードサイズ、異なる実装世代との互換性が課題になります。

## 24 ハイパースカラ

教材によって、非常に多くの命令を同時発行、実行する高度なスーパースカラ設計を**ハイパースカラ**と呼ぶことがあります。
一般的な厳密境界が1つに決まる用語ではないため、「複数命令並列をさらに拡大する考え」と捉えます。

## 25 アウトオブオーダ実行

プログラム順では待つ命令があっても、後ろの独立命令を先に実行する方式を**アウトオブオーダ実行**、順序外実行と呼びます。

```text
1. 主記憶からR1を読む  ← 待つ
2. R2=R1+1           ← 1に依存して待つ
3. R5=R3+R4          ← 独立なので先に実行可能
```

結果はプログラムの意味を壊さない順で確定させます。
依存追跡、レジスタリネーミング、リオーダバッファなど複雑な回路が必要です。

## 26 ベクトル処理

1命令で数値列の複数要素に同じ演算を行う方式を**ベクトル処理**、SIMD処理と呼びます。

```text
A[0..7] + B[0..7] → C[0..7]
```

画像、音声、行列に向きます。
条件分岐が要素ごとにばらばらだと効率が落ちることがあります。

## 27 性能測定の原則

1. 実際の用途に近い仕事を測る。
2. 入力サイズとデータをそろえる。
3. 初回と温まった後を区別する。
4. CPU時間だけでなく待ち時間、電力も見る。
5. 平均だけでなくばらつきと最悪を確認する。
6. コンパイラ、設定、版、環境を記録する。

1つのMIPSやクロック値で、全用途の性能順位を決めません。
