# 第1章2 整数と負の数――同じビット列をどう読むか


## この授業で分かること

- ビット列だけでは値の意味が決まらない理由。
- 符号なし整数と符号付き整数の違い。
- 二の補数が何の問題を解決するか。
- 表現できる範囲を越えるオーバフロー。
- ビットを左右へ動かすシフト演算。
- 十進の各桁をそのまま保存するBCD。

## 1 256枚の番号札を何へ割り当てるか

八ビットでは256通りの模様を作れます。

```text
00000000
00000001
00000010
   …
11111111
```

この256枚の札を、0から255までへ割り当てれば、負でない整数を表せます。

```text
00000000 →   0
00000001 →   1
   …
11111111 → 255
```

正か負かを示す印を**符号**と呼びます。負の値を使わない読み方なので、この方式の整数を**符号なし整数**と呼びます。

しかし、気温、口座残高の増減、建物の地下階などでは負の数も必要です。新しいビットを増やせないと仮定すると、同じ256模様を正と負へ分けて割り当てる必要があります。この読み方が**符号付き整数**です。

重要なのは、箱そのものが変わるわけではないことです。

```text
ビット列 11111111

符号なし整数として読む → 255
二の補数の符号付き整数として読む → -1
```

ビット列は札です。どの値へ割り当てた札なのかという約束が、データ型や表現形式です。

## 2 先頭を正負の印にする案

最も素朴には、八ビットの先頭を正負の印にできます。

```text
先頭0 → 正
先頭1 → 負
残り7ビット → 大きさ
```

この方式を**符号絶対値表現**と呼びます。

```text
00000101 → +5
10000101 → -5
```

分かりやすい方式ですが、問題があります。

```text
00000000 → +0
10000000 → -0
```

量として同じ0に二つの表現ができます。また、普通の二進加算回路で負数をそのまま足すと期待する結果にならず、正負に応じた追加処理が必要です。

そこで、多くのコンピュータでは別の割当てを使います。

## 3 二の補数――負数も同じ加算で扱いやすくする

多くのコンピュータで使われる符号付き整数の表現が**二の補数**です。

八ビットで`-5`の表現を作ります。

### 手順1 正の5を書く

```text
5 = 00000101
```

### 手順2 0と1をすべて入れ替える

0を1へ、1を0へ変えます。この操作を**ビット反転**と呼びます。

```text
00000101
↓ 反転
11111010
```

### 手順3 1を足す

```text
  11111010
+ 00000001
----------
  11111011
```

八ビット二の補数では`11111011`を-5として読みます。

## 4 なぜ反転して1を足すのか

作り方だけを暗記せず、加算で何が起きるかを見ます。

```text
  00000101   +5
+ 11111011   -5
----------
1 00000000
```

結果は九ビットになりました。しかし八ビットの箱には一番左の桁を置けないため、外へ出た1を捨てます。

```text
00000000 = 0
```

正の5と負の5を、普通の二進加算と同じ回路で足して0にできます。

八ビットの世界では、`100000000₂`、つまり256を一周分として考えられます。-5へ割り当てる札を`256-5=251`のビット列にすれば、5と足したとき256となり、八ビットからあふれた一周分を捨てて0になります。

```text
256 - 5 = 251
251₁₀ = 11111011₂
```

ビット反転して1を足す操作は、この`256-元の数`を二進数で簡単に作る方法です。

## 5 八ビット二の補数の範囲

八ビットには256模様しかありません。半分の128模様を0以上へ、残りを負数へ割り当てます。

0以上の側は、0も一席使います。

```text
0, 1, 2, …, 127       128個
```

負の側は次の128個です。

```text
-128, -127, …, -2, -1  128個
```

したがって範囲は`-128～127`です。

```text
00000000 =    0
00000001 =    1
   …
01111111 =  127
10000000 = -128
10000001 = -127
   …
11111110 =   -2
11111111 =   -1
```

なぜ正の最大値が128でなく127なのかというと、正側に割り当てた128模様のうち一つを0が使うためです。

### 一般のnビット

`n`ビットの二の補数で表せる範囲は次のとおりです。

```text
最小値 = -2ⁿ⁻¹
最大値 =  2ⁿ⁻¹ - 1
```

八ビットなら`n=8`です。

```text
最小値 = -2⁷ = -128
最大値 =  2⁷ - 1 = 127
```

`n-1`になるのは、先頭一ビットが正負側の区別に関係し、残る大きさが二の`n-1`乗を境に分かれるためです。

## 6 負のビット列を十進数へ戻す

`11110110`を八ビット二の補数として読みます。先頭が1なので負数です。

作ったときと逆向きに、絶対値を求めます。

### 手順1 1を引く

```text
11110110 - 1 = 11110101
```

### 手順2 0と1を反転する

```text
11110101
↓ 反転
00001010
```

`00001010₂=10₁₀`なので、元の値は-10です。

別の見方では、符号なしとしての値246から一周分256を引きます。

```text
246 - 256 = -10
```

どちらでも同じ答えです。

## 7 オーバフロー――箱の範囲を越える

八ビット符号付き整数の最大値127へ1を足します。

```text
  01111111   127
+ 00000001     1
----------
  10000000
```

`10000000`は二の補数では-128です。本当の答え128を八ビット符号付き整数では表せません。

表現できる範囲を上または下へ越えることを**オーバフロー**と呼びます。

オーバフローは、計算そのものが数学的に間違っているのではありません。答えを入れる箱が小さすぎる問題です。

```text
数学上の答え: 128
八ビットで許される最大値: 127
保存したビット列: 10000000
そのビット列の読み: -128
```

実際のプログラミング言語や処理方式では、反対側へ回る、エラーにする、より大きな型へ広げるなど動作が異なります。「整数は必ず反対側へ回る」と一般化してはいけません。

金額、時刻、個数、メモリの大きさ、アクセス権の判断でオーバフローを放置すると、見た目には計算が続いても重大な誤りになります。

### オーバフローを見つける考え方

同じ符号の数を足したのに、結果の符号が変わった場合は、二の補数のオーバフローを疑えます。

```text
正 + 正 → 負   おかしい
負 + 負 → 正   おかしい
```

正と負を足した場合、結果は二数の間に収まるため、この種類の加算オーバフローは起きません。

## 8 ビットをずらすシフト演算

ビット列を左右へずらす操作を**シフト演算**と呼びます。

正の二進数`00101100₂`を左へ一桁ずらし、右端へ0を入れます。

```text
00101100  = 44
01011000  = 88
```

各1が二倍大きい桁へ移るため、範囲内なら値も二倍になります。この操作が**左シフト**です。

右へ一桁ずらします。

```text
00101100  = 44
00010110  = 22
```

各1が半分の大きさの桁へ移るため、正の整数なら二分の一に相当します。右端から押し出されたビットは失われます。

### 論理シフト

空いた場所を0で埋める方式を**論理シフト**と呼びます。ビット列そのものを扱うときに使います。

### 算術右シフト

負数を二の補数として右へずらすとき、左端を0で埋めると正数へ変わってしまいます。そこで、元の符号を保つため左端の1を引き継ぐ方式があります。これが**算術右シフト**です。

```text
11111000  -8
↓ 算術右シフト
11111100  -4
```

掛け算や割り算と同じ結果になるのは、表現範囲、符号、端数処理などの条件を満たす場合です。端から押し出した情報は戻りません。

## 9 BCD――十進の各桁をそのまま持つ

十進数59を普通の二進数へ直すと、`00111011₂`です。

別の方法として、十進数の一桁ごとに四ビットを割り当てられます。

```text
十進の5 → 0101
十進の9 → 1001

59 → 0101 1001
```

この表し方を**BCD**と呼びます。Binary Coded Decimal、二進化十進数という意味です。

普通の二進数は数59全体を二進数へ直します。BCDは、十進の5と9を別々に二進符号へします。

```text
普通の二進数59  0011 1011
BCDの十進数59   0101 1001
```

四ビットには16模様ありますが、十進の一桁に必要なのは0～9の10模様だけです。1010～1111の六模様を使わないため、保存場所の効率は下がります。

一方、十進の各桁との対応が直接なので、十進表示や十進桁を正確に扱う処理に向きます。二桁を一バイトへ詰めて持つ形式をパック十進数と呼びます。

## 10 整数の型を選ぶ

整数を保存するときは、次を決めます。

- 負数が必要か。
- 最小値と最大値はいくつか。
- 将来どこまで増えるか。
- 足し算や掛け算の途中結果は範囲内か。
- 別のシステムと同じビット数・読み方を共有しているか。

一人の年齢だけなら小さな範囲で足ります。しかし、全利用者の利用秒数を長期間合計すると大きな値になります。入力値だけでなく、途中計算と将来の増加も見ます。
