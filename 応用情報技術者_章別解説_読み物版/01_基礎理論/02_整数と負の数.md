# 第1章2 整数と負の数――同じビット列をどう読むか

## 同じビット列が255にもマイナス1にもなる

8ビットの`11111111`には、負号も小数点もありません。
符号なし整数として読めば255ですが、二の補数の符号付き整数として読めば-1になります。
ビット列を受け取るだけでは、どちらの値か判断できません。

8ビットで作れる256通りの組み合わせを、どの値に割り当てるかという約束が必要です。
負数を表すには、その割当てを変えます。
さらに、割当てを決めても、計算結果が同じ8ビットに収まるとは限りません。

## 負数を含めた値の割当て

### 1 256枚の番号札を何へ割り当てるか

8ビットでは256通りの組み合わせを作れます。

```text
00000000
00000001
00000010
   …
11111111
```

この256通りのビット列に、0から255までの値を一つずつ割り当てれば、負でない整数を表せます。

```text
00000000 →   0
00000001 →   1
   …
11111111 → 255
```

正か負かを示す印を**符号**と呼びます。
負の値を使わない読み方なので、この方式の整数を**符号なし整数**と呼びます。

しかし、気温、口座残高の増減、建物の地下階などでは負の数も必要です。
新しいビットを増やせないと仮定すると、同じ256通りの組み合わせを正と負に分けて割り当てる必要があります。
この読み方が**符号付き整数**です。

ビット数は同じでも、割当てを変えると表せる値が変わります。

```text
ビット列 11111111

符号なし整数として読む → 255
二の補数の符号付き整数として読む → -1
```

この読み方を定める約束が、データ型や表現形式です。

### 2 先頭を正負の印にする案

負数が必要なら、先頭の1ビットを正負の印にするのが分かりやすそうです。

```text
先頭0 → 正
先頭1 → 負
残り7ビット → 大きさ
```

この方式を**符号絶対値表現**と呼びます。

```text
00000101 → +5
10000101 → -5
```

ところが、符号を独立させると、正の0と負の0ができます。

```text
00000000 → +0
10000000 → -0
```

量として同じ0に、2通りの表現を割り当てることになります。
また、普通の二進加算回路で負数をそのまま足すと期待する結果にならず、正負に応じた追加処理が必要です。

正負ごとの追加処理を避けるには、普通の二進加算を負数にも使えるように割当てを変える必要があります。

## 加算と両立する二の補数

### 3 二の補数――負数も同じ加算で扱いやすくする

普通の二進加算を負数にも使える割当てとして、多くのコンピュータは**二の補数**を採用しています。
8ビットで`-5`を表すには、正の5のビット列を反転し、1を足します。

#### 手順1 正の5を書く

```text
5 = 00000101
```

#### 手順2 0と1をすべて入れ替える

0を1に、1を0に変えます。
この操作を**ビット反転**と呼びます。

```text
00000101
↓ 反転
11111010
```

#### 手順3 1を足す

```text
  11111010
+ 00000001
----------
  11111011
```

8ビット二の補数では`11111011`を-5として読みます。

### 4 なぜ反転して1を足すのか

反転して1を足す理由は、正の5と、作った負の5を加算すると分かります。

```text
  00000101   +5
+ 11111011   -5
----------
1 00000000
```

結果は9ビットですが、8ビットで保存するため、左端へ繰り上がった1を捨てます。

```text
00000000 = 0
```

正の5と負の5を、普通の二進加算と同じ回路で足して0にできます。

8ビットの世界では、`100000000₂`、つまり256を1周分として考えられます。
-5に`256-5=251`のビット列を割り当てれば、5との和は256になります。
8ビットからあふれた1周分を捨てると0になり、正負の加算と結果が一致します。

```text
256 - 5 = 251
251₁₀ = 11111011₂
```

ビット反転して1を足す操作は、この`256-元の数`を二進数で簡単に作る方法です。

### 5 八ビット二の補数の範囲

8ビットには256通りの組み合わせしかありません。
半分の128通りの組み合わせを0以上に、残りを負数に割り当てます。

0以上の側には、正の整数だけでなく0も含めます。

```text
0, 1, 2, …, 127       128個
```

負の側は次の128個です。

```text
-128, -127, …, -2, -1  128個
```

したがって範囲は`-128～127`です。

```text
00000000 =    0
00000001 =    1
   …
01111111 =  127
10000000 = -128
10000001 = -127
   …
11111110 =   -2
11111111 =   -1
```

0以上に割り当てた128通りのうち1通りは0なので、正の最大値は127になります。

#### 一般のnビット

`n`ビットの二の補数で表せる範囲は次のとおりです。

```text
最小値 = -2ⁿ⁻¹
最大値 =  2ⁿ⁻¹ - 1
```

8ビットなら`n=8`です。

```text
最小値 = -2⁷ = -128
最大値 =  2⁷ - 1 = 127
```

先頭ビットで二つの側を分けると、それぞれに残る組み合わせは`2ⁿ⁻¹`通りです。
そのため、範囲の端にも`n-1`という指数が現れます。

### 6 負のビット列を十進数へ戻す

正負の割当てが分かれば、ビット列から負数の値を読み取れます。
`11110110`を8ビット二の補数として読んでみます。
先頭が1なので負数です。

作ったときと逆向きに、絶対値を求めます。

#### 手順1 1を引く

```text
11110110 - 1 = 11110101
```

#### 手順2 0と1を反転する

```text
11110101
↓ 反転
00001010
```

`00001010₂=10₁₀`なので、元の値は-10です。

別の見方では、符号なしとしての値246から1周分256を引きます。

```text
246 - 256 = -10
```

反転の手順も、256を引く手順も、同じ割当てを逆にたどっています。

## 表現範囲と演算の条件

### 7 オーバフロー――箱の範囲を越える

二の補数で加算をそろえられても、表現できる範囲は広がりません。
8ビット符号付き整数の最大値127に1を足すと、数学上の答えは128です。

```text
  01111111   127
+ 00000001     1
----------
  10000000
```

ところが、得られた`10000000`を8ビット二の補数として読むと-128です。
数学上の答え128を表す割当てがないため、ビット列の結果と期待する値が一致しません。

表現できる範囲を上または下に越えることを**オーバフロー**と呼びます。

この例では加算の規則より、結果を保存する形式の範囲が問題です。

```text
数学上の答え: 128
八ビットで許される最大値: 127
保存したビット列: 10000000
そのビット列の読み: -128
```

実際のプログラミング言語や処理方式では、反対側に回る、エラーにする、より大きな型に広げるなど動作が異なります。
「整数は必ず反対側に回る」と一般化してはいけません。

金額、時刻、個数、メモリの大きさ、アクセス権の判断でオーバフローを放置すると、見た目には計算が続いても重大な誤りになります。

#### オーバフローを見つける考え方

同じ符号の数を足したのに、結果の符号が変わった場合は、二の補数のオーバフローを疑えます。

```text
正 + 正 → 負   おかしい
負 + 負 → 正   おかしい
```

正と負を足した場合、結果は二数の間に収まるため、この種類の加算オーバフローは起きません。

### 8 ビットをずらすシフト演算

桁の大きさを利用すると、ビット列をずらして値を変えられます。
この操作が**シフト演算**です。
正の二進数`00101100₂`を左へ1桁ずらし、右端に0を入れます。

```text
00101100  = 44
01011000  = 88
```

各1が2倍大きい桁に移るため、範囲内なら値も2倍になります。
この操作が**左シフト**です。

ただし、左端から押し出されたビットは失われます。
表現範囲を越えれば、シフト後の値は元の値の2倍ではなくなり、掛け算の代わりには使えません。

同じ44を右へ1桁ずらすと、各桁の大きさは半分になります。

```text
00101100  = 44
00010110  = 22
```

各1が半分の大きさの桁に移るため、正の整数なら2分の1に相当します。
右端から押し出されたビットは失われます。

#### 論理シフト

空いた場所を0で埋める方式を**論理シフト**と呼びます。
ビット列そのものを扱うときに使います。

#### 算術右シフト

負数を二の補数として右にずらすとき、左端を0で埋めると正数に変わってしまいます。
そこで、元の符号を保つため左端の1を引き継ぐ方式があります。
これが**算術右シフト**です。

```text
11111000  -8
↓ 算術右シフト
11111100  -4
```

掛け算や割り算と同じ結果になるのは、表現範囲、符号、端数処理などの条件を満たす場合です。
端から押し出した情報は戻りません。

## 用途に合う整数表現

### 9 BCD――十進の各桁をそのまま持つ

整数の量を二進数へ直す以外に、十進数の各桁をそのまま符号化する方法もあります。
59全体を普通の二進数へ直せば`00111011₂`ですが、5と9にそれぞれ4ビットを割り当てることもできます。

```text
十進の5 → 0101
十進の9 → 1001

59 → 0101 1001
```

この表し方を**BCD**と呼びます。
Binary Coded Decimal、二進化十進数という意味です。

普通の二進数は数59全体を二進数に直します。
BCDは、十進の5と9を別々に二進符号に変換します。

```text
普通の二進数59  0011 1011
BCDの十進数59   0101 1001
```

普通の二進数より多くのビットを使うBCDは、保存方法として不利に見えます。
実際、4ビットには16通りの組み合わせがありますが、十進の1桁に必要なのは0～9の10通りだけです。
1010～1111の6通りの組み合わせを使わないため、保存場所の効率は下がります。

それでも、十進の各桁との対応が直接なので、十進表示や十進桁を正確に扱う処理には向きます。
2桁を1バイトに詰めて持つ形式をパック十進数と呼びます。

### 10 整数の型を選ぶ

`11111111`を255と読むか-1と読むかは、整数の型によって決まります。
型を選ぶ際には、読み方と表現範囲を用途に合わせて決めます。

- 負数が必要か。
- 最小値と最大値はいくつか。
- 将来どこまで増えるか。
- 足し算や掛け算の途中結果は範囲内か。
- 別のシステムと同じビット数と読み方を共有しているか。

1人の年齢だけなら小さな範囲で足ります。
しかし、全利用者の利用秒数を長期間合計すると大きな値になります。
入力値だけでなく、途中計算と将来の増加も見ます。
