# 第1章8 確率と統計――不確実な出来事を数で扱う

## 失敗率5パーセントだけでは、次の失敗を説明できない

バッチ処理を100回実行して5回失敗したとします。
手元の記録を単純に計算すれば、失敗率は 5% です。
しかし、ログを詳細に調べてみると、その5回の失敗がすべて「深夜2時のバックアップ処理中」に集中していたらどうでしょうか。

昼間の通常時間帯と、負荷の跳ね上がる深夜帯の処理に対して、一律に「次の処理が失敗する確率は 5% です」と言い切ってよいはずがありません。
昼間だけを見れば失敗率はほぼ 0% かもしれず、深夜帯に限れば失敗率は 50% を超えているかもしれないからです。
条件を無視して全体をひとまとめに丸めてしまうと、数字は現実の姿を覆い隠してしまいます。

割合を計算する前に、「何を1つの結果として数え、どの範囲を全体の分母とするのか」という境界を厳密に定めなければなりません。
さらに、手元で観測された過去の「割合」と、未来に何かが起きる「確率」は根本的に別物です。
データから不確実性を読み解き、将来の判断に耐えうる知見を導くための体系。
それが、確率と統計の世界です。

## 出来事を数え、条件をそろえる

### 1 確率は「起こりやすさ」を0から1の間で表す

先ほどのバッチ処理を例にとり、すべての条件が完全に同一であると仮定しましょう。
100回の処理のうち5回失敗したとき、観測された失敗の割合は次のように計算されます。

```text
失敗した回数 ÷ 全処理回数
= 5 ÷ 100
= 0.05 （5%）
```

数学において確率は、ある出来事がどれほど起こりやすいかを 0 から 1 の実数で表した指標です。

- 確率 0: 起こり得ない（有限通りの結果を扱う離散モデルの場合）
- 確率 1: 必ず起こる
- 確率 0.5: 長期的に繰り返すと、おおむね半分の頻度で現れる

確率はパーセント（百分率）で表現されることもありますが、`0.05` と `5%` は全く同じ数値を表しています。

ここで注意すべきなのは、手元の100回で5回起きたという事実は、あくまで「過去の観測結果（標本比率）」にすぎない点です。
次の100回でも寸分違わず5回失敗する保証はありません。
理論的な対称性（サイコロの目の均等さなど）、長期的な統計データ、数学的モデル、そして業務知識を組み合わせて、私たちは将来の確率を推測していきます。

### 2 標本空間と事象

確率を厳密に計算するには、まず「起こり得るすべての結果の範囲」を漏れなく定義しなければなりません。
歪みのない公平な6面のサイコロを1回振る場面を考えます。
現れ得る結果の全容は、次の6通りです。

```text
{ 1, 2, 3, 4, 5, 6 }
```

このように、起こり得るすべての結果を集めた集合を **標本空間** と呼びます。
そして、この標本空間の部分集合として切り取られる特定の出来事が「事象」です。

たとえば「偶数の目が出る」という出来事は、次の部分集合に相当します。

```text
{ 2, 4, 6 }
```

すべての目が等しい確率で出ると仮定できる場合、偶数が出る確率は次のように求まります。

```text
条件に合致する結果の数（3通り） ÷ 全結果の数（6通り）
= 3/6
= 1/2 （50%）
```

ただし、すべての結果が等確率でない場合、単純に「通り数」を割り算してはいけません。
各結果が持つ確率を個別に足し合わせる必要があります。

### 3 「AまたはB」の確率――和事象と加法定理

2つの事象が絡み合う確率を考えてみましょう。
事象 A を「偶数の目が出る」、事象 B を「4以上の目が出る」とします。

```text
A = { 2, 4, 6 }  （3通り）
B = { 4, 5, 6 }  （3通り）
```

「偶数が出るか、または4以上が出る（A または B）」確率はいくつになるでしょうか。
合致する目を実際に書き出してみると、`{ 2, 4, 5, 6 }` の4通りです。

もし A の3通りと B の3通りを安易に足し算してしまうと、`3 + 3 = 6通り` となり、全体の確率が 1（100%）になってしまいます。
両方に含まれている `4` と `6` を二重に重複して数えてしまっているからです。
したがって、重複した共通部分（積事象）を1回分だけ差し引かなければなりません。

```text
P(A ∪ B) = P(A) + P(B) - P(A ∩ B)
```

ここで記号 `P` は Probability（確率）を意味します。
数値を当てはめて計算してみましょう。

```text
P(A ∪ B)
= 3/6 + 3/6 - 2/6
= 4/6
= 2/3
```

もし2つの事象が同時に起きることが絶対にない場合、重なり部分 `P(A ∩ B)` は 0 になるため、単に足し合わせるだけで計算できます。

### 4 「AかつB」の確率――独立性と乗法定理

裏表が等確率（1/2）で出る硬貨を2回投げる場面を考えます。
「1回目が表になり、かつ2回目も表になる」確率はどうなるでしょうか。

1回目に表が出る確率は 1/2 です。
そして2回目に表が出る確率も、1回目の結果とは無関係に 1/2 となります。

```text
1/2 × 1/2 = 1/4 （25%）
```

このように、一方の事象が起きたかどうかが、もう一方の事象の起こりやすさに一切影響を与えないとき、2つの事象は **独立** であるといいます。
事象が互いに独立である場合、「A かつ B」が同時に起きる確率は、単純な掛け算で計算可能です。

```text
P(A ∩ B) = P(A) × P(B)
```

しかし、事象同士が影響を及ぼし合う関係にある場合、単純に掛け算することは許されません。
「A が起きたという事実を知ったあとで、B が起きる確率はどう変化するのか」を慎重に追いかける必要があります。

## 条件が変わると確率も変わる

### 5 条件付き確率――分母をAの世界へ絞り込む

1,000台のサーバ機器を監視しているデータセンターを想像してください。

- 実際にハードウェア障害（事象A）が発生している機器: 100台
- 障害が発生している100台のうち、警告アラート（事象B）を発報した機器: 90台

ここで、「障害が発生していると判明している状況下で、アラートが鳴る確率」を求めてみます。

「すでに障害Aが発生している」という前提条件が与えられたため、計算の基準となる分母は全1,000台から、実際に障害を抱える100台へと絞り込まれます。
その100台の中でアラートが鳴ったのは90台です。

```text
90 ÷ 100 = 0.9 （90%）
```

このように、ある事象 A が起こったという条件のもとで、別の事象 B が起こる確率を **条件付き確率** と呼び、縦線 `|` を用いて次のように表記します。

```text
P(B | A) = 0.9
```

これは「A という条件のもとでの B の確率（P of B given A）」と読みます。
一般的な計算式は次のとおりです。

```text
P(B | A) = P(A ∩ B) / P(A)
```

分子は「AとBの両方が起きる確率」、分母は「条件となったAが起きる確率」です。
全宇宙の中から「事象Aが起きた世界」だけを新たな分母（100%）として切り取り直し、その世界の中でBがどれほどの割合を占めているかを測る操作に他なりません。

### 6 独立と排反を混同しない

初学者が非常によく混同するのが、「独立」と「排反」の違いです。

**排反（互いに素）** とは、2つの事象が「同時に絶対に起きない」という関係を指します。
サイコロを1回振るとき、「1の目が出る」と「2の目が出る」は同時に起き得ないため排反です。

ここで考えてみてください。
もし「1の目が出た」と知らされたら、「2の目が出る」確率は即座に 0 になります。
片方の結果を知ることで、もう片方の確率が大きく変動してしまっているため、この2つの事象は全く独立ではありません。

一方、「独立」とは、片方の結果を知っても、もう片方の起こりやすさに「何の影響も与えない」という関係を指します。
硬貨を2回振るとき、1回目に表が出た事実を知っても、2回目に表が出る確率は 1/2 のまま変わりません。

```text
排反: 同時には絶対に起きない（交わりが空集合）
独立: 片方が起きても、他方の確率が変わらない（掛け算が成立）
```

確率がゼロでない2つの事象が「排反」であるなら、それらは「独立」ではあり得ません。
この2つの概念を明確に区別して整理しておきましょう。

### 7 ベイズの定理を導く

「原因 A があったときに、結果 B が生じる確率 `P(B | A)`」は、実験や測定から容易に把握できる場合が多いです。
しかし、現実のトラブルシューティングや医療診断で知りたいのは、往々にしてその逆向きの確率です。
「結果 B（警告アラート）を観測したとき、その背後にある原因 A（ハードウェア故障）である確率 `P(A | B)`」こそが知りたい情報といえます。

この「条件の向きを逆転させる」ための強力な数学的架け橋が、**ベイズの定理** です。
条件付き確率の定義式から、驚くほど自然に導くことが可能です。

```text
P(B | A) = P(A ∩ B) / P(A)
```

両辺に `P(A)` を掛ければ、次の式が得られるでしょう。

```text
P(A ∩ B) = P(B | A) × P(A)
```

同様に、A と B の立場を入れ替えて書けば、次の等式も成り立ちます。

```text
P(A ∩ B) = P(A | B) × P(B)
```

どちらの式の左辺も同じ同時確率 `P(A ∩ B)` ですから、右辺同士を等号で結んだのが次の式です。

```text
P(A | B) × P(B) = P(B | A) × P(A)
```

両辺を `P(B)` で割り算すれば、ベイズの定理の基本公式が完成するわけです。

```text
P(A | B) = P(B | A) × P(A) / P(B)
```

### 8 検査が陽性でも、本当に故障とは限らない（検査のパラドックス）

ベイズの定理の威力を実感するために、システム監視における有名な実例を考えてみましょう。

あるクラウド環境に 10,000台 のサーバが存在し、そのうち実際に未知の障害を抱えているサーバは全体の 1%（100台）だけだとします。

```text
障害あり: 100台
正常稼働: 9,900台
```

障害を検知するために導入したAI監視ツールの性能は、次のとおりです。

- 障害があるサーバに対して、90% の確率で正しく「陽性（障害疑い）」と警告する
- 正常なサーバに対しても、2% の確率で誤って「陽性」と誤警告（誤検知）してしまう

今、あるサーバについてこのツールが「陽性」アラートを発報しました。
現場のエンジニアは「精度90%のツールが警告を出したのだから、9割の確率で本当に故障しているはずだ」と慌てふためきます。

しかし、実際の機器の台数で内訳を整理してみると、全く異なる真実が浮かび上がります。

| サーバの状態 | 検査が「陽性」 | 検査が「陰性」 | 合計台数 |
|:---:|:---:|:---:|:---:|
| 障害あり | 90台 （100台 × 90%） | 10台 | 100台 |
| 正常 | 198台 （9,900台 × 2%） | 9,702台 | 9,900台 |
| 合計 | 288台 | 9,712台 | 10,000台 |

アラートが鳴ったサーバの総数は、`90 + 198 = 288台` です。
そのうち、本当に障害を抱えているのはたったの 90台 にすぎません。

アラートが出たサーバが真に故障している確率 `P(障害 | 陽性)` を計算してみましょう。

```text
90 ÷ 288 ≈ 0.3125 （約31.3%）
```

「精度90%」と謳われた優秀な監視ツールであっても、アラートが鳴った機器が実際に故障している確率は、3割程度にとどまります。
残りの約69%は、正常な機器が出した誤報（オオカミ少年）です。

なぜこのような直感との乖離が起きるのでしょうか。
元々の母集団において正常な機器（9,900台）が圧倒的多数を占めているため、わずか 2% の誤検知であっても、台数にすると 198台 もの大群になってしまうからです。

観測前の事象の起こりやすさ `P(障害)` を「事前確率」、証拠（陽性アラート）を得たあとに更新された確率 `P(障害 | 陽性)` を「事後確率」と呼びます。
ベイズの思考法は、新たな証拠を取り入れながら確信度を柔軟にアップデートしていく、現代AIの機械学習やデータ分析の中核をなす原理といえます。

## 結果を数値にして分布を調べる

### 9 確率変数と確率分布

出来事に「金額」や「損失コスト」といった具体的な数値を対応づけることで、確率論は意思決定の強力なツールへと進化するわけです。

サイコロを振った目に応じて、次のような賞金が得られるゲームを考えてみましょう。

```text
1 または 2 の目が出る → 0円
3 または 4 の目が出る → 100円
5 または 6 の目が出る → 300円
```

サイコロの出目という偶然の結果に応じて、値が自動的に決まる変数を **確率変数** と呼び、通常アルファベットの大文字 `X` などで表します。
この例では、確率変数 `X` は 0、100、300 の3つの値をとります。

確率変数が「どの値を、どれほどの確率でとるのか」という全体像を整理した対応関係が **確率分布** です。

| 賞金 `X` の値 | 起こる確率 `P(X)` |
|:---:|:---:|
| 0円 | 1/3 |
| 100円 | 1/3 |
| 300円 | 1/3 |

### 10 期待値――長期的な平均の見返り

このゲームを同じ条件で何度も繰り返したとき、1回あたり平均して何円の見返りが期待できるでしょうか。
確率変数がとり得る各値に、それぞれの発生確率を掛けて合計した値を **期待値** と呼び、記号 `E(X)` で表します。

```text
E(X) = Σ xᵢ × pᵢ
```

数値を代入してみます。

```text
E(X) = (0円 × 1/3) + (100円 × 1/3) + (300円 × 1/3)
     = 400 / 3
     ≈ 133.3円
```

1回サイコロを振って「133.3円」という小銭が実際に出るわけではありません。
何百回、何万回とプレイを繰り返したとき、1回あたりの平均獲得賞金がこの値へと限りなく近づいていくという「長期的な平均値」を表しています。

ただし、意思決定において期待値だけに頼るのは危険です。
「確実に100円もらえる選択肢」と、「50%の確率で0円、50%の確率で200円もらえる選択肢」は、どちらも期待値は同じ100円です。
しかし、後者には「一文無しになるリスク」というばらつきが存在します。
このばらつきを捉える指標が欠かせません。

### 11 平均値、中央値、最頻値――代表値の使い分け

観測したデータ全体を1つの代表的な数値で要約したいとき、私たちは無意識に「平均値」を使いがちです。
しかし、データの中に極端な外れ値が含まれていると、平均値は大きく歪んでしまいます。

たとえば、次の5人の年収データを考えてみましょう。

```text
300万円, 350万円, 400万円, 450万円, 5,000万円
```

- **平均値（Mean）**: 合計を人数で割った値。`(300 + 350 + 400 + 450 + 5000) ÷ 5 = 1,300万円`
- **中央値（Median）**: データを小さい順に並べたとき、ちょうど中央（5人なら3番目）に位置する値。`400万円`
- **最頻値（Mode）**: データの中で最も頻繁に出現する値。

1人だけ桁外れの大富豪（5,000万円）が存在するだけで、平均年収は 1,300万円 に跳ね上がってしまいます。
「平均年収は1,300万円です」と聞かされると、全員が裕福であるかのような錯覚に陥りますが、実態としては5人中4人（80%）が平均を遥かに下回っているのです。

このような所得分布やWebサイトの滞在時間のように、一部の極端な外れ値に引っ張られやすい左右非対称なデータを評価する際は、平均値よりも「中央値」のほうが実感に近い代表値となります。
どの代表値を使うべきかは、データのばらつき方によって慎重に判断しなければなりません。

### 12 分散と標準偏差――散らばり具合を数値化する

期待値や平均値が「データの重心」を示すのに対し、重心の周りにデータがどれほど広がっているかを示す指標が **分散** と **標準偏差** です。

あるサーバの応答時間（秒）を5回測定した2つのシステムAとBを比較してみましょう。

```text
システムA: 10秒, 10秒, 10秒, 10秒, 10秒  （平均 = 10秒）
システムB:  2秒,  6秒, 10秒, 14秒, 18秒  （平均 = 10秒）
```

どちらのシステムも平均応答時間はまったく同じ 10秒 です。
しかし、システムAは常に安定して10秒で応答するのに対し、システムBは2秒で終わることもあれば18秒も待たされることがあり、極めて不安定です。

この「平均からの離れ具合（偏差）」を数値化してみましょう。
単に平均との差を足し算すると、プラスとマイナスが打ち消し合って合計が 0 になってしまいます。
そこで、偏差を2乗してから平均をとることで、プラスの値として足し上げます。
これが **分散**（記号 `σ²` または `s²`）です。

```text
分散 = 各データの (値 - 平均値)² の合計 ÷ データ数
```

システムBの分散を計算してみます。

```text
偏差: (2 - 10), (6 - 10), (10 - 10), (14 - 10), (18 - 10)
    = -8, -4, 0, +4, +8

2乗: 64, 16, 0, 16, 64

分散 = (64 + 16 + 0 + 16 + 64) ÷ 5
     = 160 ÷ 5
     = 32
```

分散の値は `32` と求まりました。
しかし、2乗したことで単位が「秒の2乗」になってしまっており、直感的に解釈しづらいという弱点があります。
そこで、分散の平方根（ルート）をとって元のデータの単位に戻した値が **標準偏差**（記号 `σ` または `s`）です。

```text
標準偏差 σ = √32 ≈ 5.66秒
```

「システムBの応答時間は、平均10秒に対して、およそ ±5.66秒 程度のばらつきを抱えている」と、直感的に理解できるようになります。

#### 単位の異なるばらつきを比べる「変動係数」

「平均100kgで標準偏差が10kgの体重」と、「平均10gで標準偏差が5gのネジの重さ」では、どちらのほうがばらつきが大きいといえるでしょうか。
標準偏差の絶対値だけを見れば 10kgのほうが大きく見えますが、平均値に対する相対的な比率で見ると話は別です。

平均値に対する標準偏差の比率を百分率で表した指標を「変動係数（CV: Coefficient of Variation）」と呼びます。

```text
変動係数 = 標準偏差 ÷ 平均値
```

- 体重: `10kg ÷ 100kg = 0.1` （10%）
- ネジ: `5g ÷ 10g = 0.5` （50%）

変動係数を比べると、ネジの重さのほうが平均に対して遥かに激しくばらついていることが一目瞭然といえるでしょう。

#### 標本分散と不偏分散の違い

全数調査が叶わず、母集団から抜き出した一部の標本データ（サイズ `n`）から母集団全体の分散を推定したい場合、単純に `n` で割ると、真の分散よりも平均的に小さく見積もられてしまう（過小評価される）数学的性質があります。
標本データは自分自身の標本平均の周りに集まる傾向があるため、母平均の周りの広がりよりも見かけ上コンパクトに縮んでしまうからです。

このズレを補正するために、分母を `n` から差し引いて `n - 1` として計算するのが「不偏分散」です。
ITパスポートや基本情報では単純な分散（`n` で割る）が中心ですが、応用情報や実務の推測統計では、標本データに対して `n - 1` で割る不偏分散が不可欠な武器といえるでしょう。

### 13 離散型と連続型の確率分布

確率変数は、大きく2種類に分類できます。

- 離散型確率変数: サイコロの目、障害件数、Webサイトの訪問者数のように、`0, 1, 2, 3...` と飛び飛びの整数値をとるもの
- 連続型確率変数: サーバの応答時間、CPUの温度、通信トラフィック量のように、ある範囲内の任意の実数値を連続的にとり得るもの

連続型の場合、特定の「ぴったり3.00000...秒」というピンポイントの1点をとる確率は数学上 0 になってしまいます。
そのため、連続型の確率を扱う際は、「3秒から5秒の間に収まる確率」というように、確率密度関数のグラフの面積（積分）として確率を捉えるのが基本です。

### 14 二項分布――コイン投げの成功回数を数える

次の3条件を満たす試行が「ベルヌーイ試行」です。

- 各回の結果が「成功」か「失敗」の2通りしかない
- 成功する確率 `p` が毎回の試行で完全に一定である
- 各回の試行が互いに完全に独立している

この試行を `n` 回繰り返したとき、成功した合計回数 `k` が従う確率分布を **二項分布** と呼びます。

表が出る確率が 1/2 のコインを 3回 投げたとき、表がちょうど 2回 出る確率を求めてみましょう。
表（○）と裏（×）の組み合わせは、次の3通りが存在します。

```text
(○, ○, ×),  (○, ×, ○),  (×, ○, ○)
```

どのパターンも、発生する確率は `(1/2) × (1/2) × (1/2) = 1/8` です。
3通りの並び方がありますから、合計の確率は `3 × 1/8 = 3/8`（37.5%）となります。

これを一般化した二項分布の公式は次のとおりです。

```text
P(X = k) = ₙCₖ × pᵏ × (1 - p)ⁿ⁻ᵏ
```

ここで `ₙCₖ` は、`n` 回の中から成功する `k` 回のタイミングを選び出す組み合わせの数です。
製品の抜き取り検査で「100個中、不良品が2個以下である確率」を計算するときなどに幅広く使われます。

### 15 ポアソン分布――めったに起きない出来事の回数を捉える

二項分布は「あらかじめ試行回数 `n` が決まっている」状況を扱いました。
しかし、IT運用の現場では「試行回数は決まっていないが、一定時間内に平均して何件のイベントが発生するか」を扱いたい場面が多々あります。

- Webサーバに1分あたり何件のリクエストが届くか
- コールセンターに1時間あたり何件の電話がかかってくるか
- 半導体チップの一定面積の中に何箇所の微小な欠陥が混入するか

このように、滅多に起きない独立したイベントが、一定の時間や空間の中で発生する回数をモデル化したものが **ポアソン分布** です。

あるシステムにおいて、障害の平均発生頻度が「1時間に平均 `λ = 2件`」であるとします。
このとき、次の1時間に障害が「ちょうど `k = 1件`」だけ発生する確率は、次のポアソン分布の公式から計算されます。

```text
P(X = k) = (e⁻λ × λᵏ) / k!
```

ここで `e` は自然対数の底（ネイピア数: 約2.718）、`k!` は階乗（`k × (k-1) × ... × 1`）です。
数値を代入してみましょう。

```text
P(X = 1) = (e⁻² × 2¹) / 1!
         ≈ 0.1353 × 2 / 1
         ≈ 0.2707 （約27.1%）
```

ポアソン分布が成立するためには、「イベント同士が互いに誘発し合わず独立であること」「同時刻に複数のイベントが重なって起きないこと」「平均発生率が時間帯によって変動せず一定であること」という前提が必要です。
もしアクセス集中による連鎖障害のように、1つの障害が次の障害を引き起こすような状況では、ポアソン分布の前提が崩れてしまう点に留意してください。

### 16 正規分布――自然界と統計学の中心に君臨する釣鐘型

多数の小さな独立した偶然の要因が足し合わされるとき、そのデータの分布は不思議なほどに美しい左右対称の釣鐘型（ベルカーブ）へと近づいていきます。
この左右対称の確率分布が **正規分布（ガウス分布）** です。

中心の位置を決める平均 `μ`（ミュー）と、裾野の広がりを決める標準偏差 `σ`（シグマ）の2つのパラメータだけで形が完全に決まるのが大きな特徴です。

正規分布に従うデータには、極めて実用的な「幅の目安」が存在します。

```text
平均 ± 1σ の範囲内: 全データの 約 68.3% が収まる
平均 ± 2σ の範囲内: 全データの 約 95.4% が収まる
平均 ± 3σ の範囲内: 全データの 約 99.7% が収まる
```

製造業の品質管理で有名な「シックスシグマ（6σ）」活動は、不良品の発生率を `±3σ`（99.7%）よりも遥かに外側の極限まで抑え込もうとする思想から生まれています。

#### 異なるデータを比較する「標準化（zスコア）」

数学のテストで70点を取った生徒と、英語のテストで75点を取った生徒のどちらが優秀かを比べる場合、点数だけを比較しても意味がありません。
数学は平均40点の難問だったかもしれず、英語は平均80点の簡単なテストだったかもしれないからです。

異なる平均や標準偏差を持つデータを同一の物差しで公平に比較する変換処理が「標準化」です。
各データから平均値を引き算し、標準偏差で割り算を実行します。

```text
z = (x - μ) / σ
```

この計算によって得られた値 `z` が **標準得点（zスコア）** です。
zスコアは、「その値が平均値から標準偏差何個分だけ離れているか」を表す純粋な数値といえます。
zスコアを使えば、単位や難易度の異なるあらゆるデータを同一基準で横並びに評価できるわけです。

## 標本から母集団を推測する

### 17 母集団と標本

私たちがデータ分析を行うとき、調べたい対象の全員をくまなく調査できるケースは極めて稀といえます。

- 日本全国の全スマートフォンの通信速度を常時測定することは不可能
- 出荷されるすべてのハードディスクを破壊試験して寿命を測ることはできない

そこで統計学では、調査対象となる集団全体を「母集団」と呼び、母集団から一部だけを抜き出して実際に測定したデータの集まりを「標本（サンプル）」と呼びます。
手元の限られた標本データを丹念に分析し、背後にある巨大な母集団の真の姿を推し量る学問が「推測統計」です。

標本から母集団を正しく推測するには、サンプリング（抽出）の偏りを防がなければなりません。
Webサイト上でアンケートを募れば、製品に強い不満を持つユーザーが積極的に回答して不満率が高めに出るバイアス（偏り）が生じます。
母集団のすべての要素が等しい確率で選ばれるよう設計された「無作為抽出（ランダムサンプリング）」を徹底しなければ、どれほど高度な計算を行っても導かれる結論は砂上の楼閣と化してしまいます。

### 18 点推定と区間推定

標本データから母集団の平均値（母平均）を推し量るアプローチは、主に2通りです。

1つは、標本平均の値をそのまま使って「母集団の平均もズバリ50だ」と1つの数値で言い切る「点推定」です。
直感的で分かりやすい反面、別の標本をサンプリングし直せば平均値は容易に変動してしまうため、推定の「自信の度合い」を表現できません。

もう1つは、「母集団の平均はおそらく48から52の間にあるだろう」と幅を持たせて推定する「区間推定」です。
実務で頻繁に使われるのが「95%信頼区間」です。

ここで、信頼区間の解釈について重大な注意点があります。
「計算されたこの `[48, 52]` という区間の中に、真の母平均が含まれている確率が95%である」と解釈するのは、統計学的に厳密には誤りです。
真の母平均は、神のみぞ知る「決まった固定の定数」であり、動くのは私たちがサンプリングごとに計算する「信頼区間」のほうだからです。

正確な意味は、「もし同じサンプリングと区間計算を100回繰り返したとしたら、作られた100個の区間のうち、およそ95個が真の母平均を内部に捉えている」という、測定手順の信頼性の高さを表しています。
標本のサイズ（データ数 `n`）を増やせば増やすほど、推定のブレ（標準誤差）は小さくなり、信頼区間の幅をキュッと狭く絞り込むことができます。

### 19 仮説検定とp値

新しいWebデザインAと旧デザインBを比較し、「新しいデザインのほうが登録率が高い」と主張したい場面を考えてみましょう。
しかし、単にAのほうが数%高かったとしても、「それは単なる偶然の偏り（下振れ・上振れ）ではないか」という疑念を払拭できません。
この偶然性を科学的に白黒つける手法が **仮説検定** です。

仮説検定の論理展開は、裁判における「推定無罪」とよく似ています。

1. 帰無仮説を立てる: まず、自分の主張とは正反対の「新旧デザインで登録率に差などない（差はゼロだ）」という仮説（帰無仮説）をあえて立てる
2. データの珍しさを測る: 差がない世界を前提としたとき、手元で観測されたような大きな差が偶然生じる確率を計算する。この確率が **p値（p-value）** である
3. 判定を下す: もし p値 が極めて小さければ（通常 5% や 1% を下回れば）、「差がない世界でこんな珍しいことが偶然起きるのは不自然だ」と判断し、帰無仮説を捨てて（棄却）、対立仮説（差はある）を採択する

#### p値に関する最大の誤解

p値の意味を正しく理解することは、データ駆動型の意思決定において必須の素養です。
`p = 0.03（3%）` という結果が出たとき、次のような解釈をしては絶対になりません。

- 誤り1: 「帰無仮説が正しい確率が 3% である」
- 誤り2: 「新デザインが優れている確率が 97% である」
- 誤り3: 「この結果が偶然の産物である確率が 3% である」

p値とはあくまで、「差がないという前提のもとで、手元のデータと同等以上に極端な差が偶然生じてしまう確率」を表す数値にすぎません。
仮説そのものの正しさを確率として評価しているわけではない点に、細心の注意を払ってください。

#### 第1種の誤りと第2種の誤り

仮説検定の判断には、常に2つの誤りのリスクがつきまといます。

- 第1種の誤り（偽陽性 / あわてものの誤り）: 本当は差がないのに、「差がある」と誤って判断してしまうリスク。この許容上限としてあらかじめ設定する基準が「有意水準 `α`」（通常 5% など）
- 第2種の誤り（偽陰性 / ぼんやりものの誤り）: 本当は差があるのに、データ不足で見逃して「差がない」と判断してしまうリスク（記号 `β`）

有意水準を 5% から 1% へと厳しく設定すれば、第1種の誤りを確実に抑制できるでしょう。
しかしその代償として、わずかな改善効果を見落とす第2種の誤りが跳ね上がるトレードオフが生じます。
ビジネスの現場では、誤検知の損害と見逃しの損害を天秤にかけながら、適切なサンプルサイズと判定基準を設計しなければなりません。

## 関係を予測と判断に使う

### 20 相関関係と因果関係を峻別する

2つのデータの関係性を探る第一歩として使われるのが **相関関係** です。
一方の数値が増加したとき、もう一方の数値も連動して増加（または減少）する傾向を指します。
この直線的な関係の強さを -1から+1の範囲で表した指標が「相関係数」です。

- +1 に近い: 強い正の相関（一方が増えれば、他方も増える）
- -1 に近い: 強い負の相関（一方が増えれば、他方は減る）
-  0 に近い: 直線的な相関関係が見られない

ここで、データ分析における最も重要な金言を心に刻まなければなりません。
「相関関係は、必ずしも因果関係を意味しない」という事実です。

有名な例として、「アイスクリームの売上が増えるほど、水難事故の件数が増加する」という強い正の相関データがあります。
しかし、アイスクリームを食べるから水難事故が起きるわけではありません。
その背後には「夏の気温の上昇」という「交絡要因（第三の共通原因）」が潜んでおり、気温の上昇がアイスの売上と海水浴客（水難事故）の両方を同時に押し上げているにすぎないのです。

相関関係を見つけただけで安易に施策を打つと、巨額の投資を無駄にすることになります。
因果関係を証明するには、A/Bテストのような比較対照実験や、背景にあるメカニズムの解明が不可欠です。

### 21 回帰分析――関係性を数式にして未来を予測する

データ間の相関関係を一歩進めて、「一方の数値から、もう一方の数値を具体的に予測する数式」を導き出す手法が **回帰分析** です。

Web広告費 `x` を投入したときに、売上 `y` がいくらになるかを予測するシンプルな線形回帰モデルを考えます。

```text
y = a × x + b
```

ここで `a` は直線の傾き（広告費を1万円増やしたときの売上増加分）、`b` は切片（広告費ゼロのときの自然売上）を表します。

散布図の上に散らばる実際の測定点に対して、最もフィットする直線をどうやって引けばよいでしょうか。
実際の測定値と、直線が予測する値とのズレを「残差」と呼びます。
すべてのデータポイントにおける「残差を2乗した値の合計」が最小になるように傾き `a` と切片 `b` を計算する手法を **最小二乗法** と呼びます。

回帰直線が得られたあとも、モデルを盲信してはいけません。
過去のデータ範囲（例: 広告費100万円〜500万円）から大きく外れた極端な領域（例: 広告費1億円）へ無理に直線を延長して予測する「外挿（extrapolation）」を行うと、現実の飽和現象を無視した破綻した数値を弾き出す危険があります。

### 22 機械学習モデルの分類評価

AIや機械学習のモデルを使って、障害ログの検知や迷惑メールの判定（2値分類）を行う場合、その性能をどのように評価すべきでしょうか。

予測結果と実際の結果の組み合わせを整理した表を **混同行列（Confusion Matrix）** と呼びます。

| 実際の状態 | モデルの予測: 陽性（障害） | モデルの予測: 陰性（正常） |
|:---:|:---:|:---:|
| 実際: 陽性（障害） | 真陽性 (TP: True Positive) | 偽陰性 (FN: False Negative) （見逃し） |
| 実際: 陰性（正常） | 偽陽性 (FP: False Positive) （誤警報） | 真陰性 (TN: True Negative) |

この混同行列から、用途に応じた異なる評価指標が計算されます。

#### 適合率（Precision）
「モデルが障害だと予測したデータ」のうち、本当に障害だった割合です。

```text
適合率 = TP / (TP + FP)
```

誤警報（空振り）を極力出したくない場面で重視されます。
たとえばスパムメールフィルタにおいて、重要な顧客メールを誤って迷惑メールフォルダに放り込む事態を防ぎたいなら、適合率を高めるチューニングを行います。

#### 再現率（Recall）
「実際に発生していたすべての障害」のうち、モデルが漏れなく見つけ出せた割合です。

```text
再現率 = TP / (TP + FN)
```

見逃し（取りこぼし）が致命的な損失につながる場面で最重要視されます。
セキュリティ侵害の侵入検知や、人命に関わるがん検診の画像診断では、多少の誤警報（偽陽性）には目をつぶってでも、再現率を 100% 近くまで引き上げる設計が求められます。

#### 正解率（Accuracy）の落とし穴

全体の中で正しく判定できた割合が「正解率」です。

```text
正解率 = (TP + TN) / 全データ数
```

一見すると最も分かりやすい指標ですが、データに極端な偏り（不均衡データ）がある場合、正解率は完全に役に立たなくなります。

10,000件の通信ログのうち、不正アクセスがたったの 10件（0.1%）しか含まれないシステムを考えてみましょう。
もしAIが何の学習もせず、すべての通信に対して無条件に「正常です」と答えるだけのインチキなモデルだったとしても、正解率は `9,990 / 10,000 = 99.9%` という驚異的な高スコアを叩き出してしまいます。
しかし、このモデルは不正アクセスを1件も見つけられておらず、実務上は完全に無価値です。

不均衡なデータを扱う際は、正解率の高さに惑わされず、適合率と再現率、そして両者の調和平均をとった「F値（F1-score）」や、判定しきい値を変化させたトレードオフ全体を可視化する「ROC曲線（AUC）」を使って多角的に評価しなければなりません。

### 23 統計データを判断に活かすための実践的ステップ

統計学の数式を道具として使いこなし、正しい意思決定を下すためには、計算を始める前に次の思考ステップを踏むことが欠かせません。

1. 解くべきビジネスの問いを明確にする: 何を改善したく、どのような意思決定を下したいのか
2. 母集団を定義する: 自分たちが結論を適用したい範囲はどこからどこまでか
3. サンプリングの偏りを疑う: 手元のデータは、母集団を公平に代表しているか
4. 外れ値と欠損値の背景を調べる: 機械的な削除にとどまらず、なぜその異常値が生じたのかを洞察する
5. 適切な代表値と分布モデルを選択する: 平均値だけで語っていないか、前提条件に無理はないか
6. 相関と因果を混同しない: 第三の交絡要因が背後に潜んでいないかを徹底的に洗い出す
7. 誤った判断を下したときのコストを比較する: 見逃しの損失と誤検知の損失のどちらが重いかを見極め、判定基準を最適化する

冒頭で触れたバッチ処理の失敗例のように、全体を一括りにしただけの「失敗率 5%」という数字は、時に現場の真実を覆い隠してしまいます。
数字の向こう側にあるデータの成り立ちと背景条件を注意深く見つめ、不確実性の中から確かな示唆を紡ぎ出す姿勢こそが、エンジニアに求められる真のデータリテラシーなのです。
