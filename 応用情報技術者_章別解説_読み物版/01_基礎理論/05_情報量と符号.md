# 第1章5 情報量と符号――「分かったことの大きさ」を測る


## このファイルで初めて使う用語

本文で使う前に、ここでは次の意味を置きます。略語は正式名、日本語名、本文での役割の順です。

- **符号化**：情報を、保存・通信に適した記号列へ変換すること。（[詳説](<#7 符号化――対象をビット列へ対応させる>)）
- **可逆圧縮**：圧縮前と全く同じデータへ復元できる圧縮。（[詳説](<#11 可逆圧縮と非可逆圧縮>)）
- **非可逆圧縮**：一部情報を捨て、大きく小さくする代わりに完全復元できない圧縮。（[詳説](<#11 可逆圧縮と非可逆圧縮>)）
- **UTF-8**：Unicode Transformation Format 8-bit（Unicodeの8ビット符号化形式）。Unicodeの番号を1から4バイト程度の列で表す文字符号化方式。（[詳説](<#17 符号化の目的を混同しない>)）
- **ログ**：変更内容や処理履歴を順に記録したもの。（[詳説](<../02_アルゴリズムとプログラミング/17_コーディング規約・モジュール・品質.md#26 ログ>)）
- **遅延**：送信してから到着・応答するまでにかかる時間。（[詳説](<../07_ネットワーク/04_トラフィックと品質.md#5 遅延>)）
- **CD**：Continuous Delivery / Deployment（継続的デリバリ／デプロイ）。変更を、いつでも安全にリリース・配備できる状態へ保つこと。（[詳説](02_整数と負の数.md#この授業で分かること)）


## この授業で分かること

- 情報を、候補がどれだけ減ったかとして考える方法。
- 対数が何を求める計算か。
- 一つの出来事の情報量。
- 平均情報量であるエントロピー。
- 短いビット列でデータを表す符号化と圧縮。
- 誤りを見つけ、直すために余分なビットを加える理由。

## 1 知らせを聞く前と後を比べる

裏返したカードが八枚あります。一枚だけが当たりです。最初は、どのカードが当たりか分かりません。

```text
候補: 1 2 3 4 5 6 7 8       8通り
```

「当たりは左半分にあります」と教えられました。

```text
候補: 1 2 3 4               4通り
```

候補が八通りから四通りへ半減しました。この知らせには、分からない状態を一段減らす働きがあります。

さらに「その四枚の左半分です」と教えられます。

```text
候補: 1 2                   2通り
```

もう一回半分を教えられると、一枚に決まります。

```text
8候補 → 4候補 → 2候補 → 1候補
         1回      2回      3回
```

八候補を一候補へ絞るには、「はい・いいえ」で半分にする知らせが三回必要でした。この三回分の情報を3ビットと数えます。

一ビットには0または1の二通りを区別する力がありました。三ビットなら`2³=8`通りを区別できます。

## 2 「2を何回掛けるとその数になるか」

候補が16通りなら、半分にする質問は何回必要でしょうか。

```text
16 → 8 → 4 → 2 → 1
```

四回です。16は2を四回掛けた数です。

```text
2⁴ = 16
```

反対向きに、「2を何乗すると16になるか」を求める計算が**対数**です。

```text
log₂ 16 = 4
```

「ログ、底2の16」と読みます。小さく書かれた2を**底**と呼びます。

```text
2³ = 8   と   log₂ 8 = 3   は同じ関係を逆から見ている
```

| 候補数 | 必要な二択の回数 | 対数 |
|---:|---:|---:|
| 2 | 1 | `log₂2=1` |
| 4 | 2 | `log₂4=2` |
| 8 | 3 | `log₂8=3` |
| 16 | 4 | `log₂16=4` |
| 1024 | 10 | `log₂1024=10` |

候補数が二の累乗でない場合、完全に区別するための固定長ビット数は端数を切り上げます。五候補なら二ビットの四模様では足りず、三ビットの八模様が必要です。

## 3 珍しい知らせほど情報量が大きい

天気予報が「明日も普段どおり晴れです」と伝える場合と、めったに起きない大雪を伝える場合を考えます。

起きることがほぼ分かっていた出来事は、知っても候補があまり減りません。起こりにくい出来事が実際に起きたと知ると、多くの予想を捨てることになります。

確率`p`の出来事が起きたと知ったときの情報量`I`を、次の式で定義します。

```text
I = -log₂ p
```

`I`はinformationの頭文字、`p`はprobability、確率の頭文字です。単位はビットです。

### 確率1/8の出来事

```text
p = 1/8
```

`1/8=2⁻³`です。

```text
I = -log₂(1/8)
  = -log₂(2⁻³)
  = -(-3)
  = 3ビット
```

八通りが同じ確率なら、一つが起きたと知ることで八候補から一候補へ絞れるため、先ほどのカードと一致します。

### 必ず起きる出来事

確率1なら、起きる前から分かっています。

```text
I = -log₂1 = 0ビット
```

新しく減る候補がないため情報量は0です。

### なぜ先頭にマイナスがあるのか

0より大きく1以下の確率について、底2の対数は0以下になります。

```text
log₂(1/2) = -1
log₂(1/4) = -2
```

情報量を正の値にするため、先頭へマイナスを付けます。

## 4 なぜ対数を使うのか

公平な硬貨を二回投げ、二回とも表になる確率は次のとおりです。

```text
1/2 × 1/2 = 1/4
```

独立した出来事が同時に起きる確率は掛け算になります。一方、得た情報量は、一回目の一ビットと二回目の一ビットを足して二ビットと数えたいところです。

対数には、掛け算を足し算へ変える性質があります。

```text
log₂(x×y) = log₂x + log₂y
```

したがって、情報量を`-log₂p`と定義すると、確率の掛け算が情報量の足し算になります。

```text
-log₂(1/2×1/2)
= -log₂(1/2) + -log₂(1/2)
= 1 + 1
= 2ビット
```

底を2にするのは、0か1の二択を一ビットという単位にするためです。

## 5 平均すると、情報源全体の不確かさになる

出来事A、B、Cがあり、起きる確率が次のとおりだとします。

```text
A: 1/2
B: 1/4
C: 1/4
```

各出来事の情報量は次のとおりです。

```text
A: -log₂(1/2) = 1ビット
B: -log₂(1/4) = 2ビット
C: -log₂(1/4) = 2ビット
```

100回起きると考えると、Aは約50回、BとCは約25回ずつです。

```text
合計情報量
= 50回×1ビット + 25回×2ビット + 25回×2ビット
= 50 + 50 + 50
= 150ビット
```

一回当たりは次の値です。

```text
150ビット ÷ 100回 = 1.5ビット/回
```

確率を使って直接書くと次のとおりです。

```text
1/2×1 + 1/4×2 + 1/4×2 = 1.5
```

各出来事の情報量を、その出来事が起きる割合で重み付けして平均した値を**エントロピー**と呼びます。

```text
H = -Σ pᵢ log₂pᵢ
```

記号を一つずつ読みます。

- `H`: エントロピーへ付けた名前。
- `Σ`: 各出来事について全部足す。
- `i`: 何番目の出来事かを区別する名札。
- `pᵢ`: i番目の出来事の確率。
- `-log₂pᵢ`: i番目の出来事の情報量。
- `pᵢ`を掛ける: よく起きる出来事ほど平均へ多く反映する。

エントロピーが大きいほど、一回の結果を事前に予想しにくく、結果を区別するため平均的に多くの情報が必要です。

## 6 同じ四種類でも確率でエントロピーが変わる

四種類がすべて確率1/4なら、どれが出るか均等で予測しにくい状態です。

```text
H = 4 × (1/4 × 2) = 2ビット
```

一方、Aがほとんど出て、B、C、Dはめったに出ないなら、通常はAだと予想できます。珍しい結果自体の情報量は大きいものの、発生回数が少ないため、一回当たりの平均情報量は2ビットより小さくなります。

「種類が何個あるか」だけでなく、「各種類がどの程度の割合で出るか」が圧縮可能性を変えます。

## 7 符号化――対象をビット列へ対応させる

文字A、B、C、Dをコンピュータへ保存したいとします。各文字へビット列を割り当てます。この対応を作ることが**符号化**です。割り当てるビット列を**符号語**と呼びます。

四文字を同じ長さで表すなら、二ビットずつで足ります。

```text
A → 00
B → 01
C → 10
D → 11
```

文字列`ABCD`は`00011011`になります。

元のビット列から文字へ戻すことを**復号**と呼びます。

## 8 よく出る文字を短くする圧縮

Aが全体の半分、BとCが四分の一ずつ現れるなら、Aへ短い符号を割り当てたくなります。

```text
A → 0
B → 10
C → 11
```

Aは一ビット、BとCは二ビットです。平均の長さは次のとおりです。

```text
1/2×1 + 1/4×2 + 1/4×2
= 0.5 + 0.5 + 0.5
= 1.5ビット/文字
```

全文字を二ビットにするより、平均で短くなります。出現確率の偏りを利用してデータ量を減らす考え方が**情報源符号化**、つまり圧縮の土台です。

## 9 どこで一文字が終わるか

短い符号と長い符号を混ぜると、区切りが問題になります。

悪い例を考えます。

```text
A → 0
B → 01
```

ビット列`01`を左から読むと、最初の0をAと確定してよいのか、次の1まで読んでBとすべきか迷います。

ある符号語が別の符号語の先頭部分にならない性質を**接頭語条件**と呼びます。この条件を満たす符号が**接頭語符号**です。

先ほどの次の割当てでは、0を読んだ時点でA、1から始まればもう一ビット読んでBかCだと決められます。

```text
A → 0
B → 10
C → 11
```

符号の途中で別の文字を確定することがありません。

## 10 ハフマン符号

出現頻度の低い二項目から木へまとめ、よく出る項目を根に近くする方法が**ハフマン符号**です。

次の頻度を考えます。

```text
A: 50
B: 25
C: 15
D: 10
```

最も少ないCとDをまとめます。

```text
C 15 + D 10 = 25
```

残りはA 50、B 25、CD 25です。BとCDをまとめて50にし、最後にA 50とまとめます。

```text
          100
         /   \
      A 50    50
             /  \
          B 25   25
                / \
             C 15 D 10
```

左の枝を0、右を1とすれば、一例として次の符号になります。

```text
A → 0
B → 10
C → 110
D → 111
```

よく出るAが最短、珍しいCとDが長くなります。葉に到着した時点で一文字が終わるため、接頭語条件を満たします。

左右の0と1を入れ替えても平均長は変わりません。大切なのは木の深さです。

## 11 可逆圧縮と非可逆圧縮

圧縮後から元データを一字一句同じに戻せる方式を**可逆圧縮**と呼びます。プログラム、文章、帳簿など、変更が許されないデータに必要です。

人が気付きにくい情報を捨て、元と完全には同じでない代わりに大幅に小さくする方式を**非可逆圧縮**と呼びます。写真、音、動画などで使われます。

非可逆圧縮は「適当に壊す」ことではありません。人の視覚や聴覚、用途に応じ、影響の小さい情報を選んで減らします。ただし再保存を繰り返すと劣化が増える場合があります。

## 12 通信では、わざと余分な情報を加える

圧縮では余分さを減らしました。しかし通信中に一ビットが変わった場合、余分な手掛かりがなければ誤りかどうか分かりません。

そこで、誤りを見つけたり直したりするため、意図的に余分なビットを加えます。これが**通信路符号化**です。

```text
情報源符号化  余分さを減らし、短くする
通信路符号化  誤り対策の手掛かりを加える
```

目的は反対に見えますが、どちらも対象とビット列の対応を設計しています。

## 13 パリティ――1の個数で誤りを見つける

データ`1011001`には1が四個あります。1の個数が偶数になるよう検査用一ビットを加える方式を**偶数パリティ**と呼びます。

既に偶数なので、パリティビットは0です。

```text
データ       1011001   1が4個
パリティ     0
送信         10110010  1が4個
```

通信中に一ビットだけ反転したとします。

```text
受信         10100010  1が3個
```

1の個数が奇数なので、誤りがあったと分かります。

ただし二ビットが同時に反転すると、1の個数が再び偶数になり、見逃す場合があります。また、誤りがあることは分かっても、どのビットが違うかまでは分かりません。

## 14 CRC――割り算の余りを検査値にする

複数ビットの並びを多項式に対応させ、決められた生成多項式で割った余りを付ける方法が**CRC**です。Cyclic Redundancy Check、巡回冗長検査という意味です。

受信側も同じ計算を行い、余りを確認します。単純なパリティより、連続した複数ビットの誤りなどを検出しやすくなります。

CRCは、通常、偶然の伝送誤りを見つけるためのものです。攻撃者が内容とCRCを意図的に両方書き換えることを防ぐ暗号学的な改ざん検知とは目的が違います。

## 15 ハミング距離――符号語が何ビット違うか

二つの同じ長さのビット列について、異なる位置の個数を**ハミング距離**と呼びます。

```text
101101
100001
  ↑↑      2か所が異なる

ハミング距離 = 2
```

正しい符号語同士を十分離しておけば、途中のビットが少し変わっても、どの正しい符号語に近いかを判断できます。

最小ハミング距離が`d`の符号は、一般に次の能力を持ちます。

- `d-1`個までの誤りを検出できる。
- `floor((d-1)/2)`個までの誤りを訂正できる。

`floor`は小数以下を切り捨てる操作です。

たとえば最小距離3なら、二ビットまでの誤りを検出でき、一ビットの誤りを訂正できます。

## 16 ハミング符号――誤りの位置を求める

検査ビットを複数置き、それぞれが異なる位置の組を調べると、どの検査に失敗したかの組合せから誤り位置を推定できます。この代表が**ハミング符号**です。

一つの検査ビットだけでは「どこかが違う」としか分かりません。複数の検査を重ねると、住所の「都道府県、市区町村、番地」のように位置を絞れます。

検査能力が高いほど、通常は加える余分なビット、計算、通信量も増えます。許される誤り率、再送できるか、遅延、データ量から方式を選びます。

## 17 符号化の目的を混同しない

同じ「符号」という言葉でも目的が違います。

| 目的 | 何をするか | 例 |
|---|---|---|
| 文字表現 | 文字へ番号・ビット列を割り当てる | Unicode、UTF-8 |
| 圧縮 | 平均データ量を減らす | ハフマン符号 |
| 誤り検出 | 通信中の変化を見つける | パリティ、CRC |
| 誤り訂正 | 誤り位置を推定して直す | ハミング符号 |
| 暗号化 | 鍵なしでは内容を読みにくくする | 第8章で学ぶ |

圧縮しても秘密になるとは限りません。CRCを付けても悪意ある改ざんを防げるとは限りません。名前ではなく、何を保証する仕組みかを確認します。


## 応用情報技術者試験での扱われ方

- **典型設問:** 「八候補を二択で一候補へ絞るのに三回必要な理由を説明してください。」
- **条件語:** `符号化`を本文の定義と対応させます。
- **最初の着眼点:** 理由を求める対象を特定し、原因→仕組み→観測される結果の鎖を作ります。
- **途中の組立て・式:** 本文の成立条件を原因へ、処理や構造を仕組みへ、利点・欠点を結果へ対応させます。 本文の `2³=8` を使います。記号、単位、成立条件を置いてから代入し、結果の意味まで答えます。
- **典型誤答と理由:** 『速い』『安全』など結果だけを書くと、どの仕組みがなぜ効くのか、例外条件が説明できません。


## 18 確認問題

1. 八候補を二択で一候補へ絞るのに三回必要な理由を説明してください。
2. `log₂32`を求めてください。
3. 確率`1/16`の出来事の情報量を求めてください。
4. 必ず起きる出来事の情報量が0になる理由を説明してください。
5. 情報量で対数を使う理由を、確率の掛け算と情報量の足し算から説明してください。
6. Aの確率が1/2、BとCが各1/4の情報源のエントロピーを求めてください。
7. 接頭語条件が必要な理由を説明してください。
8. 可逆圧縮と非可逆圧縮を、使うデータの例とともに区別してください。
9. 圧縮と通信路符号化は、余分な情報をどう扱う点が反対ですか。
10. 偶数パリティで、データ`1100101`へ付けるパリティビットを答えてください。
11. パリティだけでは二ビット誤りを見逃す場合がある理由を説明してください。
12. 二つのビット列`101010`と`111000`のハミング距離を求めてください。
13. CRCと暗号学的な改ざん検知を同じものと考えてはいけない理由を説明してください。

   **結論:** 一回で候補が半分になるため、`8→4→2→1`と三回必要です。また三ビットで`2³=8`模様を区別できます。
   **この誤答が起きる理由:** 『速い』『安全』など結果だけを書くと、どの仕組みがなぜ効くのか、例外条件が説明できません。
   **戻る本文:** [なぜ先頭にマイナスがあるのか](#なぜ先頭にマイナスがあるのか)で、定義・条件・例を再確認します。
2. **解法の入口:** 求める量と単位を先に書き、問題文の数値を同じ単位へそろえます。 問題は「`log₂32`を求めてください。」です。
   **途中手順:** 既知量→使用する関係式→代入→単位付き結果の順に進めます。 結果は「2⁵=32なので5です。」と照合します。
